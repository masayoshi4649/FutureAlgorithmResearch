## フォルダとデータ

| 場所 | 内容 |
| --- | --- |
| `App/E01` | E01のGoソース、設定、仕様、配布物。 |
| `アルゴリズム調査` | 作業ごとの図解、報告書、検証結果、再現資料。 |
| `book` | セッションごとの生オーダーブックデータ。 |
| `candle_1min` | `book`を1分足に集約したデータ。 |
| `candle_5min` | `candle_1min`を5分足に集約したデータ。 |
| `work` | 調査用の作業ファイル、中間結果、補助プログラム。 |
| `保存データ` | 大量データを圧縮・分割したGit保存用ファイルと検証用の目録。 |
| `管理ツール` | 保存計画の作成、保存データの圧縮、検証、復元を行うツール。 |

`book`、`candle_1min`、`candle_5min`は同じ市場データを異なる粒度で表したものです。これらは読み取り専用として扱い、作業ファイルは`work`に保存します。

## Gitでの保存形式

ソース、調査HTML、小さな資料、40MiB未満の作業用ソースは元のパスでGit管理します。ファイル数・容量が多い生板と作業データ、40MiB以上の調査資料は、元のパスとSHA-256を記録した圧縮データとして`保存データ`に保存します。48MiB未満のHTMLは直接保持します。1つの分割ファイルは48MiB以下です。

元ファイルはローカルに保持します。新しく取得したリポジトリでは、[復元手順](Git保存と復元.md)を実行すると元のフォルダ構成へ戻せます。ブラウザプロファイル、仮想環境、キャッシュなどの一時ファイルは保存対象から除外します。保存範囲は[公開保存計画](保存データ/保存計画.json)、[検証用目録](保存データ/manifest.json)、[保存対象外の一覧](保存データ/保存対象外.json)で確認できます。

## 変更を送信する

ソースや文書の通常の変更は次の手順で送信します。

```powershell
git add -- App README.md
git commit -m "ソースと資料を更新"
git push origin main
```

圧縮保存の対象データを追加・変更した場合は、[Git保存と復元](Git保存と復元.md)に従って保存計画を更新し、再圧縮と検証を行ってから送信してください。
