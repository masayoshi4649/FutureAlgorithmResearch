# 二市場の即時板入力

最初に [入力と即時板特徴の仕様.json](入力と即時板特徴の仕様.json)、次に [入力十分性集計.json](入力十分性集計.json) を読みます。[保存範囲と追加時計.json](保存範囲と追加時計.json) は共通29場と追加TOPIX単独1場の区別です。単独追加場にはNK原本がなく、本検証へ補完しません。

[固定入力の因果検査.json](固定入力の因果検査.json) は全58口座の途中切断・未来側の価格/板/OFI改変に対する過去不変性です。遅延3水準で30,972配列が欠損込みで厳密一致しました。人工板・同時計先頭・ゼロ分母・同一始終行・途中resetも検査済みです。これは代理時計上の検査であり、共通受信時刻の存在を証明するものではありません。

旧69・71の価格と最良OFIは読み取りで再利用します。新しい `snapshots.pkl` は全58口座の旧 `ready.seq` と1対1です。各行の原本10段から、最良数量偏り、数量加重中値代理、最良からの呼値距離に `1/(1+距離)` を掛けた深さ偏りを計算しました。各側の最良価格を距離0とします。欠損段・価格逆転・負数量は無効、最良以外の数量0は有効です。

数量加重中値は `(bid×askQty + ask×bidQty)/(bidQty+askQty)`。厚い買板ならask寄りになります。その中値からの差は最良数量偏りと代数同値なので、独立した二つの根拠にはできません。較正した将来価格モデルではありません。

`grids.pkl` は `delay → session → {grid, markets}` です。遅延は1・5・15秒。判断グリッドは開始300秒後から安全撤収目安60秒前を含む5秒刻みです。新規禁止は目安300秒前以後、保有判断は目安60秒前までと、算法側で区別します。

`markets[symbol].current` に参照行・古さ・8板スカラー・気配差があります。参照は `time < grid-delay` の同時刻先頭、期限から30秒以内、非reset、気配差2呼値以内だけです。実受信時計がないため、代理時計上の過去対応に限ります。

`markets[symbol].windows[5/15/30/60]` に始終行、実観測秒数、両気配移動、中値変化、板偏り変化、最良OFI符号比があります。`source_valid` は始終点が異なる行で途中切断がないこと。`valid` はさらにOFI欠損がなく絶対和が正であることです。同一行、ゼロ分母、欠測を別フラグにしています。`nonzero_ofi_count` が3未満なら情報不足として算法側で判断します。

主5秒遅延では、両市場の即時板が使えるのは共通201,101判断中151,042判断（75.1%）です。両市場のOFIが有効かつ非ゼロイベント各3件以上の比率は、予定5/15/30/60秒窓で23.7%/45.3%/52.1%/43.2%。予定5秒窓の実時計差の中央値は両市場とも6秒、最大34秒でした。最終約定時計の離散性により、正確な5秒の受信履歴と解釈できません。

算法から [prepare.py](prepare.py) の `material()` を呼ぶと `ready, book, snapshots, grids` が得られます。[core.py](core.py) の `snapshot_values` は原本1行だけ、`market_features` は片市場の窓特徴、`session_features` は共通グリッドを作ります。途中切断検査ではこれらを短い入力で再呼出しできます。

抽出の再実行は `python -X utf8 work/wave_v76/inputs/prepare.py`。最大4並列で原本の同連番を照合し、58原本の指紋一致も確認します。既存入力、原本、過去成果は変更しません。API取得・実注文・損益参照は0です。

固定入力検査のみの再実行は `python -X utf8 work/wave_v76/inputs/check.py`。準備済み配列とコードの内容指紋も証跡へ保存します。
