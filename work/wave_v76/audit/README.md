# 二市場の短期板支持と途中判断の独立監査

最初に読む資料は [全996条件と固定遅延84条件の会計選定独立監査.json](全996条件と固定遅延84条件の会計選定独立監査.json) です。主996条件と事前に定めた遅延感度84条件、合計1,080条件の全58口座を検算しました。62,640口座、1,126,682決済明細、2,253,364注文、2,870,640会計項目の比較で不一致はありません。

## 判定と限界

- 買い約定は次の有効原本行の売気配、売り約定は買気配。新規・返済の双方に注文ごとの切捨て手数料を課し、全決済損失を計上しています。TOPIXminiは片方向10枚、NK225microは20枚です。
- ドテンは旧玉の返済実約定後、その時計より新しい共同格子で反対支持を確認してから発注し、さらに次の有効原本行で新規約定します。返済と新規は別注文・別手数料です。
- OFIがゼロ又は有効変化3回未満の場合は、観測できた支持不足です。真の欠測、窓始終が同一原本行の場合は無効で、確認時計を進めません。M3の支持消失は両市場の支持が揃わない状態を意味し、片側不足も含みます。
- 予定撤収時刻を超えた返済は条件の重複を含め3,475件、最大240秒。すべて保存監視終端より前に実返済しています。判断から次有効原本行への最大約定待ちは28秒です。予定時刻で必ず約定できるという保証ではありません。
- 前16場だけで代表を選び、後13場や遅延感度で選び直していません。全29場は既知保存データで、真の未見期間ではありません。
- 共通受信時計がないため、最終約定代理時計の厳密な過去参照と原本行順を監査しています。二市場の実受信順の完全な因果性、将来収益性を証明するものではありません。
- 原本の再取得・API取得・実注文はありません。生板の式検算は入力担当が添付した同じ原本のサンプルと指紋を使っています。

## 再検査用スクリプト

`full_inputs.py` → `full_states.py` → `full_accounts.py` → `future.py` → `diagnosis.py` の順です。`engine_synthetic.py` と `model_synthetic.py` は人工経路の検査です。全会計は条件単位の6並列で処理します。`full_accounts_sequential.py` は並列化前の同一会計計算を保存した資料です。

本フォルダだけを追記し、凍結済み研究コード・入力・過去成果を変更していません。
