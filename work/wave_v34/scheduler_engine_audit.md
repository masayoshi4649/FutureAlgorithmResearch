# 仮想準備行との同期注文器：実装監査

`engine_scheduler.py` は v33 の注文器から生成した別版である。売買を変える条件追加は、新規準備時の `prepare_allow[i]` のみ。既設注文・保有管理・部分返済・全玉会計の順序は変更していない。

合成 9 項目と、既知 H019 の全 26 区間で通常方式の互換検査を通過した。

| 検査 | 完全一致した入力数 |
| --- | ---: |
| 通常 A0 と v33 の旧 6 結果 | 26 |
| 通常 At と v33 の旧 6 結果 | 26 |
| A0 制御と通常 A0 の全結果 | 26 |
| 新規約定から実準備・影準備への対応 | 26 |

旧 6 結果は返済・組・時価曲線・全注文・集計・ATR 状態である。金額だけではなく、全配列の全要素を比較した。追加の準備・起点台帳も A0 恒等対照では一致した。

合成検査では、実先返済、影先返済、保有中と自身の休止中の見送り、見送った未約定への途中参加禁止、許可が消えた後の既設注文継続、期限失効後の新設、同一時刻の行順、飛値、部分返済、場末、欠測を確認した。3 人工相場に固定/現在幅と指定/観測価格を組み合わせ、売買反射と全注文からの現金・保有再構築も照合した。

影を含めた未来価格・入口 ATR・追跡 ATR・方向の削除/改変でも、過去の許可・両運転・注文・返済は変わらない。許可が全て False なら新設しない一方、既に許可行で準備した注文は次の許可を必要とせず通常どおり追跡・約定する。

最初の合成実行では、監査側の A0 恒等比較に観測約定フラグを渡し忘れたため比較が停止した。監査呼出だけを修正して全検査を再実行した。注文器の生成後ソースは変更していない。

新しい At 制御の実相場格子・損益順位は計算していない。現在 API は 0 回、現在保存物も未使用、読取元の指紋は前後不変である。
