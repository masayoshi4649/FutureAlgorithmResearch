# T/R選択器の実装前レビュー

**設計レビューのみ。実装・再生・新規条件の探索・採用は行っていない。** 現在API・保存ライブは未使用。結論は、T/Rの二択自体より、**同じ口座で切替を適用する規則と、参加時刻の対照を先に固定する必要がある**ということ。v28案の数値を今回の結果で調整しない。

## 最小比較は4本＋取消対照2本

T固定・R固定・A・Bを主比較とする。枚数、入口注文、部分利確、追跡、5分休止、場末処理はD273で共通にする。A/Bの出口だけを都合よく変更しない。

これに**Aの要求IDは動かすが入口方向は常にT、又は常にR**という2本を加える。同方向のID変更でも旧注文を取り消すため、選択の利益に見えたものが「古い注文の取消・再準備・待機」の効果だけではないかを調べる対照である。実際のAの約定時刻をコピーせず、同じ因果的な要求ID列を各対照の口座状態へ適用する。したがって約定回数や実適用時刻まで同じとは主張しない。Bは場初のフラット時だけ切り替えるため、この取消対照を重複追加しない。

v31ではH019/TOPIXのW060が、元より保有枚数分を減らしながら新規50→83、収支+521,000→−122,000円となった。**取引を待つ操作は、初期の利益を削除するだけではない。** また全12入口とEMA統合5思想で対照差の符号が変わった。固定T/Rとの差だけを、選択情報の予測力と読まない。[参加診断](h019_participation_note.md)

## 注文と建玉の所有規則

以下を全比較で一つの状態機械として実装する案とする。現在の方向列を貼り合わせるだけでは不十分。

1. **要求ID、適用ID、注文所有ID、建玉所有IDを別々に保存する。** 場初にAはT、Bは過去から選んだIDへ初期化し、存在しない旧注文の取消待ちは作らない。要求IDは両市場共通でも、適用は各銘柄のフラット時。片方が保有中なら適用IDは一時的に異なる。保有中の要求は最新の一つだけ残し、過去の要求を返済後に順次実行しない。
2. **前行から有効な注文を先に処理してから、現在行の選択を判定する。** 同じ行で約定した旧注文を、新しい要求で遡って取り消さない。約定した玉は旧注文の所有IDを引き継ぐ。
3. **保有中は所有IDと共通出口を保持する。** 要求の変更・反対方向・入口中立だけでは返済しない。部分利確後の残玉も同じ所有ID。切替による建値・初期ATR・最高利益・損失の初期化は禁止する。
4. **フラットで適用IDを変更するときは、方向が同じでも旧未約定注文を取消する。** 旧注文があれば行iで取消判断、次原本行の先頭で旧注文を失効させて取消確認、その後に新IDの現在方向から新規準備する。新規約定はさらに次行以降。旧注文がなければ余分な取消待ちは作らず、行iで準備・次行以降に約定可。価格の追跡端点・ATR・注文期限は新規準備時に再設定し、旧注文の有利な価格だけを引き継がない。同じIDを継続する場合には再設定しない。
5. **完全返済時刻から5分の休止を、ID・方向を変えても維持する。** 損切り・利確・時間返済で共通。部分返済では時計を開始しない。取消確認と休止終了の両方を満たした後にだけ新規準備できる。切替で帳簿や停止状態をリセットしない。
6. **場末返済を優先する。** 日中15:35／夜間05:50の判断から次行で全返済し、翌セッションへ玉・未約定注文を持ち越さない。場末後のID変更で新規を復活させない。価格飛びに対する損失額の保証とは呼ばない。

取消対照でも「仮の切替ID」と実際の入口源を別記する。利益帰属は約定時に表示されていたIDではなく、注文作成元・建玉所有者で集計する。旧X05ではこの二つが異なる実例があった。[旧監査](../wave_v24/logical_audit.md)

## 因果時計と評価期間を揃える

- **Aの未確定点を実装前に解消する。** v28案のER30・0.35/0.20・30分時計・2回確認を採るなら一組だけ固定。確定1分足は既存どおり足始時刻＋120秒で公開し、31本が揃うまでT。共通の要求IDには両市場とも公開後さらに60秒経過したERを使う案とし、銘柄により片方だけ新しいERを使わない。二度の確認には別の公開足を要求し、欠測・新足なしは確認回数を解除して現IDを保持する。最初に切替可能となる時刻も表にする。31本準備＋30分刻みのため、単純な「30分後に適応」ではない。
- **Bは双方の当該セッションを丸ごと学習外にする。** 最初6完了区間で初期化し、次7区間を共通評価。片方だけ先に返済した当該区間の実績を混ぜない。基準Rは両手法共通の開始20分後の利用可能ATR・固定枚数で決め、どちらか欠測ならその区間全体を学習から外す。T/R影口座は毎区間の場初から同じルールで動かす。実際に選ばれた枝の損益だけで学習しない。
- **4主比較と2取消対照を同じ後半7区間で比較する。** 全13区間は別の再現表。指定4波の多くは初期化側なので、7区間の評価証拠へ混ぜない。T/R自体も既読期間で選んだ部品であり未知検証ではない。日別にA/Bの良い方を後から選ばない。

## 実装前に決める反証と停止条件

最低限、固定IDならT/R旧台帳と一致、同方向ID変更、取消と約定の同時成立、損切り直後の切替、部分利確後の切替、片市場だけ保有、同時刻複数行を合成検査する。未来の足・板・影口座成績を削除／改変して過去の要求・適用・全注文が不変であることも必須。

実データでは、全玉損益・含み込みDDに加え、枝別の新規起源、選択時間と実適用時間、無建玉時間、買売枚数分、取消数、再準備数を保存する。選択しても一枝が発火しない、切替が一度も適用されない、固定R又は取消対照で同等以上なら、**その結果だけではT/R適性選択の効果を支持しない**。

要求IDだけの固定乱数対照はv28案の反証枠として残すが、実際の取引後に判明した切替回数・占有率を乱数へ与えない。正式なp値や新しい候補ランキングにしない。小さな遅延と観測価格約定は独立の補足軸とし、良かった遅延へ差し替えない。採否の数値目標は実行前に別途固定し、このレビューでは新しい閾値を最適化しない。

**未解決なのは「ER又は過去成績が、次にどちらを使うべきかを予測できるか」。** v31は情報鮮度と参加経路への依存を示したが、切替器の必要性も実用性も証明していない。まず上記の小さな比較でこの一問に答え、失敗後に枝・窓・出口を追加して同じ試験を救済しない。
