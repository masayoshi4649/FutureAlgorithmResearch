# 方向情報の鮮度と開始遅れを分ける固定診断

**今回の420条件は新候補を探す順位戦ではない。方向が古くなった影響と、参加開始が遅れた影響を調べ、既存候補の説明を確かめる。良かった遅延へ採用案を交換しない。**

元はv30の12入口×7管理＝84条件、既知13セッション・両銘柄のみ。5変形で420条件、10,920入力を全件保存する。元84の評価は維持し、今回の補助対照を根拠に採否を塗り替えない。追加API・現在保存物の参照は行わない。

## 5変形と変えないもの

原本行時刻をt、入口方向をE(t)、実際に保有へ使う方向をC(t)とする。Cには両確認又は自己のみを、元管理の指定どおり使う。B0はcontextを渡さない。

| ID | 入口 | 保有context | 目的 |
|---|---|---|---|
| V000 | 元E(t) | 元C(t) | 旧84の厳密再現 |
| V030 | E(t−30分) | C(t−30分) | 方向情報を30分古くする |
| V060 | E(t−60分) | C(t−60分) | 方向情報を60分古くする |
| W030 | 開始ゲート前0、以後E(t) | 同じゲート前0、以後C(t) | V030と同じ入口の遅延列から、開始できる時刻だけを移す |
| W060 | 開始ゲート前0、以後E(t) | 同じゲート前0、以後C(t) | V060の開始遅れに対応する補助 |

遅延は同じセッション・銘柄の配列内で、t−遅延以前の最後の原本行を過去asof参照する。先頭不足は0。補間・未来の近隣値・前セッションの値を使わない。同時刻が複数ある場合は、その過去時刻の最後の原本行を参照する。V000はasof処理へ回さず元配列をそのまま渡す。

Wのゲートは、同じ遅延Eが初めて非0になった観測行で開く。各セッション・銘柄で累積ORを更新し、一度開いたら閉じない。以後のEが0になってもゲートは維持する。最後まで遅延Eが非0にならなければ、そのWも全て0。両銘柄を同時に開く規則や、将来の最終非0時刻を見て開く規則にはしない。

**古くするのは方向情報だけ。** 価格・注文準備時ATR・既存価格注文・追跡極値・時刻・約定処理は、その時点の現行値を使う。過去価格へ戻して約定させない。枚数、入口追跡幅、損切り、部分利確、追跡、時間上限、休止、セッション内返済を変更しない。新規成立・撤回判断・約定の次行規則も元engineのまま。

## 分けられることと分けられないこと

主な対応差は、同一H・L内のV030−V000、V060−V000、W030−V000、W060−V000、V030−W030、V060−W060。全件を示し、平均又は中央値だけで最良例を選び直さない。

Wは**開始遅れの補助対照**であり、Vと参加時間を完全一致させた対照ではない。ゲートが開くときに現在Eが0又は逆方向のことがあり、初回約定も一致しない。その後の非0時間、方向転換、退出、再新規も異なる。したがってV−Wを「情報鮮度だけの因果効果」と断定しない。W−V000も、最初の一定時間の利益だけを引いた値ではなく、その後の注文経路まで変わる差である。

| 結果 | 言える範囲 |
|---|---|
| Vが悪くWも同程度悪い | 開始遅れ・参加減で説明できる可能性。情報の古さが無害と確定はできない |
| Vが悪くWは近い | 開始遅れ以外の、古い方向による保有・再新規の変化が重要である可能性 |
| Vが元と近く、実際の方向や売買もほぼ同じ | 方向の持続性のため比較が実質的に変わっていない。鮮度不要を実証したとは言わない |
| Vが元と近いが売買は異なる | この既知経路では細かな時刻一致がなくても近い収支。ただし損失経路・保有量・集中も比較する |
| V又はWの収支が良い | 遅い参加や露出変化が有利だった可能性。良い遅延を新手法へ昇格しない |
| V又はWが未稼働 | その経路では機会を失った診断結果。損失0を性能向上とは呼ばない |

両銘柄の円額を足して判断しない。420条件や13×2入力を独立標本と見なさず、既知期間内の機構診断として扱う。

## 全件で残すもの

各セッション・開始週・全期間の利益／損失／収支、勝ち／負け／同値決済枚数、最大下落、組数を表示する。加えて、入口と使用contextの非0時間、元との方向一致・反対・中立の時間、最初の非0時刻、Wゲート時刻、初回約定、保有時間・枚数×時間、買売別保有、再新規数を残す。非0方向行数を保有時間の代わりにしない。

指定4波×2銘柄は全420手法で3,360区間。V000に旧84が全て含まれるため別の旧比較を追加しない。20分目安とともに実際の保有時間・損益を表示し、波の結果で対象を間引かない。

同じ波の遅れを検査するため、波の時刻・終了時刻を遅延分ずらさない。注文器にも波区間を渡さない。時間が経ったのでセッション終了を遅らせることも禁止する。

## 結果前の監査と完備判定

1. 全84元仕様、5変形、原本入力・方向・エンジンの指紋を固定する。旧コードは変更しない。
2. V000の全84台帳・26入力会計・期間集計がv30と一致する。IDの変化以外の損益差を許さない。
3. 遅延及びWゲートは複数prefix切断・未来価格／方向変更・同時刻行・先頭不足・無信号・上下反射で検査する。Wのゲートは一度だけ開き、未来末尾に依存しないことを確認する。
4. 全420×26の全玉会計・上限・場内返済を検査し、保存明細から集計を再計算する。指紋・一意ID・入力集合・非有限値を照合する。
5. 参加量は実際の約定後在庫を次行まで積分し、波は固定区間へ切って積分する。同時刻行の持続時間は0。未約定方向と保有を混同しない。
6. 全420の結果、10,920入力の参加量、3,360波と各監査が揃った場合だけ「診断完了」とする。選抜ファイルや新しい採用閾値を作らない。不利・未稼働・元と同一の対照も完備対象に含める。

今回は全件へ一次反証・乱数をもう一度大量に掛ける設計ではない。因果性・会計・旧台帳再現・参加差・指定波を確認する。元候補の過去の反証資格を、今回の収支だけで強化・解除しない。
