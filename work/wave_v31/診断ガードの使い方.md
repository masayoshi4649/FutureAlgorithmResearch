# 診断ガードの使い方

新しい採用候補を選ぶ処理ではない。元84条件と補助336条件を欠けなく診断する。

## 主再生の起動

`python -X utf8 work/wave_v31/run_verified.py --workers 12`

全312入力の損益前構造監査、原本78ファイル、元入口・保有方向36ファイル、実装・固定仕様の指紋を検査してから、固定済みrunnerを起動する。全420を再計算し、既存結果のキャッシュは利用しない。前後の指紋と起動の完了は `主再生の起動証跡.json` に保存する。`--prepare` を付けると検査だけで売買再生は行わない。

## 全資料の完備確認

独立会計、波・参加、図示の資料がすべて揃った後に実行する。

`python -X utf8 work/wave_v31/completion_guard.py`

確認対象は全420条件・10,920入力・3,360波、V000の旧84一致、全独立会計実体、参加の全期間／開始週／1,008対応差、事前固定H019全35条件の910図。各資料の全件集合、明細からの再集計、台帳指紋、読み始めと読み終わりの資料指紋を照合する。

全件一致した場合だけ `診断完備の監査.json` に `診断完了: true` を保存する。`ガード実装SHA256` と `参照資料SHA256` が、表示した完了状態の根拠である。資料を後から再生成した場合はガードを再実行する。

ガードの正常系と欠損・重複・偽要約・会計不整合の拒否は `run_verified_test.json` と `completion_guard_test.json`。これらは完備性を検査し、未知期間の利益や採用適性を保証しない。実装の因果性と会計は別の独立監査が全420条件を再生して確認する。
