# 遅延方向と待機対照の独立監査計画

損益による対象選別を行わず、12入口×7管理×5変形の全420条件を対象とする。既存コード・原本は変更せず、現在データとAPIは使用しない。

## 損益前の構造検査

- V000は同一原本行の入口・C・Sに一致させる。時刻が同じ後続行を拾う0秒asofは禁止。
- V030/V060は各原本行の時刻から30分/60分を引き、その時刻以下で最後の過去行だけを参照する。参照候補がなければ0。独立な二ポインタ処理と実装を照合する。
- 参照行は常に現在行以前でなければならない。同値時刻の行、時刻の飛び、先頭・末尾、境界ちょうどを合成データで検査する。
- W030/W060の開始フラグは対応する遅延入口の非0を過去から累積したものとする。フラグの前は入口・C・S全て0、以後は現在の入口・C・Sと一致させる。C/S独自のフラグや未来の最初の発火時刻を使わない。
- 切断入力での再生成、未来方向値の変更、売買方向の反射、正の時間平行移動に対して過去の出力・対応関係が不変であることを全入口・全区間で確かめる。
- 価格・ATR・時刻・seqを遅延変換が変更していないことを確認する。エンジンへ渡すATRは注文判定時点の既存因果ATRである。
- 遅延と待機は参加時刻・中立時間・保有撤回・約定時点も変える。結果差を方向情報の鮮度だけの純粋な因果効果とは呼ばない。

## 生成後の全件会計

- 420×26＝10,920入力全てについて保存入口・C・Sを原変形から照合し、管理の使用contextを読み分ける。
- 全注文から現金、買売在庫、元建値、部分利確、残玉、全原本行時価、最大下落を再構成する。片方向枚数上限、次行以降約定、場内完結を検査する。
- セッション・期間集計の全数値、欠損比率の意味、返済台帳SHAを保存結果と照合する。Rは記録ATRと初回枚数・固定損切り幅の整合を検査する。
- 各入力で37%切断と別点73%以後の価格・ATR・入口・使用context改変、上下反射を行う。変形生成自体の因果性と執行器の因果性は分けて検査する。
- V000全84条件は旧v30結果と一致させる。凍結資料と原本78ファイルのSHAを監査前後で確認する。

構造検査・会計検査の合格は未知期間の収益性や円損失の上限を保証しない。
