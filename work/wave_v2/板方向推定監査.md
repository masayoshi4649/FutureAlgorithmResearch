# 板の約定方向推定出来高の独立監査

結論: 全六ファイルで、生板から別実装により再計算した一分ごとの出来高差分と符号付き出来高が、板特徴ＣＳＶと完全一致した。累積出来高の二重計上、次ブロックの価格による過去方向の書換え、セッション越境の混入は今回の保存データでは検出されなかった。これは約定方向の推定精度や未知データでの売買成績を保証する判定ではない。

## 独立再計算の方法

本体の Extractor を使わず、生板から約定時刻・現在値・累積出来高・出来高時刻だけを別に読み取った。セッション範囲内の順序列について累積出来高の差分を取り、価格差の符号を前方向にだけ持ち越してティックルールの方向を再計算した。各差分を次の異なる約定時刻の一分枠へ割り当て、その次時刻を持たない末尾群を破棄した。全一分枠で volume_delta と signed_volume の両方をＣＳＶと照合した。

## 二重計上と時刻の扱い

同じ CurrentPriceTime の中でも複数の累積出来高増加が実在する。最初と最後の差だけを各行で繰り返し足す方式ではなく、常に直前行との差を足している。同じ累積値の再送・板だけの更新の差分は0である。正の複数差分は合計するとブロック端点の差へ戻るため、同じ時刻の追加約定を落とさず、同じ出来高を二度足していない。

方向は当該行以前の最終価格変化の符号であり、先の価格変化を逆向き補完していない。処理を次ブロックが来るまで待つことと、次ブロックの新しい価格を方向判定へ入れることを区別している。release は新しいブロックの行を self.block へ追加する前に呼ばれ、以前のブロックの価格・出来高だけを処理する。従って遅延帰属により次約定の方向が過去へ漏れる実装ではない。

特徴量の time は帰属先一分枠の開始であり、利用可能時刻は available_at=time+1分である。research_v2.py は特徴量を time に付加し、simulate では time+2分以降の実在足の始値で仮想約定するため、特徴量確定前の使用も検出しなかった。

セッション外の残存時刻は除外し、セッションごとに価格・方向・累積出来高基準を初期化する。各セッション最初の累積値は出来高へ足さず、最後の未確定群の出来高差分も出力しない。そのため、対象セッション範囲内の最後－最初と出力総量の差は末尾破棄量で説明される。

## 解釈上の限界

- signed_volume はティックルールによる推定であり、注文識別子や成行売買側の真値を持たない。価格据置きの約定は最後の価格方向を引き継ぐ。まとめて受信した複数約定の内訳も復元できない。
- 約定価格時刻と板の受信時刻は異なる。次の約定時刻へ遅らせる方式は保守的な近似であり、実通信遅延の保証はない。
- 生板由来の特徴ではあるが、この候補が使う入力は主に約定価格と累積出来高である。十段の板厚・取消・新規注文フローが予測力を改善したという証拠とは分けて説明する必要がある。
- 20分窓では分子・分母の差分をそれぞれ合計して比率化している。１分比率の単純平均や、無約定分への出来高前方補完は行っていない。
- 保存三セッションを条件選定に使用した成績は開発成績であり、未知期間での高正答率の確認とは区別する。

## 次ブロック内容に対する反証試験

同一約定時刻に価格・累積出来高を (100,10) → (101,12) → (101,12) → (100,13) → (100,14) と与え、次ブロック時刻を２分30秒後に固定した。次ブロック価格を1と10000へ極端に変更し、出来高99999も与えたが、既存ブロックの出力行は完全一致した。出力出来高差は4、符号付き差は0（＋2－1－1）、利用可能時刻は３分後。重複差0、同一時刻内での方向反転、同値tick方向継承、次ブロック価格・出来高の非混入を実行検証した。
