# 継続波検知の第２回評価設計

本書は利用者指定波を検知できること、過剰な売買で見掛けの検知を増やさないこと、セッション内に返済することを同時に確認するための設計である。閾値は統計的有意性を保証する値ではなく、今回の開発で候補を比較するための実用上の基準である。最初の設計案では保有時間５０％・値幅２５％を提案し、統合探索の開始時に保有時間６０％・値幅４０％へ厳しくした。以下は実装と一致する最終基準を示す。

## データの位置付け

- 使用する入力は保存済みの３セッション、２銘柄の生板・１分足・５分足。３形式は同じ相場であり、独立した３種類の検証事例として数えない。
- 前回すでに全３セッションを評価し、今回はその中の２日から利用者が検知対象を指定している。全保存セッションと指定波は開発データであり、「未使用日」「独立検証」「外部検証」とは呼ばない。
- 指定波の時刻を条件式に埋め込まない。入力特徴量や閾値の探索で指定波を参照した事実は開示する。
- 現在セッションの追加取得は行わない。前回一度取得した現在セッションは、条件固定後に再生する場合にも「既取得データの再利用評価」であり、独立した未知データでの検証ではない。
- 同時に動く２銘柄の結果を独立した観測として統計的な有意性を主張しない。３セッションでは再現性・正答率を確証できない。

## 指定波の実在確認

１分足の開始時刻を用いて指定区間を切り出した。開始価格は開始分の始値、終了価格は終了時刻より前の最終足の終値である。「引け」は保存足が終了する１５時４０分を参照時刻とし、実際の取引期限は別に１５時３５分とする。値は価格ポイントであり、費用控除後の実取引成績ではない。

| 日付・方向・区間 | 銘柄 | 参照開始→終了 | 指定方向の変位 | 最大順行幅 | 開始からの逆行幅 | 終値経路の最大押し戻し |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| ９月２１日ロング１０時４５分〜１５時４０分 | NK225 | 64920→65410 | 490 | 500 | 30 | 120 |
| 同上 | TOPIX | 4072→4090 | 18 | 18 | 1 | 5 |
| ９月２２日ショート９時２０分〜１１時４５分 | NK225 | 66930→66540 | 390 | 430 | 50 | 130 |
| 同上 | TOPIX | 4130→4110.5 | 19.5 | 20.5 | 3.5 | 4.5 |

開始から６０分経過しても、終了までの指定方向の変位は順に４５０、１５．５、２１０、１０ポイント残る。４件とも単純な瞬間急変だけでは説明できない。特に９月２１日には途中に長い停滞・押し戻しがあるため、「判定後３０分で伸びるか」だけでは長い波の検知能力を十分に評価できない。

参照区間の最大順行時刻、順行終値の割合、残存変位などの再現可能な詳細は `対象波監査.csv` に保存した。未来の高値・安値から最良の売買時刻を選んだ収益を、アルゴリズムの成績として使ってはならない。

## 指定波に対する合格基準

候補ごとに４件それぞれを独立した行として記録する。平均だけで失敗を隠さない。基準未達の場合はそのまま未達とし、結果を見て検知猶予を延長しない。

1. 区間内で２０分以上続く指定方向の保有が存在し、その区間内の保有開始が波の開始後６０分以内であること。既存の保有が開始時点にある場合は遅延０分とする。３０分以内なら早期検知、３０分超６０分以内なら遅延検知と併記する。検知時刻と、次の実在する価格での仮想約定時刻を分離する。
2. 指定区間のうち指定方向で保有した時間が６０％以上であること。参照区間外で開始した保有も、区間と重なる時間だけを加算する。逆方向の保有時間も別に出すが、それ自体を合格条件へ追加しない。
3. 指定区間に重なる保有部分が獲得した指定方向の値幅から、重なった保有部分ごとに２ティックを引き、参照開始から終了までの方向付き変位で割った捕捉率が４０％以上であること。取引を区間境界で区切るため、この値は評価用の値幅帰属であり、実現損益そのものではない。実際の全取引損益と区別する。
4. 指定区間と重なった取引の実現損益、最大順行幅、最大逆行幅、最大の押し戻し、費用感応度を併記する。捕捉率だけが高く、その後の返上で実現損益が負になった場合は「検知成功・売買失敗」と明示する。
5. 検知なし、６０分超の初検知、区間末尾だけの短時間一致は、この指定波の検知成功に数えない。

時間の分母は時計時間とし、データがない区間を無条件に除外して捕捉率を高めない。データが欠ける場合はデータ観測率も併記する。欠けた足を前値で補間するなら、取引のない分と受信障害が区別できるかを確認し、補間で約定を創作しない。

## １日数回の制約と全体比較

利用者は「何もしない」回答を明示的に排除している。総検知０件は無条件で不採用とする。各銘柄・各セッションの取引開始件数、ゼロ件のセッション数、日付別の合計件数を出す。保存資料は日中２回・夜間１回だけなので、「毎日」の頻度が安定しているとは断定できない。

統合探索の頻度条件は銘柄ごとに１セッション１〜６回とする。同じ閾値で両銘柄・全３セッションを比較し、１回の長い波を細切れに検知し続ける場合は、検知継続時間・再入場回数・その費用を合わせて評価する。頻度条件は単なる全体平均ではなく、各セッションの分布で確認する。夜間と日中の両方を売買すると暦日の回数はセッションの回数より増えるため、１セッション数回と１暦日数回を区別する。

比較は次の順番で行う。個別結果も全て保存し、順位だけを示さない。

1. 因果性、セッションを跨がないこと、約定・費用計算が整合することを満たす。
2. 指定した４波の合格件数を最大化し、４件すべてが合格するかを明示する。
3. 全３セッションで過剰な検知頻度を避け、指定波の合格数と頻度条件が同じ候補では、４つの指定波のうち最大の逆方向保有割合が小さい候補を優先する。逆方向保有を減らすことで、同じ指定波の中の不要な反対売買を抑える。特定１セッションだけに損益が集中していないかも確認する。
4. 全取引の純値幅、勝率、プロフィットファクター、最大損失、最大ドローダウン、中央値の保有時間、最大逆行幅を比較する。銘柄間の価格ポイントを直接合算せず、各銘柄のティックで正規化した集計も使う。
5. 候補の閾値を少し変えた近傍でも指定波の検知と全体収支が維持されるかを確認する。近傍が全て失敗する一点だけを「解」としない。
6. １５・３０・６０・１２０分の事後方向評価は診断表として出し、長時間の継続波が短時間急変より検知しやすいという仮説を比較する。各時間の判定対象数・打切り件数を明示する。

同じ３セッションを使った多数の探索では、上位候補の高勝率は過大評価される。独立した将来セッションでの検証が必要であることと、指定波を検知できた事実は分けて報告する。

## セッション内返済と約定模擬の限界

保存日中足は８時４５分〜１５時３９分、夜間足は１７時００分〜翌５時５４分付近に存在する。返済指示時刻を日中１５時３５分、夜間翌５時５０分に固定する。これは保存データ終端より前に返済のための余裕を設ける設定であり、特定日の最後の価格を見て指示時刻を動かさない。指示時刻の足がない場合、同じ保存セッション内の次の実在する１分足始値で返済する。したがって１５時３５分・５時５０分ちょうどの返済を全ケースで保証するものではない。

- 新規判定は返済指示時刻の３０分前に停止する。終了直前の新規と同時返済を作らない。
- １分足開始時刻の１分後に特徴量・信号が確定し、そのさらに１分後以降の最初の実在する１分足始値で新規を模擬する。１分足の始値はその分の最初の約定価格であり、その時刻ちょうどの約定可能性を保証しない。
- 初期保護は新規時のＡＴＲの３倍とし、継続時は確定終値の最高順行価格から４倍または６倍のＡＴＲで追跡する。ＡＴＲは新規時と現時点の大きい方を用い、ストップを不利な方向へ緩めない。先に存在したストップへその分の高安が到達した場合、ストップまたは不利な窓開け始値で返済を模擬する。
- 同じ分で複数の返済条件が成立する場合は、時刻返済、既知の反対信号による始値返済、分中の保護返済の順とする。分中の正確な到達時刻や順序は復元しない。
- 反対信号を必要回数確認して始値返済する場合、同じ始値で反対方向の新規を可能とする。新規と返済は各取引として別々に費用を控除する。
- 他指数確認を使う２４番の系統は、自指数の長短方向が反転しても他指数が反対方向へ揃わない場合、既存保有を返済して中立となる。他指数が揃って新規条件を満たすまで待機する。自指数・他指数の情報が１０分を超えて古い場合は、新たな方向の確認に使わない。
- 保護・追跡返済の後は５分間待ち、加えて一度反対方向の信号が出るまで同じ方向へ新規を出さない。中立になっただけではこの禁止を解除しない。新規約定分に損切りした場合も同じ規則とし、同じ波での損切り直後の反復売買を抑える。
- 本実装は生板から特徴量を抽出するが、約定価格は生板の `Sell1.Price` / `Buy1.Price` から直接再生していない。スプレッド・手数料・不利約定を合わせた近似として往復２ティックを控除し、４ティック控除も示す。実スプレッドを反映した純損益や実約定成績とは呼ばない。将来の実装で板約定を使う場合は買いに `Sell1.Price`、売りに `Buy1.Price` を対応させる。
- 受信時刻を持たない板で `CurrentPriceTime` を時刻として使う場合、その時刻が約定更新時刻であって板受信時刻とは限らない。この制約を明示し、板ごとの完全な高頻度因果性を主張しない。
- 夜間・日中で特徴量、保有状態、再検知待ち時間をリセットする。前夜の高安値を意図的に特徴量として使う候補は、その設計と時点可用性を明記するが、保有状態は引き継がない。
- 返済指示以後に実在足がないケースは未返済として残す。都合の良い前値で成功した返済として扱わない。
- 入力が日中１５時４０分以降または夜間翌５時５５分以降へ達する場合は、模擬売買を始める前に入力エラーとする。返済指示後の価格が欠け、次のセッションの価格が混入した場合にも、その価格を使った架空のセッション内返済を作らない。
- セッション途中で終わる記録は未決済として残す。末尾という理由だけで強制返済した取引と、事前設定した返済時刻に実際に到達した取引を区別する。

## 最低限の実装監査

閾値探索用の全期間結果が一致するだけでは先読みを否定できない。最終候補に対し次を確認する。

| 検査 | 必須の確認内容 |
| --- | --- |
| 時点切断 | 任意の時点で入力を切った場合、切断以前の特徴量と信号が全期間実行時と一致する |
| 未来改変 | 未来の価格・板を大きく変えても、それ以前の信号が変わらない |
| 足の確定 | ５分足の時刻が開始なら、その足の終値を使えるのは５分後である |
| 次の価格 | 信号計算に使った終値で即約定させず、さらに１分待ち実在足のみで新規を模擬する |
| 欠測 | 無取引と通信欠測を可能な限り区別し、存在しない板で発注・返済しない |
| 境界 | 日中・夜間とも同じ保存セッション内で返済し、翌セッションに建玉が残らない |
| 打切り | 途中までのデータで末尾決済を捏造しない |
| 方向 | ロング・ショートの保護価格と損益符号が逆転しない |
| コスト | 往復２ティックと４ティック控除を明記し、実スプレッドが反映された約定成績と混同しない |
| 無信号 | 全期間で信号を出さない候補が上位合格扱いにならない |

`python work/wave_v2/test_v2.py` の３９検査は成功した。２４系統の全方向強度・新規返済履歴について途中切断を検査し、両銘柄の未来価格・板特徴の改変が過去特徴量へ影響しないことを確認した。加えて２４系統×両銘柄×３セッションの代表設定で全建玉が保存セッション内に返済された。最終候補の２４番・閾値０．２５・確認１回・追跡４倍・反対確認倍率１についても全保存セッションの２５％・５０％・７５％時点で履歴の不変性を確認した。人工データでは欠測、遅延、日中・夜間の境界、途中打切り、逆行窓開け、約定分の保護返済、反対信号返済の優先と同時反転、損切り後の同方向禁止と解除条件、無信号・遅延超過・短時間一致の不合格を確認した。他指数確認の系統では、中立化による返済、長期回帰の最低変位、古い自指数・他指数を新規確認へ使わないことも確認した。日中の１５時３４分以後、夜間の５時４９分以後にデータが途切れ、境界時刻や次セッションの行が混入するケースも検査し、次セッション価格で返済せず入力エラーになることを確認した。

実受信時刻がない板の制約や実スプレッドによる約定再生の不足を、これらの検査が解消するものではない。最終報告には検知成績と仮想売買の近似を分けて記載する。
