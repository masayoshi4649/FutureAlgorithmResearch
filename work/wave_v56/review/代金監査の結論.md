# 代金監査の結論

出来高と売買代金の増分から平均約定価格を作るための、数値上の整合性は確認できた。**旧執行方向代理を全面否定する結果ではなく、曖昧なまとめ更新を把握するための追加情報**である。新しい売買規則と損益は作成していない。

保存済み 46 原本の 5,945,161 行を読み、以前の監査時と SHA256 が一致した。場内の最良買い価格 < 最良売り価格、両側数量正の 5,910,415 行を対象とした。不正行を跨ぐ差分は、連続した原本行の集計と分離した。

平均価格は `Δ売買代金 ÷ Δ出来高 ÷ ラージの商品倍率` で算出した。TOPIX の倍率は 10,000、NK225 は 1,000。複数価格の約定を平均するため、平均価格自体が呼値の整数倍でなくても正常である。確認した呼値会計は `Δ代金 ÷（倍率 × 呼値）` の整数性である。

方向代理は、最後価格または平均価格が直前最良売り以上なら「買い側」、直前最良買い以下なら「売り側」、間なら「内側」とした。相違の大半は、旧買い／売り分類が平均では内側になったものだった。内側は無取引や均衡の証明ではなく、複数方向の混在を含み得るため曖昧と扱う。

前後の価格範囲外の平均が少数あっても、中間にその価格で約定していた可能性がある。不正と断定していない。原本行連続、時計先行なし、呼値会計整合、前後範囲 ±1 呼値以内という条件を加えた集計も JSON に併記したが、これは真の同期や執行方向を証明するものではない。

全有効行で `TradingVolumeTime == CurrentPriceTime` だった。最良板のキーは `Price`・`Qty`・`Sign` のみで、`Time` はなかった。受信時刻も売買代金固有の更新時刻もない。従って同じ時刻の行をまとめると、原本順に残っていた価格形成の動きを潰す場合がある。反対に原本順を残しても、通知されなかった取引所内の中間イベントは復元できない。

場の初回有効行の量は基準にするだけで、前の場からの差分は作っていない。デイの先頭に前ナイトの値が記録されている例も確認しており、累計水準をデイの新規売買量と取り違えない。

原本差分は `代金差分/*.npz`、全場の件数・分類クロス表・代表的な範囲外例は [売買代金と出来高の同期監査.json](売買代金と出来高の同期監査.json) に保存した。再実行は `audit_turnover.py` と `summarize_turnover.py`。すべて原本を読取り、当作業の監査フォルダへだけ保存する。
