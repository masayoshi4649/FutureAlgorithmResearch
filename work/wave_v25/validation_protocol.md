# 00020：大量探索と反証の事前評価案

**今回の合格は「既知データ上で反証に耐えた研究候補」を意味し、未知相場での安定収益を意味しない。** v25の成績を読む前に作成した。一次入口は実行側が結果未見で固定した基準へ一致させた。追加の反証・時間順選択案の採用範囲と実行未実行を実行側の凍結記録に残す。v23/v24の結果は既知であり、閾値も研究を進めるための運用基準で、普遍的な統計法則ではない。

原本78ファイルはv23のSHA256と全て一致。追加・削除・内容変更は０で、13セッション・７開始日のまま。詳細は `data_audit.json`。原本・旧コードの変更、現在API取得は行わない。F32_G08とX05_G08を比較基準として固定する。主結果は費用０・指定価格約定・完了セッションで全玉返済。

## まず数値入口を固定する

銘柄ごとに以下を全て満たす。両銘柄共通候補は同じ無次元条件で両方を通す。片側だけなら銘柄限定と表示する。

| 項目 | 数値入口 |
|---|---|
| 活動 | 新規約定したセッションが７以上、黒字セッションも７以上 |
| 観測量 | 無建玉から無建玉までの売買組13以上 |
| 利益と損失 | 収支が正、利益額÷損失額が1.30以上 |
| １枚当たり | 平均利益÷平均損失が1.20以上 |
| 大勝ち依存 | 最大２勝ち売買組を除いても黒字、最大２黒字セッションを除いても黒字 |
| 区分損益 | 日中・夜間・9/21開始週・9/28開始の追加週の各合計が全て黒字 |

損失０は無限大の高評価にせず、比率の観測不足として保留する。複数玉や部分決済では、返済を細分化するだけで「最大２勝ち除外」に強く見える。主判定は全保有がゼロからゼロへ戻る売買組を使い、個別返済行の除外値も別に示す。

## 研究候補合格までに壊す

数値入口通過後、次を固定して検証する。未実行は合格と扱わない。詳しい数値と丸め規則は `validation_protocol.json` が正本。

- **因果性と会計**：複数の末尾切断、未来板・価格・相手銘柄・未来セッション成績の改変で過去判断が不変。設置行より後の約定、呼値、取消順、全玉会計、片方向TOPIX10枚・NK20枚上限、場内返済を検算する。
- **勝ちの分散**：最大２黒字開始日を除いても両銘柄の収支が０以上。最悪セッション損失は全利益の50%以下。日中／夜間、週、開始日、ロング／ショートを必ず開示する。日中・夜間・両週は入口で黒字を要求するが、個別セッションや売買方向の全てで利益が出ることまでは要求しない。これらの区分条件は研究方針であり、全局面で有効な証明ではない。
- **時間感度**：信号を１・５・15秒遅らせ、それぞれ両銘柄が黒字・PF1.20以上。３条件の収支中央値が基準の50%以上。注文送信の遅延・観測価格約定も補足する。信号だけの遅延を実通信の再現と混同しない。
- **近傍**：閾値・時間窓・新規幅・損切り幅・追跡幅等を１変数ずつ±20%。確認回数など丸めて変わらない整数は隣接値も検査。各銘柄で75%以上の近傍が黒字・PF1.20以上・１枚平均勝ち負け比１以上、収支中央値が基準の50%以上、最悪近傍は基準利益の−25%以上。
- **反転**：価格と買売気配、数量側、方向・左右設定を全て鏡映した台帳は元と一致する必要がある。信号だけの反転は別診断であり、損益の厳密な符号反転を要求しない。
- **不使用・乱数対照**：追加情報や切替を外した経路も全注文管理を再計算。一様と過去完了区間の頻度による３分選択を各128seed実行する。現在頻度を使わず、128の独立相場とは数えない。情報あり版が過去頻度対照の収支・PFの75百分位以上、かつ情報不使用版の収支・PFを上回るなら、予測情報の追加価値を研究上支持する。未達でも管理だけの利益候補は別に残せる。

## 選ぶ工程まで時間順に再生する

最初の６セッションで候補を選び、次の１区間を再生する。その後は完了区間だけを追加し、計７区間を連結する。**全期間を見て残した上位候補だけから過去の採用手法を選び直さない。** 今回の事前凍結カタログ全体を対象に、過去成績だけで採否・順位・数量・学習器を計算する。

過去側の入口条件も先に固定する。活動と黒字区間は過去区間の半数以上、組数は過去区間数以上、PF1.30・平均比1.20と最大２勝ち除外を維持する。存在する日夜・週の各合計は黒字を要求するが、未到来の週を判定に含めない。順位案は両銘柄の低い方を使い、①最大２勝ち売買組除外後収支÷利益額、②最大２黒字区間除外後収支÷利益額、③PF、④１枚平均勝ち負け比、⑤少ない自由変数、⑥IDの順。該当がなければF32_G08を固定fallbackにし、不稼働で成績を良く見せない。F32自体が全期間を見て選ばれた基準なので、この工程も真の未見検証にはならない。

自動選択工程の研究合格には、次７区間が両銘柄とも黒字・PFと平均勝ち負け比1.10以上・活動４区間以上、最大１勝ち組／最大１黒字区間をそれぞれ除いても収支０以上を要求する。失敗しても全期間固定候補の入口通過という事実は残す。窓長や順位式を何通りも試した場合は、その工程も追加試行に数える。

## 枚数で利益を大きく見せない

**以下は追加提案であり、現エンジンで実施済みではない。** １枚制限の単純化版と、初期損失予算を銘柄ごとに20,000円へ揃えた複数玉版を別IDで比較する案である。複数玉の予算は未返済玉の**新規時の損切り距離×枚数×円倍率**を両方向合算し、追加玉も同じ枠内に置く。現実装には手法別の損失枠の違いがあるため、この予算統一を満たしたとは表示できない。初期ストップなし、または統一比較が未実施ならこの尺度での優越判断は保留。初期リスク予算は損失額の保証や証拠金額ではない。

TOPIXミニは１pt＝1,000円、NKマイクロは１pt＝10円。今回のNK原本はラージの10pt格子なので原本１刻みの換算額は100円。実際のマイクロの呼値は5ptで１tick＝50円であり、原本格子と異なる。[JPX商品仕様](https://www.jpx.co.jp/derivatives/products/domestic/225micro-futures/01.html)。既存エンジンの円換算は変更しない。同銘柄内で金額・PF・１枚平均勝ち負け比・全玉時価評価のドローダウンを比べる。勝ち／負け／同値の決済枚数と売買組数、最大買／売保有を併記する。枚数差は残存建玉でも独立標本数でもない。研究合格だけでF32やX05より優秀と結論しない。

## 膨大探索での後付けを残さない

候補生成式、範囲、seed、組合せ数、評価式、コードSHAをバッチ前に凍結。失敗・未稼働・重複も全試行台帳に残す。試した仕様数と独自の信号／注文経路数を分け、失敗例を消して探索数を少なくしない。一次探索の順位はrunnerと合わせ、入口合格、不合格数、最弱銘柄の最大１黒字区間除外PF、最弱銘柄の収支÷DD、最少の黒字区間数の順。同点はIDで固定し、並列完了順に依存させない。時間順選択の順位案とは別の段階である。反証を見て改善した候補は新しいID・新バッチにし、前の失敗を保存する。閾値や適用日・時間帯を後で変えて元候補を救済しない。

必要なら７開始日を両銘柄・全候補・基準へ同時再抽出する5,000回bootstrapと一開始日除外を行う。ただし７開始日の独立性は未保証、夜間は翌暦日へ続き、9/29は昼しかない。通常の95%区間や最大統計量を探索全体の正式な有意確率にしない。小標本で無理な統計確証を合格条件にせず、何を壊しても残り、どこで壊れたかを示す。

## 一次研究との対応

- [White (2000)](https://users.ssc.wisc.edu/~behansen/718/White2000.pdf)：多数比較の最良成績と時系列依存を考慮する。今回は全試行保存と共通日付再抽出へ適用し、正式なReality Check実施とは呼ばない。
- [Baileyほか：バックテスト過適合](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)：選択工程自体と既知holdoutの問題を扱う。今回は売買の先読み防止と研究者の既読性を分離する。CSCV未実施なのでPBO値は出さない。
- [Hansen (2005)](https://bashtage.github.io/kevinsheppard.com/files/teaching/mfe/advanced-econometrics/Hansen.pdf)：悪い比較候補を含む検定力の問題と、負け候補の単純除外が妥当でない点を説明する。再帰的推定を含む比較は原論文の枠組み外という制限もある。今回の逐次学習・切替へSPAの有意確率をそのまま流用しない。

ここから「未知相場でも安定」の確認へ進むには、採用仕様と選択工程を次の未読データの前に凍結し、その後の成績を順番に蓄積する必要がある。途中改訂したら別版として以後の記録を分け、過去の不調を消さない。今回の反証合格はその次段階へ進める研究上の資格であり、利益保証ではない。
