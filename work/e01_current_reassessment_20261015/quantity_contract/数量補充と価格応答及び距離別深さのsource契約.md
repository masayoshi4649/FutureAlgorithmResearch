# 数量を使う次研究のsource契約

2026-10-15。今回はコード・小schema/目録・ファイルstatだけ。**原book本文、NPZ本体、現在API、金融再生は0。新しい有効性・損益は未測定。**

結論は、旧33場の**表示十段の実数量**と**公表累計出来高**は保存されており、次の測定に利用可能、というもの。真の方向別約定量・同一主体の補充・隠れ注文まで復元できるという意味ではない。

## 1. 保存列と可用性

[小目録とstatの射影](旧33の44列保存位置と新2の未読可用性.json)に、旧33場・66口座のNPZ位置/記録済みSHA/現在statを保存した。NPZ本文を読んで現在SHA・値を再検証したものではない。

| 素材 | 直接保存している列 | 次測定での扱い |
|---|---|---|
| 同価格の表示数量 | `bid/ask`、`bid_qty/ask_qty`、十段の`bid/ask_prices`と`bid/ask_quantities` | Buyが研究側bid、Sellがask。段番号でなく**同じ価格**を照合する。 |
| 表示の資格 | 各段`*_element_valid`、`best_price_valid/best_quantity_valid/depth_valid`、`price/depth_transition_valid`とreset | 不正・欠測・clock逆行・原seq断裂を数量0や消費へ補完しない。最良Qty0は現producerの正常最良資格を満たさない。 |
| 公表活動 | `volume/volume_time_s`、`volume_delta_observed/known`、`volume_delta/usable`、volume reset | `known`と保守的な`usable`を分ける。増差は全価格の公表総量で、Last価格や方向へ全量配賦しない。 |
| 約定価格の補助 | `last/price_time_s`、`trading_value/trading_value_time_s`と資格 | Lastは全約定内訳でない。代金の専用時計が未知なら、出来高と同じ約定集合の増差だと自動認定しない。 |
| 当時行との結合 | `raw_seq`、`normal_execution_row`、`execution_to_raw_index` | 全原行は保存順のまま。normalで判断するなら対応raw行以下だけを使用。同clockの後続原行も未来側として除外する。 |
| 保存されないもの | 注文ID、約定ID、取消/追加/約定の個別message、queue順位、受信時計値、共通受信seq、CurrentPriceStatusや段Sign | この列集合からイベント種別や実受信順は復元しない。受信時計は3候補名の存在flagだけ。 |

生成は[103 input/core.py](../../../work/wave_v103/input/core.py)の全原行抽出。旧32場は[103v2 correction.py](../../../work/wave_v103/input_v2/correction.py)が直前価格clock逆行を`usable`から追加除外し、他42配列を保持する。10/13デイだけは[104 holdout_input/core.py](../../../work/wave_v104/holdout_input/core.py)の別一回抽出に同訂正を適用。両小schemaの44列・dtype・shape定義は一致した。

**追加2場（10/13ナイト、10/14デイ）**はbookのstatのみ。103v2/104追加Dayの既保存位置に当該4口座NPZはなく、当場schema・正常行・44列の生成/品質は未確認。他の全領域の不存在まで主張しない。旧33の資格/完全性を新2へ継承しない。

TG/TEや00113の現在票cacheは十段数量を保持しないため、それだけから数量を作り直せない。将来の一読計画は元44列NPZの同bytes SHA→BytesIO復元を明示する必要がある。103v2既loaderの`verify=True`はhashとnp.loadで本体を別々に読むので、そのまま「本体一読」と数えない。

## 2. 「同価格の補充下限」の厳密な範囲

同じ側・同じ価格pの表示数量をQとすると、理想化した保存則は `Q1−Q0 = A−C−E`（表示への追加A、取消C、その側の約定消費E）。

- **そのまま観測できる量**は `ΔQ`、表示正増の合計、既知減少後に対応させた回復量。`max(0,ΔQ)`は同価格の表示増加であり、同一注文/主体の新規発注量とは呼ばない。
- もし別の証拠から**同じ側pでの消費下限E_min**が確定するなら、保存則の下で `A >= max(0,ΔQ+E_min)`。例えばQが減らずE_min=1なら最低1の表示追加が必要になる。
- **現snapshotだけではE_minを勝手にΔVへ置けない。** 同じQ0=Q1、ΔV=10、Last=pでも、10枚すべてpで成立した経路と、別価格9枚＋最後のp1枚の経路を区別できない。pで1枚成立しても、行間にbid/askが動いていれば、旧ask側を消費した証明にはならない。

最小1約定についても、証明する対象を分ける。

| 段階 | 必要な条件・言えること |
|---|---|
| 商品全体の追加公表活動 | 同一銘柄/限月、隣接原seq、正常な同場累計の正増。最低単位が1枚で累計が新約定により増えるという配信契約の下では、少なくとも1枚分の活動が新たに公表された。**価格p・攻撃方向・受信間の発生時刻は未確定。** |
| pで最低1枚という候補 | `ΔV=1`、新Last=p、Last時計が前の出来高観測より後で現出来高時計以内、両時計非逆行等を要求する厳しい小集合は作れる。しかし**Lastと累計が同一約定更新に対応する契約/整合確認が追加で必要**。時計一致だけでは保証しない。 |
| pの約定価格を数量会計で確定 | 同じ約定集合を覆うΔ代金/ΔVが保証され、ΔV=1なら`p=Δ代金/商品倍率`が求まる。ただし代金clockの未知・field更新ずれを解決しない限り、現NPZで無条件の認定はできない。 |
| 同じ側pの消費を確定 | さらに当該約定直前の側・板との紐付けが必要。Last対「前snapshotの」BBOだけでは真のaggressor/同側消費の証明にならない。 |

したがって次のfeatureには、`表示正増下限`、`追加公表出来高`、`Last/代金整合候補`、`同側消費の証明有無`を別欄で保存する。未証明E_minを0と断定せず**未知**にし、補充下限へ加算しない。「補充がない」の意味にも使わない。

## 3. 消費量と価格応答をどう測るか

まず**公表活動と表示の応答**として測る。反対最良価格pが続くepisodeを原行順に定義し、当時のQ0/最小Q/終Q、既知正増/減少、公表ΔV、両BBOの進行・逆行・拡幅を並べる。ΔVのLast方向分類はあくまで代理として別保存し、活動全量をpで吸収したとは書かない。

同じ活動量でも、①数量減＋両気配進行、②数量維持/増加＋気配不進行、③数量回復後に両気配が再進行、を分ける。固定量当たりの価格変化はゼロ活動/未知活動で割らず未定義。行内の同時関係を、観測後の方向予測と混同しない。

次の非金融測定なら、元paper公開299だけでなく**全rawの該当episode**を分母にできる。価格時計が同値でも原seq順を保持し、欠測/断裂でepisodeを終了する。反応が出た時点で公開可能な根拠を一回だけ消費し、入口で使った数量/活動を保有中の「新しい支持」として再利用しない。売買にする前に当時接頭不変・買売対称・母数/unknownを人工確認する。

## 4. 価格距離を重みにする深さ変化

距離加重そのものは新発見ではない。旧wave52は最良からの距離d（呼値）に`exp(−d/2)`と`exp(−d/8)`を掛けた近/遠の供給を作っていた。

新たに厳密化できるのは、**価格固定の差分**と**表示領域の検閲**である。比較開始時のanchorを固定し、例として `w(p)=exp(−|p−anchor|/(k×tick))`、`ΔD = Σ_p w(p)[Q1(p)−Q0(p)]` を測る。kを含む式は測定前に固定し、利益で選び直さない。

- rank1の差とprice pの差を混ぜない。anchor/weightを毎row動かして生じた評価差を数量追加と数えない。現在最良基準の供給水準は別列とする。
- 正常十段のbidは`p >= max(旧最遠bid,新最遠bid)`、askは`p <= min(旧最遠ask,新最遠ask)`という両時点の既知範囲で比較する。価格集合は前後のunionを使用し、範囲内の未表示は表示0、**遠方十段外はunknown**。
- これにより旧最良の消失は拾えるが、深い未表示を取消/約定へ配賦しない。重み付き純減も売り/買いの攻撃量ではない。
- 総表示量の水準、同価格の正増/減少、最良価格の移動、重みが変わった評価分は分離する。二市場の数量を円で単純合算せず、各市場の当時表示基準量等による正規化を別に固定する。二市場を結ぶなら相手原row/価格clock/ageを保存し、価格clockによるas-ofを真の同時受信や先行市場の証明と呼ばない。

## 6. 時計と公式定義

[公式PUSH仕様](https://kabucom.github.io/kabusapi/ptal/push.html)を2026-10-15に再閲覧。先物に現値/現値時刻、売買高/時刻、売買代金、十段の価格/数量はあるが、先物の各気配のTimeは対象外。仕様はfield定義を示しており、約定ごとの配信・全fieldのatomic同時更新はこの説明から保証しない。

`CurrentPriceTime`と`TradingVolumeTime`は各fieldの時計であり、受信時計ではない。volume時計がprice時計より後でも、同じsnapshotに届いていた値を即「未来」と呼ばない。一方、両clockのmaxを受信clockへ合成もしない。[旧66頭部とcontrollerの時計確認](../clock_schema/元JSONLとNPZ及びcontrollerの時計の区別.md)は頭部の範囲までで、後の全原行の不存在証明ではない。

旧代金監査の[結論](../../../work/wave_v56/review/代金監査の結論.md)では同23場の単枚増分とLastの整合を確認していた。しかし当該46原本の整合を、旧33全66口座や未読追加2の仕様保証へ格上げしない。
