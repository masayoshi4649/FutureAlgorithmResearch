# 全normalの現在確認とNative実玉

このsourceは結果前の準備版です。所有人工は合成入力だけで完了しました。実33入力、新2場、金融、APIは未読・未実行です。根が正式source・八部品・登録・独立接続を確認してから唯一の金融を開始します。旧111/112のsourceや旧JITは変更していません。

## 候補の状態

session start基準の5分bucketを逐次閉じ、直前bucketの正常Last高安Lを使います。空足や飛ばしたbucketは未知です。確定rowは突破rowより前でなければなりません。新bucketでは最新Lだけへ切り替えますが、既保有の支持価格線は別状態として残します。

買いは両BBOがLより上、売りは両BBOがLより下へstrictに抜けた観測rowでB0/A0を固定します。①現在VOL_SEL、②VOL_SEL＋PRICE_BOTHは、後rowで両気配が各1観測T順行し、現在資格が成立した時に候補を一回公開します。①②は必要情報が未知になったら未公開probeを消し、既知へ戻った時の新B0/A0を取得できます。

③は突破より後のrowで、同窓・known連続・単調原行範囲の新反対票正増下限1以上を初めて観測したBp/Apを固定します。その後の別rowで両BBOが各2T順行し、現在VOL/PRICE資格が成立した時に公開します。B0取得以後、必要known/正常の連続が切れるか、いずれかのBBOがB0/A0から逆側へ1T超進めば、そのL/sideの③は未公開でも不成立終了です。同じ側に留まって新B0を取り直しません。

各L/side episodeで各入口種類は最大一度公開します。実busy・静観・期間・費用で拒否されても消費済みです。再武装は最新確定bucketへの切替、又は買いで両BBO<=L／売りで両BBO>=Lという反対側への戻りを観測してからの新突破だけです。FAK失効や返済直後、同じ側に留まった反復公開はありません。公開済み`consumed`と、③の不成立終了`retired`を別に保存します。

候補生成は全normalを走査し、paper CID・元PUB・paper ATR・実busyを使いません。Native側で現在実玉のbusy等を判定します。各現在VOL閾値は正なので、同じ入口種類の当行BUY/SELLが両方資格成立することはありません。未知は必要な部品の取消に使い、VOL単独へPRICE既知条件を紛れ込ませません。

## 実注文と保有支持

優先順は既知timer取消、既返済予約の約定、既受理FAKの初normal一回試行、当行の実清算・支持・退出判断、新候補の公開です。受理済FAKは公開価格限界を維持し、当行の未知で既約定を遡及取消しません。買ask/売bidが限界に届かなければ一回失効し、後の好価格で同じ予約を復活しません。

実玉はTOP10/NK20の全量、実fill価格からNを固定します。初期支持価格線は買L−1T、売L＋1Tです。買いで両BBO<=支持線、売りで両BBO>=支持線なら当行判断から次normalで全返済します。親cash stop、TP又はtrail、場loss/profit、quiet/期限を併用し、paper撤回理由151/反対price退出152は使いません。

保有支持の新probeは実entryより後の新反対差分だけです。直前の正常・必要knownが連続するBBOをB0/A0とし、新反対票の観測rowでBp/Apを保存します。最新に検出した一probeだけを保持し、逆側1T超や未知はprobeだけを取消します。後rowで各2T再順行し現在VOL/PRICEも成立したら、買線=max(旧線,Bp−1T)、売線=min(旧線,Ap＋1T)へ更新します。確定線は後退させません。入口③で使った反対票のrowは実entryより前なので保有根拠へ再利用しません。

Nとcash線は実fill時固定、前親netは親localから除きます。全量一新規一返済UIDの実注文ごとに料金floorを課し、paperの枚数や部分返済を混ぜません。timerは先の予約由来を保持しつつ優先返済します。未完成接頭で次normalが未観測なら予約を残し、全場利益・目標達成を名乗りません。

## インターフェース

`prepare(gate_packet, exit_packet, python=False, initial_capacity=32)`は二cacheのstrictjoin・PUB同値を確認し、商品別に`price`、`volume`、`bar`、`flow`、`candidates`、`breakpoints`、`consumed`、`retired`、`input_checks`を返します。原PUB/feedは同源確認だけで新候補へは使いません。

`play(account, features, config, session, finish=True, python=False, initial_capacity=32)`はdaily互換の`orders/order_uids/exit_target_uids/summary/parent/actual_legs/uid_accounts`、全行会計に加え、`uids/targets/publication_events/support_events/exit_judgments/execution_events/actual_origins/parent_diagnostics`を返します。`account`はTradeGate.accounts[symbol]、`features`はprepare()[symbol]です。

主要数値列は次です。価格線と円線を混同しません。

| 配列 | 列 |
| --- | --- |
| candidates・16列 | row, mode, side, episode, bucket, L, breakrow, B0, A0, oppositeProofRow, Bp, Ap, levelConfirmedRow, lowerBound, proof前row, row |
| breakpoints・9列 | row, episode, side, mode, L, bucket, confirmedRow, kind（0突破/1不成立終了）, reason（0通常/1正常切断/2必要known切断/3逆側1T超） |
| curve・14列 | equity, liquidation, parentLocal, parentPeak, long, short, paidFee, reservedExitFee, actualCID, sceneStop円, sceneGoal円, support価格線, armed, holdingProofRow |
| origins・16列 | CID, eventID, entryRow, pubRow, side, q, fillPrice, N, parentBase, L, initialSupportLine, supportWidth, priceCap, allowanceTicks, UID, entryOppositeProofRow |
| support_events・10列 | row, CID, side, oldLine, newLine, proofRow, Bp, Ap, lowerBound, proof前row |
| exit_judgments・13列 | row, CID, reserved, reason, local円, sceneLiquid円, peak円, line, heldq, N, armed, support価格線, sceneBlocked |

exit_judgmentsのlineは、reason143だけ支持価格、140/141/142/161/162は円です。supportWidthは公開気配から初期構造支持線までの価格幅で、未取得ATRの代用ではありません。support_eventsは支持価格更新であり追加費用ではありません。

## 時計・観測の限界

全て旧価格時計モデルです。PriceTimeは受信時刻ではなく、peerはstrict過去normal末端・age60秒の模型です。出来高代理票は正usable増分とLast対直前raw BBOの一更新一票で、真の攻撃量・心理・補充を観測したものではありません。窓正差は新票の下限で、0/負差が新活動なしを証明するわけではありません。

Tは保存ラージ板の観測呼値（TOP .5pt/NK10円）です。mini/microのnative一呼値を観測できた証明ではありません。Native全量の価格到達約定模型・注文料は従来と同じで、実queue順位や真の受信先後は未確認です。保有MFE/MAEは事後診断だけで、未保有の波や別出口の救済利益を補完しません。
