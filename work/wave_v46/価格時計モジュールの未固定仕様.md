# 価格時計モジュールの未固定仕様

`price_clock.py` は、同じ原本価格列から「価格距離で進む平均」と「物理時間で進む平均」を計算する純粋モジュールである。**売買への接続・実相場の方向生成・速度校正・新しい損益計算は行っていない。** 以下は人工検査が通る設計案であり、主案や比較件数を最終固定した文書ではない。v45の50%減量検証とは別の作業である。

## 入出力

|関数|入力|返り値|
|---|---|---|
|`candidate(scale)`|倍率 `.5/1/2/4`|短長距離 `(s,4s)` 等の暫定 `Config`|
|`model(ready, config, clock=..., slope_clock=..., warmup_clock=...)`|単一銘柄・単一セッションの `time_s/seq/last/atr/tick/start`|原本行数と同じ各配列。平均、累積距離、平均差、勾配、品質、暖機、自己方向、ATRと勾配の参照行|
|`compare(ready, config, ...)`|同じ入力と設定|距離時計・物理時計の2結果|
|`completed_groups(ready, values)`|原本と自己主方向|次の異時刻で初めて確定した同時刻群の末尾方向・素材行・公開行|
|`peer_asof(target_times, events, delay=60, freshness=120)`|自己判定時刻と相手の確定公開列|追加遅延後の過去方向、相手素材行・公開行・有効時刻、鮮度|

`seq` は素材の原本番号、`*_source_row` と `release_row` はそれぞれの入力配列の位置であり、混同しない。銘柄間で原本番号又は行番号を比較しない。数量・板入力、旧H019短期確認、注文器はまだ接続していない。

## 更新規則

中央案は短距離1・長距離4。隣接する有効価格差の絶対値を、**直前原本行までの有効ATR**（2呼値下限）で割り、距離へ加える。当行ATRは品質と方向値の正規化にだけ使い、当行価格差の分母へ遡及適用しない。

価格が宣言呼値に整合することを先に検査し、価格差を整数呼値で計算する。許容する誤差は表現上の8ULPだけであり、任意の価格を呼値へ丸めて採用する仕様ではない。EMAも開始価格からの整数呼値オフセットで計算し、元価格への加算は表示用の返却値に限る。

距離平均の更新率は `1−exp(−Δ距離/L)`。物理平均は `1−exp(−Δ秒/(L×τ15))`、`τ15=−60/log(1−2/16)≒449.33秒`。これは既存15本EMAに由来する事前の参考時定数であり、当日の観測速度から換算した値ではない。長時定数4τ15は旧60本EMAと厳密には異なる。旧H019の再現とは呼ばない。

同秒で価格が変われば自己距離時計だけが進む。物理平均は同秒のΔ秒0で更新しない。価格不変では距離時計だけが止まり、物理平均は経過時間で更新する。原本行数はどちらの時計にも使わない。

現在価格又は現在ATRの欠測・非正では平均と方向をリセットする。ATR欠測は古い有効値で無期限に埋めないため、次の有効ATR行も直前ATR不足で待ち、その次の行から再初期化する。60秒超の観測穴では当行から再初期化し、穴をまたぐ価格差は加えない。時刻逆行・原本番号重複は別状態として修復せず入力を拒否する。この扱いは旧案の「時刻逆行でリセット」より厳格であり、未固定仕様として明記する。

## 確定が必要な設計点

|項目|実装した暫定案|比較上の注意|
|---|---|---|
|方向開始・維持|平均差0.15ATRと長平均勾配0.02ATRを同符号に超えれば開始。差が逆符号なら解除し、ゼロでは維持|旧H019の閾値を参照した案。新しい平均で同じ意味になる保証はない|
|距離勾配|現在距離から `0.4×短距離L` 以前の最後の原本行を過去参照|跳躍で実距離が大きくなる。指定距離ちょうどへ補間しない|
|物理勾配|`0.4×短距離L×τ15` 秒以前を過去参照|`native` 比較は平均時計と勾配時計を同時に変える。平均だけの比較は両方 `slope_clock='physical'` を指定する|
|暖機|場始20分かつ再初期化後の累積距離が長距離L以上|この時点でも長平均の初期値重みは最大exp(−1)。収束完了とはいえない|
|勾配の鮮度|参照行から30分以内|静穏時の距離勾配は得られないことがある。活動を減らしただけの改善を区別する|
|独立物理暖機|場始20分かつ初期化後 `長L×τ15` 秒|両時計の距離暖機共通比較とは別の参加条件になる|
|相手公開|同時刻群を次異時刻の観測で確定し、さらに60秒待つ|末尾の未完群は公開しない。真の受信順を復元したとは主張しない|
|相手鮮度|追加60秒後から120秒以内|有効中立と欠測・古さは別情報。相手自己方向だけを使い、相手確認済み方向を循環参照しない|

`compare(..., slope_clock='native')` の2方式は距離暖機条件を共有するが、**勾配の参照可能性・30分鮮度まで同一母集団ではない**。平均時計だけの効果を言う場合は同じ物理勾配を使う対応を主対照にするか、共通の判断可能マスクを結果前に定義する必要がある。方向を計算した後で片方に都合よくマスクする実装はまだ作っていない。

親の設計確定後、旧短期30秒価格確認あり／なしと相手一致あり／なしを対応接続できる。管理は元A0／C01を固定する案で、v45の50%版の結果から選ばない。現モジュールだけでH019完全入口が置き換わったとはいえない。

## 人工検査と残る限界

`check_price_clock.json` は9人工経路、4距離設定、2平均時計、2勾配設定を検査した。原本先頭切断720、未来価格・ATR・原本番号変更720、上下反射144、相手公開列の切断720・未来変更720、過去参照境界8を通過した。直前ATR、同秒順序、欠測、60秒穴、人工的に両時計の増分を揃えた場合の平均一致を手計算と照合した。実相場入力の適合性、全26入力の因果性、相手確認・短期確認・注文後の同値性は未検査である。

初版では小数価格を直接引いた丸め差が、距離勾配の等号境界で鏡映前後の参照行を変えた。旧コードと反例を保存し、呼値整合の検査・整数座標差分・初期価格オフセットへ修正した。境界反例を除去して検査を通したわけではない。

細かな往復でも時計が進むため、横ばいで過敏になる反例がある。大跳躍では短長平均が同時に現在価格へ寄り、差が縮んで方向を出せないこともある。距離時計は方向そのものを予測しない。比較の優劣、未知期間での安定性、利益改善について、ここでは結論を出していない。
