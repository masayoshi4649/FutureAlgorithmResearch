# 減量開始時点の独立性確認

2026-09-30。設計・実装の読取だけで確認した。新しい売買再生、収支集計、現在データ取得、旧コード変更はしていない。

## 結論

**v41 修正注文器を変更せず、B00 の入力を外側で制限する形で実装できる。** ただし、これは新しい方向予測ではなく「既存の 1 回減量を、どの段階から許すか」の変更である。既存資料で、同じ C01 にこの許可条件を掛けた比較は確認できなかった。利益保護・追跡開始の類似比較は既にある。

主張できるのは、入口直後の小さな往復で減量回数を使い切る経路を構造的に除けることまでである。後半の利益返上が減る、全体収支が改善する、という結論は未検証。9/29 の既知図から着想したので、この設計固定後の同じ 13 区間の再検査も未知データでの検証にはならない。

## 単位を先に固定する

今回の案は、影の初回約定建値からの有利な価格幅を **初回 A0 の 1／1.5／2 倍**で測る、と解釈する。

`順行幅(i) = d × (extreme(i) − anchor) / A0`

`d` は初回買い +1／売り −1。`extreme` は買いでは当行までの高値、売りでは安値。A0 は新規準備で固定され、初回約定へ引き継がれた ATR であり、到達時の ATR へ更新しない。

既存の初期組予算は `R = q0 × A0`（価格ポイント×枚数、円には銘柄倍率を掛ける）。全枚数を同じ建値で持っている間だけ、価格の 1A0 順行と組の +1R が一致する。2A0 の整数半分利確や数量調整の後は一致しない。したがって、表示を単に「1／1.5／2R 到達」とすると組利益の尺度と混同する。**「価格が初回 ATR の 1／1.5／2 倍順行した後」**を推奨する。

組利益の過去最高額を使う案も因果的に計算できるが、別の仮説である。`plans` には金額の `peak` 列はない。これを採るなら影の当行 `curve[:,0] − plans[:,9]` を組別に累積最大化し、初期 `plans[:,4]` で割る必要がある。今回の価格順行案と混ぜない。

## 提案する入力 API

以下を `profit_gate.py` に実装した。新ゲートを実口座へ渡す損益再生は未実施。

```text
gate_bad(ready, shadow, bad, bad_source, threshold_atr,
         *, mode='direction', valid=None)
    -> gated_bad[int8, n], gated_source[int64, n], evidence
```

入力は同一の入口・数量・約定方式・伝達遅延で因果生成した A0 影と、既存 B00 の方向・公開根拠行。主案は 1.5、機序比較は 1／2、近傍診断は 1.2／1.8、対照は 0。出力は v41 `engine_partial_restore_corrected.run` の `bad/bad_source` だけへ渡す。入口、good、影、初期予算、期限、元の価格返済、最大減量 1 回、25% の整数化は変えない。

`mode='direction'` は元 B00、`inverse` はその符号だけを反転。`any_valid` は元 B00 の有効公開列 `valid: bool[n]` を必須とし、到達後の新公開なら方向条件を外して影の反対方向を出す。有効中立も対象だが無効公開は除く。最初の 1 公開だけをパルスにする方式ではなく、後の新公開も全て許可対象に残す。元部分利確などに競合すれば旧注文器が受理可能な後の公開へ進む。source の持続行でも source を現在行へ付け替えない。

0 閾値は `direction` の厳密 bypass だけとし、`inverse/any_valid` と 0 の組合せは拒否する。証拠の配列は `campaign:int64`、`arm_row:int64`、`mfe_atr:float64`（測定なしは NaN）、`armed:bool`、`eligible:bool`、`reason:int8`。eligible は公開時点と方式の許可であり、実注文の発注・約定ではない。direction の中立でも時点条件を満たせば eligible は真となるが、出力方向は 0。

使える列は v38 `engine_shadow_plan.PLAN_COLUMNS` にある。

| `shadow['plans']` の列 | 添字 | 用途 |
|---|---:|---|
| direction | 0 | 影が生存中か、買い／売りか |
| campaign | 1 | 組ごとに到達状態を初期化する識別子。初回は 0 |
| initial_atr | 2 | 固定 A0 |
| anchor | 3 | 影の初回実約定建値 |
| initial_risk | 4 | 初期組予算。価格 MFE の分母には使わない |
| entry_row | 5 | 組開始の ready 配列行 |
| extreme | 10 | 当行処理後までの有利な観測価格 |
| plan_source_row | 33 | 価格欠測時に前行計画を維持したことを識別する補助 |

`plans[i]` は i 行の処理後の情報で、同じ i 行で既に終了した売買をやり直すためには使わない。ここでは i 行で**次行以降の減量を予約する入力**を作るので使用可能。既存注文器は現在行から予約し、次以降の有効行かつ指定遅延成熟後に執行する。`execution_plans[i]` は別の「当行で執行可能な成熟済み価格注文」であり、現在の情報による減量判断をさらに遅らせる目的で混同しない。

## 許可規則と時系列

1. 影の生存組が変わるたびに、初回到達行を未到達へ初期化する。
2. 有効な当行価格と有限正の A0 があり、影が生存中なら価格順行幅を計算する。初めて閾値以上になった行を `activation_row` として固定する。その後の押し戻りで未到達へ戻さない。
3. 元 B00 の非ゼロ方向について、`activation_row < bad_source[i] <= i` のときだけ元の `bad[i]` と `bad_source[i]` を通す。不許可は方向 0、source は元値を全行で維持する。元の公開行を現在行へ書き換えない。
4. 当行に影が終了していれば新しい減量根拠を出さない。次組に到達状態を引き継がない。実が予算で早く終了していても、既存実注文器が閉鎖状態を保持するため旧組へ再参加しない。

到達と同じ行の B00 は許可しない。原本時刻が同じでも、より後の ready 行で公開された B00 は順序上新しい。秒だけの asof で同秒後続を先取りしてはいけない。`bad_source` は **rawseq ではなく ready 配列の行番号**。

「新しい B00 公開」は、到達後に符号が反転したことを要求しない。到達前から悪化方向が持続していても、新しい有効公開があれば該当する。B00 の計算窓に到達前の価格が含まれることも許す。全素材を到達後だけに制限する案は別仕様となる。

元注文器はさらに `bad == -保有方向`、前回組開始・調整・競合取消より新しい source、未予約、未予算返済、残回数等を確認する。ゲートが通ることと減量予約・約定は別である。元の部分利確が同じ行に競合すればそちらが優先され、既存障壁が更新される。ゲート外側で既設予約を取り消さない。

対照 C01 はゲート関数を通す場合でも**完全な恒等出力**にする。「閾値 0 の似た処理」で暗黙に旧根拠を除外する対照にしない。

証跡には、原本行・時刻・rawseq、campaign、d、A0、anchor、extreme、当行順行比、初回到達行、元 B00/source、許可後 B00/source、遮断理由を保存する。閾値の到達は全量計画から将来最大を取らず、前から走査する。

## 合理性と反例

狙いは、元 C01 の早い減量・早い復元で最大 1 回を消費する経路を抑え、その権利をある程度伸びた後まで残すこと。元の初期損切りと組予算は残るので、無条件の抱え込みへは変わらない。

一方、次の反例がある。

- 一度も 1A0 進まず逆行する組では、旧 C01 が持っていた早い減量効果を失う。
- 閾値へ届く直前に急反転すれば減量しない。到達しても次の有効 B00 公開までに巻き戻すことがある。
- 初回到達直後の小さな悪化で 1 回を消費すれば、その後もっと大きく伸びた局面への権利は残らない。今回案は「最大の山の後だけ減量」を保証しない。
- 到達済み状態を維持するため、利益が消えた後に初めて減量する場合もある。「利益中だけ減量」とは違う。
- 2A0 付近では元の半数利確と重なり、残枠への 25% は TOPIX 5→3 枚なら 1 枚、NK225 10→5 枚でも 1 枚になり得る。数量率の変化を開始時刻の情報価値と混同しない。
- 減量後すぐ同方向へ再加速すれば逸失利益・復元の高値買い／安値売りが増える。初回予算・期限が変わらなくても収支は改善するとは限らない。
- 1.5A0 の条件は既存の追跡始動と同じ水準だが、追跡幅は 3A0 のまま。減量許可を遅らせるだけで残玉全体の利益返上上限を保証しない。

同じ入口・同じ影・同じ数量の全組を比較し、到達した組だけを抜き出して勝率を評価しない。入口を変更せずとも、実保有枚数分と減量・復元回数が変わるため、純粋な予測精度の比較ではない。

## 実装後に必要な反例検査

新売買の前に、閾値等号／未到達、同一行公開の拒否、同秒後続行の許可、到達前から残る source の拒否、組切替、影／実先終了、2A0 部分利確との競合、欠測価格での誤始動、買売反射を人工で固定する。既存 C01 の恒等ゲートは全配列一致を必須とする。

prefix と未来改変では、元入口・影の計画・B00 を切断／再生成してからゲートを作り直す。完成済み全量ゲートを切るだけでは監査にならない。将来価格・ATR・B00/source を変えても、それ以前の到達行・許可列・注文全列が不変であることを確認する。反射では方向と価格を反射し、到達行と許可の真偽は同一となる。
