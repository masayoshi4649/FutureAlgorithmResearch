# 第二巡：観測未知の数量と超過分だけの利益保護

第一巡の源と全26Night原資料を固定し、悪化三夜の診断から次の四案を比較する。結果を見る前に登録する。旧結果・App・dist・原資料は変更しない。入力は `inputs159r2.json`、実装は `engine_go/`、候補は `configs159r2.json`。

|ID|比較元|変更|
|---|---|---|
|R00|N04|後半の初回支持が未知のときだけ元Source初回量を使う。既知支持ならJ02式のまま。前半は元P05量|
|R01|R00|後半の基準超過分だけ、玉別40pt順行で起動・最高順行から40pt戻り・最低建値床|
|R02|R00|上記の起動だけ80ptへ変更。戻りは40pt|
|R03|R02|超過分80pt逆行かつ反対短期支持5秒継続で部分返済を追加|

初回を少量へ固定しない。強い既知支持なら大量に建てる元数量式を残し、上乗せした部分の出口を分ける仮説である。支持未知を方向への弱い支持と同一視しない。

## 基準残量と対象玉

基準は**同じSource担当・同じ親の当時のSourceQty**。SourceQtyはすでに元mini枚数を10倍したmicro単位。各Source玉ごとの基準量を保証する方式ではない。

1. 元Sourceの返済通知を先に受け付け、親SourceQtyを更新する。
2. 親の全実残玉から、既存の返済予約数量を所有IDごとに差し引く。これが自由残量。
3. `超過量=max(0, 自由残量−SourceQty)`。未約定新規は実残玉に含めず、片方向上限の検査では予約として含める。
4. 超過量を約定観測番号の新しい玉から割り当てる。同じ観測番号ならID降順。割当は判定ごとに計算する。同じ初回玉の一部分も対象になる。
5. 割当済みの玉だけ、既に観測した玉別最高順行を使って保護する。元玉の全てへ新トレールは付けない。新たに超過対象となった玉でも、過去に観測済みの最高順行は捨てない。
6. 返済は対象IDと部分数量を予約し、次正常ラージ気配で約定。判定線での価格補正はしない。

例：元Source5mini＝50micro、実80micro。30microだけが新保護対象。先に元Sourceが2mini返済を通知すると、既存の比例返済で実32microを予約しSourceQtyは30になる。この同原行で新たに保護可能なのは `80−32−30=18micro` まで。

既に保護返済15microを予約済みなら、その予約を差し引く。二重返済、Sourceの返済と新保護の二重計上を許さない。Sourceが親全返済を指示した場合は、従来通り残玉全量の返済を優先する。

## 保証しないことと、部分返済の干渉

新保護による返済は、その判定時点の親基準残量を削らない。一方、**後から来る元Sourceの部分返済まで、実保有が常にSourceQty以上になることを保証しない**。

元Sourceの部分返済は第一巡と同じく、該当SourceIDに属する現在の実残量×元返済比を使う。初回の固定係数で残量を無視して返済する方式ではない。

- 単一玉：実80→超過30返済→実50。元2/5返済は実20となり実30、Source残30と一致。
- 複数玉：元50+10＝60に対し実80+16＝96。超過36を新しい玉16＋古い玉20で閉じると古い玉60だけが残る。その後、元の古い玉へ2/5返済が来ると実24を閉じて実36、Source残は30+10＝40。基準より4枚少なくなる。この既存配賦を変更せず、人工例として記録する。

この差を隠して「基準手法を丸ごと残した」とは表現しない。元Source返済の按分そのものを変える案は今回含めない。超過返済後にSourceが追加通知を出す場合は、既存の初回数量係数で追加する。新しい自律的な再エントリーは作らない。

## R03の損失側

反対支持の条件は第一巡N11と同じ：支持既知、Opp≥0.5、方向付きOwn15<0、方向付きOwn5≤0を5秒継続。未知・異常板・正常原板間隔が5秒超なら時計を破棄する。条件と玉の80pt逆行が揃った時、割当超過分だけ返済する。基準量の価格損切りや出口を置き換えない。

利益保護と同時に成立した場合は利益保護の返済理由を優先し、同じIDへ二重返済しない。新しい保護は次板で赤字約定になり得る。

## 会計と同値確認

前半P05→前後15分静観→新D07後半、共通特徴継続、価格時計、場末05:50判断、手数料0、micro100片方向上限は第一巡のまま。

新候補4×26＝104条件場。別キー `control` にN00の独立同値対照26場を保存し、元Sourceと全注文・配賦・数量・価格・時刻・収支が一致することを実行時検査する。これは新たな成功例へ数えない。金融再生後、第一巡N00保存結果とも照合する。

各保護判断にSource基準残量、自由残量、超過量、部分返済数量、玉別順行・逆行、利益床、支持、原行を保存する。最終損益だけでなく途中最小時価・最大下落を比較する。

金融前専用人工検証は `go test . -v`。第一巡の人工例を引継ぎ、未知対照、超過先返済、同原行のSource部分返済、予約控除、新玉優先、複数Source玉での保証限界、超過分の逆行返済を追加する。
