# 中期方向を保持し、短期入口を分離する第３仮説

最初に hierarchy_design_fixed.json を読む。新しい価格損益を見る前に96条件と数値を固定した。これは実装前の仮説であり、収益性は未評価。

6主方向（EMA8/30、EMA15/60、20分価格差、20分高安突破、当日VWAP、30分回帰）×主方向時間倍率2通り×入口4通り×相手確認2通り。主方向は確定1分足を120秒遅延して更新・保持する。方向の保持と、実際の建玉の出口は別で、建玉は既存管理器が損切り・利確・場内返済を行う。

入口は主方向のみ、短期価格順行、OFIと短期価格順行、短期逆行を記録して別イベントで再開、の4つ。板の短期状態が弱まっても中期の主方向は消さない。入口成立方向は120秒まで残し、主方向や相手確認が撤回されたら解除する。相手を使う場合は、その中期方向に追加60秒の遅延を置く。

時計窓、相手遅延、入口確認強度を別々に±20%反証する。開始待機20分・TTL120秒・押し戻り準備期限10分は固定する。主方向のみでは入口確認強度、自市場のみでは相手遅延を不使用として記録する。

実装は hierarchy_signals.py に追加し、catalog/build/clear_cache/neighbor_specs を公開する。因果性、未来切断、左右対称、準備と発火の分離を検査し、売買損益と現在APIは扱わない。
