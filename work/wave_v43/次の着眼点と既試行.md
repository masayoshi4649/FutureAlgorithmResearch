# 時間の数え方を変える案の確認

今回の32条件の再生後、損益集計の確定待ちに、次の候補となる時間の数え方を文献と既存コードで確認した。このメモは新しい売買実装・損益検証ではなく、今回の固定条件にも加えていない。

「何分たったか」に代えて「どれだけ価格が動いたか」で観測を更新する発想がある。[Glattfelder・Golub（2022）](https://arxiv.org/abs/2204.02682) は内在時間と物理時間の関係を、ブラウン運動と通貨のティック系列で調べている。時間尺度の分析であり、今回の先物での利益を保証する資料ではない。

[Wu・Han（2023）](https://arxiv.org/abs/2309.15383) は方向変化の閾値・減衰係数を最適化し、HMMによる状態検知を加えた外国為替の検証を報告している。今回確認したのは要旨で、再現実験や採否の確認はしていない。そこでの利益を、H019・OSE・1週間の既知データへ移せるとは判断しない。

同じ名前を新手法として増やさないため、既存との重複を確認した。

|既試行|実装された内容|残る違い|
|---|---|---|
|v13 N05|確定価格の追跡極値から0.8ATR反転したとき方向を通知|方向変化を検知する発想自体は既試行|
|v13 N03|効率比を使ってKAMAの反応速度を変える|平均線の速度を相場に合わせる発想も既試行|
|v23／v25 event_clock|原本更新回数で窓を作り、OFIなどの向きを見る|更新回数を時間として使う板の手法も既試行|
|v26／今回v43|複数の固定時間幅を合議する|同じ物理時間系列を複数窓で見る方式|

追加検証の余地としては、H019の平均線を、時計時間ではなく**過去の価格変動の累積量で更新する**組合せが考えられる。例えば公開時点までの中値変動絶対値を過去ATRで割り、一定量たまった時点を一つの更新とする。これは今回確認したコードには見当たらないが、厳密な新規性や利益は未確認である。

反証点は明確である。往復のノイズでも更新が速くなり、方向の持続と混同する恐れがある。動かない間に過去の方向が長く残るため、鮮度切れは実時間で管理する必要がある。閾値到達前へ確定イベントを戻して表示してはいけない。両銘柄は更新頻度が異なるため、相手確認も「その時点までに実際に公開された方向」に限る。N03、N05、元H019との対応比較なしに、新しい名称だけで追加価値を主張しない。

現段階では案であり、未実装・未検証。今回の32条件の成否と混ぜない。
