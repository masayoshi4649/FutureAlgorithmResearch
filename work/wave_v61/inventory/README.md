# 場内在庫の再生

最初に `集計結果.json` を読む。計算中は `中間集計.jsonl` に完成済みモデルを追記する。条件は `個別仕様.json`、損益前のコード・仕様・入力固定は `売買仕様固定.json`。売買台帳は `ledger/{モデルID}.pkl` に分離して保存する。

## 条件

5系統 × 期限6種類 × 幅2種類 × 積極度3種類 = 180条件。各条件を `quote`・`mid`・`passive` で独立に再生するため 540モデルとなる。主5条件は `H060_D075_A1_quote` で固定した。

`I1` は有限寿命の往復格子、`I2` は在庫中心移動と反対玉のFIFO返済優先、`I3` は逆行追加停止と整理、`I4` は方向と含み益を確認した追加、`I5` は期限付きカバーである。期限は各玉の元の新規約定時計から数え、再配置・利確・追加・カバーで延長しない。

`A0` は TOPIX 1枚ずつ・片側最大2枚、NK 2枚ずつ・最大4枚、休止5分。`A1` は同じ単位で最大5枚/10枚、休止1分。`A2` は2枚/4枚ずつ・最大10枚/20枚、休止0分。数量と頻度をまとめた設定なので、積極度の差を数量だけの効果とはしない。

## 集計と台帳

`methods` の各要素には `id`、`condition_id`、`family`、`price_mode`、`primary`、`config`、`accounts`、`summary`、`weeks` と台帳パスがある。`condition_id` が同じ3モデルが注文方式の比較である。

各 `accounts` は1銘柄1場の会計であり、以下を保存する。

- `gross_profit` / `gross_loss`：返済粗利益・返済粗損失の正数合計。
- `fees` / `net`：全新規返済手数料と手数料後純収支。
- `unrealized_change=0`：当場始めと終わりは全玉なし。途中の含み損を無視する意味ではない。
- `equity_change=net`：全含み・全発生費用を含む当場純資産の変化。
- `equity_min` / `equity_max` / `drawdown`：当場0起点の資産最小・最大・最大下落。
- `win_qty` / `loss_qty` / `flat_qty`：入口・返済費用を配分した返済玉の累計勝敗枚数。
- `cycles`：返済玉数。カバー玉も別玉であり、別枝の「全玉決済を1組」の件数とは異なる。
- `candidate_count`：武装した格子に成立した発火候補。FIFO返済に切り替わる候補も含む。未約定の候補を利益と数えない。
- `hold_*` / `deadline_overrun_*`：返済玉単位の実保有時間と、元coreが予定期限を超えた観測・約定の遅れ。

台帳 pickle は `(session,symbol)` をキーとする辞書。各値に `orders`、`trades`、`resets`、`cancellations`、`counts` がある。注文と返済の列名は集計の `meta.order_columns` と `meta.trade_columns`。行番号は当該場の有効原本配列に対する番号で、原本の `seq` も注文台帳へ保存する。

## 価格モデルの限界

主 `quote` は条件成立判断の次有効原本行で買ask・売bidを使う。`mid` は中値で入口や損失予算も変わる独立再生である。`passive` は前行から存在する指値をラージ1呼値以上通過した場合に指値で約定させる追加仮定であり、実際の小型商品板や注文順位を再現した保証ではない。

特に `I2 passive` は通過約定時に反対玉へFIFO割当できるネット在庫モデルである。実APIで待機時に新規/返済と対象玉を固定する運用や取消競合を完全再現しない。実行可能性の主比較には `quote` を用いる。

保存時計は最終約定の `CurrentPriceTime` であり、板の実受信時計ではない。期限を過ぎてから次観測まで間が空けば、その実際の次行価格と遅れを残す。途中の価格は補間しない。場末の同場返済ができない資料では安全停止する。
