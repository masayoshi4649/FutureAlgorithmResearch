# 選択注文器の固定契約

`engine_selector.run(ready, states, request, config, detail=False, source_override=0, observed_fill=False)` は共通 D273 専用。T と R の入口方向を選び、注文と建玉の所有者を記録する。元の `wave_v28/engine_context.py` は変更しない。

- `states`：原本行数 × 2 の `ndarray[int8]`。列は T / R、値は −1 / 0 / 1。
- `request`：原本行数の `ndarray[int8]`。要求 ID は 1=T、2=R。
- `source_override`：0 は適用 ID の入口、1 は常に T、2 は常に R。上書きしても要求 ID の変更・取消・所有 ID は記録する。
- `observed_fill`：False は従来の指定値約定。True は新規・損切り・追跡・部分利確を含む全約定で条件成立行の観測価格を使う。旧観測派生の「部分利確だけ指定値」とは異なる。
- 返り値は旧 `trades / cycles / curve / orders / stats` と `selection_events / selection_curve` の辞書。旧5項目の列と単位は不変。`selection_curve` は `detail=False` でも全原本行を返す。

## 処理の順序

1. 前行で取消要求済みなら、現在行の先頭で取消を確認し旧未約定を消す。
2. それ以外の既存注文を現在価格で判定する。現在行の要求変更を使って、先に成立した注文を遡って取り消さない。
3. 現在行の要求を読む。保有中は建玉所有 ID・実入口源・初期 ATR・価格出口を維持する。
4. フラットで要求 ID が変わり、有効な未約定があれば取消要求だけを出す。次行で取消確認して新規準備、さらに次行以降に約定する。同じ売買方向でも ID が変わればこの手順になる。
5. 未約定がない場合は現在行で適用を変えて準備できる。完全返済から5分の待機、開始20分の待機、新規締切5分前は変更しない。

保有中に複数回要求が変わっても最新要求だけを完全返済後に適用する。要求は両市場共通でも、取消・適用・保有の進み方は市場ごとに独立する。同時刻の行は原本行順で処理する。価格欠測行では先に出した取消の確認だけ行い、新規の価格判断はしない。期限切れ未約定は有効注文ではないため、ID 変更に不要な取消待ちを加えない。

## 列とイベント

列順はコードの `SELECTION_COLUMNS / EVENT_COLUMNS`、番号は `EVENT_NAMES / PHASE_NAMES` を参照する。集計では文字列から列番号を引き、番号を直接仮定しない。

`selection_curve` の主要列：

| 列 | 意味 |
|---|---|
| `request_id` / `applied_id` | 現在要求 / 当該市場の適用 ID |
| `pending_owner_id` / `position_owner_id` | 未約定 / 保有玉の所有 ID。なしは0 |
| `entry_source_id` | 現在行で使う実入口源。保有中は建玉の実入口源 |
| `pending_entry_source_id` / `position_entry_source_id` | 未約定 / 保有玉の実入口源。取消対照では所有 ID と異なり得る |
| `entry_direction` / `position_direction` | 現在の実入口方向 / 保有方向 |
| `cancel_wait` / `cancel_source_row` | 取消確認待ち / 取消判断の原本行 |
| `pending_source_row` / `pending_level` / `pending_atr` / `pending_expiry` | 未約定の判断行・水準・固定 ATR・期限 |
| `cooldown_until` | 完全返済後の再準備解禁時刻 |
| `position_atr` / `stop_level` / `trail_level` | 固定 ATR / 次行から有効な価格出口 |

枝別利益は各返済の `entry_row` にある `position_entry_source_id`、枝別所有利益は同じ行の `position_owner_id` に帰属させる。新規件数は新規注文の約定行を同様に参照する。行 i の状態を次の原本行までの時間に掛けて参加時間を測る。

| イベント番号 | 名称 | 段階 |
|---:|---|---|
| 1 | 要求更新 | 現在行判断 |
| 2 / 3 | 取消要求 / 取消確認 | 現在行判断 / 次行先頭 |
| 4 | 適用変更 | 取消確認後又は未約定なしの現在判断 |
| 5 / 12 | 新規準備 / 切替後再準備 | 現在行判断。準備合計は両方を数える |
| 6 | 追跡更新 | 現在行判断 |
| 7 | 新規約定 | 既存注文の約定 |
| 8 / 9 | 部分返済 / 完全返済 | 既存注文の約定 |
| 10 | 期限又は方向で取消 | 現在行判断 |
| 11 | 保有中要求保留 | 現在行判断 |

`source_row` は取消・発注等の判断行。所有者イベントは説明用で、価格台帳の会計を置き換えない。セッション開始時の適用はそのセッション最初の要求とし、初期化そのものは「適用変更」に数えない。セッション間の要求変更は別集計で第6→第7境界も含める。

## 確認済み範囲

`engine_selector_audit.py` は外部通信を拒否し、合成20件と旧固定 T の26区間を検査した。旧5結果は全配列で厳密一致。取消の前後、同時刻、価格欠測、締切、保有中の反対要求、部分返済、5分待機、実入口上書き、価格反射、未来削除・改変、全玉の会計と上限を確認した。新しい A/B 選択方式の相場成績は、この検査では計算していない。

根拠は [監査結果](engine_selector_audit.json)。原本と旧入力の SHA は実行前後で不変、API取得0、現在保存物の使用0。
