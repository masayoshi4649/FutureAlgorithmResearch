# P05移植同値検査

原研究の成績を増やす探索ではなく、同じ保存観測でアプリ移植の注文一致を確かめる。代表は2026-09-30、10-01、10-21の3夜に固定する。

- App/SessionTraderのstrategy/e01/rulesを隔離コピー。前半は実際のP05と独立仮想B04を時系列で動かす。主担当の効率0.25、戻り0.40R、反発0.125R、17時解禁。補完はUS+30で前半なし。
- 実玉は通知枚数・片方向上限10枚。実約定ごとの40pt利益開始、最高利益から10pt戻り、判断時利益>0。影の損切りや途中返済は実玉へ渡さない。再参加枠は作らない。US−15全返済、次正常原行BBOで約定。費用0。
- 仮想B04は独立した次正常原行BBOの約定と元の出口を保持。実約定価格や損益を影へ渡さない。
- 原資料一覧149.jsonを使い二市場時刻安定結合、CurrentPriceTime採番、未来足は名目公開まで不可。同時刻相手市場は従来の厳密過去参照。
- 売買を完了してから150のB04前半新規通知、151のP05実注文・約定を読む。比較項目は入口担当・方向・枚数・判断時刻/原行、約定時刻/原行・価格、累計損益、最終0玉。期待値を判断へ与えない。
- 登録受領registered=trueとreturncode=0が必須。既存結果上書き拒否、現在API通信・実注文なし。

実行はengine_go内で `go run . -registration ../登録受領152.json`。出力は../results。

## 実運転との区別

アプリの発注商品は各商品の実約定価格で台帳化し、出口参照は日経ラージBBO。研究同値検査では実商品もラージBBOの費用0模型へ揃える。途中起動は指標を履歴準備し、影の売買は現在観測から始めるので17時からの研究と同一結果を保証しない。再接続Advanceは影・最高益・開始済追尾を進めるが、未送信の過去利確を現在の損失返済へ変換しない。既に発注した返済要求・境界全返済要求は維持する。

実約定はExecutionID別に保持し、同じHoldIDでも建値を平均化しない。同HoldIDの返済予約は順次送信。execution.Managerは現在、同じ証券会社ExecutionIDの後からの数量増加を検出した場合は停止して照合する既存仕様であり、通常の別ExecutionID部分約定を対象とする。

## 後半の読取監査

研究S04のPortfolio.Start=USOpenとアプリの元NightStartの違いは、夜間では追加担当のNextReady初期値とepisodeの最早時刻に限られ、US+15以降どちらも過去になる。共通Featuresは元NightStartの蓄積で一致。一方、研究はUS〜US+15も影を進め、アプリは新しい枠開始から影を進めるため、この前半3夜照合だけで後半の全注文同値までは主張しない。
