# 継続波検知の独立設計レビュー

本書は保存データの読み込み・性能試験を行わず、`AGENTS.md` と研究方針だけから検証設計を点検したものである。価格データの取得、現在セッションへのアクセス、注文発注は実施していない。

## 検証前に固定する定義

- 「１日数回」は銘柄ごとに数える。日中と夜間の扱い、完全な１日の範囲、許容頻度を明示する。短い収録時間を単純に１日へ引き伸ばした件数は参考値に分ける。
- 同じ条件が連続成立する時間帯は１つの検知とする。再検知には解除と再成立、または明示した待機条件を要求する。待機時間だけで１つの長い波を分割しない。
- ロング・ショートは対称な式から作る。両方向が同時成立した場合の見送り規則を固定する。
- 継続波は、検知後の有利方向への値幅と、その方向を維持した時間の両方で評価する。最大有利値幅だけでは一瞬の跳ねも成功になる。
- 例として、検知後２０・６０・１２０分の方向付き騰落幅、２０分以上の方向維持率、最大逆行幅を併記する。正解ラベルに使う時間・閾値は評価データを見る前に固定する。
- 少なくとも１２候補を比較する場合、同じ指標の閾値違いだけを１２種類と数えず、移動平均、価格突破、回帰傾向、方向効率、押し戻り、銘柄間確認など、異なる検知原理を含める。

## 先読みと時間境界

- 確定した足の終値まででシグナルを作り、次の実在する足の始値を仮の新規価格とする。同じ足の終値で確実に約定した扱いにしない。
- 指標はシグナル時点までで計算する。中心化移動平均、全期間での標準化、将来値による欠損補間、後から確定する転換点は検知に使わない。
- １分足へ５分足指標を付与する場合は、５分足が確定した後にだけ利用する。時刻が足の開始か終了かを確認する。
- 他銘柄を確認条件に使う場合も、実際に確定済みの時点へ後方結合する。片方の更新が遅い場合、古い値を無制限に持ち越さない。
- 正規化のＡＴＲは検知時点で固定する。将来のボラティリティで過去の成績を割らない。ＡＴＲがゼロ、極小、計算未完了なら検知を見送る。
- 日中・夜間の境界、欠損区間、銘柄切替で保有をまたぐかを明示する。データのない休止時間を「継続した２０分」と数えない。
- 学習側で最大１２０分後まで答え合わせするなら、その終点が翌日日中の評価区間へ入る学習イベントを除外する。指標計算用に過去の学習データを参照すること自体は先読みではない。
- 各区間の末尾で必要な将来時間を確保できないイベントは評価不能とする。失敗・損益ゼロとして混ぜない。２０分、６０分、１２０分で評価可能件数を別に示す。
- 現在セッションを最後の１回にするには、保存済みファイルに同じセッションが含まれていないことも確かめる。最終取得後は条件・候補選択・出口を変更しない。

## 少標本での候補選択

- 初日日中と夜間を条件選択に使い、翌日日中を固定条件の評価に使う。翌日日中の結果を見て選び直した場合、その区間は学習側へ移ったと明記する。
- 候補ごとに頻度、方向維持、正規化値幅、逆行幅、コスト後損益を同じ表で示す。総損益だけで波検知の品質を決めない。
- 学習側の選択順序は、頻度の適合、持続性、逆行の小ささ、コスト後成績、条件の単純さなど、あらかじめ固定する。評価結果に応じた重み付けの変更は避ける。
- 少数の大波１件が平均を押し上げる可能性があるため、中央値、最悪値、件数、イベント一覧を併記する。数件だけの勝率を小数点付きの精密な確率として扱わない。
- 日中と夜間、ロングとショート、両銘柄を分解する。ただし、分解後に標本が少ない項目を「安定している」と判定しない。
- NK225 と TOPIX の同時刻の値動きは強く関係し得るため、２銘柄分を独立した証拠として数えない。重複する保有時間のイベントも独立ではない。
- １２候補の最高成績には選択の上振れがある。１日の評価で再現性や将来の収益性が証明されたとは言わず、採用候補と継続検証項目を区別する。
- 単純な基準条件と比較し、追加条件が頻度を下げただけか、持続性や逆行幅を改善したかを確認する。閾値を少し動かす確認は学習側で実施し、最良一点の探索にしない。

## 検知と売買試算を分ける

- 検知品質の集計と、建玉を持つ仮想売買の集計は分ける。重複した正解ラベルは検知研究には使えても、同時保有を認めない売買損益へそのまま加算できない。
- 費用は銘柄ごとの価格単位で示し、往復の手数料相当、気配差、滑りを区別する。価格単位から円へ変換するには対象商品と倍率の確認が必要である。
- 実際の費用が未確定なら、費用ゼロだけで結論を出さず、複数の往復費用による感度を示す。損益分岐となる往復費用も参考になる。
- 同じ１分足で利確と損切りの両方へ到達した場合、足だけでは先後が分からない。保守的な先後規則を統一するか、保存済み生データで判定する。
- 逆指値を飛び越す価格変動は、指定価格で確実に約定した扱いにしない。欠損直後の次足始値も通常の次足と区別する。

## 注文方法への接続

| 項目 | 設計上の注意 |
| --- | --- |
| `market` | `AGENTS.md` では返済専用。次足始値を新規価格とした研究結果は即時成行新規の実装可能性を示していない。 |
| `stop` | 上昇突破の新規買い、下降突破の新規売りに対応しやすい。条件成立時点と実約定価格の差を別途測る必要がある。 |
| `limit` | 押し目買い・戻り売りに対応するが、未約定が起きる。理論上の検知件数をそのまま約定件数にしない。 |
| `trail` | 追跡極値からの反転を条件にできる。追跡開始時点と幅を固定し、将来の最安値・最高値から追跡した扱いにしない。 |
| `ifd` | 返済条件は実約定分に対応する。新規発注数量を全量約定済みとみなさない。 |
| `oco` | 同じ売買方向の２条件である。買い突破と売り突破を同時待機する両方向新規の仕組みとして使わない。取消・照合中の残数量管理も必要である。 |
| `ifd_oco` | 新規実約定分に対する利確・損切りの組合せに対応する。部分約定と取消中の状態を実装段階で扱う必要がある。 |

最終報告では、検知ルールを採用できる根拠、翌日日中と現在セッションでの未調整の結果、未検証の約定条件を分けて示す。検知アルゴリズムの研究だけで、注文の自動送信まで実施しない。
