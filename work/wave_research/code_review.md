# 継続波検知コードの独立レビュー

対象は `research.py`。保存価格、未使用日の価格、現在セッションの取得を行わず、コードの読解と合成データによる検証を実施した。研究本体は変更せず、`test_research.py` に検証を実装した。

## 発見し、修正を確認した問題

1. **約定直後だけ追跡が１足遅れていた。** 新規約定足では順行終値を追跡極値に反映するだけで、追跡損切りを更新していなかった。約定足終了時にも水準を計算する修正が本体担当により入り、ロングとショートの両方で次足の正しい追跡決済を確認した。
2. **両銘柄の異なる価格ポイントを合算していた。** 合算ポイント損益、利益損失比、最大ドローダウンは同じ単位ではない。本体担当により両銘柄混合時はこれらを未定義とする修正が入り、検証を通過した。銘柄別集計とＡＴＲ正規化集計は利用できる。

## 合成データによる１８検証

## 結果の解釈で残る注意点

- １・５・１０分の検知時間軸は、同じ将来評価時間で比較する。５分後の成功率と１２０分後の成功率の単純な差だけでは、「長い波ほど正確」とは言えない。評価可能な件数と、同じイベント集合に限定した比較が必要である。
- 正解は将来の方向・維持率・逆行幅をまとめた定義である。３０分のうち６０％で順行という条件は、３０分間ずっと一方向だったという意味ではない。
- ラベルと特徴量では短い欠測を２分まで直前終値で補っている。これは取引がなかった区間に対する仮定であり、配信障害で見えなかった急変を再現しない。１分足の仮想約定には補完足を渡していない点を確認した。
- 共通ＡＴＲは、５分足開始時刻を確定時刻へ５分ずらした系列を判断時刻へ後方照合している。コード上は未来の５分足を用いていない。照合許容時間は５分である。
- 現在の複合得点には正答率だけでなくコスト後損益と頻度が入る。正答率を厳密に第一順位とするなら、選択前に順位規則を変更して固定する。変更しない場合は「正答率が最高の候補」ではなく「複合評価で採用した候補」と表現する。
- １０分足の区切りは各銘柄の最初の１分足を基準にする。最初の観測時刻が異なる場合、両銘柄一致条件は時刻を正確に合わせた足がなくなり得る。同時刻の観測開始であることをデータ監査で確認する。
- 設定とコードのハッシュは記録されるが、未使用日評価時の強制照合は実装されていない。最終凍結後に本体を変えた場合は、変更履歴を残して開発側の選択からやり直す必要がある。
- 同じ銘柄でも、集計入力が時系列順でないと最大ドローダウンが変わる。現在の呼び出しではセッション内順序を保持しているが、任意のイベント集合を外部から渡す際は時系列順に並べる。

本レビューでは未使用日と現在セッションの性能を確認していない。
