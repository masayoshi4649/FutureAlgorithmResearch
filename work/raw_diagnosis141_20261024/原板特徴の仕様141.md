# 原板特徴の仕様

`raw141.py` は金融再生をせず、原板を先頭から末尾まで読み取る。元ファイルは変更しない。全行を保持し、欠測や不正な行を削除せず資格マスクで分ける。

## 原文への対応

- `seq` は **0始まりの原行位置**。00140保存packetの`seq`と一致する。
- `line_no` は人間向けの1始まり行番号。`line_no = seq + 1`。
- `byte_offset`・`byte_length` は原文の位置と長さ。gzipの場合は展開後の位置である。
- `line_sha256` は各原行全体（改行を含む）のSHA256を32バイトで保持する。`source_sha256`は原ファイル全体のSHA256。
- 原文取得例：`python raw141.py excerpt --npz raw_features/NK225_2026-10-23_Day.npz --seq 192539 --count 1`。抜粋時にも行SHAを照合する。

## 配列と時計

`raw_features/{銘柄}_{セッション}.npz`は原行順。`packet_aligned/`の同名ファイルは保存packetの原seqに完全整列し、原文の`time_s`・`last`・`bid`・`ask`と保存packetを全行照合している。後者は原位置と1次元の派生特徴を保持し、全10段と行SHAは原板NPZで参照する。

| 配列 | 内容 |
| --- | --- |
| `time_s` | 元`CurrentPriceTime`のepoch秒。価格時計であり板受信時計ではない。欠測はNaN |
| `volume_time_s` | 元`TradingVolumeTime`のepoch秒。価格時計と別に保持 |
| `last`, `volume`, `trading_value` | 公表最終価格・累計出来高・累計売買代金 |
| `buy_price`, `buy_qty` | Buy1～Buy10の価格・数量、形状は原行数×10 |
| `sell_price`, `sell_qty` | Sell1～Sell10の価格・数量、形状は原行数×10 |
| `bid`, `ask`, `mid`, `spread` | 実買い気配Buy1・実売り気配Sell1・中値・気配差 |
| `top_bid_price`, `top_ask_price` | 原APIの同名フィールド。実際は前者がSell1、後者がBuy1という命名なので売買方向に流用しない |
| `book_valid` | 正の価格・数量かつ実bid＜askという構造資格。立会中、約定可能性、板の受信時刻を保証しない |
| `price_clock_valid`, `in_session` | 価格時計の有無、公式セッション開始以上・終了未満の資格 |
| `adjacent_book_valid` | 当行と直前原行の両方が`book_valid` |
| `price_clock_same`, `price_clock_backward` | 直前原行との価格時計の同一・逆行 |
| `book_changed`, `bbo_changed`, `bbo_price_changed` | 直前原行からの全10段、最良気配の価格数量、最良気配価格だけの変化 |
| `volume_delta_signed`, `volume_delta`, `volume_reset` | 公表累計出来高の差分、非負差分、累計減少。欠測と減少を取引0へ置換しない |
| `packet_atr` | 整列版に保存した既存packetのATR。新しく作った特徴ではない |

`CurrentPriceTime`が同じ原行の中でも板は変化する。これは受信遅延の直接証拠ではなく、秒単位時計の同一秒内更新や最終価格不変中の板更新を含む。受信時計がないため、同時計内の正確な経過秒や二市場間の受信順は復元できない。窓平均を作る場合も**当行seqより後の同時計行を含めない**こと。

## 供給・圧力の数値定義

距離重み数量は、各価格とその行の中値との距離をティック単位で測り、`数量 / (1 + 距離)`を可視10段で合計する。日経ラージのティックは10、TOPIXラージは0.5。`distance_imbalance`は`(加重買数量 − 加重売数量) / (加重買数量 + 加重売数量)`。ATRは使用しない。

`same_price_buy_increase/decrease`、`same_price_sell_increase/decrease`は、連続する二行の**両方で同じ価格が表示される段**の数量差の正負合計。価格を段番号で固定せず照合する。`matched_levels`で対象段数も保持する。10段から見えなくなっただけの価格を取消・撤退として数えない。この差は補充・撤退の代理であり、新規指値、取消、約定、隠れた数量を区別できない。

`ofi`は最良気配の価格と数量による次の原行差分で、正が買い圧力側。`b,a,qb,qa`を当行のbid/ask/数量、添字`p`を前原行とする。

```text
ofi = [b >= bp] qb - [b <= bp] qbp - [a <= ap] qa + [a >= ap] qap
ofi_normalized = ofi / (qb + qbp + qa + qap)
```

いずれも当行と前行の構造資格がある時だけ計算する。売買の約定方向を測ったものではない。`mid_change_ticks`も同じ資格で計算する。時間平均や売買ルールはこの抽出器に含めない。

## カバレッジと再利用

`coverage_reports/`は各原板の全読取行数・バイト数・原本SHA・時計欠測・時計不変時の板変化・packet照合を保存する。`coverage`というディレクトリ名はPythonの同名パッケージと衝突するため使わない。

最新6本の目録は`coverage_all141.json`。旧47場の並列目録は`coverage_known_01_141.json`～`03`。複数プロセスでセッションを重複させず、`--manifest-name`を分ければ同じ`raw_features/`へ出力できる。既存出力は上書きしない。

最初の6本は`raw141_initial141.py`、残る94本は保存先名・目録名・監査項目だけを追加した凍結版`raw141.py`による。数値処理の同値は`変換実装の同値確認141.json`でAST比較した。双方の実装SHAを保持する。
