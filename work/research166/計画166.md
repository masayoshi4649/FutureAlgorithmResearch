# 選定三手法の Web 実装を研究正本へ照合する計画

この作業は、利用者が指定した既存の三手法を Web アプリへ移植できたかを調べる独立再検証です。新しい手法、パラメータ探索、手法の選び直し、収益性の追加証拠を目的にしません。既知の 54 場と研究正本の約定は変更しません。

| 対象区間 | 固定手法 ID | 正本 |
| --- | --- | --- |
| 日中 27 場 | NK225_D164_15 | 00164 第二巡 |
| 夜間の米国開始 15 分前まで・27 場 | NK225_P164_06 | 00164 第二巡 |
| 夜間の米国開始 15 分後から・27 場 | NK225_U165_03 | 00165 |

時間割には三つの実手法 ID を示し、運用全体へ新しい手法 ID を付けません。研究 00164 の 54 原セッションから日中 27 と夜間 27 を読み、計 81 手法場を照合します。後半も既知資料です。日経ラージの原板・国内二市場の元指標を読み、米国データも API も取得しません。

入口・途中判断・出口は各研究の固定定義を継承します。日中は J02 の支持別数量を残して、初回失速待機の数量上限、残玉の実建値保護、追撃の短期確認・50 円逆行返済を照合します。米国前は少量初回と利益返済後の残玉の保護・追撃玉の 50 円逆行返済、米国後は反対価格帯・数量支持を見た初回の最大 30 秒待機を照合します。旧 S01・P05・D07 の定義を同名で変更しません。

## 数量・費用・約定

- 正本同値の主検査は日経 micro の片方向上限 100 枚、1 円幅あたり 10 円、手数料 0。買い・売りの実玉と確定新規予約を方向別に集計します。
- 実商品 mini の上限 10 枚・1 円幅あたり 100 円は別の整数粒度検査です。100 基準の希望数量を上限へ比例換算し、整数未満は切り捨て、1 枚未満の新規を切り上げません。完全返済は実所有残量全てです。micro と mini の損益の単純倍率一致を要求しません。
- 正常なラージの買い Ask・売り Bid を使い、判断原行より後の次正常原板で約定します。同秒内も原行順を保ち、足は当時公開されたものだけを指標へ渡します。価格時計は受信時計ではなく、実運用の到着順や約定を保証しません。
- 場末・前後境界は研究正本の時計と返済手順を保持します。残玉・予約を消して完了扱いにせず、末尾未完済は不一致として保存します。

## 合否と実運用の人工検査

100 枚の検査は、手法・場・判断原行・約定原行・時刻・方向・新規／返済・実価格・数量・返済収支を研究正本と照合します。同原行の分割返済は集約同値と個別所有 ID の会計を区別し、差分を消して成功にしません。全実玉と未約定予約、利益・損失・純額を照合します。

整数粒度は数量上限・予約上限・0 枚通知の扱い・所有 ID 返済・最後の全返済を検査します。部分約定は研究の一括約定に存在しないため、人工例で返済群の粗益判定、取消競合中の約定、残量再照合を確認します。個別取消は対象新規だけ、返済や他担当は維持し、結果不明の送信を繰り返しません。未送信新規はキューから外して戦略へ拒否通知し、送信済みは照合完了後に完了通知します。実注文は送信しません。

設定の人工検査は、標準式と旧標準四枠が厳密に一致する日経三商品の移行だけを認めます。独自枠、数量、OFF／DryRun／ON、接続先、改変式、TOPIX は保持します。稼働中の設定変更拒否と、旧 ID の選び直しを維持します。

## 登録と修正の保存

初回 App・ルール・設定・リプレイ実装、研究正本の定義・入力・保存結果を内容指紋で固定してから、共通の `manage.py check --proposal` と同一照合関数で重複を確認し、試行を登録します。巨大な旧台帳は全行の構造と対象外行の内容不変を確認し、追加行の根拠だけを深く検査します。更新可能な過去索引の指紋を修正しません。

不一致が実装不具合なら、元の実行源・出力を保持し、修正理由、差分、人工例、各再実行前の源指紋を別ラウンドへ保存します。アルゴリズム条件を正本へ合わせる修正に限ります。条件そのものを変える必要がある場合は別手法 ID と別登録へ切り分け、この同値確認へ混ぜません。

過去の 00155 の移植確認、00157／00159 の純量投影と返済配賦差、00164／00165 の利益床と次板約定差を再検証理由とします。既存の利益・損失や試行状態を改変せず、移植の一致を将来の利益保証・未見検証として扱いません。
