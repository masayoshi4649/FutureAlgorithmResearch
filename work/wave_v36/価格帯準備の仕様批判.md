# 価格帯準備の仕様批判

**共通の価格準備を先に作り、追加出来高の価値だけを対照にする方針は妥当。ただし、準備を作る条件、後続の分岐、戦略ごとの採用を別状態にする必要がある。** このメモは実装前の読取レビューであり、新しい特徴生成・売買再生・損益による選定をしていない。

その後の採用仕様は [価格帯の方向判定設計](価格帯の方向判定設計.md) と [入出力契約](band_signal_contract.md) を優先する。本稿のW待機・気配通過などは比較した案であり、最終実装への要求ではない。採用版は別行false→さらに別行trueで再武装し、突破は中値の確認幅と帯外1tickを両方満たした時に初めて成立する。中値の幅だけを先に満たしても、その時点では分岐を確定しない。また途中の無効板リセットがあるだけでは、有効endpointを持つ価格窓全体を排除しない。

## まず固定すべき点

1. **小さい端点差は停滞ではない。** W/4の間に大きく上下して元へ戻っても端点差は小さい。親が採用した `同窓のsource_mid最大−最小 <= max(.1At,1tick)` は、原案の端点差より明確。窓内の最低件数・時間被覆・最大空白も必要で、古い1点をasofしただけの短い履歴をW窓と呼ばない。
2. **準備時点の一組の素材を使う。** 既存特徴には同じ `source_last_seq` に対応する `source_mid_last/source_bid_last/source_ask_last` がある。中値だけ素材末尾、帯だけ解放行の現在気配、又は最後に出来高が増えた別原本行、と混ぜない。Buy1が買い、Sell1が売りであり、原本の英語BidPrice/AskPriceの名前から推測しない。
3. **窓と期限の時計を統一する。** 推奨は価格・出来高とも解放時刻の過去W窓。素材時刻・原本seq・解放seqは別に証跡へ保存する。素材時刻で出来高を切り、解放時刻で価格を切るなら別の窓になり、明示した比較が必要。同じ時刻群内の原本行を未来へ遡って使わない。
4. **出来高判定は準備時に凍結する。** 準備行でA0、方向s、素材中値m0、帯価格B、分岐幅D、両代理量と通過可否を保存する。「episode解決後に採用」は処理の整理として可能だが、解決までに増えた出来高を採用判定へ加えてはいけない。準備不採用でも母集団のepisodeは同じ規則で最後まで消費する。

時刻矛盾、負の出来高差／リセット、無効板、長い欠測は不明として扱う。無効行をまたぐ累積出来高差を次の小さい数量qへまとめて割らない。初期W履歴不足・未公開ATRでは準備しない。一度準備した後のAt変化では、準備帯・D・期限を変更しない。

## 出来高代理の意味を狭くする

入力担当と確認した契約では、各正の出来高差に、その原本行と前行の時刻・seq・気配・現在値、側、価格、現在側数量q、ΔV/q、stableを保持する。**準備帯Bの気配と、この出来高行の気配は別の観測**であり、価格が同じという条件でだけ対応付ける。

- 側は現在値が当該行のSell1価格なら+、Buy1価格なら−、それ以外は不明。全出来高の真の主導側を示す分類ではない。
- ②は側s・分類価格Bに対応する全正増分代理、③はそのうち両端の最良両側価格・数量と現在値が不変の部分。したがって同じ準備で必ず `0 <= ③ <= ②`、③通過は②通過の部分集合になる。これを不変条件として監査する。
- `ΣΔV/q` は各観測時の数量で割った無次元代理であり、「2回／5回補充された」「板数量の2倍／5倍を同じ人が吸収した」ではない。小さいqへの感度と、側不明で使えなかった出来高量も残す。
- 同時刻に複数価格のイベントが解放される場合は全行を集計し、最後の1行で上書きしない。価格照合は呼値単位へ正規化し、浮動小数の丸めや不正価格を同価格扱いしない。

## 「帯を突破」と「中値が順行」は同じではない

原案の `m−m0 >= D` は、スプレッドが広いと元の売り帯Bをまだ越えていなくても成立する。反対も同様。したがって次のどちらか一つを結果前に選ぶ。

- **簡明案:** 元の中値±Dだけで分岐し、名前を「準備後の中値反転／順行」とする。Bは出来高を対応させる価格であり、壁の消費・突破を観測したとは言わない。
- **帯突破まで要求する案:** 順行分岐に、s=+なら後続source_ask_last>B、s=−ならsource_bid_last<Bも必要とする。これは最良気配が帯の外へ移った確認であり、取消か約定かは依然不明。追加条件だけを後で都合よく外さない。

最初は簡明案を推奨する。追加の気配条件を使うなら、**中値が片側へ先着したが気配確認がない時点で待つのか破棄するのか**まで決める必要がある。両方向を後から見て有利な順序を採らないため、最初の中値側を記録した後の反対側への分岐替えは禁止する。

「先着」は真の市場経路の先着ではなく、**別の解放イベントの中値で先に確認された方向**と表記する。素材群内で両側へ触れた可能性を、群末尾の中値だけでは復元できない。

## 重複準備を防ぐ簡単な状態機械

価格だけで、銘柄・Wごとに次の母集団を一度生成する。出来高条件・K・分岐枝・相手確認・実口座の保有に依存させない。

| 状態 | 規則案 |
|---|---|
| 待機 | 十分な公開履歴で価格条件が成立した最初の解放行だけ準備。方向s、m0、B、A0、Dと代理量を凍結。 |
| 準備中 | 次の別解放seqから中値±Dの初回確認を待つ。一つだけ有効で、停滞条件が一瞬消え戻っても追加準備しない。準備寿命は一つに固定する。例えばWとすれば新しい調整軸を増やさない。 |
| 解決 | 初回確認で方向bを確定。反転限定はb=−s、継続限定はb=sだけ採用。反対が先なら破棄し、望む側まで待ち直さない。期限・欠測による失効も解決として記録。 |
| 再武装待ち | 簡明には解決後Wだけ待ち、次のW窓が解決後の素材で構成されてから再準備する。同じ古い進行を何度も使わない。 |

この再武装案は短い再挑戦を捨てる交換条件があるが、価格条件の真偽が一行ずつちらつくたび準備を増殖させるより意味が明瞭。寿命ちょうどでの発火と失効の優先順位、同時刻行、無効板からの復帰も固定する。**全条件で母集団の準備ID・解決行・解決理由が同一**でなければ追加情報の対照にならない。

発火後に注文器へ渡す方向のTTLは、準備寿命とは別に一つへ固定する。D273の新規期限は300秒だが、方向TTLが先に切れればstate0で未約定が取り消され、実効期限は短くなる。固定TTL、次の反対発火との優先順位、同方向再発火で延長するかを明記し、準備→分岐→採用→注文準備→約定を別々に数える。保有中のD273返済規則は変えない。

## 相手の同意と否定

相手は**準備方向sでなく、確定した初回反応b**へ比較する。発火時に解放時刻+60秒を過ぎた最新の価格方向だけを使い、同意があとから来るまで同じepisodeを待ち直さない。

| 相手方式 | 推奨する意味 |
|---|---|
| なし | 自市場だけで採用。 |
| 反対拒否 | 相手観測が有効で、その方向が−bでなければ採用。有効な中立は許す。 |
| 同意必須 | 相手観測が有効で、その方向がbの時だけ採用。 |

欠測・古さ超過・履歴不足は「有効な中立0」と別にする。反対拒否で欠測を通す案も実装可能だが、情報がないほど自市場単独へ戻る別仕様になるため推奨案へ黙って混ぜない。相手による拒否も母集団の解決を消費する。

## 90条件と事前固定する主仮説への評価

`W2 × (価格のみ1＋全増分K2種＋stable K2種) × 枝3 × 相手3 = 90` は、Kによる純価格重複を避けた対応設計として妥当。主仮説を **stable／W120／K2／初回反応で両方向／相手反対拒否** に先に固定し、他89を対照にする方針は、初期6で勝者を選び直すより検査の問いが明確。ただし主仮説が失敗した後に89中の最良を主へ昇格させれば、結局新たな選抜になる。

主仮説の最重要対照は、W・K・枝・相手を揃えた②全増分、①純価格、及び相手なし。これで気配維持の追加価値、出来高選別の価値、相手確認の価値を分ける。反転・継続の枝別収支も全組へ合算して示し、利益の出た枝だけを後付けで「選択器の判断」と呼ばない。90条件や同じ価格episodeを独立90標本とは数えない。

全13・後7はどちらも既知の再確認。前6が祝日取引3日D/Nである偏りを学習選抜に再利用しない点は改善だが、データ分布の偏り自体は消えない。新方式がH019と違う入口を選ぶ以上、これは全新規を揃えた退出改善ではなく、新しい準備選別・反応方向のアルゴリズムである。

## 実装前に壊れた規則を拒否する例

- 短期に大きく往復し端点だけ一致する価格を停滞と数えない。
- 代理③が②を超える、同時刻イベントが一件へ潰れる、未知側を片側へ流用する実装を拒否。
- 準備時はK未達、解決までにK到達する経路を採用しない。
- 不採用・反対枝・相手否定の後だけ、同じ帯を即座に新規準備へ戻さない。
- 中値と帯価格の参照原本行をずらす、未公開相手で同意する、成立行で約定する実装を拒否。
- 将来末尾の反転を消しても、過去の準備・初回反応・採否・注文が変わらない。上下反射で数量・損益と全状態の対称性を確認する。
