# 固定後確認の診断計画

選択済み最大3候補について、`locked_test161.json` が正常に完成し、rootが完了を通知してからだけ実行する。凍結済みfeatures/search・候補・モデル・期間を変更せず、新しい候補や金融再生を作らない。

1. `--authorization` の `root_completed:true` と結果/選択のSHAを先に確認する。未許可なら結果ファイルを開かない。
2. 選択済みイベントだけを正本のtest特徴/ラベルNPZへ接続する。判断添字・物理行・時計・方向・建値・先着原行・statusを照合し、保存採点の全件数と一致させる。
3. phase別、買売別、日本時間の時刻別に、全信号数・成功・逆行先着・未到達・未約定を再集計。entry前の15/60秒空白、飛ばした不正BBO、entry後の15/60秒空白・不正BBO・米国跨ぎを件数と率で示す。全信号分母と、実際にentryが観測された分母を併記し、品質で成功だけを除外しない。
4. 各phaseで最初の成功1例と最初の逆行先着1例を、判断時計→原行→方向の順で機械選択する。該当しない例は作らない。選択後の見やすい例への差替えを禁止する。
5. 具体例だけ保存原板を読んで次正常入口と最初の障壁を再確認。判断時/entry時/先着時の価格・物理行、直前60/30/15/5秒と判断時の特徴を保存する。
6. 「先着前最大順行・逆行」はentryを含めて決着原行を除外する。決着原行の板飛びを含む値も別欄で記録し、達成可能な利益や最良退出へ読み替えない。entry行で決着なら先着前の観測は0行とする。

結果は `診断161.json` と短い `診断161.md`。本計画は選択の修正根拠ではなく、観測されたことと限界を説明するためのもの。価格時計の空白中の順序、受信時計、真の約定/取消しの内訳は推測して補わない。
