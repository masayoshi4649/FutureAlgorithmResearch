# 状態残存の契約違反と経済影響

**凍結版には状態記録の不具合がある。経済検算と実装契約の合格を分け、完全合格とはしない。** 元コード・監査・保存損益は変更していない。

## 契約との不一致

旧版から継承した[数量調整エンジンの契約](../wave_v37/数量調整エンジンの契約.md)は、`phase`を0＝通常、1＝減量予約、2＝減量済み、3＝復元予約と定義する。追加の実損失R予算が未成熟の調整予約を取り消す際、凍結エンジンは`pending`を0へ戻すが`phase`を更新していない。そのため、予約がないのに1又は3が残る。監査が枠と予約から独立に算出した0又は2が、契約に沿った値である。

最初の実データ反例は`H019__B00_T120_F25_N3__R1__L015`、9月24日ナイトのNK225。20:08:53の行46748で予算予約が未成熟減量を取り消した後、行46759まで12行がphase1・pending0になった。20:08:56の行46760では元停止が優先して終了し、phase0へ戻る。[抽出証拠](adaptive_phase_revision_probe.json)は独立会計担当が保存したものを読み取った。本検査ではこの実相場を追加再生していない。

## 凍結コード内で注文へ伝播しない理由

構文木で`simulate`の全読込・代入を列挙した。

1. `phase`を注文判断に読むのは新しい減量・復元を準備する2箇所だけで、どちらも`not budget`の内側にある。残る1箇所は状態証跡の書出し。
2. 問題の取消時には必ず`budget=True`になる。この予算は価格回復でも解除されず、新調整の予約・約定を禁止する。
3. 元部分利確が先行した場合、予算は保持したまま、phaseを復元権の有無により0又は2へ再設定する。
4. budgetをfalseへ代入するのは初期化、新組開始、組全返済の3箇所だけ。いずれも同じ処理経路でphaseを0へ設定する。予算を解除し、古いphase1/3だけで次の調整判断へ戻る経路はない。

これは**現エンジン内部**の到達性についての結論である。外部表示・監視・別の注文プログラムが誤ったphaseを利用してよいという保証ではない。記録自体の契約違反は残る。[全参照と代入のAST証拠](phase_control_flow_proof.json)を保存した。

## 状態を直した人工対照

元ソースをメモリ内だけに複写し、予算取消直後の1箇所へ`phase = 2 if np.any(restorable) else 0`を追加。人工入力810件・計1,620再生で、全注文・返済・損益・保有・枠・予約・分岐・影注文計画と、phase以外の管理列が厳密一致した。

| 検査 | 入力数 | 実際に状態差が出た入力 |
| --- | ---: | ---: |
| 6指定経路＋64固定seed×2銘柄×1/5/15秒×指定/観測約定 | 774 | 10 |
| 復元予約取消×1/5/15秒×元停止/元部分優先/予算成行×指定/観測約定×上下反射 | 36 | 36 |

減量予約取消10件、復元予約取消36件を実際に通過した。元部分利確を挟む14件、後続組がある4件でも、状態以外の全出力は変わらなかった。取消後の同じ組で新調整が再発火しないことも全行確認した。人工の乱数seedは0～63をすべて使用し、損益で選別していない。

先行774件の入力ラベル「予算成行」は経路作成時の意図名で、実際の終了理由は元停止だった。予算成行による終了自体は追加36件で明示的に通過確認した。検査範囲を名称だけで水増ししない。

証跡：[774入力](phase_state_counterfactual.json)、[追加36入力・AST](phase_control_flow_proof.json)。新しい実相場損益・現在データ・APIは使用していない。人工経済同値を全実相場の修正版再検査済みと読み替えない。

## 今回の扱い

原監査の状態比較を実装に合わせて緩めることはしない。別の診断版で全不一致行を残し、経済項目の検算と状態契約の不合格を別に報告する。診断版の限定読取では、残存型の記録後も元の枠・注文・予算・両建て等の検査が継続され、状態契約falseが全監査合格falseへ反映されることを確認した。

[未採用の修正候補](engine_partial_restore_phase_candidate.py)も別名で保存した。これは人工対照と同じ機能差分を持つ候補で、正式なrunner・採否・保存台帳へは接続していない。採用する場合は、全対象の旧経済出力・phase以外の証跡の完全一致と、正しいphaseの全行一致をあらためて検査する必要がある。
