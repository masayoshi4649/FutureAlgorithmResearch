# 公開資料と監査出力の接続確認

対象は `completion_guard.py`、`assess_results.py`、`report_adaptive.py`、`report_contract_audit.py`。各独立監査・採否・設計のソースと固定された件数を読み合わせた。今回の実損益・台帳は読まず、新しい売買再生、条件選択、API取得、既存コードの変更は行っていない。

## 結論

主206条件と補助768条件の振り分け、主案と前回8条件の判定の分離、会計・因果・波の基本的なキー接続は一致している。ただし公開前に次の接続漏れと説明の誤りを直す必要がある。これらは売買や採否条件を変更する指摘ではない。

### 1. 比較表が欠けても表示監査が合格し得る

`report_contract_audit.py` は `zip(('all_symbols','symbols'), main.select('table')[:2])` で比較表を検査するが、2表の存在と最後の `compared == 24` を要求しない。比較表を全部削除した場合も、このループだけは0回で終了する。先頭表の並べ替えにも依存する。

`#main-all_symbols` と `#main-symbols` を各1表必須にし、各12行、合計24行を要求する。同じ理由で、全条件表は辞書化前のDOM表数1,948と一意キー集合を照合する。現状は同じ `(data-id,data-symbol)` の表が重複すると辞書で上書きされ、余分な表を検出できない。全金額・枚数行33,116も明示的に要求すると、保存する成功件数と契約を直接結べる。

### 2. 主案の判定表示と前回8条件表の照合が不足

表示監査は全条件の損益表と主章の6方式比較を検算する一方、次を検査していない。

- 主案の3つの通過表示と `独立判定.json` の `基礎候補`、`十四感度頑健性`、`分岐の利益付加価値` の対応。
- 前回8条件表の各ID、各条件の基礎候補フラグ、TOPIX/NK225の全13期間の収支・最大下落。
- 主章6方式比較の方法ラベルとIDの対応。数値が正しくても別の方法名へ付け替えられた場合は通過する。
- 前回8条件表に実際に書かれたリンク先。現在のJavaScript検査は期待するハッシュを直接与えており、HTML側の誤った `href` を検出しない。

前回8条件は `既選抜八条件` の記述対照であり、主案の採否へ昇格させる経路はない。現実装の表示もその分離を保っている。その関係を表示監査でも必須にする。正式版では `既知比較の採用候補` と監査完了も明記すれば、基礎候補だけ通った場合の読み違いを減らせる。

### 3. 感度条件の秒数説明が基準値のまま

`report_adaptive.py:description` の分岐説明は「自市場600秒」「120秒待ち」を固定文字列にしている。実際には主案・逆選択の `C080/C120` は分岐窓480/720秒、`T96/T144` は復元待ち96/144秒である。末尾の倍率表示があっても本文の秒数と矛盾し、T96/T144の実秒数は分岐本文に現れない。

分岐窓を `600 * spec['branch_scale']`、時計待ちを `spec['policy']['restore_seconds']` から表示する。基準主案を説明する本文の600秒・120秒はそのままでよい。時計復元は秒数が過ぎれば無条件に成立するわけではなく、その後の新しい有効な公開根拠や残存枠等も必要なので、主案の短い説明も「120秒後から復元を許可する」等にすると条件と一致する。

### 4. 完備ガードの明細単位で新しい検査旗を必須化

`completion_guard.py` は会計ヘッダーの `全分岐独立一致`・`全成熟注文独立一致` を確認するが、各26入力の会計明細では次の実在する検査結果を確認していない。

- `全分岐独立一致`
- `全伝達遅延一致`
- `影の独立公開と執行` 内の `影全会計一致`、`独立公開計画一致`、`独立準備一致`、`最新成熟計画一致`、`全行注文成立不成立一致`

各旗を真として要求し、同じ入れ子の `原本行数` も当該入力長と照合する。現監査コードは実際にこれらを計算しているため、検査の追加ではなく、既存証拠の欠落・偽ヘッダーを完備時に拒否する接続である。ヘッダーだけ真のまま明細の旗を削除・偽にし、ファイル指紋だけ更新した人工資料を拒否できることも確認する。

`assess_results.collect` は主と補助を別フォルダから読み、IDの重複・欠落、完了ヘッダーの探索固定SHA、全条件集合を確認する。`completion_guard` は保存済み集約・個別明細・会計独立値・指定波を結合する。これらの既存キーや主案IDについて、v37の古い件数を残した取り違えは見つからなかった。

## 場末会計改訂の結合について

旧境界assertの修正は別作業中であり、このレビューは修正版の採否を判断しない。最終完備時には、改訂前資料のSHAと移設先、新旧158条件の保存数値・全台帳指紋一致、全974条件を新しい固定で再生した証跡へ接続する必要がある。因果・波の固定は会計再構成コードを参照していないため、売買コードと各固定対象が不変ならそのまま使える。一方、全監査の出力は新しい探索固定SHAと新しい主台帳へ結び直す。

この段階では正式な全件完了や経済合格を宣言しない。
