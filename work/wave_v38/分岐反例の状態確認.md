# 分岐反例の状態確認

注文だけでなく、公開元・入力品質・復元できる枠を確認した事後説明。指定の2入力について主案・固定信号復元・固定時計復元の6再生を行い、実側15配列・影側10配列の指紋が保存台帳とすべて一致した。条件・採否は変更せず、API・保存ライブは使用していない。

## TOPIX 9月25日ナイト・組3

**時計を選んだのは、有効な中立情報を得たからではなく、600秒の参照窓の品質が不適格だったため。** 公開元そのものは存在し、減量直前に更新されていた。

| 時刻 | 状態と処理 |
| --- | --- |
| 20:50:14 | 5枚を4,113.5で売り。 |
| 21:21:32 | 2枚を4,112.5で減量。B01は方向0・有効性falseの分類0なので、120秒時計復元を選択。 |
| 21:23:35 | 期限21:23:32以降の新しい有効公開を受け、次原本行で2枚を4,113.5で売り直す。B01は買い方向だが、時計方式は方向一致を要求しない。 |
| 21:33:47 | 元A0の損切り条件により4,116.5で全返済。収支−13,000円。 |

減量判断のB01公開元は原本行41731・rawseq42279、時刻21:21:32。素材は21:21:28で4秒前、現在端点も有効だった。600秒窓は71公開・70有効で、最低5公開、長短の過去参照、正のATRも満たす。

失格原因は窓内の**21:13:13公開**で、前公開から87秒、素材21:12:10から63秒だったこと。いずれも60秒以内という品質条件を超える。`continuity_reset_count=1`も記録されるが、この値自体をB01の直接失格条件には使っていない。「履歴が全くない」「観測数不足」「有効な中立」とは異なる。

減量後から終了まで、新しい有効な売り回復は0件。固定信号方式は復元せず−7,000円だった。主案との差−6,000円は、時計で戻した2枚の4,113.5→4,116.5の逆行に対応する。情報不適格を時計側へ分類した、この1組の経路である。

## NK225 9月24日ナイト・組5

**回復待ちの失敗には、価格が反転するまでの待ち時間だけでなく、窓品質による信号無効と、空いた枠の復元権終了が重なった。**

| 時刻 | 状態と処理 |
| --- | --- |
| 23:30:16 | 10枚を65,530で売り。 |
| 23:31:37 | 5枚を65,540で減量。B01は有効な買い方向なので、保有売りと逆の情報を確認して信号復元を選択。 |
| 23:44:29 | 元2ATR利確条件が成立。空いている低番号5枠を退役させ、復元権5枚→0枚。空の枠なので、この時点の実約定はない。 |
| 23:50:49 | 減量後初めて新しい有効な売り回復が成立。しかし復元権は6分20秒前に終了済み。 |
| 翌01:15:03 | 残った5枚を元追跡条件の65,370で返済。収支＋7,500円。 |

減量時は公開元row93350・rawseq93955が23:31:37に公開され、素材は8秒前。600秒窓86公開がすべて有効で、長短の価格変化は＋90／＋15だった。最初の逆行判定には欠測はない。

一方、23:44:29には600秒・150秒の価格変化が−170／−70まで下向きになっていたが、B01は依然として有効性falseだった。原因は**23:38:05公開の解放間隔62秒・素材遅れ62秒**。窓は36公開・35有効、現在端点・過去参照・ATRは適格だが、窓内にこの品質違反が残っている。ここでは`continuity_reset_count=0`であり、同カウンタが原因ではない。

元部分利確の直前、低番号5枠は「生存・空・復元可能」、直後は「退役」になった。成立済み復元注文の取消ではなく、回復待ちの権利が終了した。360分期限・場末・追加実損失R予算による終了でもない。

固定時計方式は23:33:53の新しい有効公開（買い方向）で5枚を65,570に復元し、その5枚を23:44:29に65,390で部分利確した。追加＋9,000円で組収支＋16,500円。時計方式の方向不要という仕様と、その時点で生きていた枠が差を生んだ。

## 読み取りの限界

この2例は事後に指定された反例で、時計・信号方式の一般的な優劣は示さない。品質条件を緩める再生や、別の復元規則は試していない。同一秒でも判断行と約定行は別で、次原本行の規則を守っている。詳細な公開元、品質内訳、枠状態、全配列指紋照合は[状態確認JSON](分岐反例の状態確認.json)に保存した。
