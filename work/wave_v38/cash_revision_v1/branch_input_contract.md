# 減量後の復元方式を選ぶ入力契約

呼出窓口は `branch_inputs_runtime` とする。既存の方向関数をそのまま公開し、旧入力を読むための検索パス変更だけを復元する。既に読み込まれた旧注文器は置換しない。注文器は v38 の明示パスから読み、`__file__` を照合する。

## 使用する列

`initialize(inputs)` の後、`entry(H, clock_scale, key)` は既監査の入口方向を返す。H019 は時計倍率 0.8・1・1.2、他の 11 入口は 1 のみ。入口を変更する追加探索は行わない。

`directions(B, key, window_scale, seed=None, role='bad')` は方向・公開元行・証拠位置の 3 列を返す。方向は -1・0・1、公開元は **ready 配列の行位置**であり rawseq ではない。公開前や鮮度切れは公開元・証拠位置とも -1。方向 0 でも有効な公開元は残る。

`publication_valid(B, key, window_scale)` は自市場の公開品質である。公開済み価格・ATR・過去窓が有効で、公開後 60 秒以内の場合だけ真となる。相手市場の同意を意味しない。有効な中立と欠測を分け、欠測を悪化や回復へ変換しない。

B00・B01・B06・B07 の窓倍率は 0.8・1・1.2。基準は既存保存列、B06 の倍率変更も既存保存列を再利用する。新規作成は B00・B01・B07 の 0.8・1.2 の 6 本だけである。相手市場の追加遅延 60 秒と公開鮮度 60 秒を変えない。

## 分岐と乱数対照

通常の分岐は減量の約定行で一度決める。その行で既公開の B01 が有効かつ保有逆方向なら信号による復元、それ以外は時計による復元とする。**分岐用 B01 の窓倍率と、復元信号そのものの窓倍率は別設定**である。時計の 96・120・144 秒は注文器側で扱う。

乱数は `SHA256('v38|役割|seed|session|symbol|source_rawseq')` の先頭 8 byte を little-endian 整数にした bit 0 を用いる。seed は 0～63。役割は bad・good・branch の三つに分ける。公開元が同じ間は引き直さず、条件 ID や将来の配列長を使用しない。公開元なしは rawseq=-1 のままとする。

- bad・good は bit 0 なら +1、bit 1 なら -1 を元方向へ掛ける。非 0 の機会、公開元、品質は保つ。
- `branch_choice(key, seed, window_scale)` は bit 0 を時計、bit 1 を信号とする。減量約定行の値だけを保存して使用する。方向や品質は変更しない。

同じ役割・公開元の乱数は条件間で共通である。銘柄間・役割間にあった元の依存関係を保持する対照ではない。元の非 0 機会や公開情報の時刻は残るため、全市場情報を除去した対照でもない。価格と方向を上下反射すると bad・good は反転し、branch の選択は不変となる。

## 固定と監査

`branch_input_fixed.json` は元入力関数・新規保存列・再利用証跡・原本 78 ファイルの因果監査を固定する。`branch_input_runtime_fixed.json` はその指紋を変えず、検索パス復元の窓口・人工監査・この契約を追加して結合する最終入力固定である。

新窓は全 156 入力で原本の途中切断・未来変更・上下反射を確認する。乱数は全 64 seed と両銘柄全期間で確認する。既存列は過去監査の指紋と保存物の一致を継承し、不要な旧全探索を再実行しない。新しい売買損益、現在セッション保存物、API は使用しない。
