# 経済専用の完備ガード

元の`completion_guard.py`を変更せず、状態契約の不具合を不合格のまま残す別ガードを作成した。売買エンジン・採否基準・保存結果は変更していない。これは欠陥発見後の検証手順であり、結果前の探索設計とは呼ばない。

対象は主206・補助768の全974条件、25,324口座入力、3,918因果入力、7,792波・15,584境界。原ガードのcash改訂、原158条件790資料の一致、保存数値、全台帳指紋、因果境界、指定波、原本78ファイル、暫定経済判定との一致を保持する。主要な照合区間は元コードとの全文又はAST一致を確認した。

会計は`adaptive_accounting_diagnostic.json`を読む。主の原版成功205条件は原版実体へ、主の1条件と補助768条件は診断版実体へ結び、保存先・実体SHA・全26口座・各検査の合否を別々に確認する。診断版は状態差を列挙した後も元の経済検査を通過した資料に限る。既知の12行は行番号・原本時刻・実状態と期待状態まで確認し、欠落・状態合格への偽装を拒否する。今回説明した予算中残存型と異なる不適合があれば追加診断を要求する。

正式に実行できるのは、主・補助の全会計・因果・波資料が揃ってから。出力は次の2ファイルで、旧`完備監査.json`は生成しない。

| 出力 | 重要な合否 |
| --- | --- |
| 経済完備監査.json | 経済検証完了=true、実装状態契約合格=false、完全実装合格=false、検証完了=false、全体目標達成=false。全状態不一致行も保存。 |
| 独立判定.json | 既存assessmentをverification=Falseで呼んだ経済判定を維持。監査完了=false・既知比較の採用候補=falseに、経済検証完了=true・実装状態契約合格=false等を追加。 |

準備時の専用破損試験は44種類を拒否した。状態差の隠蔽、明細の行脱落・重複・時刻変更、原版と診断版の混同、指紋や件数改変、経済不合格の混入、cash改訂未完了等を含む。主の完成済み証拠を使ったメモリ上の試験であり、未完成の補助監査を作ったり、全完備を宣言したりしていない。

```powershell
python -X utf8 work/wave_v38/economic_completion_guard_test.py
python -X utf8 work/wave_v38/economic_completion_guard.py --prepare
# 主・補助の全独立証拠が揃った後だけ実行する。
python -X utf8 work/wave_v38/economic_completion_guard.py
```
