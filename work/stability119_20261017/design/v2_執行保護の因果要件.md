# v2 執行保護の因果要件

初回の固定候補の失敗は保存し、別実装で対照する。これは[凍結v1エンジン](../engine119.py)の読取だけから作った設計要件で、保護による利益を確認した結果ではない。新市場・原入力・金融再生は0。

**最重要：発注後の悪い気配を見て、約定だけを消してはいけない。保護指値が届かない間も、現在のbid/askで全損失を評価する。**

## 1. 新規の最大気配幅・Last距離

- 判定は、公開足の新規判断までに既に観測した最新の正常BBOとLastだけ。v1の同原行は「気配観測→足公開」なので、同原行の先に処理した気配は利用できる。原行が後のquoteを探して埋めない。
- 例えば気配幅は`ask−bid≤最大幅`。Last距離を**絶対距離**`|ask−Last|／|Last−bid|`にするか、**不利距離**`max(0,side×(約定側価格−Last))`にするかは別条件であり、固定前に決める。前者なら情報不整合も拒否し、後者なら有利方向の大きい乖離は拒否しない。途中で都合よく混ぜない。
- 上限は観測呼値又は当時幅に対する比率など、単位込みで固定する。ラージのTOPIX0.5pt・日経10円と、実ミニ／マイクロの注文呼値を混同しない。
- Last／BBOの欠測・古さは新規拒否。次の正常行へ元判断を移して救済しない。新しい根拠で再判断するなら、別の判断行と公開注文として残す。
- **成行の判断前に通過しても、到来quoteの気配幅や距離が上限を超える場合はある。その成行約定を後から拒否しない。** 到来価格も制限するなら、発注時に価格上限を置くFAK等の別モデルにし、未約定・失効も保存する。
- 既に公開した新規指値が到達した同行で、気配幅の悪化を見て架空取消しない。live指値の到達と取消の順序を固定する。入口拒否で以後の参加も変わるため、元の負けだけを取り除く計算にしない。

実装しやすい第一対照は「新規公開時の既知quoteでだけ審査」。当日相場を見て上限を選ぶ、又は約定行を見て枚数を選び直す条件は追加しない。

## 2. Last基準の返済保護指値

返済条件が成立した行で、元の返済理由・対象数量・親・元判断行・当時Last/BBOを一度保存する。気配幅が固定条件を超えた場合だけ、返済保護へ進む。保護対象を利確・追尾・仮説撤回・親損切り・場予算のどこまでにするかは、理由の集合として結果前に固定する。悪かった返済だけへ後付け適用しない。

- 返済の売買方向をs（買い+1／売り−1）、当時LastをL、許容不利幅をaとすれば、買い返済の上限は`L+a`、売り返済の下限は`L−a`。注文価格は買い上限を呼値切下げ、売り下限を切上げる。丸め後の線と幅を保存する。
- 保護線と期限は**最初の判断時に固定**。その後のLastや気配回復で線を有利へ動かす、30秒期限を毎回延長する、元の損切り判断を取り消す、という変更はしない。
- 判断原行の後で、買いならaskが上限以下、売りならbidが下限以上になった最初の正常quoteだけが到達候補。Lastが線に触れただけでは約定としない。
- 約定値を到達BBOとするか、固定指値価格とするかも先に統一する。前者なら買ask／売bidを使う。後者は指定価格全量約定の仮定であり、待ち順位や部分約定の実証ではない。BBO未到達なのに指値価格へ清算しない。
- Lastが正常でなければ、出口を無効にして放置せず、通常の次正常BBO返済へ戻す。元理由を保持し、保護不成立として記録する。
- 半返済の待機中に新しい全量返済条件が成立する場合、半返済のまま放置するか、残玉全量へ引き上げるかを理由優先表で固定する。全量へ変更する場合も、旧注文の取消・既約定数量を照合し、二重返済・負保有を作らない。

## 3. 30秒fallback・場末・同行の順序

**現在の入力時刻はLast更新時計であり、真の板受信時刻ではない。「価格時計で30秒後に切替」と「壁時計で30秒以内に実決済」は別。** 時刻停滞中の多数原行、時刻飛び、正常quoteの欠落を含むため、最大30秒での実約定を保証する表現は使えない。

1. 期限は最初の返済判断時刻＋30秒。期限後は成行返済へ不可逆に切り替え、後から保護線に到達しても戻さない。
2. v1と同じ観測駆動で作るなら、最初の`quote時刻≥期限`の行を切替判断とし、その**後の正常原行**で約定する。これは保護判定30秒で、実保有時間は30秒を超え得る。
3. 別の既知timerイベントを置き、期限以上の最初のquoteで成行約定する方式も設計できるが、時刻・取消受理を仮定した別の執行模型。前項と結果に応じて使い分けない。同じ行で「新たに気配を見て成行判断」と「その気配で約定」を兼ねない。
4. **場末は保護を使わず次正常原行の成行返済。** 既存保護の期限を場末の後まで延ばさない。新規予約も停止し、場末以前に成立した返済の元理由と場末の切替理由を別に残す。
5. 保護到達と期限又は場末が同じ原行で競合するときは、結果を見ず優先順位を一つ固定する。新たな気配を見ての取消で既存live指値の同行約定を消さない一方、事前既知timerを実装するならその実行順も明示する。v1の「pending約定→場末判定」と無自覚に混ぜない。
6. 正常quoteが無いままEOFなら実返済は未了。最後の正常清算気配で参考評価し、未清算を残す。Last・保護線・期限時刻へ架空約定して黒字／損失上限を作らない。

## 4. 待機中の会計と記録

保護中も`実現現金＋残玉の現在bid/ask清算損益−残返済料`を毎観測・公開足に記録する。保護線を清算時価に使わない。元判断後の最大逆行、保護待ち中最大損失、実返済後損益を別に残す。返済を待って大きな損失を負う代償が見えないなら、改善と評価できない。

保存項目は元判断行／時刻・理由、保護公開行・価格・対象数量、期限、切替判断行・理由、実返済行・価格・数量、当時Last/bid/ask、注文ごとの切捨て料、残数量。取消・切替は約定ではなく、手数料は実約定数量だけに課す。部分返済の入場料配賦と、親の全残玉完結を維持する。

第一対照は **v1／新規審査のみ／返済保護のみ／両方** の四つ。入口・途中判断・数量・出口幅を同時変更しない。新規審査のために消えた利益、保護待機で増えた損失、新たに参加した親の損益も保存する。取消件数などを後で検証するため、今回は集計末尾だけでなくイベント保存を先に用意する。

## 5. 最低限の独立人工ケース

| 人工例 | 期待する判定 |
| --- | --- |
| 公開時は狭いが次quoteが拡幅 | 成行発注済みなら悪い実価格で約定。後知恵で入口を消さない |
| 公開時点で幅超過／Last距離超過 | その公開は拒否。未知も許可に補完しない |
| 買い／売り、距離が上限ちょうど／1呼値超過 | 両方向で同じ不等号、単位、丸めが成立 |
| Live新規指値の到達同行で幅も悪化 | 事前固定した到達・取消の順序で処理。都合のよい方を選ばない |
| 買玉の保護売り／売玉の保護買い | 判断同行の返済なし。反対気配の到達が必要 |
| Lastだけ保護線に到達、BBO未到達 | 未約定のまま。Lastを実清算価格にしない |
| 期限前に保護線へ到達 | 最初の正常到達で所定の価格模型に従って返済 |
| 到達しないまま期限、さらに悪いquote | 成行切替を保持し、悪い価格・損失超過をそのまま計上 |
| 29秒／30秒／31秒で到達と期限が競合 | 固定した境界・優先順位で同じ入力は同じ処理 |
| 同じ価格時計の原行が多数続く | 架空の30秒経過を生成しない。実時間上限を証明したと言わない |
| quoteが飛んで期限超過、又はEOF | 次正常原行まで待つか未清算を残し、期限価格で清算しない |
| 保護待ち中のLast更新・反対信号消失 | 初期線・期限・元返済判断を勝手に戻さない |
| 半返済保護中に全量停止、取消と一部約定の競合 | 現在残数量だけ返済し、二重返済なし。料金は注文単位 |
| 期限前でも場末に到達 | 保護を打切り、場末判断後の次正常原行で全返済 |
| 保護中は好い指値だが、実bid/askは大きく悪化 | 全清算資産・最大下落・未返済評価は悪い気配を反映 |
| 保護なし・新規審査なし | v1の全注文・親P/L・公開時価が一致。不要な経済変更を検出 |
| 保護待ちの途中で接頭切断、未来を改善／悪化 | 過去注文・状態・時価が不変。未来場末の清算を接頭へ入れない |

特に「指値が届くまで待つことによる見かけの勝率向上」と「待機中リスクを含めたセッション安定化」は別に採点する。
