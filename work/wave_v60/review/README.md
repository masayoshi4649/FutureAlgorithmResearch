# 独立監査

最初に [在庫管理と週内持越しの事前反証](在庫管理と週内持越しの事前反証.md) を読む。理論が支持する範囲、両建ての会計、指値約定の限界と、実装中に訂正した点を記載している。

読む順序は次のとおり。

1. [手数料と両建ての独立合成監査](手数料と両建ての独立合成監査.json)：注文単位の端数・同じ売買キャッシュフローの恒等関係。
2. [中期特徴](中期特徴の独立合成監査.json)、[中期売買器](中期売買器の独立合成監査.json)、[中期全口座](中期全口座の独立監査.json)：120条件・12,000口座・129,652注文・64,826返済を独立検算済み。
3. [グリッド方向材料](グリッド方向材料の独立監査.json)、[グリッド売買器](グリッド独立合成監査.json)、[グリッド全口座](グリッド全口座の独立監査.json)：公開5分足、注文順・在庫・費用・未来非依存・期限に加え、720週・6,000場・178,071注文・96,584返済玉の全原本行時価を検査。
4. [主グリッドの人工相場](主グリッドの人工相場検査.json)：上昇・下降・往復・V反転・場間ギャップの50再生。実相場の利益や証拠金余力を証明する資料ではない。
5. [現在中期](現在中期の独立監査.json)、[現在グリッド](現在グリッドの独立監査.json)：親が一度だけ取得した現在原本と保存注文を検算。現在のグリッド買2枚を仮想清算せず、発生済み費用と含み増減を分けて確認した。
6. [HTML表示](HTML表示の独立検査.json)、[現在確認の追記表示](現在確認表示の独立検査.json)：主報告と全160表、計6,570数値、案内リンクと広狭画面を確認。

各 `check_*.py` は監査の再現用。監査対象の売買条件は変更しない。監査側は保存済み資料だけを読み、現在APIの追加取得や注文送信を行っていない。現在確認資料の最初の取得は親担当が状態1回・板各1回で実施し、その記録も照合した。
