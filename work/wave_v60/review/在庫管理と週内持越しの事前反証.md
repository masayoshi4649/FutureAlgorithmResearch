# 00057：在庫管理と週内持越しの事前反証

今回の損益計算前の独立レビュー。既知25セッションを用いる。後ろ2場も前回既に検証済みであり、今回の未見試験とは呼ばない。保存データだけを用い、現在APIを取得しない。

## 一次研究から取り入れられること

Avellaneda・Stoikov は、指値による売買の成立と、残った在庫の価格変動リスクを同じ問題として扱う。在庫量によって提示価格を変える考えは、反発待ちの買い玉が増えるほど追加買いを抑え、返済を優先する設計の根拠になる。ただし、モデル上の約定到着過程は、今回の板スナップショットだけでは保証できない。この論文を参照することと、その最適解を日本先物で再現したことは別である。[著者公開版：High-frequency trading in a limit order book](https://people.orie.cornell.edu/sfs33/LimitOrderBook.pdf)

Guéant・Lehalle・Fernandez-Tapia は在庫上限を明示し、上限へ達した方向には新規の指値を出さない制御を扱う。評価は実現益だけでなく、現金と残存在庫の価値を含む。今回も片方向上限、在庫に応じた増玉停止、期限での返済、残玉を含む資産曲線を評価する。ただし同論文の最終残玉は基準価格で評価するモデルであり、実際の成行清算費用や週末ギャップまで検証済みという意味ではない。[Dealing with the Inventory Risk](https://arxiv.org/abs/1105.3115)

今回の実装仕様は、中値で格子の条件へ到達してから次行でask買い・bid売りする。待機指値でbid買い・ask売りする流動性供給とは異なる。上記研究は在庫管理の参考であり、その利ざや獲得の仕組みを今回再現したとは言わない。こちらの検証対象は、売買気配と手数料を負担しても、往復や方向変化による値幅が上回るかである。

グリッドの一次研究として、Chen らの2025年のプレプリントも確認した。有限範囲の単純モデルで期待値ゼロを論じ、動的な再配置を暗号資産で比較する。ただし現物・1分データで、著者自身が上昇相場の寄与を説明し、比較用の全期間価格帯も使用している。したがって、この結果を日本先物の週内グリッドの安全性や期待利益の根拠にはしない。無限資金・無限時間なら必ず利益という記述も、有限資金・枚数上限・期限のある今回の設計へ採用しない。[Dynamic Grid Trading Strategy](https://arxiv.org/html/2506.11921v1)

## 両建てについて断言できること

同一商品・同一期限で、買いq枚の建値Lと売りq枚の建値Sを同じ価格Pで評価すると、合計損益は倍率を除いて `q(P−L)+q(S−P)=q(S−L)` となる。同量を保有している間の価格変化は相殺される。これは既存の損失を消す操作ではなく、その時点の価格感応度を止める操作である。

ただし、両建てが減量より必ず手数料を増やすとも言えない。買い玉を残して売り新規で覆い、その売り玉を買い返済する手順は、買い玉を売り返済して後で買い直す手順と、枚数・時刻・価格・注文のまとめ方が同じなら、同じ売買キャッシュフローと手数料になる。別々の建玉として管理することによる追加の相殺売買が発生したときに、取引量や費用が増える。今回の比較では実際の注文から数える。

利益玉だけを閉じると取引勝率は高くできるが、残る損失玉と手数料を含めた資産が増えたとは限らない。両建ての利点を主張するには、出口・再配置が将来のネット保有量をどう変え、損失制御へどう寄与したかを示す必要がある。

今回の主評価では残玉を返済可能な気配で評価するため、等量両建ての清算価値は上式に `q(bid−ask)` を加えたものになる。中値方向の感応度が相殺されても、両側を解消するスプレッドは残り、気配間隔の拡大によって清算価値が悪化する。同じネット建玉経路との恒等式は共通中値評価で確認し、売買気配による清算価値は追加の総建玉の解消幅を含めて別に照合する。

## 週と手数料の監査

- 週はセッション開始日の月曜起点で管理する。金曜Nightから翌土曜05:50付近までは同じ週に含める。日付が土曜になっただけで別週へ移さない。
- 金曜Nightの決済判断後、次の有効原本行で全返済する。週末観測が欠ける場合、月曜へ持ち越したのに週末返済済みと記録しない。
- 最後の週は水曜までの資料である。残玉評価または調査終了時の仮想清算を明示し、通常の金曜返済と区別する。最後の原本行を未来から知って有利なタイミングで返済したとは扱わない。
- 片方向最大10枚・20枚を別々に守る。ネット0枚でも買い10枚と売り10枚なら両側に10枚の建玉がある。
- 料金は提供条件どおり、TOPIX miniは1注文 `floor(418×枚数/10)` 円、NK225 microは `11×枚数` 円とする。新規・返済・両建て両側を課金し、JNET料金を使わない。整数演算で端数境界を守る。
- 同時に複数玉を閉じる場合の注文のまとめ方を損益を見る前に固定する。手数料の端数を有利にする目的で、事後に注文を分割しない。
- セッションの時価収支は、実現損益から当場の注文手数料を引き、終了含みと開始含みの差を加えたもの。取引単位の料金配分と、注文時点の現金控除を二重計上しない。

## 指値と空白時間の監査

「価格へ触れたら全量約定」は、通常の指値注文では板の順番を省いた仮定である。controllerの指値条件到達後に次の原本価格で発注する再生なら、その条件注文方式として明記する。小型商品の実際の指値約定をラージ板から復元したとは呼ばない。

データが飛んで複数の格子を一度に越えても、未観測の途中価格で新規と利確を繰り返してはいけない。前の観測時点で存在していた注文だけを、固定した優先順と次行約定の規則で処理する。観測のない夜昼間・日曜に、存在しない価格列を作って約定させない。

セッション切替で移動平均などを初期化するか引き継ぐか、グリッドの中心と未約定注文を引き継ぐか、保有玉の追跡高安を引き継ぐかを個別に固定する。価格ギャップを損切り線ちょうどで返済できたことにせず、最初の観測で判断して次行価格で返済する。

## 損益選抜に使わない機構試験

1. 上昇のみ・下落のみ：片方向上限、逆行中の追加停止、残玉込み損失が表に残ることを確認する。
2. 長い一方向の後に反転：利確したカバー玉の利益と主玉の損失を別々に消さず、全残玉込みで一致させる。
3. 一度に多数の格子を飛び越えるギャップ：仮想途中価格で往復利益を作らず、上限を超える同時新規を作らない。
4. 中値一定で最後値や気配だけが往復：中値の変化がないのに表示値の往復だけで利益を作らない。費用は確実に減る。
5. 同時両建てと同じネット保有経路の減量：同じ売買キャッシュフローなら費用前後の資産が等しいことを照合する。
6. 金曜Nightの終了・欠測・翌月曜開始：正しい週に全玉と手数料が帰属し、禁止された持越しを隠さない。

これらは人工経路で機械の性質を確認するものであり、各相場の発生確率や期待利益を推定する試験ではない。結果が悪かった経路を捨てたり、その経路だけの特別なルールを足したりしない。

## 実装中の確認と訂正

中期の初回再生は、任意の運用期限（15:35/05:50）より後まで最終約定時計が飛んだ夜間11口座を検出し、安全停止した。最終行をさかのぼって決済する救済は行っていない。初版を保存し、新規停止・返済判断の時刻は維持したうえで、返済の次観測行だけを同じザラバの終了前まで許すv2へ再固定した。これは当初期限までの返済保証ではない。実際の遅延・期限超過数を別集計する。

指数先物のザラバは日中15:40、夜間05:55までであり、今回の上限はこの終端を含まない。[JPX立会時間](https://www.jpx.co.jp/derivatives/rules/trading-hours/)

監査では当初「ラージ中値が半呼値だと指値に使えない可能性」を指摘したが、実売買商品の呼値で確かめる必要がある。ミニTOPIXは0.25ポイント、日経225マイクロは5円で、それぞれ参照するラージ板の半呼値に一致する。このためラージ中値の格子中心を外向きに丸める変更は不要であり、実商品呼値との一致を確認する。通過約定の判定幅は固定したラージ1呼値のままとする。[ミニTOPIX商品概要](https://www.jpx.co.jp/derivatives/products/domestic/mini-topix-futures/index.html)、[日経225マイクロ制度概要](https://www.jpx.co.jp/derivatives/products/domestic/225micro-futures/01.html)

待機指値モデルの「1呼値以上の通過」も全枚数約定を保証しない。参照板はラージであり、小型商品の注文列・待ち順・消化数量を取得していないためである。主評価の気配成行と区別した約定仮定の感度として扱う。
