# 安定性採用判定

最初に読むファイルは [assessment.py](assessment.py)、人工の境界確認は [安定性採用判定の人工検査.json](安定性採用判定の人工検査.json) です。

`assessment.assess(summaries)` は、確定121条件の `config / rows / periods / stability / ledgers` を引数で受け取ります。`periods` と `stability` の `全32`、64会計行を検算します。金融結果のファイル、原本、APIを自ら読む機能はありません。

`results[ID]` に両商品の候補資格、金額80%達成、旧G0に対する全3安定性指標の非悪化、最大利益セッション除外後の両商品黒字、採用達成を保存します。完全な全32黒字は別の `all32_profitable` です。商品別の値と不成立理由は `symbols[商品]` で確認できます。

無損失かつ利益正の場合は平均利益/平均損失を `None` のまま保持し、別表示で活動十分時の損小利大候補に含めます。無損失・無利益と無取引は候補にも勝ちにも含めません。

`ranking` は両商品で資格がある新条件だけです。悪い商品側の活動赤字率、配置予算単位の下方偏差、配置予算単位の最大赤字を昇順で比べ、続いて悪い商品側の金額利益割合を降順、IDを昇順で比べます。旧G0は順位に含めません。順位があっても採用基準未達なら `comparison_only=True` と理由を示します。

人工検査は次のコマンドです。実損益は読みません。

```text
python -B -X utf8 work/wave_v104/evaluation/artificial.py
```

全32は既知資料です。配置予算単位は実リスク等価を意味せず、人工検査も収益性を証明しません。
