# 夜間：元の売買判断を固定し、守れる範囲だけ枚数を増やす

出典：00129。根拠は [順行後追加の経路分類](夜間の順行後追加は何を改善し何を壊すか.md)。

**この文書時点では実装と純人工まで。新数量方式の実市場成績は未計測。** 固定0.5R／1Rで6割を追加すると、元の利益床より全体平均建値が悪くなるため、追加数量を利益床の余裕で制約する。

## 比較する4条件

元の判断をN36／NV02それぞれについて固定し、次の2方式を比較する。

1. **単純減量対照：** TOPIXミニ2枚・日経マイクロ4枚で開始し、そのまま元の出口で返済。
2. **利益床内の追加：** 同じ2枚／4枚で開始。全手数料を払っても守れると判断した場合だけ1枚／2枚ずつ増やし、合計5枚／10枚を上限とする。

元の全枚数基準は保存結果を引用する。新方式の入口や出口を改めて探索しない。追加数量によって元判断やトレーリングの基準建値は変更しない。

## 追加判断

当時までの正常な自己BBOから、初回実建値に対する返済可能幅の最高値を更新する。買いならbid、売りならaskで測る。

- 初期Rは元の入口判断で既に固定された幅を使用する。
- 最高順行幅が1Rに達したら利益床を起動し、`最高順行幅 − 0.75R` を単調に追尾する。
- 現在の追加取得気配を、さらに1呼値不利にした価格を追加予算価格とする。
- その時点の利益床価格を不利な方向に呼値へ丸め、さらに1呼値不利にした価格を返済予算価格とする。
- 初回と全追加玉をこの返済予算価格で返した粗損益から、**既支払手数料・予定追加手数料・追加後の全玉返済手数料**を引く。
- 差引が0円以上なら、次の正常原行への追加を1回予約する。実際の追加はその次行のask／bid。

これは予算判定であって黒字保証ではない。次の正常行で1呼値以上飛べば、予定追加価格も予定返済価格も悪化し得る。実損益を予算値へ丸めたり、後から注文を消したりしない。

## 元の通知と競合した場合

処理は、前行までの予約約定→当行の元判断通知→当行の追加判断、の順。

- 同じ行で元の出口判断と新たな追加条件が成立すれば、出口が優先。追加予約をしない。
- 前行で予約した追加が当行の正常気配で約定した場合、その後に判明した当行出口を見て遡及取消しない。増えた全量の返済を次行へ予約する。
- 追加が気配不明で未約定のうちに元の出口通知を受けたら、追加予約を取り消し、元返済を優先する。
- 元の返済通知後は追加しない。元の場末・未知資料時の返済判断も保存通知どおり扱う。
- 元の新規が未約定のまま影終了通知を受けた特殊な人工では、新規予約を取り消す。

元注文の**判断行**を昇順に一度だけ消費する。元の将来約定値・出口値・将来MFE・損益は判断に使わない。保存`base_trades`で読むのは、影IDに対応する初期幅の列11だけ。実約定値は新核自身が次の正常原行から取得する。

## 入出力

源：[../sizing129.py](../sizing129.py)

関数：

`simulate(times, bid, ask, qok, base_orders, base_trades, tick, initial_quantity, maximum_quantity, step_quantity, multiplier, fee_tenths, addition_mode)`

`addition_mode=0`が単純減量、`1`が利益床内追加。返り値は次の4配列。

| 配列 | 列 |
|---|---|
| orders：8列 | 実行行、判断行、元影ID、方向、枚数、価格、理由、新規flag。追加理由は81、新規flag=1 |
| parents：16列 | 元影ID、初回実行行、最終返済行、建方向、初回枚数、最大枚数、初回建値、R、粗損益、全手数料、差引損益、追加枚数、追加注文数、最終返済理由、残枚数、最終平均建値 |
| curve：4列 | 全行差引清算価値、符号付き枚数、累計費用、実現収支−費用 |
| events：13列 | 判断行、種別、元影ID、床価格、追加予算価格、返済予算価格、保有数、追加数、支払済費用、予定追加＋返済費用、予定差引、最高順行幅、利益床幅 |

イベント種別は1＝元新規通知、2＝元返済通知、3＝追加予約、4＝未約定追加取消。追加予約には予算の計算材料を全て保存する。純人工の接頭切断も扱うため、関数末尾では未返済を強制的に消さない。完全場の実行側は残枚数0を必ず確認する。
