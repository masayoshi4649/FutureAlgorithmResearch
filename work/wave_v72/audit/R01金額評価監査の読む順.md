# R01 全セッションの金額評価監査

最初に読む資料は [R01既存28場の金額会計独立監査.json](R01既存28場の金額会計独立監査.json) です。全56口座の注文を別のFIFO会計で再計算し、利益・絶対損失・収支・手数料・回数・勝負枚数を保存しています。

読む順序：

1. [既存28場の独立会計](R01既存28場の金額会計独立監査.json)：`全場独立会計` が場別の結果、`商品別全28` が二商品を分けた合計です。
2. [金額損失割合での位置](R01金額損失割合順位の独立確認.json)：既知全28の直近846条件に対する別集計。順位の全表を新報告に要求する資料ではなく、「金額でも損失最少か」という確認です。
3. 追加再生が完了すると、別名の `R01追加1場と全29場の金額会計独立監査.json` を追加します。旧28の監査は上書きせず、追加場と全場の合計を分けます。

R01は元玉だけを満額で建て、全量返済します。今回の台帳では一組と一決済明細が一致します。利益玉だけを勝ちに数える方式ではありません。TOPIXミニ10枚、日経マイクロ20枚、それぞれ片方向上限内で、保存各場の終端には残玉がありません。

手数料は、新規と返済の各注文について `floor(枚数×片道料金)` を課します。TOPIXミニは41.8円、日経マイクロは11円です。新規料金と返済料金の明細配賦を整数の累積切捨て差分で独立に計算し、全12列決済へ照合します。

金額損失割合は `絶対損失÷(利益+絶対損失)`、PFは `利益÷絶対損失`。二商品を円で足し合わせません。無取引場の金額割合は未観測です。勝敗頻度、平均負け金額、最大負け金額も別に示し、勝率の高さを資金損失の小ささに読み替えません。

実装は [r01_money_audit.py](r01_money_audit.py)。旧成果の結果と注文台帳を読み、監査領域だけに新しい証跡を保存します。原本・現在APIを読みません。注文価格の原本照合と全行時価の監査は旧00067で実施済みで、今回新たに行うのは保存台帳の独立金額再会計です。

```text
python -X utf8 work/wave_v72/audit/r01_money_audit.py
python -X utf8 work/wave_v72/audit/r01_money_audit.py --extra-results work/wave_v72/replay/T1L1_R01_追加セッション.json --extra-ledgers work/wave_v72/replay/T1L1_R01_追加台帳.pkl
```

後者は追加台帳が完成してから実行します。過去の監査と同一内容なら再確認だけを行い、異なる内容へ上書きしません。
