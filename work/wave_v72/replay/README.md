# 凍結T1L1_R01の全保存場接続

最初に `T1L1_R01_全セッション.json` を参照してください。2026/09/21デイから2026/10/09デイまでの29場・58口座です。

読む順序:

1. `T1L1_R01_全セッション.json`: 既存28場の結果をそのまま再利用し、追加1場を接続した集計。期間別は前16・後12・全28・追加1・全29。
2. `T1L1_R01_追加セッション.json`: 追加10/09デイだけの凍結条件・各口座損益・参照入力パス。
3. `T1L1_R01_追加表示データ.json`: 追加2口座の図解用注文10列と五分足。元の9列に約定行のUNIX秒を添付。
4. `保存範囲の照合.json`・`再生前固定.json`: 原板と1分・5分足の全保存範囲、58原板の準備時指紋一致、凍結実装と条件。
5. `追加再生の因果検査.json`・`再生後の保全照合.json`: 追加場の入口・親予約・管理を三地点で切断／未来改変して一致を照合。旧結果・入力・台帳は変更なし。

`T1L1_R01_追加台帳.pkl` は追加2口座のみ、`T1L1_R01_全台帳.pkl` は既存56口座と追加2口座を接続した台帳です。辞書キーは `(セッション, 銘柄)`、注文は旧9列、決済は旧12列を維持します。

手法はwave70のT1L1入口＋R01利益段階固定を変更していません。R01Pという旧EMA入口部品とは別です。TOPIXミニ10枚・日経マイクロ20枚を初回に建て、片道料金41.8円／11円を1注文ごとに切り捨てます。ラージ板の買いask・売りbidを条件成立後の次有効観測で約定し、場内ですべて返済します。初回から3630秒の共通管理枠も維持します。

`run.py` は既存28場を再生し直さず、追加1場だけ同じエンジンで再生します。`display.py` はその追加台帳へ五分足と時計を接続します。完了済みファイルを上書きしないため再実行は停止します。API取得・実注文は0、元の原板・足・過去成果への書込みは0です。

因果検査は保存原板の順序とCurrentPriceTimeの代理時計に対する照合です。実際の受信時計による因果性、ミニ／マイクロ板での約定、数量の価格影響や通信遅延は再現していません。追加デイは別の調査で閲覧済みであり完全未見検証ではありません。ここで条件を選び直していません。
