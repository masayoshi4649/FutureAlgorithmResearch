# SessionTraderの仕様

1プロセスにつき1つの発注商品を設定します。TOPIXミニと日経マイクロは、実行ファイルを含む別々のフォルダから起動します。判断材料はどちらもTOPIX・日経225のラージ板です。

## 設定と起動

配布先は `dist/{windows-amd64またはlinux-amd64}/{TOPIXminiまたはNK225micro}/` です。それぞれ実行ファイル・`conf`・説明書を含みます。各 `conf/settings.toml` を編集し、実行ファイルを引数なしで起動します。

読み込み先は実行ファイルのフォルダにある `conf/*.toml` だけです。作業ディレクトリには依存せず、設定がなければ別の場所を探さず終了します。通常の設定は13項目です。省略した通信・保存・商品規格・係数には従来の標準値を使用します。

TOPIXミニの `TOPIXmini/conf/settings.toml`：

```toml
[startup]
action = "run"

[controller]
base_url = "http://10.10.100.1:8080"

[trading]
instance_id = "topix-mini"
dryrun = true
```

同じファイルの商品選択：

```toml
[market]
product = "TOPIXmini"
max_per_side = 10

[methods]
day = "T06"
night = "T04"
```

日経の `NK225micro/conf/settings.toml` は `instance_id = "nk-micro"`、`product = "NK225micro"`、`max_per_side = 20`、`methods.night = "U06"` です。主担当と未参加補完はそれぞれ `max(1,片方向上限÷2)` 枚を基準にします。基準担当・追加担当を合わせた同方向保有が上限を超えることはありません。

Windowsは各商品フォルダの `sessiontrader.exe` を起動します。端末からは次のように実行できます。Linuxは対応フォルダの `sessiontrader` です。

```text
.\TOPIXmini\sessiontrader.exe
.\NK225micro\sessiontrader.exe
```

| `startup.action` | 動作 |
|---|---|
| `"run"` | 運転。`duration_seconds=0` は連続運転 |
| `"check"` | 設定検査だけで終了 |
| `"probe"` | 読み取りAPI・受信接続の検査だけで終了 |
| `"migrate_legacy"` | `legacy_conf` に指定した旧設定から台帳を移行 |

通常のサンプルには `duration_seconds` と `legacy_conf` を掲載しません。必要な場合だけ同じ `[startup]` に追加します。正の `duration_seconds` は `action="run"`・`dryrun=true` のときだけ使えます。`legacy_conf` は移行時だけ指定します。操作を変えるときも引数は付けず、設定を書き換えてから同じ実行ファイルを起動します。

発注商品は `NK225`・`NK225mini`・`NK225micro`・`TOPIX`・`TOPIXmini` から1つです。銘柄ID・限月・立会時間はcontrollerから取得します。`instance_id` は小文字ASCII英数・`_`・`-`の1〜64文字で、Windows予約名は使えません。大文字は小文字へ正規化されます。

ソース直下の `conf` は `system.toml`・`markets.toml`・`algorithm.toml` に分かれています。同じテーブルを複数ファイルに重複定義しないでください。`.toml.sample` は実行時に読みません。開発時は `go build -o sessiontrader.exe .` の後にその実行ファイルを起動します。`go run .` は一時実行ファイルの隣に設定がないため使用しません。

`dryrun=true` は注文・取消を送信しません。約定価格は発注商品の新鮮な最良気配です。実注文は `action="run"`・`dryrun=false` で有効になります。`action="probe"` は仮想指定にかかわらず読み取り接続検査のみです。

## 時刻と手法ID

時計はすべて日本時間で記入します。海外イベントに連動する2項目は冬時間を基準にし、夏時間はアプリが自動補正します。

```toml
[schedule]
force_close_before_seconds = 600
day_extra_jst = "12:30"
us_open_jst = "23:30"
us_extra_delay_minutes = 30
london_extra_jst = "01:30"
```

`us_open_jst` は冬23:30・米国夏時間22:30です。`london_extra_jst` は冬翌01:30・英国夏時間翌00:30です。両地域の夏時間は個別に判定するため、切替日がずれる週も扱います。日経の未参加補完は米国開始30分後、TOPIXの夜間補完は上記ロンドン連動時刻です。静観幅や追尾幅は手法に含みます。

| 手法ID | 対象 | 主担当と未参加補完の組合せ |
|---|---|---|
| `T06` | 日中・両市場 | 二市場への追従と継続逆行による撤退、未参加時の始値方向補完 |
| `T04` | 夜間・TOPIX系 | 二市場の突破確認、未参加時の二市場方向補完 |
| `U06` | 夜間・日経系 | 突破後の押し戻りと再進行、未参加時の幅に応じた枚数調整 |

これらは00131の既存候補と同じ条件です。未実装IDや商品・昼夜の組合せ違いは起動前に拒否します。係数を個別入力して新手法を組み立てる形式を通常のconfから外しました。

旧設定は互換のため読み込めます。旧 `us_open`・`london_extra` は従来どおり海外現地時間なので、新しい `_jst` キーへ単に名前だけを変えないでください。同じ時計の新旧キーを併記すると拒否します。旧 `[algorithm]` の有効な上書きや独自の数量・保存先も継続して作用するため、独自設定がある場合は削除せず引き継ぎます。旧 `[products]` が一部商品だけの表なら、その表も残してください。削除して標準5商品へ増えると照合条件が変わります。同じ実効設定で日本時間表記・標準手法IDへ変えただけなら、既存台帳の照合条件は維持します。

## 注文と所有の分離

実注文はcontrollerの生KabuStation API転送へ送り、トレーリングや担当の切替はアプリ側で計算します。注文受付を約定とは見なさず、上流の明細で確認した数量だけを建玉へ反映します。

初期化時に作ったランダムな注文名前空間（Namespace）をSQLiteへ永続化します。表示用の `instance_id` や戦略の判断IDだけで所有を決めず、上流の `OrderID`・`ExecutionID`・`HoldID` と対応付けます。返済するのは、その正本で所有が証明できる担当建玉だけです。似た時刻・価格・数量の他注文を推測で採用しません。

同一OSユーザー・同一一時領域・同じcontroller URL・同じ商品・同じモードの組合せは排他します。共通の一時領域にOSロックを置くため、保存先や `instance_id` を変えても二重運転できません。TOPIXミニと日経マイクロは商品が異なるため同時運転できます。

この排他は異なるOSユーザー・ホスト・一時領域や、同じcontrollerを指す別URL間では共有できません。そのような構成では同一商品を重複運転しないでください。状態DBの複製から同時運転を始めることも避け、再起動には元のDBを引き継ぎます。

## 保存先

相対保存先は実行ファイルのフォルダが基準です。商品別フォルダの中に、さらにモード・実行IDで分けて保存します。次は `TOPIXmini` フォルダから見た保存先です。

| TOPIXミニの仮想運転例 | 内容 |
|---|---|
| `data/dryrun/topix-mini/market.sqlite` | 二市場の原板・判断材料・運転状態 |
| `data/dryrun/topix-mini/TOPIXmini.sqlite` | 注文・約定・所有玉・戦略・復旧状態 |
| `log/dryrun/topix-mini/TOPIXmini/2026-10-21_Day_dryrun.csv` | 確認済み新規・返済 |
| 同じ場所のセッション別 `.jsonl` | 約定と判断根拠 |
| `log/dryrun/topix-mini/market/trace.jsonl` | 履歴同期と定期稼働状態 |

日経は `nk-micro/NK225micro` に分かれます。実運転は `live` を使い、セッションファイル名に `_dryrun` を付けません。SQLiteが正本です。CSV・JSONL出力だけの障害で、保存済み約定を取り消した扱いにはしません。損益は手数料前です。

別商品用フォルダを作る場合は、実行ファイルと `conf` を複製し、商品・実行ID・上限枚数と夜間手法ID（TOPIX系はT04、日経系はU06）を変更できます。既存の `data`・`log` を複製して同時運転しないでください。

## 旧版からの移行

旧版の2商品を有効にした設定は起動を拒否します。旧プロセスを停止し、旧設定フォルダを内容を変えず `conf-legacy` として退避します。旧設定は、接続先・数量・戦略条件が保存時と一致するか検査するために必要です。新しい商品別フォルダの売買条件を旧設定に合わせ、各 `conf/settings.toml` を移行指定にします。

```toml
[startup]
action = "migrate_legacy"
duration_seconds = 0
legacy_conf = "../../旧app/conf-legacy"
```

`legacy_conf` は旧設定フォルダのパスです。相対パスは新しい実行ファイルのフォルダが基準で、絶対パスも指定できます。各商品の実行ファイルを引数なしで起動し、移行が完了したら `action="run"`・`legacy_conf=""` に戻して起動します。

移行は旧設定から参照した対象商品の正本を、新しい実行ID配下へ引き継ぐ処理です。旧DBを削除したり、新しい空DBから既存建玉を推測で取り込んだりしません。移行完了を確認してから通常起動します。元の設定と売買条件が異なるなど、移行が拒否された場合はDBを消して回避せず、表示された不一致を解消してください。退避する旧設定の相対保存先が変わらないよう、`conf-legacy` は元の設定フォルダと同じ親フォルダに置きます。

旧DBと旧ログは残します。移行元DBの隣には、`TOPIXmini.sqlite.migration.json` のような移行記録を作り、移行先・実行ID・元状態の指紋・完了状態を保存します。同じ旧台帳から別実行IDへの再複製は拒否します。途中シャットダウンで移行記録が残った場合も自動再移行せず、記録と移行先DBを確認します。移行記録を消してやり直す運用にはしないでください。

この版で移行した台帳は移行元データフォルダの場所も保存し、新版の運転中は旧版の起動と排他します。旧版が動いていれば、新版は注文台帳を変更する前に停止します。この更新以前に移行済みの台帳には移行元の場所がないため、その場合は旧exeを再起動しないでください。

すでに単一商品版の `conf-topix`・`conf-nk` を使っていた場合、旧フォルダは自動では読みません。実設定を対応する新商品フォルダの `conf` へ引き継ぎます。移動で相対保存先も変わるため、実行IDと既存DBを維持して保存先を旧正本へ向けるか、停止中に正本を移してから起動してください。旧状態を残したまま新しい空DBで再開しないでください。

## 時間と待機表示

途中起動時は二市場の当場生板をcontrollerから取得し、過去注文を出さず指標だけを準備します。再起動は永続化した実約定状態を復元します。日中・夜間の選定手法と米英夏時間の扱いは[運転と保存](運転と保存.md#時間による切替)を参照してください。

寄前の「採用0行」は、前場価格を当場指標へ混ぜなかったことを示します。日中は60本EMA・3本分の傾き・公開待機が必要で、08:45開始なら方向判定は最短でも概ね09:50です。その後も売買条件の成立を待ちます。

無約定でも既定30秒ごとに受信・判断時刻、保有枚数、指標準備や通信の待機理由を表示します。詳細は[運転と保存](運転と保存.md)、注文照合は[APIと注文照合](APIと注文照合.md)、判断関数は[アルゴリズム](アルゴリズム.md)に記載しています。
