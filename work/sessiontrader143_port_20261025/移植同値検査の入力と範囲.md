# TG04・PG04移植の入力と検査範囲

00143の保存済み条件・期待注文をGoへ移すための独立同値検査。手法の追加探索や、新たな有効性の立証ではない。元の研究成績・原データは変更していない。

## 入力

`fixtures/` は標準4場、`fixtures_all/` は2026-09-21デイ～2026-10-23ナイトの全50場。4場版は10/22デイ、10/21ナイト、10/15デイ、9/29デイで、残玉と後続親の見送りが実際にある場を含む。

全50場は日経7,356,840行、TOPIX6,981,269行、計14,338,109保存packet行。これは元rawの全行件数ではなく、00143で使用した保存入力行である。出力約369MB。元packet、原板派生、期待注文、抽出結果のSHA-256を各manifestに残す。

| 資料 | 内容 |
| --- | --- |
| `{場}_input.json.gz` | 当時の特徴配列の参照先、セッション境界、源の判断通知 |
| `{場}_expected.json.gz` | 保存済み注文10列、残玉の期待経過、会計。判断処理には渡さない |
| `*_market.f64.gz` | 価格時計・Last・Bid・Ask・正常板フラグ・既知ATR・元行番号 |
| `*_features.f64.gz` | 公開特徴30列 |
| `*_history.f64.gz` | 既存中値履歴15列 |
| `*_band20.f64.gz`、`*_band40.f64.gz` | 公開20/40分帯9列 |
| `legacy/` | 元E01方向と開始再許可、Last/中値の厳密窓、Last履歴 |

数値行列は行優先・リトルエンディアンfloat64。未知はNaN。源通知は判断行・親・方向・数量・理由・新規区分・玉IDの7列だけで、未来の約定行・価格・費用・利益を含まない。対応する判断行になるまで源通知を公開しない。

## 特徴の同値検査

`TestResearch143SavedPriceFeatures` は全50場の二市場を時系列に逐次処理し、価格由来26列、20/40分帯、個別MA20の値と既知フラグを全行照合して成功した。MA20は履歴全15列の既知性と分離し、元 `history[1]` の有限性に一致させる。全50場の実行は44.879秒。

`TestResearch143ArtificialFeatures` は956イベントで30列すべてを照合した。同じ価格時計の複数行、欠測板、数量ゼロ、180秒空白、途中の保存・復元を含む。`TestResearch143OnBoardWiring` は通常の受信経路で40分帯の公開、45分保持、37分時点で保存・復元した後の一致を確認した。

価格時計の同値行を未来までまとめない。自己窓端と相手参照は厳密な過去行だけを使い、帯は確定1分境界から60秒後に公開する。

**範囲の限界：** 実データの全行比較はATRを保存済み値として注入し、新特徴の変換を検査している。元E01の足ATR生成までをこの検査単独で証明するものではない。原板OFI・距離加重数量の24～27列は、元rawにpacket採用外行があるためこの実データ検査から除外し、人工原行列で同値を確認した。今回選定されたTG04/PG04の判断条件はこの4列を使わない。

## 主枠用の旧特徴

古いpacketの `features.gate` は全偽の仮置きなので、そのまま入口拒否として使用しない。保存された正規Gがある40市場場は、元の凍結済み `model_from_bars`・`expanded`・`gate_mask` の3関数による結果と全行一致した。残る60市場場も同じ3関数で公開済み1分足と既知ATRからGだけを再構築した。

1分足はセッション内の確定足だけを対象に、開始時刻から120秒後を公開時刻とする。相手はさらに60秒遅延させる。売買核は呼ばない。足ファイル・元関数のSHAを記録した。全50場版のGは全場既知、標準4場版の9/29の旧G未収録表示は元のまま保持している。

## 注文・会計の期待値

抽出時に10種類×50場の保存500口座について、判断後の次正常板での約定、買Ask/売Bid、注文ごとの手数料切捨て、玉IDごとの返済数量、全返済、粗損益−手数料＝純損益を検算した。日経mini、1pt100円、片道1枚38.5円である。

源生成・overlay・H04実玉のGo照合は別テストで行う。保存通知を与えて実玉が一致する検査と、源通知そのものをGoで生成する検査は別の証拠として扱う。今回の同値はラージ板BBOを用いる研究約定モデルに対するものであり、実miniの約定価格を保証しない。
