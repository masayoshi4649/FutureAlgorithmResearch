# 完備監査と経済判定の接続

対象は主363＋補助64の427件。全件会計11,102入力、指定波3,416／境界6,832と、代表因果1,730入力を区別する。いずれも固定主案の経済条件とは別の実装監査であり、監査合格だけで採用候補にしない。

最終ガードでは次の接続を要求する。新しい採否条件の追加ではなく、結果前の規則を正しい資料に適用するための完全性確認である。

1. **集約JSONと各手法summaryを全427件で同値照合する。** 暫定集約 `assess_results.collect()` は全条件の期間集計を読む。一方、独立会計は各手法のsummaryを検査する。この2経路が同じID集合というだけでは、別の数値を判定へ入れられる。spec・全13・後7・台帳SHA・波通過数まで各実体と一致させる。
2. 各条件はsessions/ledgers/waves/accounting/summariesの5資料を必須とし、主と補助の保存先・ID・仕様・乱数seed0..63を固定設計へ照合する。各26行は13セッション×両銘柄の完全な一意集合とする。辞書化前に重複を拒否する。
3. 会計headerの条件集合・件数・版の指紋を各独立detailへ接続する。detailのsessionsと全13/後7を主保存値へ全必須項目照合し、検査26行は原本長・全枠・予約・予算・両建て時価の真偽を要求する。保存資料SHAは5資料の正確なパス集合とし、記録された一部だけを検査して済ませない。
4. 因果headerの1,730入力を各詳細へ接続する。全427×代表4入力と固定主案の追加22入力という対象集合を照合し、同時刻切断・未来改変・反射・独立影再生成4回・保存指紋の各検査を要求する。会計の11,102入力すべてで因果改変したとは表記しない。
5. 全427の8波を旧固定のsession・銘柄・開始/終了時刻・方向へ照合する。独立波の台帳由来数値・境界2件を主波へ比較し、正方向20分判定の8件合計をsummaryの `wave_passes` と一致させる。主案の8波合格だけで他426の波資料を省略しない。
6. 原本78・入力固定・探索固定・起動記録・各監査固定にある実装/素材SHAを再照合する。ガードが読んだ保存資料も開始時と終了時のSHAを一致させる。完成後の報告では保存された参照指紋を再検査する。
7. 全証拠を通した同じ `index/sessions/session_names` で `partial_assessment.assess(..., verification=True)` を再実行する。固定主仮説IDの一致を要求し、暫定Falseとの差が `監査完了` と `既知比較の採用候補` 以外にないことを検査する。経済条件そのものを監査後に変更しない。

負例は、集約側だけの対照収支改変、summaryの波数だけ改変、主案IDを別管理へ変更、seed重複/1件不足、26行の重複、独立詳細の必須字段欠落、監査規則の指紋不一致、全件完了headerだけ真、原本/台帳の読取後変更を含めると、上の経路の抜けを具体的に検出できる。

全件会計実行前の読取レビューであり、実データの監査完了を宣言するものではない。
