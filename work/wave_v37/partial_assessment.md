# 減量・復元の判定規則

主案は `H019__B06_RB06_F50_N1__V000` の1件に固定する。309管理と54診断、別64符号対照の合計427件を保存するが、最良管理・入口・変形・seedを主案へ差し替えない。新しい実データ損益を見る前に本文・判定実装・人工検査を固定する。

次の全項目を満たした場合だけ、既知比較の採用候補とする。

1. 全13と共通後7、それぞれTOPIX/NK225の4セルで収支が正。元A0組ごとの合算損益を使うPFと平均勝ち/平均負けが1超。最大1勝ち元組と最大1黒字セッションを各々除いて非負。比率未定義は未確認扱いとする。
2. 4セルで減量と復元がそれぞれ実際に約定する。予約・取消は実行回数に含めない。
3. E080/E120/O000/D080/D120/R080/R120の7変形は後7の両銘柄で収支正・元組PF1超・平均元組勝敗比1超。感度の大勝ち除外と全13も表示するが、追加の採否条件にはしない。
4. 既存と同じ指定8波の正方向ネット20分目安を8/8達成。コアを残すだけで保有分が維持される場合、予測精度向上とは呼ばない。
5. 元A0に対し4セル全てで収支非劣位・時価DD非劣位、全体で最低1項目を厳密改善する。これは今回の代替改善目標であり、ユーザー要件全体の必要条件とはしない。未達だけで手法全体を無価値としない。
6. 減量のみ、120秒復元、固定コア、通常半分利確型小数量のいずれにも4セルの収支/DDで厳密に支配されない。同値は非支配だが追加価値の証明ではない。単純対照と同値の項目を明示する。
7. 回復符号64の各セル中央値に収支/DDで非劣位、全体で最低1項目を厳密改善する。全64の分布・対応差・主を上回る本数も保存する。正式p値とはせず最良seedを採用しない。
8. 入力、注文、全行会計、枠・予約、同約定両建ての独立検査が完了する。

元組は減量・復元で分割しない。全実現と含みを含む組損益・元q0基準Rを用いる。返済脚金額と勝敗決済枚数・同値枚数・一枚平均勝敗比は別に表示する。両建てと純数量は同約定なら全行時価が同じでも脚別PFや途中実現損益が変わるため、脚数増加を独立した利益源とはみなさない。

乱数は元B06の非0公開機会を保ったまま、`v37|seed|session|symbol|source rawseq` の符号を元方向へ掛ける。同じsource中は固定する。完全無情報の方向置換ではなく、別イベント・別銘柄の相対方向関係も保持するとは限らない。

判定APIは `assess(index, sessions, session_names, verification=False)`。indexは427件のid→summary、sessionsは同じ427件のid→全26明細。summaryのall_symbolsは全13、symbolsは後7。追加約定回数は `reductions` / `restorations`。PF・平均元組勝敗比は保存比率の名称に依存せず利益/損失額と元組数から再計算する。最大勝ち除外は各明細の `maximum_trade_profit` と収支から再計算する。

`経済目安合格` と `監査完了` を分け、監査未完なら採用候補を真にしない。全資料の指紋・詳細波・注文からの再集計は別の完備監査へ接続する。全13は既読であり、この研究基準に届いても未知相場の統計的優位や利益保証を意味しない。
