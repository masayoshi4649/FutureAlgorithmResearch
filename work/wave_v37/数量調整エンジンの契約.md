# 数量調整注文器の契約

`engine_partial_restore.run(ready, state, config, bad, bad_source, good, good_source, policy, observed_fill=False, detail=True, shadow=None, *, good_valid=None)`。

方向は原本行に対応した `int8` の −1/0/+1、根拠は同じ ready の `int64` 行番号で、−1又は当行以前を受ける。rawseq そのものではない。`good_valid` は時計復元のとき必須の bool 列であり、方向0でも有効な自市場公開があれば真になり得る。方針の正は [partial_design.py](partial_design.py)。損益列は旧注文器と同じ**価格差×枚数**で、円換算は銘柄ごとに外側で行う。

## 約定判断と影

[engine_shadow_plan.py](engine_shadow_plan.py) は旧v34を新領域へ複写し、各行の処理が終わった時点の有効注文計画だけを追加出力する。元ファイルを変更しない。`build_shadow_plan.py` と `shadow_plan_build.json` に生成差と旧新指紋を保存する。

実注文器は原本行 i の価格を、**plans[i−1]** と組み合わせて、新規、元損切り、元追跡、元部分利確を独立に判断する。影の orders や cycles、未来の終了行を約定判断には使わない。価格欠測行の計画は前の有効価格行の計画を保持する。計画内の current_atr 等は全状態を表すものではなく、その計画を作った有効価格行時点の診断値であり、実側はこれを調整価格に利用しない。

`make_shadow` は全利用原本列（時刻・価格・ATR・seq）、入口、設定、開始・終了等の時刻、呼値、約定モデル、影実装SHAを内容指紋に結合する。`shadow` キャッシュは同じ内容指紋の場合だけ使える。独立未来監査では影も再生成し、完成済みの影結果を切って流用しない。

優先順位は、前行から有効な元 A0 の注文、実口座の全返済予約、調整予約。元部分利確は非重複の調整予約も取消し、以後の新しい根拠を要求する。実の予算予約は元部分利確で消さず維持する。元価格条件と予算の成行予約が同時成立すれば元条件を優先する。

時計復元は「現在が減量約定後120秒以上」に加え、**根拠の公開時刻そのものが減量約定後120秒以上**であることを要求する。119秒で公開された根拠を120秒まで保持しただけでは復元しない。

## 返す資料

| キー | 内容 |
|---|---|
| trades/cycles/curve/orders/stats/atr_curve | 旧6配列。列・損益単位を維持。atr_curve は実保有中の元A0参考線で、早期全返済後は非保有へ落とす。 |
| prepare_events/entry_preparations | 共通組開始の元準備と対応。復元新規を含まない。小数量対照の準備予定枚数は影q0、実新規枚数はordersで確認する。 |
| control_curve | 原本全行の管理状態。列名は CONTROL_COLUMNS。影数量、実数量、復元可能数、調整回数、予約状態、組損益、固定R、予算超過等。 |
| slot_curve | 原本行×初期q0枠。ビット1=その実組で有効な元枠、2=実玉あり、4=復元可能。永久に持たない小数量枠は復元可能にしない。 |
| slot_events | 枠単位の初回・減量・復元・元利確退役・全返済。SLOT_EVENT_COLUMNS/NAMES を公開。qty=0の退役は空き枠の復元権消滅で、架空の取引ではない。 |
| adjustment_events | 調整予約、約定、元注文又は予算による取消、復元資格の消滅。ADJUSTMENT_COLUMNS/NAMES を公開。kind=−1が減量、+1が復元。 |
| budget_events | 予算到達の予約、全返済完了、元部分利確により予約が継続した行。BUDGET_COLUMNS/NAMES を公開。元R・全組損益・超過・待機秒数を残す。 |
| shadow | 独立影の旧8配列、plans、入力指紋。全行配列を毎条件JSONへ保存する必要はない。 |

`control_curve.phase` は0=通常、1=減量予約、2=減量済み、3=復元予約。`campaign_closed` を併せて読み、通常0と全返済済みを混同しない。pending_kind=0の行では予約行・根拠行は−1、予算予約なしならbudget_source_rowは−1。`slot_mask` は第1枠を最下位ビットとする整数。イベント列の全要素は有限数で、該当しない行番号は−1。旧ATR列と価格注文計画の未設置価格にはNaNがあり、保存する場合はNPZ等か明示したnull変換を使う。

`detail=False` は全行curve/atr_curve/control_curve/slot_curveの生成を省く。注文・返済・枠・調整・予算イベントと、影の有効計画は引き続き生成する。監査・図ではdetail=Trueを使う。

## 保証しないこと

追加の実損失予算は全実現＋含みが元Rの負値へ達した時点で退出を予約する。R以内の損失保証ではなく、次行価格や優先される元利確で損失は超過し得る。復元時に元R、初期A0、期限、2ATR利確枠を再設定しない。

新方針の実相場損益はこの実装段階では未計算。合成反例と旧A0同値の記録は `partial_engine_audit.json`、影の独立監査は `shadow_plan_independent_audit.json`。これらは注文・会計・因果性の検査であって、将来収益の証拠ではない。
