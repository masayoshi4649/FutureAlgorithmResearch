# 入口確認四水準

最初に `入口確認の事前固定.json`、次に `入口確認の因果検査.json` を読む。具体的な根拠行は `trace.pkl`、再現する場合は `core.py` と `prepare.py` を確認する。

## 判定

| 水準 | 候補当行で追加する確認 |
| --- | --- |
| G0 | 前作業の入口候補をそのまま使う |
| G1 | 直近4中値イベント前から両気配が候補方向へ1ラージ呼値以上 |
| G2 | G1＋16イベントの純進行2呼値以上・価格効率0.30以上・同方向OFI比0.10以上 |
| G3 | G2＋1秒以上遅延した相手市場の30秒気配進行とOFIが同方向 |

G1/G2の履歴は120秒以内。無効板・reset・2呼値超の気配差・時計の不連続で履歴を捨てる。G2はOFI欠測区間を使わない。許可されなかった候補を確認待ちで後から復活させない。

G3は相手の同じ時計の先頭板を採用し、参照の古さと30秒前端のずれを各5秒以内にする。区間内のreset・無効板・OFI欠測は不許可。原本には受信時計がないため、G3は**最終約定の代理時計上の同期参考**であり、実受信順の完全因果性を証明できない。主選定から除外する。

確認できるのは、直前の気配・表示数量変化が候補方向に一致したこと。OFIは取消と約定を識別しない。将来の正答率が上がることは保証せず、動き終盤の追随や、取引数が減っただけの結果になる可能性も親の損益検証で確かめる。

## データと24系列

旧28セッション・56口座を選定の既知範囲とする。追加の `2026-10-09_Day` 2口座は同じ固定規則を使った追試であり、選定に使わない。合計29セッション・58口座。

入口順は `T1L1、T2L0、T3L1、T4L0、E01P、R01P`。各入口に `G0、G1、G2、G3` を組み合わせ、配列番号は **source_index×4＋gate_level** とする。最後の2入口は旧アルゴリズム全体の再現ではなく入口部品の対照である。

- `signals.pkl`：key＝(セッション, 銘柄)、値＝int8配列 `(24, 原本行数)`。
- `schedule.pkl`：同じkey、値＝24配列。各配列の列は `fill_i、decision_i、source_i、side、anchor`。
- `trace.pkl`：同じkey、値＝元6入口ごとの候補根拠13列。列名は `core.TRACE_COLUMNS`。
- `states.pkl`：24系列の末尾に残った予約・成立状態。保存終端を将来の清算条件として使わない。

共通初回は前作業と同じ、予約行→後続有効行で成立→さらに後続有効行で約定。初回約定後3630秒は次の親予約を禁止する。

## 関数APIと検査

`core.build(inputs, features, base_signals)` は上記4種類を辞書として返す。同じセッションの両銘柄、原本行順が一致したready／特徴、元6行の入口候補を渡す。API通信や損益ファイル読み込みは行わない。

旧56口座のG0は、旧signals・共通scheduleとも6入口すべて完全一致。新58口座の24系列は途中切断・未来変更で過去が不変であり、予約行＜発注判断行＜約定行を確認した。人工経路では履歴不足、同中値行の増加、OFI欠測、reset、上下鏡像、相手同時計先頭と末尾改変を検査した。

入口規則・コード・入力・出力のSHA256を保存した。損益計算開始後に入口を変更しない。現在API取得、実注文、旧損益参照は0。
