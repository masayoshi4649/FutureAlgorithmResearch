# 時間帯別手法の切替設計

## 採る方式

商品ごとに「時間帯→手法」の一覧を持つ。設定と実際の当日予定を分け、米国夏時間は既存の `schedule.Build` が確定した米国開始時刻から計算する。時間帯を増やすだけでアルゴリズムの内部をコピーしない。

既存 `day` / `night` は残し、時間帯一覧がない旧設定では従来と同じセッション全体の2枠へ解釈する。時間帯一覧がある場合はそちらを唯一の選択元とし、空白時間は静観する。昼夜の手法は互換表示・旧設定用であり、明示枠との二重実行はしない。

新手法は研究結果・Go再現一致の確認後に登録する。現段階で運転中のアプリや設定へ配信しない。

## 設定の形

商品 `Instrument` に `windows []MethodWindow`、単品worker `Config` に同じ配列を追加する。

| 項目 | 意味 |
| --- | --- |
| `id` | 商品内で一意な時間帯ID。ログ・発注IDの名前空間にも使う。 |
| `session` | `Day` / `Night`。これは立会区分であり手法の切替数を制限しない。 |
| `start` / `end` | `HH:MM`、`SESSION_START`、`SESSION_END`、`US_OPEN`、`US_OPEN-00:15`、`US_OPEN+00:15`。通常時計は日本時間。 |
| `method` | `NK225_D07` 等の銘柄付き手法ID。明示した空文字は静観。 |

画面では定数文字列を覚えさせず、開始/終了それぞれを「日本時間」「立会開始/終了」「米国開始の前/後」から選ぶ。米国相対は分数入力。当日解決時刻は必ずJSTで表示する。翌日00:00〜06:00は夜間として翌日へ解決する。

旧設定を初めて画面で開く時も、日中全体・夜間全体の2枠として見せる。既存の昼夜2値を変更する旧APIは後方互換用として残すが、時間帯配列のある設定を知らずに上書きすることは拒否する。

`max_per_side` は商品全体の当運転所有玉・未約定新規に適用する。枠ごとに10枚ずつ増やさない。手法の初期/追加配分は各手法の仕様に任せる。

## 予定の検査

1. 区間は開始を含み終了を含まない `[start,end)`。同一時刻に2枠を有効にしない。
2. ID重複、不正時計、未知手法、銘柄不一致、昼夜不適合、ゼロ又は逆転区間、重複区間を拒否する。
3. 空白は静観として予定一覧に表示する。無指定を勝手にD07へ補完しない。
4. JST固定と米国相対が混在する場合、夏・冬の両解決で重複を検査する。保存時の構文/相対検査に加え、controllerの当場Start/End/USOpenで最終検査する。
5. 立会開始・終了を設定ファイルで複製しない。`SESSION_START` / `SESSION_END` はcontroller由来の時計。終了前の全返済は既存 `ForceClose` を引き続き最優先にする。
6. 全予定を起動時に固定し、設定版・手法ルール指紋を記録する。時計が戻っても終了済み枠を再実行しない。

## 境界の状態遷移

時間帯切替は商品OFFとは異なる。OFFはユーザーの指示どおり建玉を管理外へ外すが、自動時間帯切替は当運転の所有玉を管理し続ける。

`実行中 → 旧枠新規停止 → 旧枠未約定新規の取消・照合 → 旧枠所有玉の返済 → 所有玉0・未確定注文0を確認 → 新枠開始`

- 新規送信直前にも枠IDと期限を再確認。境界前に判断した未送信新規が境界後へ遅れた場合は破棄する。
- 取消中の部分約定を無視しない。旧枠の所有玉として受け入れ、返済を続ける。
- 時刻に到達しただけで仮想返済を成立させない。DryRunは次の正常気配、実注文はcontrollerからの約定結果で処理する。
- 次枠の開始時刻を過ぎても旧注文の結果が不明なら新枠を始めない。状態表示は「時間帯切替・返済照合待ち」。
- 外部/手動/前起動の建玉IDは触らない。切替は当起動の管理範囲だけ。
- 原板が来ない時も壁時計で境界へ移行し新規を止める。欠測価格で決済せず、既存の返済継続・照合を利用する。
- 静観枠への遷移も同じ返済手順。画面のモードはDryRun/ONを維持し「時間帯静観」と表示する。

## 特徴・建玉・仮想影

現行の `runner.activate` はセッションごとに `Portfolio` を1つ作り、`bootstrap.prepareHistory` は指標だけを履歴準備する。単純に手法名だけを変更すると旧玉とD07内部影の関係を失うため不可。

- 板・確定足・回帰などの市場特徴はセッション全体で因果的に更新し、時間帯切替で蓄積を捨てない。利用予定手法の特徴設定が異なる場合は設定ごとに特徴器を分ける。最初の手法の特徴設定を他の手法へ流用しない。
- 実建玉状態・予約状態・部分利確床・連敗予算・確認時計を別手法へ移植しない。
- 基本形は境界で旧玉をゼロにして新Portfolioを開始する。途中起動と同様、履歴を見て過去の注文を復元発注しない。
- D07の後半を比較する研究が「同じD07影を前区間も継続観測」している場合、後半開始時にD07影を初期化したアプリと同じ成績とは言えない。研究採用時には影のみ継続するアダプターを明示し、全夜統合を再生して一致させる。旧影の仮想建玉を実建玉扱いしない。
- 同じ手法の隣接枠を連続運転とみなす場合も仕様を固定する。初期実装では無意味な境界を自動連結して既存2枠互換を保つか、明示境界の返済を保持するかを選び、研究と同じにする。

## REST・画面・保存

- 既存 `GET /api/settings` の商品設定へ `windows` を追加。`PUT /api/products/{product}/settings` で枚数と枠を一括保存する。
- 商品OFF・旧運転終了・未約定照合完了以外の保存を既存 `editableProduct` で拒否する。版番号競合・ディスク原子的保存を維持する。
- `GET /api/rules` の銘柄・Day/Night対応を枠の手法候補にも使う。未実装ルールファイルは選択不可。
- 商品モーダルを「上限枚数＋時間帯の表」へ変える。枠追加/削除、Day/Night、開始/終了、手法又は静観を編集可能にする。
- 商品カードは「現在の枠・手法・次の切替JST」を主表示にする。昼夜2IDだけの表示は補助へ下げる。
- 既存 `conf/web-ui.toml` に日本語コメント付きで保存する。元の `settings.toml` と手編集コメントは残す。入れ子配列を浅いコピーで共有しない。
- 発注・返済ログへ `window_id`, `method`, `schedule_revision`, `transition_reason` を追加。既存の商品/運転ID/建玉IDの追跡を保持する。

## 主な変更箇所と担当境界

| 箇所 | 変更 |
| --- | --- |
| `internal/config/windows.go`（新規） | 型、旧2枠変換、構文・手法検査、コピー |
| `internal/schedule/windows.go`（新規） | controller時計を使った実区間解決、空白静観、重複拒否 |
| `config/web.go`, `web_settings.go`, `web_persistence.go`, `web_catalog.go` | worker伝播、REST変換、保存コメント、選択ルール検査 |
| `webui/api.go`, `manager.go`, `assets/app.js`, `assets/index.html` | OFF時のみ枠編集、RESTとUIの同一条件 |
| `runner/*` | 枠選択、期限直前再検査、返済・照合遷移、時刻状態の表示 |
| `strategy/*` | 新手法と切替アダプター。既存D07影との一致をroot担当で検証 |

## 必須検査

旧day/night設定の無変更運転、明示した2全体枠との一致、隣接境界、静観空白、夜間日付越え、米国夏冬、JSTとUS相対の季節重複、OFF以外保存拒否、REST/TOML往復、入れ子コピー独立、取消中部分約定、境界後新規禁止、他人/前起動玉に触らない、再接続で枠が逆戻りしない、D07影継続の全夜再現一致を確認する。
