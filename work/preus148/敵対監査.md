# 米国開始前の勢い入口・利益トレーリングの敵対監査

米国開始前だけの新手法を対象とする。現在のD07を変更済み、又は収益改善が確認済みとは扱わない。以下は実装前に固定する問いと確認条件であり、成績の採否は保存夜間全場と当日部分を分けて評価する。

| 番号 | 自問・反例 | 実装・検証で必要な確認 |
| --- | --- | --- |
| 1 | 上昇が減速しただけなのに売っていないか | 価格の傾きと傾きの変化を分ける。傾きが正で加速が負なら上昇減速、傾きが負で加速が正なら下落減速。買売反転の人工入力で時刻と数量が対称になることを確認する。 |
| 2 | 今夜の3波を知ってから入口時刻・窓を合わせていないか | 3・5・10・20本など少数の期間と理論的な因子別対照を成績計算前に固定。全候補を残し、今日の指定時刻を自動検知時刻と呼ばない。 |
| 3 | 現在足の最終価格を先に見ていないか | その時点で終わったバケットだけを回帰へ渡す。将来行の価格改変と接頭辞再計算で、過去の特徴・発注判断が変わらないことを確認する。 |
| 4 | 約定がない分を勝手に滑らかな線で埋めていないか | 分足欠損、原価格時計の飛び、無効気配を区別する。補間又は直前値保持を行う場合は明示条件を固定し、実際の将来終値で穴埋めしない。 |
| 5 | 比較の30秒を観測していないのに連続成立としていないか | 指標の未知・気配無効・許容を超える価格時計の飛びで確認開始を解除する。未知区間を越えた直後に昔の開始時刻で即発注しない人工例を検査する。 |
| 6 | 同じ行の安い値で買い、高い値で売る仮想利益になっていないか | 判断した原行より後の最初の正常気配でのみ約定。買いは売気配、売りは買気配。原行番号が後でも時計同値の場合の扱いを明示する。 |
| 7 | 勢いの反証が実は黒字玉の即利確になっていないか | 今回の『利確は利益が乗った後のトレール』に合わせ、soft exitは清算気配で評価損益が非正のときだけを標準とする。黒字中の勢い減速だけで返済する比較を混ぜない。 |
| 8 | トレーリング未発動の間に損失を無限に抱えていないか | 初回実約定を起点にした固定最大損失幅を常時有効にする。勢い指標が欠測でも正常気配があれば損失停止を判定する。約定飛びで停止幅以上の損失が出る可能性も会計へ含める。 |
| 9 | まだ利益が出ていない時から利確トレールが効いていないか | 実際の建値に対する清算気配の最高順行が発動幅に達した後だけ有効。中値利益を清算可能利益と取り違えない。発動幅と戻り幅が同じ又は逆転する条件では、トレール発動後でも損切りになり得ることを区別する。 |
| 10 | 追撃で平均建値が動いた際、保護していた利益を再び危険にさらしていないか | 追加は実約定価格・数量で平均建値と評価損益を更新する。買いの停止価格を下げず、売りの停止価格を上げない。最高利益幅・最高利益金額・各玉追尾のどれを使うか固定する。 |
| 11 | 5枚から10枚への追撃が、未約定を含めると上限超過にならないか | 保有数量と予約新規数量の和を上限へ計上。同方向に重複新規を積まない。返済と反転新規を同じ行で都合よく約定しない。 |
| 12 | 米国開始前限定のはずが、その後も新規を約定していないか | USOpen−15分の境界以後は新規・追加を禁止。境界前判断でも次正常気配が境界後なら新規予約を取消。旧玉の境界返済は次正常気配まで待ち、境界価格を捏造しない。 |
| 13 | 米国後のD07と足し算しただけで、全夜の改善と呼んでいないか | D07の境界またぎ玉、仮想影、残玉予算、次親状態は独立ではない。前区間を入替えた全夜運転は別途統合再生する。保存D07の後半損益を単純に足した値は参考比較に留める。 |
| 14 | 利確後の再参加が、往復損切りを増やしていないか | 再準備時間を少数条件で比較し、初動回数・連敗・同じ価格帯での往復回数を記録する。今日の3波の回転成功だけで採用しない。 |
| 15 | 累計黒字が一夜の大勝ちだけで作られていないか | 黒字・赤字・無取引の場数、中央値、平均・中央・最大赤字、上位3黒字場除外後の収支を比較。合計だけで順位を決めない。 |
| 16 | 夜間の上げ下げの一方だけを取っているのではないか | セッション始終値と、検証対象の米国前区間始終値の分類を分ける。終点の方向を入口に使わず、上昇・下落別の場数・収支・売買方向を事後評価する。 |
| 17 | 25夜で選んだ上位を未見検証と呼んでいないか | 既知期間は開発比較。条件を決めた期間と、固定して評価した後半区間を区別し、当日部分は未完結の確認として分ける。過去研究で既に見た後半を完全な未見と表現しない。 |
| 18 | 勝率を上げるために無取引を増やしていないか | 無取引を勝ちに含めず、米国前の参加数・最初の入口時刻を併記する。最新指定にない古い最低回数・利益額を隠れた選抜条件として復活させない。 |

実装・人工試験が提示されるまで未確認。コードの行番号、実施した検査、残る制約をここへ追記する。監査担当自身は過去データの金融再生を行わない。

## 時間帯切替アプリの確認

新手法の収益評価とは別に、時間帯別の切替機構を監査した。

| 確認点 | 証拠・判定 |
| --- | --- |
| 旧昼夜設定を勝手に変えない | `TestLegacyWindowsRemainImplicit` とrunnerの `TestSlotLegacyKeepsPortfolio`。windows未指定では旧経路を維持。標準D07を変更していない。 |
| 枠を全部消した結果、旧昼夜売買が再開しない | `TestExplicitEmptyWindowsNeverFallsBack`。TOML・Config・全般更新で明示空配列を拒否。商品REST空配列400、全般REST空配列409も人工HTTPで確認。 |
| 入れ子のコピーが空配列と未指定を混同しない | `CloneInstruments` は非nil空配列を保持。worker・設定適用・商品更新は複製前に明示空を拒否。 |
| 米国夏時間だけ重複する枠を許さない | `TestWindowSyntaxAndSeasonalOverlap`。JST固定の22:30終了とUS開始15分前開始の組合せを夏冬双方で検査し拒否。 |
| 境界時刻で旧枠と新枠を二重選択しない | `TestWindowResolutionDSTAndBoundaries`。半開区間、空白静観、翌日03:00、場前の安定した識別を確認。 |
| 時間帯違いの銘柄・手法を混ぜない | 銘柄接頭辞、Day/Night対応、未知ルールを設定検査で拒否。CLIも明示時間帯の選択手法全件を検査。 |
| 稼働中の編集を許さない | `TestWindowRESTPersistenceAndRunningRejection`。OFF以外の変更をRESTで拒否。旧画面による明示枠の消失も拒否。 |
| 画面だけ変えて設定が保存されていない | Headless Edgeで枠追加/削除、米国15分前/後の指定、REST保存、再表示を実操作。`画面確認.json` と `時間帯編集_*.png` を保存。全商品OFF、controller接続先localhost無効ポートで実施。 |
| 取消受付で次手法へ飛ばない | `time_slots.go` のcancel/close分離と `TestSlotCancellationReconcilesPartialFillAndPreservesExternal` を確認。取消競合の約定も旧Portfolioへ反映してから返済。 |
| 外部玉・前起動玉まで返済しない | 所有台帳のPositionとSignal.TargetsのHoldIDだけを返済。上記人工HTTP試験では外部8枚を残し、当運転の競合約定2枚だけを返済。 |
| OFFと自動切替の意味を混同しない | tick/processReferenceのdetaching優先と、dispatchのnew/close共通tradePermitを確認。OFF後の送信は禁止。自動境界は当運転所有玉を返済する。 |
| 時計逆行で終了した時間帯へ戻らない | 最大評価壁時計を保持する `slotClockReversed` と専用人工試験を確認。新規停止中も返済・取消照合は継続。 |

別担当へ修正を依頼した2点もコードと回帰試験を確認した。①新枠直後はLastRawHashを解除し、同場再準備では新枠開始より前のTime/Receivedの原行を新Portfolio.Advanceから除外する。`TestSlotHistoryReconnectSkipsPreActivationRows` で旧枠2原行の除外・過去発注なしを確認。②送信許可ロックの取得後、Submit直前に現在時計を再取得し、枠・場終了・判断期限・静観・鮮度を再確認する。`TestSlotSubmitRechecksClockAfterPermit` でロック取得と境界越えの新規破棄を確認した。

監査担当も `go test ./internal/runner -run 'TestSlot|Test.*Detach' -count=1` を実行し通過した。外部HTTP先は試験サーバーだけ。実機の注文・設定への書込みは行っていない。

研究との相違は `App/SessionTrader/docs/時間帯切替.md` に記録した。切替アプリは境界で旧所有玉を返済して新Portfolioを作り、D07の過去の仮想売買を影状態として引き継がない。DryRun境界返済も送信時の最新の鮮度確認済み商品気配であり、研究の次正常原行約定とは別である。機構の動作確認を、研究上位手法の全夜利益の実装一致と読み替えてはならない。
