# 先物・OP履歴と分足

アプリが受信したPUSHのうち、登録済み先物一覧で`FutureCode`が`NK225`または`TOPIX`の銘柄と、登録済みOP一覧の銘柄を保持します。銘柄IDは各登録一覧から照合します。OPは商品コード・限月・コール/プット・権利行使価格ごとに別銘柄として保持・保存します。履歴用のREST取得や上流接続は追加しません。追加設定なしで有効です。

OPの履歴コードは`{OptionCode}_{限月}_{CまたはP}_{権利行使価格}`です。例の`NK225op_202610_C_65000`は日経225オプション・2026年10月限・コール・権利行使価格65,000円を表します。`C`はコール、`P`はプットで、同じ権利行使価格でも限月やコール/プットの種別が違えば履歴は分かれます。権利行使価格は桁区切りなしで指定します。

## セッションと保持期間

既存のデイ・ナイト判定を流用します。日本時間06:00以上15:45未満は当日開始のDay、15:45以降は当日開始のNight、06:00未満は前日開始のNightです。`SESSION.SkipDates`に該当する開始日は収集しません。生データには開場前に受信した値も含み、価格の足は日中08:45、夜間17:00以降の新しい価格から形成します。

現在のセッションをメモリへ保持し、セッション交代後に前セッションを非同期保存します。保存完了後は参照を除去し、メモリの回収対象にします。APIから過去セッションは取得できません。取得中に交代した生データ配信も中断します。

OPの履歴領域は初回受信時に作成します。そのセッションで受信済みのOPは登録銘柄の更新で対象から外れても、セッション終了まで取得でき、終了時の保存対象にも残ります。以後の収集対象は現在の登録一覧で判定します。

保存の遅延や失敗時は終了済みデータをメモリに残し、失敗から約30秒後に再試行します。保存待ち件数・本文バイト数・直近エラーは状態APIで確認できます。保存待ちに件数や容量の上限を設けないため、ディスク障害が続くとメモリ使用量は増加します。

現セッションは通常終了時も保存せず、再起動時の読戻しも行いません。異常終了時は現セッションと未保存分を失います。

## OHLCV

- `open`・`high`・`low`・`close`は、対象の1分間に実際に受信した`CurrentPrice`から求めます。上流の`OpeningPrice`・`HighPrice`・`LowPrice`を流用しません。
- 価格の所属分は`CurrentPriceTime`、出来高の所属分は`TradingVolumeTime`で判定します。確定した分への遅着は無視します。同じ秒でも価格や累積出来高の変化は取り込みます。
- `volume`は累積`TradingVolume`の差分です。最初の観測は基準値として差分を0にし、累積値が減った場合もその値へ基準を置き直します。初回基準が足の途中だった場合や減少があった足は`volumeComplete: false`になります。
- `volumeComplete: true`は出来高差分の基準を取得できていることを示し、未受信期間も含めた取引所全体との完全一致を保証しません。
- 無観測の分を前値で補完しません。形成途中は`closed: false`で返し、時間が進むと確定します。
- 5分足は、その5分区間に存在する1分足を最大5本だけ集約します。生データの読み直しは行いません。

セッション交代後に到着した前セッションの引け値も、前セッションの足へ戻して反映しません。アプリへ届かなかった価格変動の推定や復元は行いません。

## ファイル

起動時の作業ディレクトリを基準に、セッション開始日と`Day`・`Night`を使用します。

```text
log/book/TOPIX/2026-09-21_Day.jsonl
log/book/NK225/2026-09-21_Day.jsonl
log/book/NK225op_202610_C_65000/2026-09-21_Day.jsonl
log/candle_1min/TOPIX/2026-09-21_Day.csv
log/candle_1min/NK225/2026-09-21_Day.csv
log/candle_1min/NK225op_202610_C_65000/2026-09-21_Day.csv
log/candle_5min/TOPIX/2026-09-21_Day.csv
log/candle_5min/NK225/2026-09-21_Day.csv
log/candle_5min/NK225op_202610_C_65000/2026-09-21_Day.csv
```

JSONLは受信JSONの項目をそのまま1行化したものです。独自の項目は付けません。CSVの列は`time,open,high,low,close,volume,volume_complete,closed`で、時刻は日本時間のRFC3339形式です。受信のなかった商品にはファイルを作りません。

配布更新スクリプトは実行ファイル・`conf`・`mst`だけを置き換えます。`dist`から起動して作成した`dist/log`の保存済み履歴は保持します。

書出し中は同じディレクトリの一時ファイルを使用し、完成後にハードリンクで最終パスを公開します。保存先にはローカルNTFSなどハードリンク対応のファイルシステムが必要です。再試行時に同名・同内容のファイルがあれば成功扱いにします。同名で内容が異なるファイルは上書きせず、保存待ちとエラーを残します。

## 別PCから取得

すべてGETです。`{code}`は大文字の`NK225`・`TOPIX`、または`NK225op_202610_C_65000`のようなOP履歴コードを指定します。OPも先物と同じAPI・応答形式を使用します。

| URI | 応答 |
| --- | --- |
| `/api/v1/history/status` | 現在の件数・本文バイト数・足数、保存待ち状態 |
| `/api/v1/history/{code}/book` | 生JSONを逐次送信する`application/x-ndjson` |
| `/api/v1/history/{code}/candles/1min` | `snapshot`と`data`配列を持つJSON |
| `/api/v1/history/{code}/candles/5min` | `snapshot`と`data`配列を持つJSON |

`status`の`current`には先物2商品と、現セッションで受信したOPの履歴コードが含まれます。取得したい限月・コール/プット・権利行使価格に対応する`code`を選び、板や足のAPIへ渡してください。

`from`・`to`は任意のRFC3339日時で、`from`以上・`to`未満を取得します。片側の指定も可能です。省略すれば取得開始時点までの全件を返します。生データは**アプリの受信時刻**、足は**足の開始時刻**に対する指定です。`+09:00`の`+`は`%2B`へURLエンコードしてください。

```text
http://192.168.0.10:8080/api/v1/history/NK225/book
http://192.168.0.10:8080/api/v1/history/TOPIX/candles/5min
http://192.168.0.10:8080/api/v1/history/NK225op_202610_C_65000/book
http://192.168.0.10:8080/api/v1/history/NK225op_202610_P_65000/candles/1min
http://192.168.0.10:8080/api/v1/history/NK225op_202610_C_66000/candles/5min
http://192.168.0.10:8080/api/v1/history/TOPIX/candles/1min?from=2026-09-21T09:05:00%2B09:00&to=2026-09-21T09:06:00%2B09:00
```

`snapshot`には`sessionId`・`generation`・`code`・`session`・`asOf`・`sequence`を含みます。`sessionId`は`2026-09-21_Day`の形式、`session`は既存のセッション情報です。`generation`はメモリー内のセッション領域識別子で、セッション交代時や同日再起動時に変化します。同じ領域での受信・足確定では変化しません。取得開始時点の上限を固定するため、配信中に届いたデータは混ざりません。

生データでは対応する情報を`X-History-Session-Id`・`X-History-Generation`・`X-History-Code`・`X-History-As-Of`・`X-History-Sequence`ヘッダーで返します。**全本文を読み終えた後、HTTPトレーラーの`X-History-Complete: true`を確認してください。** `false`またはトレーラー未取得は、セッション交代・切断・通信失敗などによる不完結として扱います。本文にエラーJSONを混ぜません。トレーラーを取得できるHTTPクライアントを使用してください。

現セッションが存在しない場合や足の取得途中で交代した場合は409、不正な商品・時刻範囲は400です。現セッションがあって対象商品の受信がまだなければ空データを返します。有効な形式の未受信OPコードも同じ扱いで、取得だけでは`status`や保存対象へ追加しません。生データの同時取得は先物・OPを合わせて4件までで、超過は429と`Retry-After: 1`を返します。

読み取りは書込み用ロックを取得せず、生データは指定範囲の分だけ参照します。全件取得でも一括複製は行わず、32KiBの送信バッファで順次配信します。各ネットワーク書込みに10秒の期限を設け、遅い読み取り先による配信資源の占有を制限します。

## 分足の継続表示と差分取得

分足APIは初回に全件を取得し、以後は前回の`snapshot.generation`を`generation`へ指定して取得します。最後の足が形成途中ならその開始時刻、確定済みなら開始時刻に足幅の1分または5分を加えた時刻を`from`へ指定します。同じ領域では`from`以降の足だけを二分探索で取り出すため、確定済みの過去足の再取得・再集計を必要としません。足は開始時刻をキーに上書き・追記します。

`generation`が現在領域と異なる場合、APIは時刻クエリーを検証した後に`from`・`to`を破棄し、新しい領域の全件を返します。応答の`generation`が変わっていれば、画面側の旧データをすべて破棄して応答データへ置き換えてください。これにより、夜間から日中への切替や同日再起動後の空データを安全に反映できます。`generation`の省略時は既存の範囲取得動作を維持し、空文字・重複指定は400です。

画面側では商品と足幅ごとに取得済みの足を保持し、銘柄や足幅の再選択時も差分取得を続けます。非表示中は定期取得を止め、再表示後に保持済みの位置から再開します。参照元を`NK225`とする銘柄と、`TOPIX`とする銘柄でデータを共有し、上流への追加取得は行いません。

分足チャートの横軸は`snapshot.session.startsAt`から`endsAt`までのセッション全体に固定します。日中・日付をまたぐ夜間とも、足の追加や1分足・5分足の切替で時間のスケールを変えません。未到来・未受信の時間帯は空欄とし、セッション情報を取得済みなら最初の足の受信前も時間軸を表示します。
