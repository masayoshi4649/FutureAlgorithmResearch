# 二段階再生器の独立レビュー

`conditional_runner.py`、`conditional_assessment.py`、`conditional_inputs.py`、`conditional_design.py` を、新しい損益の再生前に読取確認した。コード変更・新売買再生・現在データへのアクセスは行っていない。

**重大な不具合は見つからなかった。** 初期6の全840条件を完了した後、選択にはV000の168条件×初期6×2銘柄だけを渡す。方式を固定しSHAを確定してから後7を再生する順序で、選択関数は期間外・欠落・重複・未完了・締切後の完了行を拒否する。後7の開始時刻は締切の定義にだけ使われ、後7の損益は選択へ渡されない。全13は既知データとの留保がある。

影は入口・入口時計・約定モデルが同じ固定A0の通常運転で、悪化条件や実側の成績から独立している。新設準備と新規起点の全配列、全新規注文が影と完全一致することを確認し、対応する全返済行が影以前であることを全組で要求している。初回リスク・A0・方向も一致を検査する。

14項目の計数は、保有行、保有に逆の悪化行、追加短縮の許可行、At<A0行、丸め後に固定候補より狭い行、実際の線進行、組ごとの返済差を分けている。`exit_difference_r` は同じ組の初期予定Rで除した収支差であり、銘柄の円額を直接合算していない。旧8結果と追加2記録は形状・配列SHAを保存し、軽量保存する7台帳以外の3曲線も指紋へ結んでいる。

解釈上、次の区別を維持する必要がある。

- `changed_repayments` は返済価格・数量・行だけでなく理由の差も含む全返済台帳差。金銭結果が異なる組数そのものではない。
- `held_rows` 等は原本観測行数であり、保有時間や独立した悪化イベント数ではない。実線進行は別の疎なイベントとして数える。
- 全期間の固定条件集計と、自動運用の「初期6固定A0＋後7選択方式」は別の経路。選択方式を初期6へ遡及した診断を運用実績としない。
- 全指定波は初期6内のため、選択後7の目的適合を示す証拠ではない。

このレビューは起動ガード・全件独立会計の代用ではない。監査時点で起動前の補助監査ファイルは準備中のため、実行可否は最終の固定SHAと起動ガードで確認する。
