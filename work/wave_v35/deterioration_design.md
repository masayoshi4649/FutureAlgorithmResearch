# 条件付き追跡短縮の根拠

観測方向を上昇 +1・下落 −1・根拠なし 0 とする。保有と反対の根拠があるときだけ、固定 3A0 の追跡候補へ 3min(A0,At) の候補を追加する。直接全返済はしない。不発でも固定 3A0 の運転は続く。

|機序|観測するもの|
|---|---|
|価格だけ|窓全体と直近1/4窓の価格が同じ方向へ動く|
|板だけ|OFIと距離重み板変化が同方向で、1/2窓前も同方向|
|逆価格応答|OFI・推定売買が偏る一方、価格は反対へ進む|
|両価格|60秒待った相手市場と自市場の価格方向が一致|
|両板・価格|両価格に加え両市場のOFIも一致|
|補充の後|1/2窓前の強いフロー・反対側補充・価格停滞から、後続価格が逆に動く|

各機序を120秒/600秒で固定する。価格確認は max(0.25ATR,2呼値)、直近価格は max(0.10ATR,1呼値)、OFI0.10・距離変化0.05・推定売買0.15・補充偏り0.20。停滞は max(0.25ATR,1呼値)以内。閾値は正負対称、境界を含む。

自板は原本解放seq、相手は解放+60秒から利用する。60秒を超す解放遅延、参照の古さ、窓内の解放空白は根拠不足として0にする。最低5イベント、過去窓の参照点も必要。ATRと原本時刻の因果性は既存の公開済み入力に限定する。

板数量の増減・OFI・推定売買・同価格補充は観測代理量で、真の約定/取消、発注者、新規/返済を識別できない。価格逆行を誰かの吸収行動と断定しない。CurrentPriceTimeが受信時刻と等しい保証もない。

今回は入口時計0.8/1/1.2を比較し、悪化窓は120/600秒から変えない。APIは任意窓を生成できるが、悪化窓自体の感度を検査したとは記載しない。仕様の「時計診断」説明を入口時計へ明示する変更だけ履歴保存し、数値・機序を追加していない。新格子損益・現在APIは未使用。
