# 条件付き追跡短縮の注文器契約

`run(ready, state, config, detail=False, context=None, width_mode=0, observed_fill=False, trail_atr=None, prepare_allow=None, deterioration=None, deterioration_source=None)`。

- `width_mode=0` は固定A0、`1` は常時 `min(A0,At)`、`2` は `deterioration[i] == -保有方向` の行だけ `min(A0,At)` を追加する。**前版のモード1（Atそのもの）とは意味が異なる。旧版の厳密互換はモード0について確認する。**
- 新規準備時A0、初回枚数、初期組予算1A0、1.5A0追跡始動、2A0部分利確、最長360分、全返済後5分休止などはD273のまま。TOPIX初回5・上限10、NK225初回10・上限20。
- 毎有効保有行に固定3A0候補を必ず計算する。許可された追加候補と固定候補の有利側を、既設線より有利な時だけ採用する。条件が消えても短縮済み線を緩めず、固定候補の更新も止めない。
- 当該行では既設注文を先に執行し、新しい線は次原本行から有効。新設時点で既通過なら次の観測価格で返済する。同一時刻でも原本行の順序を守る。
- Atは有限正値だけを2呼値以上に補正して保持し、欠測・非正値は直前を維持する。各新規時の初期値はA0。Atは追跡幅以外へ作用しない。
- 悪化方向は原本行対応の `ndarray[int8]`、値−1/0/1。根拠行は同長 `ndarray[int64]`、非中立時は0以上かつ当該行以下。省略時は非中立の当該行を記録する。外部板特徴・相手市場の公開時刻は入力側で監査する。
- 影は固定A0通常運転として独立に再生成し、実側のAt・悪化条件・損益を使わない。影の新しい準備行だけを `prepare_allow` とする。既設未約定注文は許可が消えても存続し、途中参加は禁止。
- `observed_fill=True` は新規・部分・全返済をすべて条件成立後の観測価格で執行する。影と実側は同じ約定モデルを使う。

旧 `trades/cycles/curve/orders/stats/atr_curve/prepare_events/entry_preparations` の列と単位を維持する。追加の `conditional_curve` は全原本行（詳細なしでは1行へ省略）、`trail_events` は線が実際に進んだ行だけを詳細なしでも保存する。列順はモジュール定数 `CONDITIONAL_COLUMNS`、`TRAIL_EVENT_COLUMNS` を使用する。

`advance_kind` は1=固定候補、2=常時最小幅の追加、3=悪化根拠による追加。追加候補が固定候補より有利でも既設線を超えなければイベントを増やさない。現在の悪化方向と、残っている追跡線を進めた過去の根拠行は別に記録する。根拠あり、At<A0、候補が固定より有利、既存線も実際に進めた回数、最終退出が変わった組数を混同しない。

同一入口・同一D273・同一価格モデルという制約の下、実側は固定幅より早い追加の全返済だけが可能である。双方が共通状態にいる間の初期予算・部分利確等は同一であり、実側が先に全返済した後は、影の次の準備まで待つ。実の休止は影の休止より遅く終わらないため、影の次準備へ再び参加できる。この帰納の前提を合成相場と将来の全件監査で反証し、確認前に一般的な約定保証や収益改善の証明としない。

検査は合成相場、壊れた線凍結実装を拒否する負例、既知H019固定A0全26入力の旧8結果同値に限る。新しい常時最小幅・条件付き最小幅の実相場損益は、全仕様固定前には計算しない。現在API・保存ライブ・原本変更は行わない。
