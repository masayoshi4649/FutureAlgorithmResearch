# E01以後の知見を改修へ使う範囲

本メモは00046〜00063の保存成果を読み、今回の改修成績を見る前に整理した。原本・App・APIを変更していない。「支持」は下記の観測事実や設計上の条件を指す。どれかを足せば利益が増える、という意味ではない。

## 入口の因果で禁止すること

1. **確認の遡及。** 反転確認が時刻tで成立したら、入口はtの判断後の次有効行。最初の圧力発見時刻の価格で入らない。確認が後で成立した事例だけを、発見時点で選べたことにしない。
2. **場末最大値による選別。** 場末までのMFE、最終方向、後で助かったか、実保有時間、最後に広がったレンジを新規許可へ渡さない。保有中に逐次更新した「現在までの最高順行」は利用できるが、原簿の将来MFE列は利用できない。
3. **入口集合の取り違え。** 出口変更で保有中の見送り・休止・次の入口が変わる。実運用全体の差と、凍結した同じ検知点を独立採点する差を分ける。共通の実入口も運用結果で選ばれた部分集合で、純粋な因果効果ではない。
4. **仮想逆張りの混入。** 原方式が負けた後だけ逆方向を試したり、未来に回復した時だけ再新規を認めたりしない。反転条件は現在までの価格・確定足だけで定義して全候補へ同じように適用する。

## 二市場ゲートと夜間時計

- 同一銘柄では原板連番を守る。同じCurrentPriceTimeの後続行を、その時計の最初の判断へまとめて使わない。
- 保存時計は最終約定時刻で、受信時刻ではない。相手市場の最後の板を単に時刻順で結合すると、まだ到着していない行を知ったことになる可能性がある。相手の確定・公開済み特徴だけをas-of参照し、従来の60秒相手待機を保持する。これも未知の受信遅延を完全に保証するものではない。
- Go版の `Snapshot` は自市場を `Available <= t`、相手を `Available <= t−PeerDelay` で探す。名目足終了時刻だけで選ぶ改修をしない。保存再生とGo実受信版の時計前提も区別する。
- 「一致」と「新鮮」を分ける。期限を超えて古い指標しかない場合を、最新の両市場一致と表示しない。新鮮さ上限を追加するなら値を事前固定し、見送り数と削った勝ち／負けを併記する。
- 欠測を埋めた足の連続性から傾き・収束・ERを人工的に作らない。必要足の実観測割合、公開遅延、時計空白を記録する。
- ナイトは開始日のセッションIDを保持し、00:00に休止・連敗・ATR・保有期限を初期化しない。米国開始で切り替える案は、公式営業日と夏冬時間、使用時計を別に定義する必要がある。後から負けたJST時帯だけ禁止しない。
- 返済期限15:35／05:50などの任意監視期限と、保存ザラバ末15:40／05:55を分ける。観測が飛んだとき、期限ぴったりの架空価格で返済しない。次有効行が遅れた件数と実返済時刻を保存する。

## 比較設計の固定案

**約定前提を共通化する。** 今回の指定は旧E01を忠実再生し、費用を追加する主比較。改修も同じ価格モデル・数量・費用に揃える。旧指定値・観測最後値モデルの結果と、次行気配モデルの結果は別枠にし、混在させて改善と呼ばない。実行可能性に近づける気配・遅延感度も有用だが、固定注文の価格置換と、気配で出口・次入口まで再運転する比較を区別する。

**同じ数量で部品を一つずつ変える。** TOPIX初回5枚、NK初回10枚、片方向上限10/20、増玉なしを共通化し、少なくとも以下の部品対照を残す。全枚数への増加は後段の感度とし、期待値改善と混同しない。

|改修部品|事前に置く対照|解ける問い|
|---|---|---|
|待機新規の失効取消|保持方向だけ／現在の開始条件まで要求|古い準備信号を追う負けを減らす代わりに、押し目成功を何件消すか|
|再参加時計|通常影維持／実フラットで休止開始|再参加機会の増加で本流参加と往復損がどう変わるか|
|再武装|固定休止だけ／一度中立化した支持の再成立を要求|同じ継続信号を何度も売買する費用を抑えられるか|
|未進捗保有の整理|なし／10分・20分で現在まで0.25ATR未達なら返済|伸びない損失玉の滞在を減らす効果と、遅い成功を削る代償|
|利益追跡の最小幅|旧係数／参照2呼値下限|細い価格刻みの往復決済を減らす代わりに、利益の戻しをどれだけ増やすか|
|二市場の直近状態|保持方向一致／両方が直近で明確に逆向きの場合だけ見送り|最新不一致の回避が、単なる取引数減少より価値を持つか|
|統合|上の事前指定組合せ／各部品の単独対照|管理を重ねた効果が単独効果と整合するか|

複数幅を探索する場合も、前半を見る前に一覧、同値処理、取消・損切り・利確・場末の優先順を固定する。高い収支を見つけた後に主条件を差し替えない。

**期間は先頭16場で選択、後ろ12場で測定。** 親担当指定に合わせ、先頭16場は9/21〜9/30のデイ＋ナイト、後ろ12場は10/1〜10/8のデイ＋ナイトとする。昼夜を同じ日付でまとめ、選択と測定の境界で同じ日の昼夜を分割しない。以前の25保存場は既知であり、後半にも多く含まれるため「既知資料の時間順再検証」であって後12場全体を未見試験と呼ばない。新しく追加された場でも旧APIで参照済みの前半がある場合は、その部分と新規追加行を区別する。後半を見て閾値・方向・部品・数量を変えたら新候補として別に固定する。

前半の選択条件案は、両銘柄で10決済組以上、費用後黒字、平均利益／平均損失1以上。どれも満たさなければ「選定なし」とする。複数ある場合は、各銘柄の初回数量×最初のセッションの観測始値×円倍率を全候補共通の固定分母とした費用後収益率のうち、小さい方を最大化。同率は最大資産下落の比率が小さい方、次に少ない追加部品、最後にID順。銘柄の円収支を足して選ばない。選定なしでも全主対照の後半測定は継続し、無取引を勝ちに含めない。この選択案を用いる場合は実行前固定へ明記し、後半結果を見て採用することはしない。

**利益額以外の合格基準を併記。** 全玉費用後収支、平均利益／平均損失、勝率、無取引場、最大含み込み下落、最大負け日、損失連続回数、取引数、同時最大枚数、日別収支を両銘柄別に出す。最大利益場と最大利益日を除く感度、隣接閾値、発注遅延感度も保存する。改修が基準より赤字を減らしただけなら「改善対照」であって「有用な採用候補」としない。

後半の各銘柄黒字を、統計的証明や将来の安定へ昇格させない。取引、複数枚、同日の昼夜を大量の独立標本として数えない。今回の28場の後半が改善しても、将来データを同じ固定条件で測る段階は残る。

## 親担当が結果前に示した改修案への短評

G10（新規時EMA再検査）、G11（両慢EMA逆向き拒否）、G12（両速EMA同方向）、G01（直近5分逆方向の組合せ見送り）は別々に比較する。保持方向、慢EMA、速EMA、過去5分変化は同じ判定ではない。ゲート強化による収支差は、見送った勝ちと負け、実新規集合の変更まで含む。

予約120秒、反発幅0.5ATR、15分で0.5ATR未達なら損切り0.5ATR、1ATR順行から1ATR幅追跡、0.75ATR順行で組建値、通常影を廃止し出口影へ参加時計同期、という部品の固定には因果上の問題はない。ただし各閾値の利益効果は未証明である。予約と反発幅は確認中の遅れ、途中進捗と建値線は遅い成功を削る代償、影同期は往復再試行の増加をそれぞれ調べる。

「組建値」は、料金前の建値価格線なのか、既払料金と部分返済済損益を含む組全体の純収支ゼロ線なのかを固定する。条件線で停止しても、次行気配・遅延による悪化は残る。費用後のゼロを保証する呼び名として使わない。
