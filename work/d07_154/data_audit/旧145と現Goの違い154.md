# 旧145のD07と、今回の現Go基準は同じ成績ではない

重なる50場で、旧145は**+4,159,000円**、現Goは**+3,050,000円**。29場で収支が異なり、差は**−1,109,000円**。今回追加された10/26昼の+9,000円は、この比較に入れていない。

これは利益保護などの今回の改修差と別の問題である。旧145で有望だったD07の結果を、そのまま現在アプリの期待収益として示すことはできない。

## 同じことを確認できた範囲

- 両方とも日経mini・倍率100円・手数料0・片方向10枚、主担当5／追加3／別入口2。
- 旧145のキャッシュ`limit`と今回Goの`force_close`は**全50場で一致**。昼15:35／夜05:50であり、今回の−110.9万円を場末時刻の差では説明できない。
- 旧145で採用された全原行について、今回原板の同じ行番号の時計・Last・bid・askが一致。元の値段が別物になった差ではない。
- 今回Goの実判断に対応し旧145にも存在する**806行の先頭24特徴は、全行で一致**。ただし、判断の間のすべての状態、旧だけにあった準備、主担当のE01内部全変数まで同値を証明したものではない。
- 今回の夜25場の収支は、研究00149の現Go対照C00と**25場すべて一致**。夜の差は今回の利益保護改修で新たに生じたものではない。

## 異なる入力の扱い

旧145は、買気配と売気配が同値・交差している異常BBOを除外した後で準備状態を更新する。Goは価格時計とLastが有効ならその原行を受け取り、異常気配では約定せず、未保有の準備や確認時計を解除する経路を持つ。

今回50場では、Goだけが採用する異常BBOが**12,586行**あった。これに加え、7デイに正常気配46行の違いがあるが、すべて15:40:00の原行で、各場の最終返済より後だった。正常46行を「異常板」とひとまとめにしていない。

一度入口が分岐すると、親を持っているか、次の入口を受け入れるか、利益予算、追加の可否まで変わる。このため、異常原行の数に比例して収支差が生じるわけではない。

|担当|旧145|現Go|差|注文まで一致した場|
|---|---:|---:|---:|---:|
|主担当core|2,358,000|2,570,000|+212,000|44/50|
|追加担当addon|691,000|296,000|-395,000|26/50|
|別入口episode|1,110,000|184,000|-926,000|26/50|

主担当は夜25場すべて同値。昼では6場に注文差があった。Goで改善した親もあるので、異常板を除く旧方式へ戻せば必ず改善するという結論にもならない。

旧145+512,000円、現Go+100,000円。主担当+54,000円は一致し、追加担当が−251,000円、別入口が−161,000円の差となった。

**22:45:36、買=売64,070の異常BBO（1始まり原行98,640）**をGoだけが処理した。その後、旧145には22:46:03の別入口買1枚64,090（親+159,000円）、22:46:16の追加買2枚64,080（親+251,000円）があるが、Goにはない。

## 基準として何を信頼できるか

今回の基準D07は、現ローカルAppのコピーと昼夜各1,000行の人工通知・保有・出口診断一致を確認した**現Go版**。同じGo入力経路の15条件間では、変更した条件の比較として使える。

一方、旧145のPython実装と金融経路まで同値であるという証明はない。運用中PCの実行ファイル・ルールの指紋も取得できていないため、現ローカルGoとその実機が完全に同じ版かも未確認。今日の実損益との違いを、今回の改修効果やこの−110.9万円だけで説明してはいけない。

今後、旧D07で期待した運転へ寄せるなら、異常板で「準備を解除」「新規だけ保留」「短い猶予で準備保持」を別仕様として比較する課題になる。現時点の保存比較だけで、どれかへ変更する判断はしない。
