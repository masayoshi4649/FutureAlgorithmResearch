# 00154 第二巡の事前固定仕様

初巡15条件は不変で保存し、以下の8条件だけを別の再生器で比較する。金融再生は新しい登録受領後に限る。

| ID | 変更 |
| --- | --- |
| S00 | 別入口だけ0.5R相当から親利益の半分を保護 |
| S01 | S00と基準D07旧親占有中の別入口再参加抑止 |
| S04 | 別入口だけ1R相当から親利益の半分を保護 |
| S02 | S04と基準D07旧親占有中の別入口再参加抑止 |
| S03 | 全担当1R保護と別入口の旧親占有中再参加抑止 |
| J01 | 早い同方向玉が1R進んだ昼主担当だけ初回1枚 |
| J02 | J01の判定時だけ1枚から順行確認で段階追加 |
| J03 | J02と昼の追加担当の通常追撃停止 |

## 入力

inputs154.jsonを初巡と共用。51完了場+2026-10-27 Day12:08排他の途中場。追加API取得なし。

## 価格と数量

日経mini片側上限10枚、point_value=100、費用0。初巡と同じ二市場特徴・次正常原行のラージBBO。

## 影運転

S01/S02/S03だけ、各場で未変更D07を同じ観測列・次正常BBOで独立駆動する。候補より先に当原行の約定・判断を完了し、episodeの親ID・実保有有無・未約定有無をコピーする。保存未来約定/終了時計は参照しない。

## 影抑止

episodeの未知新親の初回採用時、基準D07が異なる親の実玉又は未約定を持てばその親を不採用とする。同じ親は元のBlocked/残玉/予約規則に従う。基準が空になるまで未送信注文を保持する方式ではなく、拒否した親は後から再採用しない。次の新しい親で再判定する。core/addonは影で抑止しない。

## 親利益保護

初回R×初回実約定q0×100の0.5倍/1倍へ親実現+残含みが到達後、その合計の最高益50%を単調な下限として全返済。初巡G01/G02と同じ元退出優先/追加抑止/次原行約定。

## J判定

Dayのcore新親が採用された原行で、実episodeが同方向に1枚以上保有し、返済側気配と現在実玉の数量加重平均建値との差がepisodeの初回固定R以上なら、当親だけJabMode=2(J01)/3(J02,J03)。他は元5枚。利益幅は未実現だけで、過去確定利益を含めない。判定はその親で固定。

## J数量

モード2はC02、モード3はC03をそのまま適用。初回実1枚・元仮想5枚。0.5R順行ごと実+1枚、最大core枠5、30秒間隔、自己30/120順行・他市場30非逆行、退出優先、部分返済後追加なし。丸めとTicket配賦は初巡と同じ。

## J03

J02にDayのaddon.add_ready=falseだけ追加。Nightは全Jで基準D07のまま。

## 観測順

原行で既予約の約定→当行判断。core新親判定はこの時点で実episodeに残る玉を見る。同じ行で後からepisodeへ返済判断が出ても、まだ約定していない玉は実保有に含める。

## 出力

results_round2/{session}_D07.json。初巡schemaを保持しreference_rejectionsに拒否時刻/原行/候補親/基準占有を追加。jab_mode154と基準占有は保存snapshotsの診断に含める。

## 完了場

場末規定強制返済を維持。途中資料末尾で架空清算しない。

## 比較

S01-S00/S02-S04は影抑止の純効果、S03-G02は全担当保護のepisode再参加抑止。J01/J02は進行後重複時の数量/追加、J03-J02はDay通常追撃停止。

## 実行

```powershell
go run . -manifest ../inputs154.json -configs ../configs154_round2.json -registration ../登録受領154r2.json -out ../results_round2 -workers 4
```

基準の時価利益を将来利益の保証として使わない。基準の旧親が占有する時間も当時までの独立状態から決まり、保存済みの将来の返済時刻を見て新規を除外しない。
