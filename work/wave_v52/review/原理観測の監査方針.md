# 市場原理から始める観測の独立監査

現段階で売買規則を先に固定しない。保存板から何を観測でき、何を識別できないかを明確にし、その観測が後の価格とどう関係するかを測る。以下は計算結果閲覧前の監査方針。

## 原本と既存処理で確認した仕様

- 買い指値の最良は `Buy1`、売り指値の最良は `Sell1`。生JSONの `BidPrice` / `AskPrice` は名前だけで経済的な側を決めない。
- `CurrentPriceTime` は最終約定時刻であり、板の受信時刻ではない。同じ値のまま複数の板更新が続く。
- `TradingVolumeTime` は別時計。既存抽出は、同じ行の約定時刻より出来高時計が先の行を計数し、特徴公開時刻以下であることを検査している。
- `raw_features.release_row` の `mid/bid/ask` は公開時の先頭行。一方 `source_mid_last/source_bid_last/source_ask_last` は前の集計ブロック末尾。同じ時計の値として混ぜない。
- `raw_features` の公開は、同一約定時刻ブロックの後に別時刻の先頭行を観測してから。未公開の最終ブロックは出さない。
- `depth_features` の数量差分は、連続する二枚の板で共通して見える同一価格だけ。10段外へ消えた数量を取消とは扱わない。
- `released_depth` は公開先頭行の10段を直接読み、価格順・重複・非有限値・交差板を別々に検査している。

確認先: `work/wave_v8/raw_features.py`、`work/wave_v23/depth_features.py`、`work/wave_v40/released_depth.py`、`book/TOPIX/2026-10-06_Day.jsonl` 冒頭。

## primitive の定義で確認する点

### 出来高増分と執行側の代理

累積出来高の正の差を、現在の最終価格と直前の気配で分類しても、その間の全約定が同じ方向とは分からない。増分は複数約定の合計かもしれず、現在の最終価格は最後の1件しか表さない。

- 価格が直前売り気配以上なら買い側代理、直前買い気配以下なら売り側代理、間なら未知、という等号を含めた固定定義を確認する。
- 未知へtick-ruleを混ぜない。混ぜるなら別特徴とする。
- 出来高欠測を0に代替しない。負の差はリセット、双方が正しい数値で等しいときだけ増分0とする。
- 代理の正・負・未知の数量合計が、有効な正の出来高差合計と一致する。
- 不正板・時刻逆行・セッション切替を跨いで差を作らない。
- 当該増分の `TradingVolumeTime` が公開時計以下かを確認する。

呼称は「買い主導の実約定量」ではなく「前気配に対する最終価格で分類した出来高増分の代理」。

### 出来高増分0での同価格数量増減

これは「出来高の増分を同時に観測していない状態で、表示数量が増減した」という事実。約定更新と板更新の非同期があるため、注文取消・追加の真値とは呼べない。

- 同じ価格の共通部分のみを比較し、段番号のずれや観測範囲外への移動を増減へ混ぜない。
- 数量が同じで価格だけ近づいた場合、距離重みの増加を新しい数量追加としない。
- 板重複は数量フローを増やさない。滞在時間やイベント平均に使う場合は、その区別を明記する。
- 売り数量減少と買い数量増加を上向きとして合算するときは、両方の原数量も残す。異なる現象の相殺を隠さない。

### 気配の値直し

買い・売り両気配が上がる場合、片側だけが動いてスプレッドが縮む場合、逆に広がる場合は異なる。

- bid差とask差を別々に保持し、両側同方向・片側・拡大／縮小を区別する。
- 中値変化そのものを価格予測情報として二重に数えない。同区間価格との関係と、公開後の価格変化を分ける。
- 中値の変化と実約定価格の変化を混同しない。評価指標でどちらを使ったか残す。

### 同価格の回復

同じ価格の数量減少後、一定時間内に増加が観測された場合の量的対応は測れる。これは消費後の補充、取消の戻し、別人の注文などの区別を含まない。

- 過去の減少残高を超えて回復を数えない。
- 一つの増加を複数の減少へ重複計上しない。
- 減少→増加の順序を守り、窓外の減少や不正行を跨いだ減少を使わない。
- 秒数は約定時計の代理である。無約定中に実時間が進んでも同じ約定時計なら、実際の30秒回復とは一致しない可能性を明記する。
- 価格が10段の外へ消えて戻った場合は、観測できなかった途中の数量推移を補間しない。

### 距離ごとの供給

- 買い側は最良買気配から下方向、売り側は最良売気配から上方向の価格距離で重み付けする。
- 遠近の帯、指数重み等の尺度を計算前に固定する。今回の将来成績で境界を最適化しない。
- 水準ごとの数量と、最良気配が動いたため重みだけ変化した効果を混同しない。
- 複数の距離尺度が似た結果でも、独立した情報が複数存在したとは数えない。

## 情報が使える順序の監査

1. 原本物理行を保持し、時刻で並べ替えたり同時刻を先に集約したりしない。
2. 未来を切断した再抽出の公開済み出力が、全原本抽出の対応部分と完全一致する。
3. 未来行の価格・数量・出来高を変えても、それより前に公開済みの値が変わらない。
4. ブロックの最終源行番号が公開行番号より小さい。
5. 時間窓にはその時点までに公開された特徴だけを使用する。
6. 相手市場を使う場合は公開時刻のas-of照合と固定遅延を使い、近い未来の値を補間しない。
7. 将来価格は効果測定のラベルにだけ使う。将来の欠測を入口条件や現在の特徴へ入れない。
8. 同区間の説明と将来変化の予測を分け、将来価格の測定開始は特徴公開以降に置く。

## 心理・主体への過剰解釈を避ける

|観測|許される説明|このデータだけでは言えない説明|
|---|---|---|
|売り側数量が減る|表示売り数量が減った|売り手が怖くなって逃げた|
|出来高増分が売り気配側に分類される|買い側の執行を示唆する代理|買い手が自信を持って成行を連打した|
|数量が減って戻る|同価格の数量回復を観測した|同じ大口の隠れ玉が吸収した|
|高い出来高でも価格が停滞|観測量に比べ価格進捗が小さい|売買エネルギーを使い切ったので反転する|
|両市場が同方向|共通する向きが観測された|独立した二つの市場の多数決で確信度が倍増した|
|一方が先に動いたように見える|代理時計上では先行している|真の受信時刻で先行し、相手を動かした|

価格が動く理由の候補を記述することと、それを観測データで識別したことは別。先に売買の物語を決めず、観測数・品質除外・期間別の関係・反例を示してから、何を新しい規則へ使えるか判断する。
