# 板の動作の測定

最初に `観測品質.json` と `観測定義.json` を読み、次に `監査.json` を確認する。分析用データは `features.pkl`、再生成コードは `extract.py`。

```powershell
python -X utf8 work/wave_v52/measurement/extract.py
python -X utf8 work/wave_v52/measurement/quality.py
```

Linux でもプロジェクトルートから同じ Python コマンドを使用する。原本と過去成果は読み取り専用。API 呼出しは行わない。

## 何を測るか

売買では買い手と売り手が常に同時に存在する。「買う人が多い」という人数ではなく、どちらが提示価格を受け入れ、どちら側の提示数量が増減し、提示価格がどう動くかを分けて測る。焦り、仕掛け、隠れ注文、同一発注者はデータから直接識別できない。

| 観測 | 数値 | 分かる範囲 |
|---|---|---|
| 提示価格を受け入れた側の代理 | `exec_buy / exec_sell / exec_unknown` | 出来高増分を最後の約定値と直前気配で分類。集約された全約定の方向を確定するものではない |
| 出来高増がない時の提示数量変化 | `noexec_bid_add/remove`, `noexec_ask_add/remove` | 前後とも上位10段に表示された同価格の増減。取消と断定しない |
| 提示価格自体の移動 | `both_up/down`, `quote_ticks`, `spread_widen/narrow` | 過去の価格変化の観測。独立した先読み情報には数えない |
| 減少後の同価格数量回復 | `refill_bid/ask`, `refill_bid/ask_fixed_quote` | 約定時刻差30秒以内の未対応減少を上限に対応。同一主体や約定後補充ではない |
| 距離に応じた提示数量 | `supply_bid/ask_near/far` | 最良値から呼値距離に対する指数重み。厚い板がそのまま残る保証はない |

## 既存特徴との違い

- 従来の `trade_pos/neg` は約定値が直前に上がったか下がったかで出来高を配分するため、価格方向の言い換えを含む。今回は tick-rule を使用せず、未知を残す。
- `quote_move_ticks` は最良気配の値動きそのもの。動いた理由の候補と動いた結果を区別するため、価格対照として使用する。
- 従来の `micro_bias` は定義上 `imb1 / 2` と同一。独立した2つの証拠ではない。
- 距離加重数量、同価格増減、同価格回復は現在・過去価格だけでは一意に決まらない。ただし追加の将来予測力があるとは、測定だけでは言えない。

## 時刻と公開の扱い

`features.pkl` は `(セッション, 銘柄)` をキー、pandas の DataFrame を値にした辞書。`time_s` は公開行の UNIX 秒、`seq` は原本0始まり行番号。`bid/ask/mid/last` は公開行の価格。`source_*` は封印を解いた過去ブロック。`atr` は既存監査済みの過去確定足指標で、数量の抽出や執行側分類には使用しない。

同一 `CurrentPriceTime` の行をまとめ、次の時刻の先頭有効板で初めて過去ブロックを公開する。`source_last_seq < seq` と `source_time_s < time_s` を必須とし、未完の最終ブロックは出力しない。公開行の数量はその過去ブロックの特徴に入らない。

流量は前ブロック末尾から今回ブロック先頭への遷移を含む。これと同区間の価格変化対照には `quote_ticks` を使用する。`source_mid_last - source_mid_first` だと先頭への遷移が抜ける。

`CurrentPriceTime` は約定時刻であり、板の受信時刻ではない。同一時刻内の複数行の実際の時間間隔は不明。30秒回復や60秒集計は約定時刻を時計とする代理測定であり、板の真の更新速度・人間の焦りの速さを測定したとは言わない。

両銘柄が同じ約定時刻を持つ場合の実際の受信順序も不明。両銘柄の比較はそれぞれ公開済みのブロックだけで行い、ミリ秒単位の先回りや通信遅延を再現できたとは扱わない。

## 誤認を避けるための制約

- 出来高欠測・リセットを出来高ゼロと扱わない。
- 価格が表示10段の外へ出た数量を消滅・取消に数えない。
- 不正板を跨ぐ差分を作らず、回復履歴も切る。
- 最良板は正常でも10段に同価格重複・順序不正・欠測がある場合は `depth_*` 列に記録し、深板の数量差分・回復履歴を切る。距離供給平均は10段正常行だけを使う。影響窓を除くには `depth_valid_events == valid_events` を必要とする。
- `refill_*_fixed_quote` は回復を観測した隣接行で両最良気配が同じだった数量。減少から回復までの全期間に値動きがなかったことを意味しない。
- 発注者ID、注文ID、個別約定一覧、約定の売買主導、正確な受信時刻は含まれない。
- 将来価格、将来損益、買い・売りの正解ラベルはこの抽出器に含めない。

## 最良気配の約定置換用キャッシュ

`python -X utf8 work/wave_v52/measurement/quotes.py` で `quotes.pkl` と `気配キャッシュ監査.json` を再生成できる。`quotes.pkl` は同じ `(セッション, 銘柄)` キーに対して、既存の有効原本行と完全に対応する `seq/time_s/bid/ask/mid` の配列を保持する。

用途は、固定した売買注文の同じ約定行で、買いを売り気配、売りを買い気配へ置換して損益の変化を見る感度試験。置換した価格で入口条件・保有判断・損切り時刻を再計算した結果とは異なる。受信遅延、実際の注文待ち、板消費、ミニ・マイクロ固有の気配まで再現したものでもない。

この抽出処理は取引台帳・売買成績を開かず、価格入力と原本・過去の原本ハッシュだけを読む。

`python -X utf8 work/wave_v52/measurement/check_quotes.py` は別抽出経路の公開時気配と全数照合する。

売買台帳の完成後、`python -X utf8 work/wave_v52/measurement/fill_sensitivity.py` で固定注文スケジュールの価格感度を計算する。結果は `約定価格感度.json`、個々の組の入口差・出口差は `約定価格感度_組別.pkl` に保存する。

`original_net` は元の最終約定値、`mid_net` は同じ行の中値、`quote_net` は買ask・売bidへ置換した収支。`entry_delta` と `exit_delta` はそれぞれの置換による損益差で、負数が悪化。`quote_net = mid_net - spread_cost` に分けることで、古い最終約定値の位置の影響とスプレッドの影響を区別する。`spread_cost` は取引手数料ではない。
