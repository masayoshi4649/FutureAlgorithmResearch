# 00057・00067とのSOURCE照合

公開READMEと設計MD、参照された実装だけを読んだ。市場入力、NPZ/cache、金融結果JSON、試行台帳本文は読んでおらず、金融再生・共有ファイル編集も行っていない。

**番号と実装先に注意。** 公開00057の現行READMEは `work/wave_v60/medium` と `grid`、公開00067は `work/wave_v70` を指す。名前が近い `wave_v57/67` のみを見て同一検証と扱わない。

| 部品 | 検証済みの重なり | 今回と同一とはいえない点 |
|---|---|---|
| 段階新規 | 00057の `grid/engine.py::place_levels/entry_condition` は上下に複数段を配置。G4は固定中心から順方向の水準を突破して新規。 | 幅は初値割合とラージ呼値による固定段。待機中の安値から+3/+4/+5、売りは高値から−という**動く極値からの各段追尾新規ではない**。G4は公開済み方向で側を制限し、無予測の両方向独立運転とも異なる。 |
| 利益追尾・部分決済 | 00057のG4には各slotの保護線と利確。00067の `engine.py` には元玉の部分利確と、利益がある保険全体の追尾返済。 | G4は原則slot全量を返し、固定2段幅利確も併用。00067は保険**全体**の利益を条件に反対側全部を返済するので、全UIDのうち費用後利益玉だけを個別に選んで追尾する方式ではない。 |
| 空き枠再利用 | 00057は返済slotの再武装、00067は保険返済後のgrid基準/段数resetと持替後の数量復元を持つ。 | 00057は同じ固定段で新たな不成立観測を要求する。00067は共通初回から3630秒まで次の親を待ち、部分利確後の連続再増玉は公開文書でも未検証とされる。現在値から新しい追尾新規を即再準備する仕様とは同一でない。 |
| 両建てと全玉精算 | 両研究とも両方向の在庫・次有効気配・注文別手数料を扱う。00057には場内型、00067は場内全返済を持つ。 | 00057の週内型を場内型の成績と混同しない。00067は元方向と保険の非対称な運転で、最初から買/売それぞれ独立した追尾枠群を同時運転する方式とは異なる。 |

00067は、利益保険を返済しても元玉や残った保険の損失が消えないこと、同じ売買時刻なら両建てと減らして戻す方法のネット曝露が対応することを設計段階から区別している。これは新方式の否定ではなく、**勝ち玉の多さと、全残玉を返した後の収支を分ける必要**を示す既知の会計上の論点である。

## 意味のある最小対照案

1. **入口の差を一つにする。** 同じ数量・方向別上限・出口で、固定中心からのG4型突破と、待機中極値からの追尾新規を比較する。+3/+4/+5という数値の類似だけで旧グリッドと同一扱いせず、準備・発火・次気配約定を記録する。
2. **回転の差を一つにする。** 同じ追尾新規・利益玉選択・幅を使い、各枠一回限りと、返済後に新規追尾を再準備する方式を比較する。追加の確定利益だけでなく、追加手数料・残損失玉・全玉返済・含み込みDDを含める。これなら空き枠再利用が利益を増やしたのか、回転コストを増やしたのかを分けられる。

いずれも未実施の設計対照であり、旧結果の勝ち条件を選び直したものでも、新方式が無効だという結論でもない。
