# 00120の表示設計（実測前）

金融結果・原市場・実台帳は未読。ここでは表示構成だけを固定する。`合成表示.html` は架空の40場・30政策による私有モックであり、公開しない。

## 最初に見せるもの

1. **結論1文。** 毎場黒字、両商品共通の安定黒字、単なる合計黒字を区別する。未達なら未達と書く。
2. **共通条件上位3候補。** 商品別に後から別設定を選ばず、同じIDを両商品へ適用した比較を示す。各候補の入口・保有・出口を各1文にする。
3. **全40場の損益。** 1行を1場とし、TOPIX／日経それぞれの利益・損失・収支・返済枚数と最終未返済枚数を並べる。手数料は利益損失の内数と明示する。
4. **全30政策の選択欄。** 選択により説明・集計・全40場表を切り替える。表示されない政策も会計JSONへ全数残す。

表上部は各商品別の「黒字／赤字／無取引、全場平均、中央値、最悪、上位3黒字除外、手数料、未返済」を優先する。商品を合算して片方の赤字を隠さない。

## 比較順位の案

00119と同じく、両商品とも費用後合計・中央値・上位3黒字場除外合計が正で未返済がないものを内部比較の資格とする。これはユーザーが新たな必須数値目標を指定した意味ではない。

順位は、資格→弱い方の黒字場数→弱い方の中央値／平均絶対場収支→悪い方の最悪赤字／黒字場平均→ID。円額を商品間で直接比べず、最大合計利益だけで選ばない。上位3は異系統を優先する案とし、最終仕様を根担当と合わせて結果読取前に固定する。資格0の場合も比較上位は表示するが「未達の参考」とする。

## 会計の表示契約

- `sessions[40]`、`specs[30]`、`runs[30×40×2]` を仮契約とする。1場でも欠けたら0補完せず停止する。
- `spec` は少なくとも `id/family/name/description/unit_fraction/trail_units`。HEDGE／NET／FLIP／RECYCLE／HARDの違いを説明する。
- `run` は `session/symbol/method/profit/loss/net/fees/closed_lots/wins/losses/unclosed/max_long/max_short/max_drawdown/min_equity/step` とcurve参照。存在しない列は作らず、確定収支は完結玉の `profit-loss` として表示できる。
- root確定の利益・損失の母集団は**1枚玉ごとの完結net正負**。1注文1枚のlot UIDが対象で、親群へ丸めない。部分返済の利益と残る損失玉を区別し、確定収支と全玉清算時価を別表示する。
- 未返済があれば、確定収支と残玉を含む清算時価を分離し、未返済を0又は勝ちへ補完しない。全場成功・上位3除外等の成功判定へ使わない。
- 観測ラージの刻みを使う `unit` と、実ミニ／マイクロの最小刻みを混同しない。初回mid比例幅と観測刻みへの切上を併記する。
- 利益追尾の判断時は純利でも、次正常BBOで赤字化した返済はその赤字を表示する。判断時の利益を実現利益へ置き換えない。
- 商品別に選んだ条件は共通上位と別欄へ置き、同じ規則が両方で通用した実績へ混ぜない。全40場は既知開発であり、未知成功としない。

## 読取・生成・公開

正式結果は根の完成SHA通知後に一目的で一読し、同bytes私有コピーを保存する。表示源は金融を再実行せず、原市場や注文NPZを勝手に読み直さない。公開表を元小会計へ全数照合し、抜き取り台帳監査は別担当の証跡と区別する。

純合成の生成先と正式生成先を別フォルダにし、生成証跡の `fixture` と入力SHAを必須にする。正式版の上書きや合成版の公開混入を拒否する。README、会計JSON、指定原結果のpath/SHAへの案内を付ける。
