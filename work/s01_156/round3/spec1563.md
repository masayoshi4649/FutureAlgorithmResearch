# 00156 第三巡：再参加玉だけの損失幅を制限する

第二巡で利益回収後の再参加は実現したが、一度も順行しない再参加玉が、旧Sourceの出口まで持たれて大きな損失を生んだ。その箇所だけに20/40/80ptの固定損失判断を追加する。App、第1・2巡のソースと結果は変更しない。

|ID|比較元|再参加玉の損失幅|
|---|---|---:|
|S01/R01/R04|第二巡の保存対照|変更なし|
|L01/L02/L03|R01（利益追尾20pt・再参加20pt）|20/40/80pt|
|L04/L05/L06|R04（利益追尾40pt・再参加20pt）|20/40/80pt|

固定正本は [configs1563.json](configs1563.json) と [spec1563.json](spec1563.json)。同じ26完了Day＋10/27 15:20未満の途中1場、日経mini片側上限10、手数料0、全判断ラージ板のみ。入力は `../inputs156.json` を共有し、追加取得しない。元Sourceの観測・保有・出口、初回玉、通常追撃、利益床、親予算を変更しない。

負番号ticketの各実所有玉だけ、買いは `Bid <= 実建値−幅`、売りは `Ask >= 実建値＋幅` の正常で新鮮な観測で返済目標を作る。未約定新規は保有とみなさない。研究の新規は全量一括約定なので実建値はその約定価格に固定される。実運用の同HoldID分割約定は今回の移植対象ではない。

元Source退出、親床、玉別利益床、既存部分返済目標を先に処理する。その玉に実残数未満の目標があれば理由を上書きしない。担当の未確定注文がある間も新しい局所返済を予約しない。元部分返済が実約定して完了した後、次の観測で残数だけを再判定する。同じ行の通常新規より成立済みの返済を優先する。

局所損失返済は理由 **15631**。発注判断の次正常原行で約定する。建値±幅での約定は保証せず、気配飛びによる超過損失も全額計上する。新規理由15630と区別する。

**局所損失返済で完済した後は再参加armを作らず、その同じ波の回転は一旦終了する。** 通常Sourceからの後続通知は従来どおり扱う。元の利益床が先に成立していた玉は、その理由を保持するので、第二巡どおり全玉保護返済ならarmを作り得る。利益床と局所損失の返済理由が同じ群に混在した場合、群全体を再参加不適格にする。損切り幅の効果には、この再参加停止による後の勝ち・負けの消失も含まれる。

会計・所有ID・親/玉区別・原行採番は第二巡と同じ。対照S01/R01/R04の27場は、第二巡保存結果と全通知・約定・所有玉・親極値・確定/含み会計を場の終了後に照合する。未来結果は判断へ渡さない。買売鏡像、初回玉非対象、旧利益床非継承、元部分/未確定予約優先、利益床優先、次板gap、損切り後armなしを人工検査する。
