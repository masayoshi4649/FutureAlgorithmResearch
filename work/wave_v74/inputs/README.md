# 始値と前保存場参照の準備

最初に `refmetadata.json` を参照してください。次に `prepare_refs.py` で価格の固定順と原本同seq照合を確認できます。

29場・58口座の既存系列を再利用します。原本の有効入力行数は7,523,673です。新しい入力pickleは生成せず、`input_paths.ready` と `input_paths.features` に旧56口座と追加2口座の保存先を記載しています。`rows` に各場の開始・返済期限・排他的末尾・全行長・各特徴配列のshapeがあります。原板から最初・中間・最後の準備済seqを読み、価格・時計・Buy1のbid・Sell1のaskを174点で直接照合しました。58原板の準備時SHAも一致しています。

`references['セッション|銘柄']` に三種類の参照を格納します。

- `ref_open`: 最初の有効準備行で、OpeningPriceTimeが現在場内かつその観測時点以下ならfeed始値を固定。それ以外は原板先頭から最初に現れた場内CurrentPriceを「観測始値」として固定します。採用はfeed24口座・観測34口座です。後に判明したOpeningPriceを遡って使いません。
- `ref_prev`: 直前保存場の監視範囲内で最後に現れた新鮮CurrentPriceです。初日の2口座は欠測のままです。金曜ナイトから月曜デイへの参照4口座は `weekend_gap=true` としています。公式終値と保証された値ではありません。
- `daily_previous_feed`: PreviousCloseとPreviousCloseTimeの参考記録です。日次の前値であり、直前ナイト／デイの最終観測とは別です。ref_prevの欠測補完には使いません。

各refの `value` が参照価格、`known_from_i` が利用開始できる準備済行です。新規判断はその行以降に限ります。今回の始値は全て0行から、前場参照は0行から、欠測は価格None・行−1です。

`source_seq` と `source_time` は実際に価格を観測した原板連番とCurrentPriceTimeです。始値の `source_ready_i` はその原板連番・時計の両方が既知になる最初の準備済行を指します。`source_raw_has_valid_quote` は元seqがその準備済seqと完全一致するかを示し、falseだけでは原板気配自体の無効を証明しません。前場の `source_ready_i` は元seqの完全一致行であり、原板の末端行が準備系列に採用されていない場合はNoneです（47口座）。生のCurrentPriceは同値・無効気配の末端行でも観測できるため、前場参照の元seqが準備系列外になる場合があります。

鮮度の定義は、CurrentPriceが有限正値でCurrentPriceTimeが現在場の開始以上・末尾未満であることです。時計は受信時計ではありません。原本の保存行順に対する因果性を扱い、実通信の鮮度を証明するものではありません。旧準備と同じ監視末尾はデイ15:40／ナイト翌05:55、返済期限はその5分前です。

10/09デイの観測始値はTOPIX4097.5・NK22568370、前場最終観測はTOPIX4104.5・NK22568400です。原板OpeningPriceは前ナイトの値だったため採用していません。末端の広い気配中値も前場約定値の代用にしていません。

本作業は入力と参照の準備のみです。売買損益の閲覧、新しい売買条件の選定、API取得、実注文、原本・過去成果の編集はいずれも行っていません。
