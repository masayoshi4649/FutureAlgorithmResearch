# 独立監査の読む順序

最初に見るファイルは、[主480条件の会計・前半選定](全480条件の会計と前半選定の独立監査.json)と、[追加240条件・再利用48条件の会計・前半選定](純トレール追加240と再利用48の独立監査.json)です。ともに合格です。後半で有望条件を満たす代表が得られたことを意味するものではありません。

1. [参照価格と方向配列](参照基準と全方向配列の独立監査.json)：保存29場・58口座。基準の利用開始、直前保存場、前値欠測の未補完、品質切断を跨がない過去30／60秒、全方向の別計算。
2. [前値の原本末尾照合](前場参照価格の原本末尾による独立監査.json)：全56前値を限定的な後端読込で直接照合。準備配列に元序数がない47口座も価格・時計・原本序数が一致。指紋照合済み総行数を起点に序数を求め、埋込市場IDと同一視しません。
3. [人工経路](人工経路と未来切断の独立監査.json)：2,016条件口座、売買反射2,016件、未来切断・改変12,096件。急変、無効気配、同秒順、連敗待機、収束、全返済、料金を検査。
4. [実保存経路の未来切断](保存実経路の未来切断と改変監査.json)：8固定条件・10口座・3切断位置。未来を切る／価格と品質を変える計480件で、過去注文・決済・休止・清算時価・準備配列が一致。途中末尾を人工返済しません。
5. [主480全会計](全480条件の会計と前半選定の独立監査.json)：27,840口座の注文、全決済、手数料、全行清算曲線、期間商品会計、前半だけの選定を別会計で再構成。
6. [追加240・再利用48全会計](純トレール追加240と再利用48の独立監査.json)：16,704口座を同じ方法で確認。再利用48は重複して再検査しているため、全720条件のユニーク口座数は41,760です。第一段階結果を閲覧した後の追加であり、追加240を見る前の固定と別選定を維持しています。
7. [主案の収束再開](全収束方式の最初再開行独立監査.json)・[追加の収束再開](追加収束方式の最初再開行独立監査.json)：128＋96条件の全収束待機を、方向・品質ごとの区間極値で別計算。最初の成立行／終端まで不成立が記録と一致。
8. [気配差診断](気配差診断の独立照合.json)：主3代表の18期間商品会計。約定行を同じ時点の中値へ置換する差と、広い約定気配の件数を確認。中値で実際に約定できることを示す検査ではありません。

金額は新規・返済の注文単位切捨て手数料を引き、全決済の負けを含めています。TOPIXミニ10枚・NK225マイクロ20枚の各商品を別集計し、円金額を銘柄間で足していません。清算時価には未返済玉を今返済する予定片道料金も含めています。

安全撤収の目安はデイ15:35／ナイト05:50です。その60秒前から全返済を判断し、次の有効気配で仮想約定するため目安超過は発生しています。全返済は保存監視区間終端（15:40／05:55）より前で、欠損中に架空の価格で返済していません。超過件数・最大超過秒・判断から約定の最大秒は各全会計監査に記録しています。

前16／後13は既知データの時間分割です。未知の将来成績の証明とは扱いません。外部API取得・実注文は0。原本は監査で許可された末尾の参照値照合だけを読み、変更していません。

再実行する検査器は [full_accounts.py](full_accounts.py)、[causality.py](causality.py)、[synthetic.py](synthetic.py)、[convergence.py](convergence.py)、[previous_tail.py](previous_tail.py)、[spread.py](spread.py)です。会計の基本部は [independent_account.py](independent_account.py)、清算予定料金の接続部は [adapters.py](adapters.py)です。
