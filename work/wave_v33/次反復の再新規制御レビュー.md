# 仮想の固定ATR玉による再新規制御

**設計・保存資料の読取レビューのみ。新実装、新損益再生、API取得、現在保存物の使用は行っていない。** この案は機械的に実行できる。ただし「仮想玉の全返済まで待つ」だけでは、実玉の方が後まで残った場合と未約定注文の扱いが未定義になる。

## 先に決める必要がある二つの方式

**独立した旧A0経路を基準にする方式**と、**実玉と仮想玉が両方空になるまで仮想側の新規も止める方式**は異なる。後者は実玉の返済時刻によって仮想側も変わり、旧A0の新規経路を維持しない。

今回の目的には前者を主案として提案する。仮想A0注文器は実玉と無関係に、H019・D273の全注文・部分返済・完全返済・5分休止を場初から実行する。実玉を建てる機会は、**仮想側の新規注文を準備する時点**に限定する。その時点で実玉もフラットかつ自身の5分休止終了なら、同じ条件の新規注文を実側にも事前に設置する。

仮想玉の約定を見てから、実側を同じ過去価格で約定させてはいけない。行iの準備を両方へ渡し、各注文は行i+1以降の価格で判定する。両方が同じ行で約定するのは、前行に存在した同条件注文がそれぞれ成立した結果である。ゲートは新規準備にだけ作用し、仮想が先に約定して「保有中」になったことを理由に、既設の対応実注文を遡って消さない。

この主案は単なる「仮想フラット時なら実側が自由に新規準備できる」方式より厳しい。後者は、仮想未約定の途中から実側だけ別の価格・ATRで入り、新規経路の差が残る。両者を混ぜず、実装前にどちらを採るか固定する必要がある。

## 主案の状態規約

| 状況 | 規約 |
|---|---|
| 実玉だけ先に完全返済 | 実側の5分休止を開始。対応仮想玉が残る間は新規禁止。仮想側の全返済・5分休止後の新しい準備機会を待つ。 |
| 仮想玉だけ先に完全返済 | 実玉は既存At出口で継続し、仮想返済だけで強制返済しない。仮想側は独立して5分休止後に運転を続ける。実玉保有中・実側休止中の仮想新規準備は見送る。 |
| 実側が空になった時、仮想側は既に次の玉を保有 | 途中から乗らない。次の仮想完全返済と休止を待つ。見送った機会を後から順に実行しない。 |
| 実側が空になった時、仮想側には見送り済みの未約定 | 同じ未約定の追跡更新途中へ参加しない。取消・期限切れ後の新しい準備機会を待つ。新規準備IDとその更新を区別する。 |
| 部分返済・同時返済・未約定取消 | 部分返済はフラットと扱わず5分時計も開始しない。前行注文の成立を先に処理してから当行判断。共有した新規注文の取消・追跡は元のD273と同じ行順で扱う。 |
| 場末 | 実・仮想の両方を場内で全返済。新規締切は既存どおり。翌セッションへ玉・注文・見送り予約を持ち越さない。 |

Atが大きいと固定A0より追跡幅が広くなり、**仮想側だけ先に閉じる経路もあり得る**。実側が常に先に返済するという前提は置けない。実玉の全利益・全損失・含み損を記帳し、仮想損益を実損益へ足さない。仮想側を実都合で初期化・停止しない。

## 最小比較と反証

主比較はH019だけの3本とする。

1. 旧A0・通常の再新規。
2. 現At・通常の再新規（v33の再現）。
3. 現At・上記の仮想A0による再新規制御。

検査用に「実側もA0＋同じ制御」を加え、1と全台帳・曲線が完全一致することを必須にする。同一入口の仮想注文まで余計に遅らせていたら、基準との対応が崩れている。保有中At、初期A0、初回枚数、部分利確、5分休止、360分期限等を同時変更しない。待機時間や見送り回数を今回の悪化セッションへ合わせて調整しない。

新しい問いは「Atで早期に空いた時間の新規を、元A0の因果的な注文機会へ制約すると、退出変更の全口座成績が改善するか」。主案は未参加の仮想取引も生じ得るため、差額を純粋な出口効果と呼ばない。全13・共通後半7を同じ区間で銘柄別に比較し、収支・利益損失比・含み込みDD・利益返却・新規数・見送り理由・保有枚数分を残す。指定8波は初期6区間の目的参考として分離する。仮想待機で削れた利益も全て含める。

必須反例は、実先返済／仮想先返済／同時返済／部分返済／未約定更新中の実側解禁／価格飛び／同値時刻の複数行／締切での解禁。未来の仮想返済時刻を先に読む実装を防ぐため、価格・ATR・方向の未来削除と改変で、過去の仮想状態・ゲート・実注文が不変であることを検査する。仮想の完成済み取引表を参照して「あと何分待つ」と判断しない。既存の15秒入口遅延・観測価格・追跡ATR5分遅延は補足の単独対照として残せるが、最良の遅延へ差し替えない。

## v33の事後分解の静的確認

[entry_path_analysis.py](entry_path_analysis.py) は、セッション・銘柄・原本新規行・建値・方向・初回枚数・A0が全て一致する組を対応させ、組番号同士は直接対応させていない。共通D273には増玉がなく各組の新規は1件なので、組番号→新規注文の辞書化は今回の範囲で妥当。部分利確を含む組収支を使い、共通／固定だけ／更新だけの集合は排他的かつ全件を覆う。差の合計を元の全期間差へ照合しており、明白な分類不具合は見つからなかった。

TOPIXの共通41組では返済差−194,000円、非共通の新規経路差−344,000円。後者には固定のみ9組と更新のみ54組の両方があり、**再新規禁止で344,000円を回収できるという推定ではない**。共通組も出口変更後の経路から選ばれた部分集合で、全取引に対する無偏な出口効果ではない。資料は既に事後分解と明記しており、この区別は適切。[保存結果](新規経路の事後分解.md)

退出差自体もTOPIX・NK225とも合計で負なので、再新規を抑えれば旧A0を上回るとは現段階で言えない。改善を示すには、上の規約を先に固定して全実口座を再生する必要がある。本レビューはその実験や採用を行っていない。
