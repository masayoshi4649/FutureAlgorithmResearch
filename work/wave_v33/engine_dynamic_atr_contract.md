# 保有中ATRによる追跡幅の更新

`engine_dynamic_atr.run(ready, state, config, detail=False, context=None, width_mode=0, observed_fill=False, trail_atr=None)` を使用する。共通 D273 だけに限定し、旧 `wave_v28/engine_context.py` は変更しない。

| 引数 | 意味 |
|---|---|
| `width_mode=0` | 新規準備時の固定 A0 で追跡幅 `3×A0` を計算 |
| `width_mode=1` | 保有中の公開済み At で追跡幅 `3×At` を計算 |
| `trail_atr=None` | 原本行対応の `ready['atr']` を追跡にも使用 |
| `trail_atr=配列` | 同じ原本行数の1次元浮動小数配列を追跡だけに使用。入口・初期 A0 を変えない |
| `observed_fill=False/True` | 指定値約定／条件成立行の観測価格で全約定。後者は新規・部分利確・損切り・追跡を全て含む |

At は保有開始時に A0 で初期化する。保有中に有限かつ正の公開値があれば採用し、既存 ATR 定義と同じ2呼値以上へ補正する。NaN・無限大・0以下なら最後の有効値を維持する。約定行で新しい有効値がある場合は、その行の価格判断後に追跡計算へ反映する。ATR の計算・公開時刻は呼出し側の責務であり、この注文器は未来行を使わない。

変わるのは追跡の幅だけ。入口0.25A0、初期組の損失基準＝初回枚数×1A0、追跡始動1.5A0、部分利確2A0、初回枚数、5分休止、360分期限、場内返済は同じ。部分返済後も初期組予算を維持するため、残玉1枚当たりの損失余地が広がる既存仕様も変えない。

買いでは高値−3At、売りでは安値＋3At を計算し、既設線を利益方向へ進める場合だけ更新する。ATR拡大で線を後退させない。1.5A0 の順行前には始動しない。現在行では前行までの注文を先に判定し、更新線は次の原本行から有効。更新時に既に通過した線は、過去の指定水準に遡らず次行観測価格で返済する。

返り値の `trades / cycles / curve / orders / stats` は旧列・旧単位のまま。追加の `atr_curve` は `detail=True` で全原本行、Falseでは1行のNaN配列。列名は公開定数 `ATR_COLUMNS` を使用する。

| 診断列 | 意味 |
|---|---|
| `direction` | 当該行の判断後の保有方向。フラットは0 |
| `initial_atr` / `current_atr` / `used_width_atr` | 固定 A0／保持している At／実際に幅へ掛けたATR |
| `extreme` / `trail_active` / `trail_level` | 追跡端点／始動済みか／次行から有効な追跡線 |
| `initial_risk` / `stop_level` | 不変の初期組予算（ポイント×枚数）／次行から有効な損切り線 |
| `pending_initial_atr` | 新規未約定に固定されている A0 |
| `current_atr_source_row` | Atとして最後に採用した入力配列の行。初期A0補完は−1。遅延配列の元時刻は呼出し側の別参照列で確認 |
| `trail_source_row` | 追跡線を最後に利益方向へ更新した行。未始動は−1 |

価格欠測行では保有中Atの入力値だけ更新できるが、価格注文の約定・線の再設置は行わない。旧金銭曲線の欠測行の扱いは変更しない。

合成11件でATR拡縮、始動、同値価格での次行執行、欠測、部分返済、上下反射、未来改変、会計を確認した。固定モードは H019・L000・V000 の既知26入力で旧5結果の全配列に完全一致し、旧保存の収支・利益・損失・DDとも一致した。[監査結果](dynamic_atr_engine_audit.json)。新しい動的ATRの実相場格子・現在保存物はこの監査では使っていない。API取得0。
