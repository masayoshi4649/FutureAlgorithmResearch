# 条件凍結後の現在セッション一回照合

保存データで条件を検証してから、答え合わせとして現在セッションを一回使うという依頼に従う。今回の追加照合は2026年９月23日開始の夜間セッションだけを対象とする。

## 取得前に固定するもの

`live_check.py --prepare` は通信しない。保存５セッションから各群で既に選ばれた条件の重複を除いた集合と、事前固定比較の `T01_追跡0.25ATR_追跡2ATR`、`T06_追跡0.25ATR_追跡2ATR`、`T12_追跡0.25ATR_追跡2ATR` だけを採用する。取得後に条件を増やしたり選び直したりしない。

実行器、転換信号、研究実行コード、生板抽出器、既存の取得補助、今回の取得評価コード、この計画、転換入口の定義、既知５セッション選択、旧取得記録をSHA256で固定する。選択ID・条件辞書・選択した群も記録する。新しい凍結記録は排他的な新規作成とし、上書きしない。

## 一回取得

`--fetch` はすべての凍結ハッシュを照合してから、新しい `work/wave_v9/live/一回取得開始.json` を排他的に作る。既存のv7の取得記録やロックは変更しない。

NK225とTOPIXの生板・１分足・５分足、合計６URLを各１回だけ要求する。全要求に、当日の17:00以上、要求開始直前を分単位で切り下げた共通時刻未満の範囲を指定する。状態APIは呼ばない。自動再試行・リダイレクトを許可しない。一部が失敗しても再取得しない。

４つの足応答について銘柄コード・セッションID・開始終了・応答作成時刻・足の確定・高安・時刻順序を検査する。生板は銘柄名・限月・必要項目・時刻順序を調べ、共通締切以降の時刻があれば拒否する。原応答と変換済み足を保存し、再評価時にも取得・変換時のハッシュを照合する。

## 評価範囲と継続状態

以前確認済みの夜間データは **19:14未満** である。この締切は旧取得記録から読み、今回の凍結記録へ転記する。

売買の再生は17:00から今回の取得上限まで連続して行う。19:14で建玉・注文・トレーリング・休止時間を初期化しない。主評価は、**転換イベントの時刻 `signal_time_s` が19:14以降である取引だけ**とする。以前の転換から生まれた取引は別表へ出し、19:14後に返済された場合でも主評価に混ぜない。

利用する指標・入口・出口・費用・観測遅延は凍結コードのまま。データの差し替えはメモリ内のルート参照を新LIVEへ一時変更するだけで、凍結コードを編集しない。生板特徴と約定監視系列は保存された今回の原本から同じ抽出器で作り直す。

セッション途中の取得締切で強制返済しない。確定済みの利益・損失・収支と、未返済建玉の評価損益を分離する。セッション返済時刻に達した場合の返済規則は通常の実行器に従う。

## 表現と限界

追加分は今回読むまで使用していなかったデータだが、実際には取得前に発生した値動きである。**実時間の前向き運用とは呼ばない**。追加結果を見てから条件を変えない一回照合として報告する。

生板の時刻は受信時刻ではなく最終約定時刻である。２銘柄の同時性と全気配の約定可能性の限界は、保存データの検証と共通である。

## 保存物と再計算

- `現在照合_凍結記録.json`：取得前の固定条件とハッシュ。
- `live/取得記録.json`、`現在照合_取得記録.json`：６要求、上限時刻、変換検査。
- `現在照合_セッション集計.csv`：追加区間の新規転換だけを主評価したv9互換指標。
- `現在照合_既知起源集計.csv`：以前の区間の転換による取引を分離した参考表。
- `現在照合_全取引.json`：両区分を識別できる全取引。
- `現在照合_転換イベント.json`：固定条件の系統に対応する転換イベント。
- `現在照合_監査.json`：原本抽出・イベント作成・評価区分・条件不変の記録。

`--evaluate` は保存済みデータだけを再計算し、通信を一切行わない。`--prepare` と `--fetch` は親の明示した実行でのみ行う。
