# 先物以外を含む候補と、今あるデータで測れる範囲

**オプションは方向以外の「変動の大きさ」「保険料」に賭ける選択肢を増やします。ただし、追加データでも板・IVの受信時計が保存されていないため、複数銘柄の同期売買や所定時刻の場内精算を正しく再生できる状態にはなっていません。** 単一銘柄の原行順だけを使う検証とは区別します。未検証であって、不採算を確認したという意味ではありません。

**TradingVolumeTimeやCurrentPriceTimeがnullであることは、板を無効にする理由にしていません。** 売買が成立していなくても、提示価格・数量・補充・取消しの変化は観測できます。今回のBBO資格はBuy1/Sell1の価格・数量から独立して判定しています。制約は、その有効な板が他銘柄のどの行より前に届いたかを保存資料から確定できないことです。

## 再点検で分かったこと

- 2026年10月7日ナイト～23日ナイトの24場、990原板、約15.91GB。生JSONLとgzipは重複計上せず、現在の生JSONLを参照した。
- 各ファイル最大9位置、計7,438標本。最終約定時計がnullの標本は5,415、当場内の約定時計を持つ標本は1,733。受信時計・共通連番・気配時計・IV計算時計は標本に見つからない。
- 価格時計と出来高時計の両方が同じ5,257標本対のうち、IV等が5,166対、最良気配価格又は数量が5,054対で変化。価格時計でIVや気配を時系列結合すると、後から到着した情報を過去に置くことになる。
- 正常両側気配は5,696標本、そのうち気配差が中値10%以内は4,786標本、50%超は167標本。標本の時間密度は不明であり、約定可能な時間の割合ではない。
- 追加3場も同じ問題が残る。限月は11月。参照先物は12月であり、プット・コール合成値と先物の差を無条件に裁定利益とは扱えない。
- ローカルcontrollerの`future_history_store.go`は受信時刻と連番をメモリに持つが、`future_history_archive.go`の保存処理は`record.payload`だけを書き出す。OPには分足を書き出さず、現在の`op`配下のCSVは0。ローカルコードの確認であり、稼働版との完全一致はここでは検証していない。
- Buy1～Buy10・Sell1～Sell10内を含む全階層のキーを再帰的に調べた。標本内で見つかった時計はCurrentPriceTime・TradingVolumeTime・PreviousCloseTime・OpeningPriceTime・HighPriceTime・LowPriceTimeの6種類だけ。AskTime/BidTimeや各段のTimeは確認できず、各行の受信時計を補うsidecarも見つからなかった。ファイル更新日時は取得・保存の時計なので行ごとの市場時計へ代用しない。

数は全行頻度ではなく限定標本の集計。[保存資格診断](オプション保存資格140.md)、[標本と原位置](オプション保存資格140.json)、[再現コード](options140.py)。[00124の旧オプション調査](../../アルゴリズム調査/00124_追加セッションと日経オプションの検証/README.md)で指摘した問題を、増えたデータと現在の保存形式で再確認した。

## どの組合せにどんな意味があるか

| 候補 | 利益・損失の仕組み | 今回の扱い |
|---|---|---|
| 先物＋逆方向の買いオプション | ロング先物にプット、ショート先物にコールを組み合わせ、急な逆方向への損失を和らげる。保険料が通常日の収益を削る。停止注文の飛び越し対策と方向予測改善は別 | 11月OPと12月先物の基差も残る。場中の保険購入・評価・返済価格の時計が不明なので実損益未検証 |
| 方向を読むデビット・スプレッド | 同限月の近い権利を買い、より遠い同種権利を売る。支払額を抑える代わりに上限利益を設ける。買い側・売り側とも方向を選ぶ根拠は必要 | 優先度は保険型と並ぶ。両脚の価格・約定順が必要。買い脚成立前に売り脚を裸で出す仮定を置かない |
| ロング・ストラドル／ストラングル＋先物デルタ調整 | 上下どちらへ動いても有利になる凸性を買い、動いた後に先物を売買して方向リスクを戻す。変動が小さい間の時間価値減少と気配差が費用 | 「方向を当てず、変動を取る」という意味で別性質。ただし実現変動が購入時の価格へ織り込まれた変動と費用を上回る必要があり、上下動だけで自動黒字にはならない。現在は未検証 |
| 幅を限定したクレジット・スプレッド | 受取保険料を利益源とし、遠い権利を買って満期損失を限定する。静かな時に勝ちやすい代わりに急変で大きく負けやすい | ユーザーが避けたい高勝率・大敗型になり得る。利益率だけで優先しない。最大損失・連続損失と両脚約定が必要で未検証 |
| 前の完了場のIVを、次場の先物枚数・停止幅へ使う | 前場までに知られていた保険価格から、次場の許容数量や幅を決める。方向の答えとして使わない | 現在データで因果的に比較可能な案。直前完了場のみ、先の場へ遡らない、欠測時は基準へ戻す。00124のグリッド型は改善未確認であり、現行の追随型への有効性とは別 |
| 場中IV・歪度・合成先渡しで先物方向を補助 | 先物の価格反応と別の保険需要、満期を揃えたC−Pの価格修正を測る | 保存時計不足のため今回は未測定。単なるC上昇・P下落を独立した強気票に数えない |
| 単一OPの原行順による売買 | 1銘柄の原行順を因果順として、気配・数量の変化で準備し、次の正常原行で売買する。約定時計nullでも観測を捨てない | 壁時計や他市場に依存しないモデルは研究可能。ただし秒指定・多脚同期・所定時刻の場内強制返済は再現できない。終端に残る玉は事後の時価評価として別計上し、実現利益に強制変換しない |

上表の満期における損失限定と、セッション末に市場気配で両脚を返す損失は異なる。場内返済の比較では途中の気配差・片脚約定・返済費用を含める。OP売買手数料は現行の先物料金表に含まれず、既知の先物手数料を代用しない。

日経225オプションの取引単位は価格×1,000円。現データをミニオプションの約定可能性へ転用しない。現行公式仕様では日経225オプションにストラテジー取引はないため、別々の脚を常に同時・同価格で成立させる前提は置けない。[JPX制度概要](https://www.jpx.co.jp/derivatives/products/domestic/225options/01.html)

## 理論から絞る順序

1. **利益後の先物再参加・新しい方向判断を先に比較する。** これは保存データから即座に検証できる。
2. **次に前場IVによる先物のリスク配分を独立対照として比較する。** IVの高さを将来の売り方向や高勝率の直接の証拠にしない。
3. **OP実売買は買い保険／デビット・スプレッド／ロング・ガンマを別々に扱う。** 同じ「損小利大」の言葉でも、保険費用・方向予測・変動予測という違う収益源がある。
4. **時刻を新規保存した期間でOP売買を確認する。** この調査では収集プログラム・稼働環境を変更していない。受信時刻と全商品共通順序、商品・満期・権利価格、原payload、発注／約定／手数料を保持する。旧ファイルの行数から時刻を等間隔に捏造しない。

新規のオプション金融再生0、現在API取得0、実注文0。データ不十分な条件を0円や不採用の損益へ置換しない。

前完了場のコンテキストは[options_context140.json](options_context140.json)へ50場分保存。提供IVが既知20場、同じ末尾で正常気配と幅20%以内も確認できたIVは1場。25Δの両側歪度と同Kストラドルは末尾の適格対が足りず未知のまま。IV上昇幅は2つの直前完了場の資料が両方ある場合だけ計算した。当場以後を改変しても当場までの特徴が不変であることを[因果確認](options_context140_因果確認.json)で確認した。

## 一次資料から言える範囲

IVは価格へ織り込まれた変動を表し、その上昇だけで上下の方向を指定しない。デルタ・ガンマ・セータはそれぞれ異なるリスクの変化を表す。[JPXオプション理論](https://www.jpx.co.jp/ose-toshijuku/column/futures_option/option/03.html)

ガンマは原資産が動いた際のデルタ変化で、一定ではない。買いオプションとデルタ調整を組み合わせても、その凸性を購入する費用の評価が必要になる。[CMEのガンマ解説](https://www.cmegroup.com/education/courses/option-greeks/options-gamma-the-greeks)

プット・コールの関係を使うには、同一権利価格・満期・原資産を揃える。資料中の簡略式を、異なる限月の日経先物とそのまま比較しない。[CMEのプットコールパリティ](https://www.cmegroup.com/education/courses/introduction-to-options/put-call-parity)

以上の一次資料は構造の説明であり、今回の期間の利益や予測率の証拠ではない。2026年10月24日の調査で参照。
