# 共同方向と短期再加速の入力

最初に [metadata.json](metadata.json)、次に [入力十分性.json](入力十分性.json)、最後に [価格窓と直前レンジの因果検査.json](価格窓と直前レンジの因果検査.json) を読みます。損益・将来ラベルは入力準備で参照していません。

共通30場60口座です。既往29場58口座は旧69・71の価格／最良板と旧76の同seqスナップショットを読み取りで再利用します。今回追加された日経10/09ナイトによって相手が揃った最後の1場は、今回の唯一の未見確認場として区別します。追加ナイトの損益は前29場からの設定固定まで計算しません。

追加2口座は `extra_inputs.pkl`、`extra_features.pkl`、`extra_snapshots.pkl` です。旧最良気配フィルタ、旧57の逐次板状態、旧76の10段距離重みを使用しました。追加readyは `seq/time_s/last/session/symbol/start/limit/tick/us_open` のみです。旧ATRや入口familiesは今回未使用なので複製しません。

`grids_delay1.pkl`、`grids_delay5.pkl`、`grids_delay15.pkl` は `session → {grid, markets}`。共通格子は開始300秒後から撤収目安60秒前を含む5秒刻みです。新規の受付は算法側で目安300秒前までに制限します。同時計先頭だけを `time < grid−delay` で採り、参照期限から30秒以内を要求します。共通受信時計は新ナイト原本にも見つからず、実受信順を証明できません。

`markets[symbol]` の素材は次の通りです。

- `current`：価格・気配・Q／距離加重偏り・参照行と古さ。価格の `valid` と板の `q_valid` を区別します。
- `windows[30/60/180/300/600]`：過去の中値変化 `ret_bp`、売買両気配の呼値変化、実観測秒数、総変動、効率。総変動は同時計先頭の中値だけを並べた絶対価格差の合計、効率は絶対始終差÷総変動です。ゼロ分母はNaN。
- `ranges[60/180]`：`old` 以上 `now` 未満の同時計先頭だけの高安。現在の先頭とその同時計後続を含めません。位置は `(現在中値−安値)/(高値−安値)`。0未満や1超は逸脱として残し、値幅ゼロは位置不明です。
- `flow[15/30]`：旧76と同じ最良OFIの窓素材。源泉有効性、OFI有効性、非ゼロイベント件数を別々に持ちます。

窓とレンジは途中のreset・不正板を跨ぎません。QやFの不足を価格窓の必須条件にはしません。`ret_bp` は相対変化×10000、総変動・高安・値幅は現物価格単位、気配／高安距離はラージ呼値数です。実観測秒数は予定窓と異なり得ます。

主5秒遅延の旧29場201,101格子では、両市場の価格窓が有効なのは30/60/180/300/600秒で104,981/86,795/45,227/26,153/8,494格子です。600秒窓は4.2%と少なく、長い窓を条件に足す場合の入力制約になります。新ナイト9,169格子では3,276/2,782/1,454/809/375格子でした。

算法から [prepare.py](prepare.py) の `material(delay=5)` を呼ぶと `ready, book, snapshots, grids, meta` が得られます。[core.py](core.py) の `market_features` と `session_features` は短い準備系列でも再実行できます。

検査では全60口座・遅延3水準の途中切断と未来側改変で54,360配列が厳密一致し、総変動・効率・レンジ6,263件を直接過去配列から検算しました。これは代理時計上の前方参照禁止の検査です。

準備は `python -X utf8 work/wave_v77/inputs/prepare.py`（完成メタ存在時は上書き拒否）、検査は `python -X utf8 work/wave_v77/inputs/check.py`。原本・旧成果の変更、現在API取得、実注文、損益閲覧は0です。
