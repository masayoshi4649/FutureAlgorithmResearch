# 実装前の独立レビュー

`実装前の研究範囲.md` と既存板特徴の公開処理だけを読んだ。v38の売買・採否条件は変更せず、v39の売買損益は計算していない。

残差を新しい入口として検証し、同時区間の値動きを利益に含めず、価格のみ・乱数・相手市場の対照を置く方針は整合する。実装前に以下を数値と処理順まで固定する必要がある。

1. **60秒区間の帰属と確定順。** 既存特徴の `time_s/seq` は公開時点で、`source_time_s/source_last_seq` は素材側である。区間を公開時計の半開区間として定義し、素材時刻で過去区間へ振り戻さない。境界後の最初の原本行で確定する際も、その行まで公開されたものだけを使う。確定後に同秒の後続行から前区間を埋め直してはならない。区間端と同時刻の公開をどちらに入れるか、境界に原本行がない場合の解放時刻も固定する。これは実時間の1分間に発生した全フローではなく、1分間に公開されたブロックの集約である。

2. **分母の実体。** 「先行区間末尾の両側数量」を使うなら、最後に公開されたブロックの平均数量と、最後の有効板の数量を区別する。採用する列と素材行を固定し、分母が欠測・非正・古すぎる場合は無効にする。現在区間末尾の板や後続区間の数量で遡及補正しない。

3. **欠測とラグの連続性。** 区間内に公開がないこと、実測OFIが0であること、継続性リセットを分ける。有効区間の最大公開間隔・末尾の古さ・必要ブロック数を事前固定する。学習の「過去3区間→次区間」は時計上連続する4区間で作り、無効行を落とした後に別区間同士を隣接させない。セッション境界も越えない。

4. **学習と残差尺度。** 予測は現在区間を観測する前の3区間で計算し、区間確定後にだけ実測との差を求める。訓練の目的変数も、そのセッションの完了時点までに公開済みであることを要求する。標準化・ridge強度・ゼロ分散処理・残差尺度下限は過去だけで固定する。訓練内残差尺度は将来混入ではないが小さくなり得るため、未学習区間の誤差尺度や有効標本数を別に記録し、尺度自体の予測精度と取引成績を混同しない。

5. **板の付加価値と参加の違い。** 残差と生OFIでは尺度も発火回数も変わる。過去訓練だけで各閾値を設定し、価格確認・休止・出口・評価開始を揃える。残差だけでなく、予測成分のみ／生OFI／価格のみのどこから改善したか、全発火数・実取引数・保有時間を示す。板通過時刻での符号乱数は活動時間の情報を保持するので、独立の価格入口を残す現在案が必要である。フィルター追加後に残った勝ちだけを比較しない。

6. **相手市場の共通母集団。** 自市場の残差発火を先に固定し、その同じ候補時刻に「追加確認なし／相手残差一致／相手価格一致」を適用する。相手の参照は公開時刻からさらに60秒遅らせ、同値時刻の将来公開行へ進まない。欠測・古さによる不採用と反対方向による不採用を分ける。価格のみの独立機会との比較は、この母集団内比較とは別表にする。

7. **最小売買と棄却条件。** rの確定行、同一原本行で損切りと利確の両方が成立した場合の優先、場末の判断・有効化・真の境界を固定する。「十分な取引数」や最大勝ち除去の単位、乱数seedと再武装、遅延時の判定、両市場の合否を数値化してから再生する。5分／15分反応は区間公開後から測り、場末跨ぎラベルを除外し、重複窓と既知13期間による探索の制限を残す。

以上は未実装部分の契約を具体化する指摘であり、現時点で有効な手法を発見したという判定ではない。

## release_minutes.py の読取確認

親担当の集約実装を追加で確認した。次の接続は因果的に構成されており、読取上の未来参照は見つからなかった。

- 決定行は原本時間が次の分へ進んだ最初の行。公開ブロックの `seq` を決定行へ `searchsorted(..., side='left')` で割り当てるため、その行で既知の公開だけが確定区間へ入る。同じ秒でも後続の原本行で公開されたものは次の決定区間へ送られ、過去の確定値を変更しない。
- 分母は直前決定区間の最後の公開板数量であり、現在区間の末尾数量を使わない。`wave_v8/raw_features.py::release_row` の確認では `bid_qty/ask_qty` は公開行の `current` の数量で、`MEAN_COLUMNS` の対象ではない。先の「平均値と末尾値を取り違える懸念」は、この採用列について解消した。`source_mid_last` は過去ブロック末尾価格、数量・スプレッドは公開行の現在板という違いは説明に残す。
- ラグ行列は現在の `flow` を目的変数とし、過去3つの `flow`、過去1つの価格変化・スプレッドだけを説明変数へ入れる。過去行の有効性と分番号差を同時に確認するので、欠測区間を削除してからラグを接続する処理ではない。

固定前に残すべき具体事項は以下のとおり。

1. 集約対象は厳密な時計半開区間ではなく、**前の決定行の次から今回決定行までに公開されたブロック**である。決定行の到来に揺らぎがあるため、区間長が常に60秒とは限らない。素材時刻の「次の1分OFI」と区別して、決定時刻差・ブロック数も診断へ残す。
2. 現コードの有効条件は公開間隔60秒以下、ブロック公開遅延60秒以下、末尾素材の古さ60秒以下、決定間隔90秒以下、隣接する分番号、連続性リセットなし等である。これらを正式設計へ列挙する。最初の公開ブロックは間隔不明として不適格になることも固定仕様として明記する。
3. `build` の当行 `valid` だけでは直前決定区間の有効性を要求しない。`model_rows` のマスクなら過去3区間まで有効性を要求するので問題を避けられる。価格のみや生OFIの入口を作る際にどの有効マスクを使うかを揃え、無効な前区間を価格変化の起点として使わないことを別途確認する。
4. 原本行・公開行・素材行が対応すること、公開時刻が原本の該当行以前であること、時刻順が単調であることは、入力固定と構造監査へ結ぶ。現関数は公開 `seq` と素材 `source_last_seq` の順を検査する一方、その全対応を関数単体で再確認する設計ではない。

これはコードの読取確認であり、実装全体のprefix・同秒境界・未来改変・上下反射の合格を代替しない。新しい売買再生は行っていない。
