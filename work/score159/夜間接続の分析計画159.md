# 夜間の保存初回玉と支持の校正

夜間再生器の正常終了後に、`Saved.sources[].Initials` の当時の判断を `Events` の初回新規実約定と `Lots` へ接続する。新しい金融売買再生は行わない。接続器は [adapter_night159.py](adapter_night159.py)。実行前に root の終了通知と、終了コード0・参照改変0の証跡を必要とする。

- 初回母集団は元P05/D07の全初回判断。数量候補の採否・収益で選ばない。親IDは前半/後半を含め、同じ `core/1` が時間帯を跨いでも別親とする。
- 全初回玉の実現収支を初回mini枚数と100円/ptで割る。追加玉の損益を初回玉へ混ぜない。返済は所有IDごとに数量・価格から再計算し、保存粗損益へ照合する。
- 既知25夜を主区分、10/26Nightを「既知途中場の完了版確認」として別表示する。21:13まで旧研究で既知なので完全未見と呼ばない。日中のラベルを夜の学習へ入れない。
- 支持帯、5000回の場bootstrap、正則化10、短期変速の速度換算は日中固定計画と同じ。MFE/MAEと最終勝率を別に測り、極値だけから先着率を推定しない。
- 時系列は先行8完了Nightから翌Nightだけを予測する。P0は担当＋前半/後半、P1はP0＋M×T、P2はM/T分離、P3は短期変速・中短期一致も追加。日中から特徴の係数を移さない。10/26完了版の予測は、それより前のNightだけで学習する。
- 自己価格未知は0支持へ潰さず、補助の欠測フラグも保持する。学習期間だけの補完・標準化を行い、同場・将来ラベルを使わない。

## 極値の定義照合

日中の旧保存値は `work/s01_156/analyze156.py:109` で実新規原行を含む範囲を取り、110行で買いBid/売りAskから実建値を引く。新規直後の気配差損をMAEへ含める。初回玉完済後の親の値動きは含めない。

夜間は `work/night159/engine_go/source159.go` の `markSource159` が約定前と各約定後に残玉を測る。同じ定義で新規直後の負の気配差を含む。保存Best/Worstの到達時計は現schemaにないため、値は比較するが到達順や先着率は未測定とする。部分返済後の最高値を初期全量で得られた利益とはしない。

接続の人工検査は時間帯ID分離、上下対称の部分返済、未知支持、途中未約定の分離、次原行、粗損益不整合・新規気配差欠落の検出を確認する。実資料の分析開始は夜間再生の終了通知後。
