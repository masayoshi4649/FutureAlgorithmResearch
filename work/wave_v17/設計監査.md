# 可変建玉の設計監査

既知の保存済み10セッションを使う開発比較である。今回の結果を未読データの検証とは呼ばない。現在セッションの取得は行わない。

## 先に満たす５条件

1. **両建ての利益は建玉操作全体で測る。** 同一銘柄・同限月・同じ価格尺度では、買い枚数から売り枚数を引いた数量が、その後の価格変化による損益を決める。費用ゼロの今回、両建ての価値は「一時的に方向リスクを減らし、再び増やす時点を別々に管理すること」にある。両建てだけで利益が増えるとは扱わない。
2. **カバー利確と主玉含損を足し合わせる。** 全行で「確定損益＋全未決済玉の評価損益」を記録する。全体の損失上限、最大下落、セッション収支はこの合計に対して判定する。カバーの利確だけを勝ちと呼び、主玉の含損を除いた成績を主結論に使わない。
3. **昇格しても約定履歴を変えない。** カバーを主玉へ昇格する際も元の新規価格・時刻・枚数を保持する。以後の追跡幅を測る基準価格は、会計上の新規価格と別に持つ。役割の変更だけで損益は増減しない。旧主玉の損切りは確定損益に残す。
4. **成立行で生まれた新判断は次行から動かす。** 既存注文の成立判定、現在行の情報・極値の更新、次行以降に有効な注文生成の順に処理する。同じ秒の行でも原本行番号で順序を守る。新たな極値で作った追跡注文を、その行でさかのぼって約定させない。事前に置かれた注文は、その条件に到達した現在行で指定価格約定してよい。
5. **同じ入口から部品ごとの効果を調べる。** 初期10単位・同じ初期ストップ幅・同じ信号を固定し、「基準」「順行増玉のみ」「カバーのみ」「カバーと反転」「全部」を同じ幅設定で比較する。初期リスクが同じでも全体リスクは同じとは限らないため、損失予算、最大買い・売り枚数、最大ネット枚数、保有量の時間平均、全体の最大下落を併記する。

## 枚数と評価の数え方

- 買い100単位、売り100単位をそれぞれ上限とする。両側合計は最大200単位。増玉、カバー、反転後の注文が重なっても別々に上限を超えない。
- 「利益玉数／損失玉数」は約定レコード数ではなく決済数量の合計とする。「１単位平均利益／１単位平均損失」は、それぞれ金額を対応する数量で割る。
- 金額の利益損失比は全勝ち金額÷全負け金額。これに加えて、全玉をまとめた一連の運用単位の利益損失比、全体最大下落を示す。利益玉だけを細かく決済しても評価がよく見えすぎない。
- 成績は単位数量、初期損失予算に対する損益比率、元データの倍率を使った参考円で示す。実際のミニ・マイクロ先物の板・約定を再生した成績とは記載しない。
- 初期10単位×１単位当たり１ＡＴＲの損失幅なら、初期損失予算は10ＡＴＲ単位。後から枚数を増やす場合は、共通の全体損失予算の範囲で行う。観測価格の飛びによる予算超過の有無は別途数える。

## 独立会計で照合する式

各売買の買い数量を正、売り数量を負として、売買ごとに現金勘定から「売買数量×約定価格」を引く。現在の総評価額は「現金勘定＋ネット数量×現在価格」。これが脚別の確定・未確定損益合計と全行で一致することを確認する。

価格が観測行を飛び越えても指定価格で約定する前提では、単純な「前行のネット数量×価格差」だけでは比較できない。１行の資産増減には、その行の各約定について「売買数量×（観測価格−約定価格）」も加える。この差を落とすと、理想約定の効果をエンジンの会計不具合と誤認する。

## 小さな価格経路で確かめること

| 場面 | 必要な確認 |
|---|---|
| 買い10を100、売りカバー10を98、その後95 | 全体損益は−20価格単位。主玉−50とカバー＋30を合わせる |
| 上記のカバーだけ95で返済、その後100 | 返済直後の資産は変わらず−20。その後の全体損益は＋30 |
| 上記の主玉だけ95で返済し、売りカバーを主玉へ昇格 | 昇格時の全体損益は−20。売り玉の元約定98を保存。90で全返済なら全体＋30 |
| 追跡ストップに触れた行で反転判断 | 新判断による反転は次行以降。既存ストップと新しい反転を混同しない |
| 一度の大きな順行で複数の増玉段を通過 | 事前に置いた注文だけ当該行で成立。今回の行で追加生成した注文は次行以降 |
| 高値更新後の反落でカバーを建てる | 高値が更新された行より後に条件成立。カバー返済注文も建てた次行以降 |
| カバーを多く利確した後に主玉が大きく逆行 | 全体損失上限で閉じ、利益玉だけの比率に加え全体損失を報告 |
| 買い・売りとも100単位に達した状態 | 追加注文は上限を超えない。反転の一時的な重複を含め各行で検査 |
| セッション終盤の未決済・未成立注文 | 指定返済時刻以降の有効価格で全返済し、新規注文を停止。翌セッションへ残さない |
| 入力を途中で打ち切る | 打切り前の信号・約定・資産が全入力時の同じ範囲と一致 |
