# 00114 固定価格の数量と公表活動後の価格応答を一回測る計画

2026-10-15。rootが新作業`00114_公表活動と表示数量の維持後の価格応答`へ進めるためのSOURCE_ONLY資料。**結果未測定の計画であり、測定結果・新アルゴリズムの有効性・新損益ではない。実装はroot/engine担当へ移り、この資料はSOURCE_ONLYで閉じる。** 既存00113の金融17源を変更しない。数量本体・NPZ・cache・金融・現在APIの読取0で作成した。

## 1. 問いと主評価

同じ最良両気配が続いている間に、公表総出来高が開始時の反対側表示量以上へ増えたとき、**反対側の表示量が初期より減っている場合と、維持/回復している場合で、その後どちらへ先に値直しされるか**を比べる。

仮説は、活動が増えても反対供給が残る状態では、最初の活動proxy方向への継続が減る可能性がある、というもの。異なる/逆の結果ならこの観測上の仮説を否定する。非減少を補充の証明、または自動的な反転シグナルとしない。**主評価は両BBOの同方向1観測T対反対方向1観測Tの先着だけ**。手数料、約定、損益、費用を超える値幅は今回未測定。

観測Tは保存ラージのTOPIX 0.5pt、日経10円。ミニ/マイクロの実商品呼値や到達全量約定を意味しない。1Tを結果から2/4T等へ変更しない。保有時間n分や未来極値による観測点選択も行わない。

## 2. 一つのepisodeを当時だけで構成する

対象は旧33場×2商品、全rawの保存順。各商品で正常な同一`(bid0,ask0)`が連続する一つの区間をepisodeとする。開始row r0でbid0/ask0、両初期Qty、価格時計、原seqを凍結する。テクニカル水準のlabelは今回作らない。

1. **開始行r0の出来高差は加算しない。** 前の価格区間をまたぐ可能性があるため、r0+1からの正常な`volume_delta_observed`を加算する。
2. 最初のknown正増行T0で、Last>=直前askならd=+1、Last<=直前bidならd=−1を一度だけ固定する。これは**Last位置proxy**で、増差全量の方向でも約定枚数でもない。Lastが気配内側/欠測ならd=0の方向不明を凍結し、当該episodeに方向付き観測を作らない。後の都合のよいLastで選び直さない。
3. d=+1ならr0のask Qty、d=−1ならr0のbid QtyをQ0とする。Q0は正で有限。新公表総出来高の累計VがQ0以上へ初回到達した行T1を一度だけ保存する。最初の正増の大きさだけで到達する場合、T0=T1でもよい。
4. T1で反対側`Q*/Q0 < 1`を**減少群**、`>=1`を**判定時の初期比維持/回復群**とする。最小Q/Q0と最初の減少/回復rowも保存するが、主採否には足さない。維持群の中に、一度も初期を割らない例と、割った後回復した例がある。
5. 同じrowでBBO変更とQ0到達が観測されたら、**価格変更によるepisode終了を優先**し、旧価格で耐えたT1達成へ数えない。新episode開始行の当該ΔVも新価格へ持ち越さない。
6. 必要な数量/価格/出来高の不明、原seq断裂、必要clock逆行/resetはepisodeをunknown終了。復旧後の別episodeへ古い数量・方向・Vを継承しない。同価格を後で再訪しても新IDにする。

type0はT0、type1はT1の各初回だけ。episodeごと各type最大1観測。同じepisodeの二つを独立標本に数えない。方向不明、正増なし、Q0未達、価格変更終了、数量未知、出来高未知、clock/seq不正、予定末尾近傍/保存末尾は分母ごとに残す。reset等の重複理由は原flagを残し、排他的な最終終了理由の優先順はcore事前仕様で固定する。

## 3. 主ラベルは判定後の純粋な先着

各観測T0/T1の当行bid=B、ask=Aを固定し、**その次の原rowから**調べる。当行に至る価格変化や数量回復を「後の的中」へ含めない。同じ価格clockでも、後続原seqは別観測として順に扱う。

- 同方向到達：`d×(bid−B)>=1T`かつ`d×(ask−A)>=1T`。
- 反対方向到達：`d×(bid−B)<=−1T`かつ`d×(ask−A)<=−1T`。
- 先に成立した方を先着とする。片方の気配だけの移動や拡幅を、両気配進行へ置換しない。
- 応答phaseで必要なBBO・原seq・価格clockの未知/逆行/不正が先に現れたら**応答unknown打切**。都合のよい次正常行へ飛ばさない。後続の出来高/十段Qtyが不要なphaseでは、その欠測をゼロや価格の勝敗へ変換しない。必要資格はphase別に固定する。
- 原row順で先着を決める。真のイベント発生時刻、受信順、注文到着順ではない。

主集計は`同方向先着/反対先着/unknown打切/末尾未解決`の全件数と、**解決した二先着だけを分母とする率**を併記する。未解決を負け/勝ち/取引0へ補完しない。全観測母数に占める未解決率も必須。

末尾はclockの限界がある。最終価格時計が予定場末−1秒以内なら**予定末尾近傍**、それ以外は**保存末尾打切**として記録する。前者も収録完備の保証ではない。末尾近傍の判定に未来受信時計を捏造しない。

**単純到達との区別：** 一度反対1Tへ先着し、後に同方向1Tへ到達しても、主ラベルを同方向勝ちへ変えない。「最終的に一度でも同方向へ到達」は別の到達評価。今回coreが先着時で打切るなら、その後の到達/最大値は未測とし、到達率を作らない。追加1/4T等の探索はしない。

## 6. 識別できないことと既試行との差

- **全ΔVをLast価格へ配らない。** 同価格での消費も、最初のLast位置proxy方向の数量も不明。Q0以上は「全価格の追加公表活動が初期表示量を超えた」という観測だけ。
- **方向票と枚数を混同しない。** 今回は公表出来高差と実表示Qtyを別量で保存し、旧2票/比率を注文量へ置換しない。
- **非減少は同側補充の証明でない。** `A>=max(0,ΔQ+E_min)`を使えるのは同側消費下限が別証明された場合だけで、本測定はE_minをΔVから捏造しない。同一主体/在庫/焦り/隠れ注文も未同定。
- **field時計は受信時計でない。** VolumeTime>PriceTimeを即未来とせず`known`を使うが、両clockのmaxを受信clockへ合成しない。二市場は各自の原seqで別測定し、同期や先導関係を推定しない。

[00054](../../../アルゴリズム調査/00054_補充監視3手法の実装とセッション損益/README.md)は、同価格の表示減少後80%以上回復などを周期にし、正ΔVを必須にしなかった。減少表示を見せない同時消費/追加を周期にしない。[00055](../../../アルゴリズム調査/00055_補充監視が赤字になった原因/README.md)は、その識別の穴と、入口後の中値や出口を診断した。本測定は**全raw・同両BBO・公表活動Q0到達の初回・その後の純先着**を分ける点が違う。以前の赤字を無効化したり、板読みの有効性を証明する検証ではない。

[数量source契約](../../e01_current_reassessment_20261015/quantity_contract/数量補充と価格応答及び距離別深さのsource契約.md)、共通知見の[入口](../../../アルゴリズム調査/共通/知見台帳/入口.md)・[継続](../../../アルゴリズム調査/共通/知見台帳/継続.md)も参照。公開候補299だけの数量gateゼロ発火を、市場全rawで数量に意味がない証拠としない。一方、今回数量を追加すれば黒字になるとも仮定しない。
