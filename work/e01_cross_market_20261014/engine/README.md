# 十六対照の実行部品

正式16条件の金融再生を一回完了しました。完成会計は `finance/結果.json`、公開資料は `アルゴリズム調査/00104_E01の銘柄差の原因と修正検証` です。同じ仕様・同じ入力は再実行せず、保存結果を再利用してください。以下は実行時の接続記録です。

`catalog.py` の A01〜A10 は同じ旧入口からの出口十対照、B01〜B04 は票の強度二つと出口二つ、C01/C02 は自己又は相手の保存normal両気配端点応答です。旧基準は別保存再利用で、十六新条件へ含めません。

| 接続 | 用途 |
| --- | --- |
| `reuse.values(旧P1台帳, normal長)` | 保存GUの七配列を復元。旧政策の実注文をGUへ流用しない |
| `interface.execute(口座, entry_id, 相手口座)` | 新入口四種類について元紙上の全feedと実枚数・busy・後参加を再生 |
| `interface.prepared(場名, 口座, GU値, finish)` | 原seq/価格時計/実料清算と最初の受理qを確認 |
| `interface.apply(文脈, 条件, 公開採否)` | 固定線又は逐次高水準の初先着で次正常UID返済し場停止 |
| `interface.baseline(旧文脈)` | 旧P1経済を同じ保存GUから確認。新GU再実行なし |

最初の受理q・公開ATR・spreadは将来取消でも保持します。Rはそのq×公開ATR×円倍率、公開費用はq×spread×円倍率と注文別往復floor料です。費用後清算には前親の実現、発動前部分返済、現在保有、支払料、残UID返済料を含みます。後の実枚数又はピークへ線を選び直しません。

途中保護線は当時までの清算高水準だけから更新します。合成返済の注文理由96は高水準走査経路を示し、損失発動は `control.種別=損失予算`、保護発動は `control.種別=利益保全` で区別します。固定線は利益94・損失95です。影GUの場停止後診断は実政策の取引として数えません。

Cの価格応答は保存normal端点の模型です。自己endは公開当行、相手endは価格時計strict過去。比較点は最後normalで、十秒前基準の遅れと相手endの年齢を十五秒以内に限ります。全raw中間経路、物理受信の先後、実ミニ／マイクロ板の待ち順位は未保証です。観測一呼値はラージのTOPIX0.5pt／日経10円で、実商品では二呼値です。

```powershell
# 根が八部品の重複照合と登録を完了してから一回だけ実行

```
