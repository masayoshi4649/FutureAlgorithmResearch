# 生板の一行ずつトレース

追加4場・8原本の **1,116,226行をすべてJSON解析**した。独立した有効板判定で残った **1,109,773行**について、原本行番号・現在価格時刻・現在価格が従来キャッシュと完全一致した。

各原本行で3方式を同時に実行し、**24口座すべての注文・返済が高速再生結果と完全一致**。場末の買い・売り枚数は全口座0だった。原本8件のSHA256も、以前の追加4場調査で固定した値と一致した。

最初に `監査.json` の総数・各場収支、次に `独立確認.json`、必要な場の `logs/*.csv` の順で読む。実行可能コードは `trace.py`。

## 何を一行ずつ渡したか

```python
event = policy.on_tick(now, seq, current_price, published_atr)
```

JSONLは先読みして並べ替えず、ファイルの行順で解析する。同じ価格時刻が連続しても元の行順を保持する。セッション時間外、最良気配不正、ロック板、交差板は既存研究と同じ条件で除外するが、採否は今回のスクリプトが現在JSONから独立に判断する。

価格と時刻は現在のJSON行から取得する。ATRだけは既存の確定5分足・公開遅延処理を経たキャッシュから、**現在の原本行に対応する値1個**を取る。キャッシュ全体を判断器へ渡さない。判断器は未来の価格・板・ATR配列を持たない。ATR抽出自体は以前の因果監査を継承しており、今回独立に再実装したとはしていない。

OCO・両建て・予測なし方向の注文管理を試したトレースであり、板数量から方向を予測する新機構ではない。CSVには最良気配と数量も残し、判断時の市場状態を確認できるようにした。

## どのログを見るか

方式は先頭10場のみで選んだ次の3代表。CSVファイル名は `{手法ID}_{セッション}_{銘柄}.csv`。

|手法ID|簡単な内容|
|---|---|
|`O01_P025_C30_T120_X0`|上下0.25ATRのOCO突破、組終了後30分休止、準備から120分上限|
|`O02_P000_C30_T60_X1`|同時両建て、片脚損切りと時間で狭める追跡、組終了後30分休止|
|`O03_P000_C05_T60_X0`|固定seedで方向を決め、損切りと追跡。組終了後5分休止、60分上限|

例えば、E01の連敗が目立った10月5日ナイトのTOPIXを注文管理3方式で見る場合は以下。

- [OCO](logs/O01_P025_C30_T120_X0_2026-10-05_Night_TOPIX.csv)
- [両建て](logs/O02_P000_C30_T60_X1_2026-10-05_Night_TOPIX.csv)
- [固定seed方向](logs/O03_P000_C05_T60_X0_2026-10-05_Night_TOPIX.csv)

24CSV・15,190記録。注文準備・判断・約定・組状態が変わった行に加えて、各分で最初の有効行の時価を記録した。全ティックをCSVへ重複保存してはいないが、売買判断器自体には全有効行を渡している。

`合計円` は **実現累計＋買い・売り両脚の含み**。両建ての利益脚だけを見る集計ではない。`買保留注文`・`売保留注文` は0=なし、1=新規判断済み、2=返済判断済み。`段階` は0=待機、1=OCO待機、2=新規保留又は保有。`当行約定注文JSON` の列定義は [注文管理の台帳形式](../order_methods/台帳形式.json) を参照する。準備不足期間のATRは `nan` で、新規しない。
