# 原版Ｅ０１と三部品の実行接続

最初に `policy126.py` の `play` と `bind_runtime`、次に `build_last_core126.py`、`原版保持の三部品生成.json` を確認する。`legacy_root` は旧数値源１０２個と小固定設定３個の同bytes写しで、元源は変更していない。原市場の読取と金融実行はこの接続担当では零。

## Last比較の手順

`legacy126.isolated()` 内で `legacy126.runtime()` を一回作る。一場二商品の保存packetを読み、`policy126.bind_runtime(rt, inputs, signals)` で当場の入力と元小設定を注入する。保存特徴の再計算は不要。各条件について `policy126.play(rt, config, ready, feature, market, observed=True)` を呼び、`normalized_summary` で手数料零の返済脚正負と親組正負を別集計する。

`original_features` は元の `new_columns` と `joint_features` を同じ数値関数のまま呼ぶ。原版で無効な追加入口ゲートとＥＭＡ方向停止専用の列は未計算の未知として保存し、必要のない全場１分足再読を省く。今回の全１６条件は原版の `mask=0`、ＥＭＡ早期退出と方向停止は無効に固定する。未知を実測中立や零の根拠に使わない。旧入力資格の混在と追加８場の確定足消費版は `../input_audit` の資料に記録されている。

通常影・出口影・追跡新規・元の半量利確と悪化半減・実組一ＡＴＲ予算・通常影からの五分再開待ちを保持する。手数料零のため、元会計の料金を条件へ加えない。初回数量はＴＯＰＩＸミニ五枚、日経マイクロ十枚。追加も復元も行わない。

新部品は、十分順行後の両市場反対時だけ利益床を上げるＰ、赤字実組後に新アンカーからの両市場進行を確認するＡ、初回実組の固定リスクで場損失を止めるＬ。全て既定無効で、原版の分岐を削除しない。現在行で作った制限解除や返済予約は次行から使い、当行の元予約を遡及取消しない。価格方向の観測はLast、相手は厳密過去で１５秒以内、窓端は指定時刻以前の最新で３０秒以内。

## 価格モデルの区別

このLast比較は発動行のラージ現在値約定であり、実商品のＢＢＯ約定ではない。旧３０場の原版は保存結果を再利用し、同じ金融を再実行しない。追加１１場と新１５条件は親の登録後の担当実行で測る。

`bbo_next` は別段階の次正常原行約定核。元Last影は保存引用し、実建値・実現済み損益・残玉ＢＢＯ清算から予算と三部品を逐次判定する。Lastの価格へＢＢＯを上書きしたり、注文行に未来行の価格を挿入したりしない。こちらの源と人工はLastの固定集合から除外し、別登録と独立監査を必要とする。

## 固定後の扱い

LastのPython源は親の正式登録後に変更しない。人工用ＪＩＴと金融用ＪＩＴは別保存先とし、同じ人工module名のキャッシュを金融へ持ち込まない。入力・実装・約定の不一致を検出した場合は例外で停止し、無取引零円へ補完しない。
