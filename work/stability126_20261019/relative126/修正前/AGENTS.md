# データについて
- 以下3フォルダは同じデータを意味している。
  - book
    - 生オーダーブックデータ
  - candle_1min
    - book を1分足にしたもの
  - candle_5min
    - candle_1min を5分足にしたもの


# 作業について
- `work` は自由に使用して良い。
- `book` `candle_1min` `candle_5min` は読み取り専用

## 調査成果の整理
- 調査成果は作業ごとに `アルゴリズム調査/{5桁0埋め番号}_{内容}` へまとめる。
- 新しい作業には次の未使用番号を付け、過去の作業フォルダを上書きしない。同じ作業の修正はそのフォルダで行う。
- `アルゴリズム調査/index.html` と `README.md` に、最新の作業と各作業の主なHTML・報告書へのリンクを載せる。
- 各作業の `README.md` に、最初に見るファイルと資料の読む順序を明記する。
- 今後作成するHTMLはダークテーマとする。グラフの描画背景・目盛・文字・売買マーカーも暗色背景で読める配色にする。

## 共通知見と試行の重複防止
- 調査の目標・優先順位・損失の具体箇所から改善する手順は `アルゴリズム調査/調査方針.md` を参照する。特定日の大勝ちより各セッションの小〜中利益を優先し、合計損益だけで判定しない。新たな知見は共通の分類別Markdownへ実測値・限界・元調査の出典付きで必ず追記する。
- 調査開始時は `アルゴリズム調査/共通/知見台帳/README.md` と同領域の `入口.md`・`継続.md`・`出口.md`・`売買の工夫.md` を参照する。知見本文の追記・訂正先はこれらのMarkdownとする。試行履歴と照合ツールは `アルゴリズム調査/00101_共通知見台帳と試行重複の確認/試行照合/` に配置する。
- 知見は研究単位ではなく「入口・継続判断・出口・売買の工夫」の法則単位で記録する。当時判定できる条件、測った事象、銘柄別の分子・分母、観測の終点、対象範囲、使える場面、限界、根拠を残す。未測定は未測定とし、到達率と先着率、取引勝率、損失の内訳、比較損益を混同しない。
- 新しい金融再生の前に、入口・途中判断・出口・枚数と配分・費用・約定・対象データ・実装版を記録し、上記 `試行照合/manage.py check --proposal 計画JSON` で照合する。比較元、変更点、再検証理由を `試行照合/data/trials.json` へ登録する。共通領域には知見Markdownだけを置き、旧HTMLや生成データを再配置しない。
- 完全に同じ仕様・入力の保存済み結果は再利用する。独立再検証、新データ、不具合修正には目的と差分を残す。再集計や同値確認を新たな有効性の証拠に数えない。
- 未整理の過去試行は「重複なし」と判定しない。類似する既存レポートを確認してから進め、確認範囲を記録する。これらはユーザーへの追加承認を求める規則ではない。
- 各知見には、その知見を得た調査フォルダの正式名（例：`00099_板の定着と進行失敗の入口検証`）を出典として記し、元のREADME・レポートへリンクする。5桁番号は既存の調査番号であり、知見に独自の5桁番号を新設しない。複数の調査を根拠とする場合はそれぞれ示す。対応する公開調査がない作業資料には番号を捏造せず、その旨を記す。知見本文をJSONやHTMLへ二重管理しない。

# 取りうる注文手法について
| 手法         | APIの`method` | 対象       | 動作                                                                                                               |
| ------------ | ------------- | ---------- | ------------------------------------------------------------------------------------------------------------------ |
| 成行返済     | `market`      | 返済       | 指定建玉を成行で返済する                                                                                           |
| 指値条件     | `limit`       | 新規・返済 | 買いは指定価格以下、売りは指定価格以上で発注する                                                                   |
| 逆指値       | `stop`        | 新規・返済 | 買いは指定価格以上、売りは指定価格以下で発注する                                                                   |
| トレーリング | `trail`       | 新規・返済 | 買いは追跡安値から一定幅の反発、売りは追跡高値から一定幅の反落で発注する                                           |
| IFD          | `ifd`         | 新規→返済  | 新規注文の実約定分に対し、返済条件を１つ設定する                                                                   |
| OCO          | `oco`         | 新規・返済 | 同じ売買方向の２条件を監視し、先に成立した側を発注する。他方の成立時は、先行注文の取消・照合後に残数量を切り替える |
| IFD-OCO      | `ifd_oco`     | 新規→返済  | 新規注文の実約定分に対し、返済用のOCOを設定する                                                                    |

# 今後の検証条件（2026-10-07のユーザー指定）
- 手数料を含める。下表はユーザー提示画像の税込・片道・約定1枚当たりの立会手数料。新規と返済の双方に課金し、1注文の合計額について1円未満を切り捨てる。
- J-NET約定を仮定せず、標準では立会手数料を用いる。売買気配差や約定価格の悪化は、手数料とは別に計上・説明する。

| 商品 | 片道1枚当たりの税込手数料 |
| --- | ---: |
| NK225 | 275円 |
| NK225mini | 38.5円 |
| NK225micro | 11円 |
| TOPIX | 330円 |
| TOPIXmini | 41.8円 |

- セッションを跨ぐ手法も検証対象に含めてよい。ただし週末を跨がない。週内持越し型は金曜ナイト終了前に全返済し、月曜へ残建玉を渡さない。
- 利益玉だけを決済するグリッド・両建ても、損失建玉を含む全建玉の評価損益、手数料、最大保有枚数を記録する。セッション別収支では持越し含み損益の変化を含め、週・全体合計と一致させる。
- データが週の途中で終わる場合、その終端の仮想清算を通常の週末返済と区別して示す。
