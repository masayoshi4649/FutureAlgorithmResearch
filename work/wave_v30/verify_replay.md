# 主探索結果の再利用を検証する

凍結済みの `context_split_runner.py` は変更していない。保存結果が存在すれば即座に再利用する元の分岐を補うため、**今後の再実行は `verify_replay.py --run` から行う。**

今回の初回結果について、全12入口×7管理×26入力＝2,184区間を照合した。B0の実設定は旧D273と両銘柄で全値一致し、他6管理の設定差は方向反転返済・中立時間だけだった。固定設計・探索仕様と全元ファイルSHAも一致した。

保存した36方向集合について、区間集合・型・長さ・方向値域と指紋を確認し、元のv27入口及びv28のC/S方向と全値一致した。全84のセッション明細から期間集計・最低基準を再計算し、12個のsummary、全期間集計、全84の反証予定と照合した。勝敗同値枚数の合算、組収支、上限も確認した。

`result_manifest.json` に固定元と全科学成果のバイトSHAを登録した。進捗表示と後続の反証・乱数・波成果はこの主探索の再利用記録の対象外である。全再利用の前に登録指紋との一致を要求する。実行後も内容を再照合し、全期間gzipの圧縮ヘッダーと候補固定の日時だけの書換えを許す。候補内容・金額・枚数・方向・仕様の変更は拒否する。

「今回の初回再利用0」は親エージェントの空の新規領域からの起動確認に基づく記録である。後日の集計だけから初回の実行履歴を証明したという意味ではない。また、台帳SHAは保存集計間の対応を確認したものであり、ここではエンジン再生による原取引の再計算をしていない。

合成では破損16件を拒否した。正常に再集計できる形に直されていても登録SHAが違えば、runnerを呼ばないことも確認した。記録は `verify_replay_test.json`。

- 登録済み成果の検査のみ：`python -X utf8 work/wave_v30/verify_replay.py`
- 検査後に主探索を再実行：`python -X utf8 work/wave_v30/verify_replay.py --run --workers 12`
- 初回登録は実施済み。`--initialize` の再実行は既存記録があると拒否する。

このガードは結果公開後に追加した完全性検査であり、採用規則・利益順位・凍結実装を変更しない。現在保存データやAPIは参照しない。
