# 注文処理と順位選択の独立レビュー

対象は `hedge.py`、`test_hedge.py`、`hedge_search.py`、`search.py` と、返済順序の比較に必要な `exits.py`。この担当では注文エンジンを編集せず、見つけた不整合は両建て担当へ直接連絡した。追加ＡＰＩ取得、原本フォルダ・v4成果物の変更は行っていない。

## 発見した不整合と修正

既存の両建て脚で「始値が既に利確価格を越えているが、その後同じ足の高安が損切り価格にも達する」場合、当初のコードは損切りを優先していた。

例として買い建値100、損切り95、利確120の次足が始値125・高値130・安値94なら、始値で先に利確条件を満たす。それにもかかわらず95で損切りした扱いになっていた。これは利益を多く見せる不具合ではなく、過度に悲観的で、始値先着を区別する方向方式との比較を歪める不整合だった。

両建て担当が探索計画の凍結前に次の順序へ修正し、買い・売りの回帰試験を追加した。修正後のコードを読み取り確認した。

1. セッション返済時刻なら実在足の始値で返済。
2. 既存脚が始値で損切りを飛び越した場合、不利な始値で返済。
3. 既存脚が始値で利確を飛び越した場合、改善益を加算せず指定利確価格で返済。
4. それ以外で高安が利確・損切りの両方に接触した場合は損切り優先。

修正後に担当が実行した `test_hedge.py` は9件すべて成功し、その後に計画を凍結して全探索を開始している。このレビューでは、その成功後に同じ試験を重複実行していない。

## 両建て処理の確認

|確認項目|コード上の処理|判定|
|---|---|---|
|新規時点の情報|過去に確定している参照価格±1ＡＴＲの買い上限・売り下限に、実在足の始値が同時に収まる場合だけ開始|未来の足高安から都合のよい新規価格を選んでいない|
|同一始値での買い・売り|各方向1枚、同時開始という約定近似|実際の２注文の同時成立を保証するものではない|
|各脚の費用|各脚の粗損益から往復2ティック、感度では4ティックを控除|両建て1組は基本4ティック、感度8ティック。片脚分を省いていない|
|新規と損切りが同じ足|各脚を独立に判定し、両側へ動けば両脚の損切りが計上される|同足損失や時間ゼロの損失を隠していない|
|同足利確・損切り|始値の既知先着を除き損切り優先|未知順序を利益側に固定していない|
|残存脚の追跡|両脚の一方がなくなった後だけ追跡し、確定足で更新した価格は次の実在足から有効|同じ足の新高値・新安値を使って過去の価格へ返済させていない|
|再開|残存脚がある間は新規しない。両脚返済後の待機時間が経過してから次の組を開始|負け脚だけを繰り返し建て直したり、倍掛けしたりしていない|
|期限|終了30分前から新規停止。日中15:35・夜間05:50以後の最初の実在足で返済。末尾に脚が残れば例外|無約定分に仮の返済価格を作らず、次セッションへ持ち越さない|
|乱数|セッション・銘柄と固定種から方向列を生成し、全100種を保存|良かった種だけを選んでいない|

確認範囲では、修正後に利益を過大にする注文順序・費用・再開の実装不整合は見つからなかった。ただし、これは下記の約定近似そのものを正確な実取引にするという意味ではない。

両建ての固定利確・損切りは、各脚の新規に対する返済用ＩＦＤ－ＯＣＯに相当する。買い新規と売り新規の２方向を一つのＯＣＯとして扱っていない。`market` は返済専用であるため、新規は価格条件を満たす始値による近似として明示されている。

## 利益・損失・差引の意味

方向方式の `cell_metrics` は、費用控除後に正となる取引の合計を `profit`、負となる取引の絶対額合計を `loss`、全取引の合計を `net` とする。実行中に全セルで `profit - loss == net` を許容誤差内で検査している。粗利益・粗損失・控除費用も別々に保存するため、費用を再度差し引く必要はない。

両建て方式の `positive_points` は費用控除後の利益合計、`negative_points` は負符号付き損失合計で、両者を足すと `net_points` になる。正符号の損失として表示するための `loss_points = -negative_points`、`profit_points = positive_points` も用意されており、`profit_points - loss_points == net_points` と対応する。

両建ては脚ごとの利益・損失と、２脚の組を合算してから分類した利益組・損失組を分けて保存している。両者は差引収支が同じでも利益合計・損失合計の内訳が異なるため、表で脚と組を混在させない。

ＮＫ２２５の円幅とＴＯＰＩＸの指数ポイントは別単位である。銘柄をまたいだポイントの単純合算は行わず、候補選択では明記されたＡＴＲ単位の得点を使う。

## 順位と分割の確認

`search.py` の方向主候補は、５セッション全ての収支から選ばれる開発上の候補である。指定された波の正解ラベルや全波捕捉数は今回の順位に使っていない。費用を厚くした収支、低調なセッション、決済済みドローダウンによって順位を付ける。

別に保存する分割検証では、各候補のセルを訓練セッションだけに絞ってから `ranking_metrics` を再計算し、その順位で１条件を選ぶ。検証セッションのセルを訓練順位へ混ぜていないことを読み取り確認した。時系列の順番は、9/21日中→9/21夜間→9/22日中→9/22夜間→9/23日中となる。

ただし５セッションは過去の研究や指定例で既知の期間である。分割を行っても、新たな未閲覧データでの検証にはならない。条件集合を考える段階で既知期間の経験が入っているため、全５セッションの最良成績、時系列分割、一セッション除外の成績は区別して示す必要がある。

`eligible` は各銘柄の平均取引回数が１回以上、全セルの最大12回以下等を要求するが、各セッションで必ず１回以上を要求する条件ではない。ゼロ取引のセル数は `zero_cells` として別に保存している。

## 残るモデル上の限界

- 同一始値で２脚が同時に約定するのは仮定である。実際の売買気配差、片脚だけ先に約定する状態、注文の到着・取消遅延、約定数量を直接再現していない。
- ２枚換算コイントスは１枚の結果を２倍して総絶対枚数を揃える。両建てと片建てでは組の終了時刻・再開時刻・回転数が違い得る。価格感応度や証拠金まで等しい比較ではない。
- 100種は同じ５市場セッション上で方向を変えた標本で、100の独立した市場期間ではない。
- 追跡返済は確定一分足ごとの水準更新で、ＡＰＩの各観測ごとの連続トレーリングとは異なる。
- 両建て側の `ambiguous` は「同一足がＳＬ・ＴＰの両水準へ接触した件数」である。始値で先着が分かる場合もこの接触フラグは立つため、「順序不明件数」と呼ばない。返済価格と理由は修正後の既知先着を反映している。
- 順位得点のドローダウンは決済済み損益系列に基づく。保有中の最大含み損や必要証拠金とは別の指標である。

全条件・全乱数種の探索結果そのものが完成した後の件数・取引台帳の総突合は、ここに記載した読み取りレビューとは別の最終確認になる。
