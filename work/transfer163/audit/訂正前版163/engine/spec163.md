# 00163 隔離再生器の固定仕様

正式な登録仕様・段階許可の指紋は `../計画163.md`。この文書は実装上の数量・所有・時計の定義を補う。新金融実行前に全源・本書・条件を固定する。App、過去研究、原資料は変更しない。

## 対象と比較

`../inputs163.json` の既知完了53場（27 Day、26 Night）。前 train 30＋validation 10を実行してから昼夜各1案を固定し、test 13を別許可で全10案実行する。完全未見の検証とは呼ばない。

候補は `configs163.json` の B00/C50/D40/D80/G40/G80/R40/R80/E40/E80だけ。B00は日中S01、米国前P05、後半D07を原Sourceの全通知量で運転する。C50は全通知量の厳密半分。Dは40/80円逆行で一度半量、Gは同逆行に短期逆進行も要求、RはGの後の不利極値から40円回復で一度復元、EはGの後の初回中値回復で一度復元する。

元Sourceは `work/night159/engine_go` の生産コード・外部規則を複製し、独立逐次運転する。政策の損益・残量をSourceへ渡さない。Source既存特徴にはTOPIXがあるが、新設数量層はラージ自己中値だけを使う。旧支持M/TやbpのOwn5/Own15を円幅へ流用しない。

## 原行と約定

旧159の読取・採番を維持する。CurrentPriceTimeを価格時計代理として使用し、独立受信時計は捏造しない。有限正値Lastと読める時計を持つ原行を市場別に採番し、時計巻戻りを除き、二市場を安定結合する。不正BBOもSourceの準備解除へ渡す。約定は有限 `0 < Bid < Ask` かつQuoteOKの、判断原行より後の最初の正常原行。時計が同じでも後続物理原行なら約定可能で、異常板は約定しない。

数量はmicro単位、1円幅×1micro=10円、手数料0。元1miniをB00は10micro、C50は5microとする。買Ask・売Bidで新規も返済も次板約定する。元10mini相当の方向別上限100microに実玉と発注済新規を含める。返済予約だけでは枠を空けない。

各正常行は当行BBOで既保有を評価→前行以前の予約を約定→同じBBOで新在庫を評価する。返済行を保有極値へ含め、保有秒を新玉へ遡及させない。場内最低時価、初期0を含む最大DD、全玉の買Bid/売Ask清算値を保存する。

## SourceIDと数量変更

親キーは `phase/owner/campaign`。元Sourceの初回約定行中値を親の固定AnchorMidにし、追加や復元で更新しない。同親の後続newの方向が違えば不整合として停止する。

SourceMiniは元通知の新規・返済だけで更新する。各SourceIDの現在残mini数に、通常・復元後は10、縮小中・C50は5を掛けた量を実残量の目標とする。元部分返済では通知をSourceMiniへ先に反映し、同IDの実残数から既予約返済を控除した自由数量が新目標を超える分だけ返す。同IDの複数実約定玉は古い順で返す。親の別SourceIDへ数量を流用しない。

例：元5mini→実50micro→独自半量化して25→元2mini部分返済で目標15へ、実10を返す。復元は生存中の元3miniに対して実15から30へ15だけ追加する。終了した元IDの目標は0のまま。これは各IDの残数を直接写す模型で、親合算や昔の初回比率から新しい初回量を作らない。

同じcampaignで実玉0になった後、元Sourceが別の新SourceIDを通知すれば管理を再開する。元IDを復活させることとは区別する。同親のAnchorMidと既消費の減枚・復元権は保持する。

固定順序は **元返済→元新規→政策減枚→政策復元**。同親に予約がある間は政策を出さない。元Source自体の通知順は保存し、政策台帳だけ同原行の返済を先にする。B00同値は全通知IDの判断/約定原行、時計、価格、数量、Targets、収支を照合する。同一原行内の通知順が並び替わる場合は同値判定でID対応する。C50はB00とイベント順も一致し、配賦・収支・場内最低・DDが厳密半分になることを確認する。

減枚・復元は各親1回、実際に数量がある発注確定時に権利消費。判断だけ成立し数量0なら消費しない。復元はSourceIDごとの現在残mini×10から、同ID実玉と新規予約を引く。返済予約で復元余地を先取りしない。元Source全終了・米国静観帯・場末返済期限以後は復元しない。

## 短期円幅と回復

現在をt、目標窓をh=5/15秒とする。原行prefix内の最後の正常板で `時刻 <= t−h` を選ぶ。端点遅れ `(t−h)−端点時刻 <= 1秒` の場合だけ、`(現在mid−過去mid)×h/(t−過去時刻)` を計算する。正確なh秒実変化とは区別し、実経過・端点時計・遅れ・未換算幅も保存する。不正板の価格は選ばない。過去両端正常なら途中の不正だけで全窓を無効にせず、連続経路の完全観測を保証しない。

G減枚は方向符号dに対し `d×Own15 <= −20` かつ `d×Own5 <= 0`。R/E復元は両方 `>0`。未知は0へ置換せず見送り、親別に5秒端不足/15秒端不足/閾値不一致の判定原行数と初回未知の入力を残す。これは見送った注文数ではない。

Rの極値は実減枚完了行のmidを最初とし、その後全正常原行で買は最安、売は最高を追う。短期が未知でも極値は更新する。減枚判断以前の値は使わない。復元は減枚fillより後の原行でだけ許す。Eはその極値を回復条件に使わず、固定初回midまで戻ることを要求する。

## 時間枠と終了

元15:35/05:50の返済期限を保持する。Night前半P05のUS−15分終了、US＋15分以降に前半Sourceの全返済・予約解消を確認して新D07を作る。指標は継続、後半Session.Startは元NightStartの159/App仕様。各政策の旧SourceIDが終われば全実玉を返し、別phaseは別親ID。00162の場末既知板proxyは採用しない。データ終端で未返済・未約定が残れば成功保存せずエラーにする。

## 出力と再現

1場JSONは `scene/cases/sources/transitions/exact_checks/half_checks/raw_files_checked`。casesは `config/actual/parents/decisions/counts/observation_end/max_reserved_long/max_reserved_short`。actualは全Events、Targets、Pieces、Lots、親実現損益、最悪時価・DD断面を持つ。parentsはSourceMini・固定mid・減枚/復元権・原行・ExtremeMid・Diagnosticsを持つ。減枚/復元の発注根拠はdecisionsへ保存する。

原資料六ファイルのパス集合と内容SHAを各場読取前後で照合する。登録源・入力・条件・公式計画・許可・凍結のSHAを前後確認する。全40/13場成功後だけ `再生完了163_{stage}.json` を保存する。既存結果は上書きしない。

```powershell
# engine を作業ディレクトリとして、登録と前半許可が作成された後だけ実行する。
go run . -manifest ../inputs163.json -configs configs163.json -spec ../計画163.md -registration ../train_validation_許可163.json -stage train_validation -out ../results/train_validation -workers 8
# 前40の選択凍結と後半許可が作成された後だけ実行する。
go run . -manifest ../inputs163.json -configs configs163.json -spec ../計画163.md -registration ../locked_test_許可163.json -stage locked_test -freeze ../results/selection_frozen163.json -out ../results/locked_test -workers 8
```

共有人工は `go test . -count=1`。コピーに含まれる旧internal配下の一部テストはAppの未同梱config/confを参照するため、この隔離器の正式な人工検査対象へ含めない。生産コードは旧源のまま、独立監査コピーでは本体S01/P05/D07の予約→約定→返済通知も接続検査する。
