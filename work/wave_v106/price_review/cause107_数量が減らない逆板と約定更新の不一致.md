# 次に調べる一部品：数量が減らない逆板と約定更新の不一致

状態は**未測定の仮説**。この文書では、新しい実装・金融再生・保存原行の読み出し・API取得を行っていない。知見台帳の既測法則としては追記しない。

## 提案

**買いの取引更新が同じ売気配へ何度も当たるのに、売板の表示量が減らず、買気配も上がらないなら、その場で新たに買わない。売りは対称。**

取引更新の方向が強いことと、価格を実際に動かせたことは違う。表示された逆板を克服できない間は、同じ方向を追う根拠が弱いという仮説である。真の補充、同一主体、攻撃注文の数量を確認したという意味ではない。

検証は入口の見送り部品一つに限定する。途中返済・反転・枚数・利確幅・損失枠・停止後の再参加ルールを同時に変更しない。

## この部品を先に調べる理由

- 狭い損失枠では、回復する元の勝ちを切ってしまった。E01の損失2・4呼値の12比較は、両商品とも全条件が合計赤字だった。
- 反対方向票と損失4呼値の組合せでも、7〜11秒後に切った玉が約1分で回復する例があった。逆方向の更新そのものも通常の押し戻りに現れる。
- 取引更新を入口で肯定する方式でも、同方向の6票・釣合い0.333を伴った負けが残った。票の多さだけを要求しても、逆板を越えたかは分からない。
- 既存の数量部品は、主として「表示が減った後に増える」ことを測っている。**取引更新が続くのに一度も表示が減らない枝**は、既存の入口の減少条件から落ちることが明記されている。

## 機械的な定義案

以下は結果を見る前に固定する一つの定義。2票は既存W60門の最小票数を引き継ぎ、多数の回数・数量比・期間を探索しない。

1. E01が新規を公開する自己原行を `i`、注文方向を `s` とする。買いは `s=+1`、売りは `s=-1`。対象は当該原行以下だけ。
2. 既存 `votes.measure` の60代理秒窓が既知で、方向票が2票以上ある場合だけ、この部品の判定対象にする。欠測・価格時計逆行・原連番断裂・出来高資格不明は吸収なしに補完しない。
3. 買いの反対最良価格はask、売りはbidとする。窓内の末尾で、この価格 `p` が現在まで同値である連続区間を取る。区間開始の正常原行を `e`、その反対最良表示数量を `Q0` とする。途中で価格が変わった古い区間は引き継がない。
4. `e` の次原行から `i` まで、全原行の両気配・最良数量が正常で連番が連続し、反対最良価格が `p`、反対側数量が常に `Q0` 以上であることを要求する。初期最良数量が0又は不明なら判定未知。
5. 同区間に、利用可能な正の出来高更新と `Last=p`、かつLast対直前BBOの方向票が `s` になる原行が2回以上あることを要求する。出来高差の全量を買い又は売りの数量へ配賦しない。同じ価格時計の別原行は、公開済みの自己原行順だけで数える。
6. 区間開始から現在まで、支持側最良気配が一度も方向 `s` へ進んでいないことを要求する。買いなら全bidが `bid[e]` 以下、売りなら全askが `ask[e]` 以上。1呼値でも支持が進めば、この非進行の仮説は不成立とする。
7. 上記が全て既知かつ成立した公開候補だけ見送る。未知は別記録とし、この部品だけでは新たな見送りにしない。入口予約後の次原行を後から使って当時の予約を取り消さない。

この定義の「数量非減少」は、隠れた注文の完全補充を同定する条件ではない。単に、記録された全更新で減少を観測できなかった条件である。少量の取引・反復した最終値・集約更新・取消と追加の相殺でも成立し得る。

部品を付ける比較元は、rootが現在固定している **W60_KNOWN_VETO_D0_P1L8** とする案。まだ金融結果を知らない段階の指定であり、同条件の成績を見て比較元を選ばない。rootが別の比較元を採用する場合も、今回の原行診断より前に固定する必要がある。

## 検証の順序

1. **非金融の可用性を先に固定する。** 上の一述語・窓・情報資格と、対象の全紙上新規公開行を保存する。全33場・両商品を一回ずつ読んで、成立・不成立・未知、原連番、同価格区間開始、票接触の原行、数量最小と初期量、支持気配最大進行を記録する。原本を再読・API再取得しない。
2. 原行不足・該当0・全て数量不明なら、金融前にその可用性結果を残す。未知を真偽へ埋めて金融を開始しない。
3. 同じ定義を途中で切った接頭にも適用して一致させる。人工で売買反射、同時計後行の未公表、最良価格変更、数量一瞬減少、支持一瞬進行、古いLast、出来高reset、相手市場を使わないことを反証する。
4. 元の全実入口で、成立する勝ち・負け・金額を分ける。この分類は有効性の証明ではなく、見送る根拠が損失を識別し得るかを見る材料とする。赤字3件だけで条件を決めない。
5. rootが8部品・入力指紋・実装指紋を登録後、対照と見送り版の2政策だけを全33場へ金融再生する。入口が消えた後の再参加、費用、次BBO、利益停止、損失停止を全て再実行する。単に古い負けだけを削除しない。
6. 銘柄別の全33利益・損失・収支、各場中央値・活動数・赤字頻度・最悪損失、金額利益割合、利益上位3場除外、前半/後半、買い/売りを示す。差は避けた損失・失った利益・共通入口の出口変化・新たな入口に分ける。

この順序で、**どの当時観測でどの負けを避けたか、どの勝ちも避けたか、後の参加で何が起きたか**を同じ部品の単位で確かめる。

## 入力と未測定の限界

必要入力は既存44列派生の自己 `raw_seq / price_time_s / bid / ask / bid_qty / ask_qty / last / volume_delta / volume_delta_usable / volume_reset_reason`、最良板の資格 `best_quantity_valid / price_row_valid / price_transition_valid`、E01保存feedとnormal対応、既存料金・執行・静観設定。追加の外部入力は不要だが、最良数量の記録資格を事前確認する。候補原行の映射を推測しない。

### 既存のKNOWN_VETOへの最小接続

`e01_known_veto/policy.py` は公開行だけに `known && direction_votes>=2 && balance>−0.25` を要求する。既存の `e01_trade_gate/prepare.py` は保存feedの新規公開行 `feed[:,7]==1` に対し、normal行 `entry[0]` を `mapping=execution_to_raw_index` で元の原行へ対応させ、票の原行・価格時計・Last・bid・askを全件一致させている。この対応と既存の票はそのまま用いる。

追加する最小要素は、**公開行より前の同価格区間と、その区間の最良数量・支持価格・既存方向票の原行**だけである。新たな期間、数量割合、OFI、影取引、相手条件を加えない。

- 現在のE01票準備cacheには `mapping` と公開行の票要約はあるが、`bid_qty / ask_qty` や、各票が当たった価格の時系列は入っていない。公開時の「6票」という要約だけから反復接触を再構成してはいけない。
- 最良数量・資格・原行方向を追加測定するには、既存NPZを別目的で一回読む新しい非金融準備が必要。読取前に対象33場、66入力指紋、追加する列、公開候補の元feed指紋を固定する。旧準備cacheを上書きしない。
- 新判定のnormal公開行 `r` で、`raw_seq[mapping[r]] == record.seq[r]`、価格時計・Last・bid・ask一致を再確認する。判定終点は `mapping[r]` まで。同じ価格時計のそれより後の原行を拾わない。
- 基準maskを先に計算し、基準が許可した公開行にだけ、追加述語が**既知かつ成立**なら拒否理由を別コードで付ける。基準の未知・2票未満・強逆票の拒否理由は上書きしない。追加数量が未知なら、その新部品は許可／拒否を変えず、未知理由を別に保存する。
- `feed` の親・部分返済・後続公開を削らず、従来どおり影状態は全順で運転する。実玉busy・利益停止・損失停止は元エンジンが処理する。新しく選別した公開候補を「実エントリー数」と数えない。
- 旧normalの執行行資格は変更しない。追加数量の `price_row_valid / price_transition_valid` は、この述語を既知にできるかだけへ使う。執行行を新資格で除外すると、入口部品以外の約定も変わるため別仕様になる。

**固定する閾値は、既存の60代理秒、反復2回、同価格の差0、数量非減少（初期量の1倍以上）、支持進行0。** 数量が少しでも減った区間、支持が一度でも方向へ進んだ区間を、後で戻ったから成立にしない。割合の成績を見て緩めたり厳しくしたりしない。

相手の同時刻情報はこの部品に加えない。同じ最良価格の反復接触を単独で検証してからであり、二市場受信時計が未保存という問題も増やさない。入力はラージ板で、実ミニ・マイクロの待ち順位・真の約定方向・注文主体・板受信時刻は不明。窓は価格時計の代理であり、実時間の60秒とは証明されていない。

仮説が成立しても、次の注文で正の期待値が得られる保証はない。売板の維持は、これから崩れる直前にも起きる。今回の部品は逆張り方向を新たに出すものでもなく、損小利大や金額80%達成はまだ計算していない。
