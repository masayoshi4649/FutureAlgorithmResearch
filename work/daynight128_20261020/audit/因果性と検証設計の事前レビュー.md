# 00128 の因果性と検証設計

本資料は金融再生前の独立確認。新しい売買損益は計算していない。

## 保存入力の契約

- `inputs` は原行順を保持する。`seq` は厳密増加、`time_s` は非減少。価格時計の同秒内に複数行がある。価格時計は実受信時計ではない。
- `quotes` の `seq` と `time_s` は `inputs` と完全一致する。正常気配は有限かつ `0 < bid < ask` で元の `quote_valid` も満たす。買いは ask、売りは bid。ラージ気配をミニ／マイクロの代理とする限界がある。
- `markets` の十二列は、自Last、相手Last、自ATR、相手ATR、自30秒差、自120秒差、相手30秒差、相手120秒差、相手価格時計、自30秒窓端、相手30秒窓端、現在値の資格。
- 相手は `peer_time < own_time` の最新行で、15秒以内。両市場の同時刻行は参照しない。
- 30／120秒差は、指定時刻以前の窓端が目標から30秒以内の場合に限り有効。有限の公開ATRで正規化する。`current_known=1` だけでは短期差の有効性を保証しない。使う列は個別に有限確認する。
- `features.columns` は既存の十列信号。先頭は入口方向、B00 と B01 の方向・公開元行・有効列が続く。新しい板補充の実数値ではない。
- `gates` は既存の G 条件。確定一分足の開始から120秒で公開、相手は追加60秒遅延し、EMA15／60の差と長期傾きで入口を確認する。`markets` と公開遅延が異なる。
- Day の予定清算は15:35、Nightは05:50。保存入力はそれぞれ15:40／05:55直前まである。次正常原行での全返済に必要な末尾を確保する。

根拠：00126 の `engine/policy126.py`、`input_audit/prepare126.py`、`rearm126/adapter126.py`、`engine/bbo_next/core126.py`、追加二場の `run_update126.py` と保存 packet。

## 過去だけで計算できる候補特徴

1. 自己と相手の一定実時間差分、過去経路長に対する純進行幅、過去高安帯への位置。価格更新回数を時間平均の代わりに使うと活発時の比重が増えるため、実時間窓を固定する。
2. 過去だけで固定した高安帯の外に出た後、元の帯内へ戻ったこと。反対方向の新規は帯内復帰を観測してから予約する。
3. 帯外での滞在と相手の同方向進行。ブレイク当行の高値を事前の上限へ混ぜず、更新前の帯を参照する。
4. 正常気配の幅、Lastとの乖離、買いなら実際の返済bid・売りなら返済askで測る順行。方向予測と実約定の初期不利を分ける。
5. B00／B01の既存の公開済み反対信号。公開元行と情報鮮度を維持し、未知・古い状態を中立や反対と決めつけない。

夜間の候補思想は、往復帯への復帰を待つ反発型、両市場の帯外定着を待つ追従型、その二つを当時状態で切り替える型。夜間の赤字だけから「薄商い」「補充」「市場参加者の焦り」が原因と断定できない。これらは必要な観測値を別途用意し測るまで未証明。

## 比較と選定

- 既存43場は何度も調査した既知標本。今回前後半へ分けても未知データの検証にはならない。
- 固定候補群、共通の選定順序、商品別の集計、使う前半範囲を金融前に固定する。
- 前半で選んだ昼候補と夜候補を後半へそのまま適用し、後半を見て第一候補を選び直さない。
- 後半で不調ならその不調を残し、変更は次の開発ラウンドとして別候補と明示する。全既知データでの最適化を新たな成功証拠へ数えない。
- 週別、上昇／下落、上位利益場除外は採点だけ。終値による上昇日ラベルを当日の入口へ渡さない。
- 昼夜それぞれ、TOPIXと日経で負け場数・中央値・平均黒字対平均赤字・最大赤字・参加場数を確認する。合算円額で日経の不調を隠さない。
- 費用は注文ごとに円未満切捨て。TOPIXミニ片道41.8円、日経マイクロ11円。固定初回5枚／10枚と上限10枚／20枚を区別する。

## 新エンジンの独立人工確認項目

- 未来の価格／ATR／相手データを変えても、それ以前の特徴・判断・約定は不変。
- 同秒末尾の毒値、相手の同時計毒値、古い相手、NaNを使わない。
- 予約は行 i の判断後、最初の正常な原行 j > i で約定。約定行の気配が悪化した結果だけを見て新規を遡及取消しない。
- 価格の鏡映と売買交換で方向に依存しない結果になる。ただし実際の入力値の呼値丸めを伴う場合は差を説明する。
- 損切り・追尾は実約定建値と返済可能側気配を基準にする。買いask／売りbidの即時不利を消さない。
- ATRによる初期リスクを固定するなら、保有中にATRが増えて損切りが広がらない。追尾床も一度上げたら下げない。
- スプレッド拡大、飛び値、途中欠測、予定終了前の最終注文、清算時の正常気配待ち、再参加待機、反転注文を人工で確認する。
- 全新規数量＝全返済数量、片方向上限、全返済、FIFOの独立損益、注文料金の合計、全行時価を照合する。
- 特徴の接頭一致と金融の接頭一致を区別する。短縮入力の終端強制清算だけが増えた場合、終端前の予約／約定の不変性で確認する。
