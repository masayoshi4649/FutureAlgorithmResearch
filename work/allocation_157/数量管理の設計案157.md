# 00157 数量管理・カバー・支持崩壊を分ける設計案

実装・金融再生前の案。入口の当たり外れと、数量の選び方と、両建てという保有形式を一斉に変えない。まずS01の独立仮想3担当から当時の親・方向を受け取り、その上に実数量管理器を一つ置く案を推奨する。元5/3/2枠は比較元に残すが、新案の初回・追加の固定枚数にはしない。

## 比較単位と旧S01

- 単位はmicro1枚相当＝mini0.1枚、1pt当たり10円。片方向100単位＝mini10枚まで、予約を含む。両方向最大合計200単位はあり得るので、差引数量とは別に報告する。
- 元S01の厳密な同額対照は、判断・実約定の数量と返済配賦をすべて10倍し、残1miniも10単位にする。単に既存S01へCap=100を渡すと残玉1microや整数丸めが変わり、同額対照にならない。
- 新数量政策を10単位刻み／1単位刻みの両方で動かし、微細化の効果を分離する。初回を必ず1枚・5枚・上限の半分にする指定ではない。
- ラージ気配で判断・次正常BBO約定、手数料0の同一模型。実microの約定しやすさを証明する模型ではない。

## 一つの数量管理器で行うこと

初回目標は例として `q目標=floor(100×元方向支持M×同方向短期支持T)` を共同上限へ配分する。0も100も取り得る。複数担当の希望が重なったら同一スコアと元親のリスク残高で共有枠を配分し、先に5枚を確保する固定枠をなくす。これは設計例で、式と閾値は登録前に確定する。

|局面|数量の扱い|
|初回|当時の支持から目標数量へ。必ず少量から、必ず半分から、とはしない|
|順行追加|支持目標が増え、直前の同方向実約定より新しい返済側気配が有利になった場合だけ差分を足す。旧MAの傾きだけで高値へ枚数を集中させない|
|セーブ|短期反対支持が増えれば元方向の差引数量を減らす。利益の有無だけで判断を止めない|
|逆行追加|損失額や平均建値を下げることを理由にしない。元方向Mが維持され、逆行後の新極値から回復し、反対支持が弱まった場合だけ目標まで追加。連続同方向新規の価格間隔・回数・総リスクで制限|
|カバー|元方向Mが残り短期反対Tが強い時だけ反対数量を作る。強さによって元玉を超える反対数量も制度上可能だが、片側上限と総リスクを超えない|
|カバー解除|元方向の短期支持が回復すれば減らす。逆玉が赤字なら返せない、という条件にはしない|
|支持崩壊|長短両方が元方向を否定すれば、元玉を損益に関係なく閉じる。利益カバーだけ返して大きな負け元玉を放置しない|

間隔は価格と状態の両方で決める。例えば新しい価格帯への順行・逆行後の回復を要求し、同じ価格・同じ支持のまま毎原行1単位ずつ補充しない。間隔・数量差の不感帯・支持の確認時間は全数量政策で共通に固定する。値幅候補の総当たりはしない。

追加・カバーを含む各実玉には新しい実建値からの最大逆行幅を置く案とする。旧Sourceの遠い停止線をそのまま新玉へ引き継ぐ問題は00156で確認済み。幅と親の総時価リスク限度は登録前に明記し、確定した小利益を無制限に新しい損失予算へ戻さない。数量が減っただけの少損失は効率改善と区別する。

## 両建てと減枚を同じ純数量へ対応させる

状態を次の四層に分ける。

1. `SourceState`：元S01の独立仮想親・方向・通常退出。実側の損益を元へ戻さない。
2. `PolicyState`：長短支持、基準方向、回復極値、希望元玉／カバー数量、間隔・親リスク。全候補共通の当時観測だけ。
3. `CanonicalBook`：保護やカバー解除の判断に使う仮想の元玉・カバー玉。両建て版と縮小復帰版の判断時計を同じにするため共有定義する。
4. `ExecutionBook`：実所有ID・建値・実数量・予約・返済配賦。両建て版は両側を保持し、対応版は `q買−q売` だけを実保有する。

同じ指示列を、反対玉の新規／返済へ写す版と、元玉の減枚／復帰へ写す版で比較する。0枚でもCanonicalBookは止めず、その後の判断を同じにする。実現損益を政策へ戻すと両者が別の判断列になるため、この形式対照では戻さない。

同じ売買キャッシュフローを保ち、建て・返済の区分だけ付け替えれば、終端flat収支と中値時価は一致する。ただし場内の全玉BBO清算時価は一致しない。Hの重複数量を `h=min(q買,q売)`、気配幅をs、倍率をVとすると、同キャッシュフローの純建玉版よりHのBBO時価は `h×s×V` 悪い。BBOの最悪時価・DDを完全同値とは置かない。

差引目標だけを執行して相殺往復を省く実行版では、売買キャッシュフロー自体が変わり、終端収支も気配差分だけ異なり得る。こちらは同原行の純数量経路を検査し、中値変化の寄与と省いた約定の気配差を別に再会計する。余分な往復だけで差が説明できたら、その結論を採用する。数量上限と予約競合によって純数量が一致しなかった場面も別記する。

未約定中は約定済みと数えず、両側の新規予約を上限へ含める。返済予定を空き枠とみなさず、返済実約定後に追加する。両建てと縮小復帰の写像が一括注文模型でしか一致しない場合、その制約を明記し実運用保証へ広げない。

## 必須の場内評価と支障

各原行で `確定収支＋買玉Bid評価＋売玉Ask評価` を計算する。場末収支に加え、場内最悪時価収支、最大時価DDと山/谷の時刻、最悪含み、最大gross/net数量、両建て時間、元玉/順行追加/逆行追加/カバーの寄与を残す。勝ち場数、平均/中央/最大赤字、上位3黒字除外、初回からの順逆行も従来どおり併記する。

- 00153では強いMA傾きの後の追加が赤字を増やした。速度・直近価格進行と同一視しない。
- 00151では利益カバーの回転増で新規172→696回、赤字4→12夜、最大赤字16.4→43万円。利確金額だけを改善としない。
- 00067の同判断比較では、両建てより縮小復帰が終端気配差・手数料分だけ良かった。今回は費用0でも気配差と全時価を残す。
- 同一Source制約は元の入場時刻を改善しない。今回の数量政策が有効でも、S01の入口精度が上がったとは言わない。
- 現S01は整数miniと担当別の独自予算・部分返済を持つ。実Quantityだけ無造作に10倍して継ぎ足すより、独立仮想Source＋新ExecutionBookへ分ける方が安全。
- スコアの数式、尺度、間隔、最大逆行幅、総時価リスク限度、全担当競合時の配分順はまだ凍結していない。この文書だけで金融再生してはならない。
