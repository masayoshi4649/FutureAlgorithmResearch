# 既存候補1の早期保護比較

最初に見る資料は `早期保護の比較.json`。元の候補1と出口だけを変更した10条件を、旧15セッション・問題の09月30日ナイト・全16セッションに分けている。

読む順序は、比較JSON → `条件の事前固定.json` → `完了.json`。各場の損益は `sessions`、注文・決済は `ledgers`、検算と因果検査は `audits`、期間集計は `summaries` に保存。

全条件で、初回の時刻・方向・価格・枚数・準備時ATRと、次の入口を許す元通常影の時計が一致する。初回はTOPIXミニ5枚・NK225マイクロ10枚、片方向上限10枚・20枚。途中の悪化時半減・復元なしという数量ルールも同じ。早く退出しても元通常影の次の入口まで休むため、この比較は再エントリー回転数を増やす実験ではない。

出口は旧売買エンジンを改変せず、初期ストップ・トレーリングの発動と幅・建値保護・時間による見切りの設定だけを変更した。既存の2ATR部分利確、3ATR以降の幅0.75ATR上限、360分上限、場内返済は維持する。新20モード版とは別の実験である。

設定を更新する行で既に返済線を通過していれば、過去の良い価格に遡って約定させず、次の観測価格で返済する。指定価格約定・費用ゼロという従来の前提は共通。

初期損切幅を0.75ATR・0.5ATRへ狭めても、実口座の既存R集計は初回枚数×1ATRのまま。売買に使った初期幅は台帳の `config.stop_atr`、集計の比較尺度は1ATRとして分離している。既存統計器へ渡す `risk_config.stop_atr=1` はこの尺度の表現であり、売買幅を1ATRへ戻す操作ではない。

E09の「建値保護」は、基準影の収支ゼロ水準へストップを引き上げる意味。途中の減量損益によって実口座と影の収支は異なり得るため、実口座全体の収支ゼロを保証するとは説明しない。

各取引組の入口が同じなので、元勝ち組の収支差・元負け組の収支差を直接比較できる。損失を減らした金額だけでなく、伸びたはずの利益を早い退出で失った金額も含めて判断する。今回を見た後の再探索であり、未見試験ではない。
