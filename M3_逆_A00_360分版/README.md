# M3_逆_A00_360分版の損益

最初に **[損益.html](損益.html)** を開きます。

1. TOPIXミニ・NK225マイクロのセッション別損益と週別合計。
2. 必要に応じて「１回の保有枚数」「検証区分」「時間帯」を切り替える。
3. 更新するときだけ、以下の手順を確認する。

## データを追加したら

同じセッションの次の６ファイルを、これまでと同じ形式で保存します。ナイトのファイル名は開始日です。

- `book/TOPIX/YYYY-MM-DD_Day.jsonl` と `book/NK225/YYYY-MM-DD_Day.jsonl`
- `candle_1min/TOPIX/YYYY-MM-DD_Day.csv` と `candle_1min/NK225/YYYY-MM-DD_Day.csv`
- `candle_5min/TOPIX/YYYY-MM-DD_Day.csv` と `candle_5min/NK225/YYYY-MM-DD_Day.csv`

ナイトは `Day` を `Night` に置き換えます。プロジェクトルートで実行します。

```powershell
python "M3_逆_A00_360分版/更新.py"
```

実行後、[損益.html](損益.html) を開き直します。追加・変更されたセッションを自動検出して再計算します。同じデータで繰り返しても二重計上しません。HTMLを開くだけではデータの再計算は行いません。

必要なファイルが揃わない、セッションの末尾まで収録されていない、読み取り中に原本が変わった場合は「集計待ち」に分けます。両銘柄の信号を使うため、片方だけのデータでは新しいセッションを確定集計しません。原本は読み取りのみです。

## 集計の読み方

- 利益・損失は決済した玉の金額合計。収支＝利益−損失。途中の含み損は別の概念です。
- 枚数は累計決済枚数。枚数差＝利益枚数−損失枚数。損益０枚数も別掲します。
- 固定枚数を一度に新規・全返済します。TOPIXミニ１〜10枚、NK225マイクロ１〜20枚。再エントリー可能なので累計決済枚数は上限を超えます。
- 表示枚数を変えると金額・決済枚数を比例換算します。売買時刻・取引回数は同じです。
- 週別合計は、その週の収録済みセッションの合計です。ナイトは開始日の週へ計上します。
- 9月21〜25日は条件調整に使ったデータ。9月28日以降は条件固定後の検証として区別します。
- 費用０・指定価格約定。従来のラージの価格系列を使い、TOPIXミニは１ポイントの変動につき1,000円、NK225マイクロは指数１円の変動につき10円で換算します。

## 固定条件と保存先

[固定条件.json](固定条件.json) にV0800・S00・最長360分の条件を保存します。データ追加時の再探索は行いません。条件や計算コードを変えた別手法の成績は、この台帳へ混在させません。

[セッション損益.json](セッション損益.json) が固定１枚基準の集計台帳です。[表示生成.py](表示生成.py) はJSONからHTMLだけを再生成します。通常は `更新.py` だけを実行すれば両方を更新します。

更新処理は、このプロジェクトの既存の `work` 内の計算コードを参照します。更新用キャッシュ・検算は `work/wave_v21` に保存します。このフォルダだけを別の場所へ移しても再計算はできません。HTML単独での閲覧は可能です。
