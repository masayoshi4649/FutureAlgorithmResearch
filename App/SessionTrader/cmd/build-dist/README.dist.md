# SessionTrader 配布版

**1つの起動で1商品だけを売買します。** 判断には、選んだ商品にかかわらずTOPIX・日経225のラージ板を使います。

このフォルダの [conf/settings.toml](conf/settings.toml) を編集し、実行ファイルを**引数なし**で起動します。Windowsは `sessiontrader.exe`、Linuxは `./sessiontrader` です。他の商品の配布先は [商品一覧](../README.md) から開けます。

| フォルダ・`market.product` | `trading.instance_id` | 片方向上限 | 日中ID | 夜間ID |
|---|---|---:|---|---|
| `TOPIX` | `topix` | 2枚 | T06 | T04 |
| `TOPIXmini` | `topix-mini` | 10枚 | T06 | T04 |
| `NK225` | `nk225` | 2枚 | T06 | U06 |
| `NK225mini` | `nk225mini` | 2枚 | T06 | U06 |
| `NK225micro` | `nk-micro` | 20枚 | T06 | U06 |

新規配布は全商品 `dryrun=true` です。TOPIXラージ・日経ラージ・日経ミニの上限2枚は主担当1枚・補完1枚の準備値で、実運用の推奨枚数ではありません。既存の実設定は更新時も保持します。

主担当1枚では日中の部分利確・悪化時の半減が行われないため、研究時の初回5枚・10枚から損益を単純に倍率換算したものではありません。

主担当・未参加補完は各々上限の半分（端数切捨て・最低1枚）を基準とします。細かな係数は手法IDに含まれる標準値を使います。複数商品を動かす場合は、対象の商品フォルダからそれぞれ起動します。

```toml
[startup]
action = "run"
```

操作は `[startup]` で選択します。`action="run"` は運転、`"check"` は設定検査、`"probe"` は読み取り接続検査、`"migrate_legacy"` は旧台帳の移行です。通常は連続運転です。時間制限や旧版移行用の項目は、必要な場合だけ追加します。

設定は13項目です。時計は日本時間で、`us_open_jst="23:30"` と `london_extra_jst="01:30"` は冬時間基準です。夏は米国・英国それぞれの切替日に従って自動で1時間早めます。旧設定の海外時刻キーは互換読込のため意味を変えていません。詳しくは [仕様](docs/仕様.md) を参照してください。

端末の作業ディレクトリにかかわらず、実行ファイルの隣の `conf/*.toml` だけを読みます。`conf` がなければ停止します。`.toml.sample` は参照用です。

エラー時は理由を画面と `log/error.log` に残します。Windowsで直接起動した場合はEnterキーを押すまで画面を保持します。既存のPowerShell・cmdから起動した場合、入出力を転送した場合、Linuxでは確認待ちをしません。保存時と異なる上限枚数などを指定した場合は、対象DBと保存値・現在値を表示します。

初期設定は `dryrun = true` で、実注文を送信しません。実注文は `[trading]` の `dryrun = false` と `[startup]` の `action = "run"` で有効になります。

`instance_id` は小文字ASCII英数・`_`・`-`の1〜64文字です。`docs/仕様.md` に設定例と旧版の移行手順を記載しています。旧版で2商品を有効にした設定は、そのまま起動できません。

状態は `data/{dryrunまたはlive}/{instance_id}/` のSQLite、約定は `log/{モード}/{instance_id}/{商品}/` のセッション別CSV・JSONLに残ります。再起動時は実行ID・保存先・SQLiteを維持してください。上流の注文・約定・建玉IDで所有を照合し、結果不明の注文は自動再送しません。

相対保存先は実行ファイルのフォルダが基準です。別商品用に複製する場合は実行ファイルと `conf` をコピーし、商品・枚数・実行IDと夜間手法ID（TOPIX系はT04、日経系はU06）を変えます。既存の `data`・`log` を複製して並行運転しないでください。

同一OSユーザー・同一一時領域・controller URL・商品・モードの二重起動は拒否します。別ユーザー・別ホスト・別一時領域やURL別名では排他できないため、同一商品を重複運転しないでください。

約定がなくても既定30秒ごとに受信・判断時刻、枚数、待機理由を表示します。寄前の「採用0行」は正常です。日中の方向準備は08:45開始の場合、最短でも概ね09:50までかかります。

更新時は実行中のアプリを自動停止しません。配布の再作成は各商品フォルダの実行ファイル・説明書・設定サンプルを更新し、既存の実設定・`data`・`log` を保持します。運転済みの実行IDも変更しません。

親のOS別フォルダ直下には一覧READMEと5商品フォルダだけを置き、共通の実行ファイル・`conf`・`docs`・旧 `conf-topix`・`conf-nk` は再生成しません。旧配置の状態を使う場合は [旧版からの移行](docs/仕様.md#旧版からの移行) を参照してください。
