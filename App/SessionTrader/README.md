# SessionTrader

**1つの実行ファイルで1商品を売買します。引数は不要です。** 実行ファイルと同じ場所の `conf/*.toml` を読みます。判断にはTOPIX・日経225のラージ板を同時に使います。

00131の比較候補を日中・夜間で切り替え、基準手法と独立した初回追加を動かします。既知データの比較候補であり、実運用で同じ収益になることは未確認です。

## 商品別の起動

配布物は次の5商品について、実行ファイル・`conf`・`docs` を含む商品別フォルダを用意しています。売買する商品の `conf/settings.toml` を編集し、そのフォルダの実行ファイルを起動します。

| フォルダ・`market.product` | `trading.instance_id` | 片方向上限 | 日中ID | 夜間ID |
|---|---|---:|---|---|
| `TOPIX` | `topix` | 2枚 | T06 | T04 |
| `TOPIXmini` | `topix-mini` | 10枚 | T06 | T04 |
| `NK225` | `nk225` | 2枚 | T06 | U06 |
| `NK225mini` | `nk225mini` | 2枚 | T06 | U06 |
| `NK225micro` | `nk-micro` | 20枚 | T06 | U06 |

新規配布の設定は全商品 **dryrun=true** です。新しく追加したTOPIXラージ・日経ラージ・日経ミニの上限2枚は、主担当1枚・補完1枚を準備するための値であり、実運用の推奨枚数ではありません。既存のTOPIXミニ・日経マイクロの実設定は保持します。

主担当1枚では日中の部分利確・悪化時の半減が行われません。研究時の初回5枚・10枚から、損益を単純に枚数倍した運用とは異なります。

Windowsの配布先は [dist/windows-amd64](dist/windows-amd64/README.md)、Linuxは [dist/linux-amd64](dist/linux-amd64/README.md) です。複数商品を動かす場合は、対象商品の実行ファイルをそれぞれ引数なしで起動します。例えばTOPIXミニと日経マイクロなら次の2つです。

```text
.\TOPIXmini\sessiontrader.exe
.\NK225micro\sessiontrader.exe
```

Linuxは `dist/linux-amd64/{商品名}/sessiontrader` を起動します。設定の探索先は実行ファイルの場所で固定し、端末の作業ディレクトリが違っても変わりません。そこに `conf` がなければエラーとし、他の場所を探しません。

OS別フォルダの直下は一覧の `README.md` と上記5商品フォルダだけです。共通の実行ファイル・`conf`・`docs`・`conf-topix`・`conf-nk` は配置しません。

すべての操作は設定の `[startup]` で選びます。

```toml
[startup]
action = "run"
```

`action="check"` は設定検査、`"probe"` は読み取り接続検査、`"run"` は運転です。初期設定は **dryrun=true**。通常は連続運転です。必要な場合だけ `startup.duration_seconds` を追加し、dryrunの運転時間を秒で制限できます。終了は `Ctrl+C` です。

通常の設定は **13項目** に絞り、配布物の `conf/settings.toml` にまとめています。通信待ち時間・保存先・商品規格・係数は内部の標準値を使います。ソース直下の `conf` は `system.toml`・`markets.toml`・`algorithm.toml` に分かれています。どちらも `*.toml` をまとめて読みます。

主担当・未参加補完はそれぞれ片方向上限の半分（端数切捨て・最低1枚）を基準にします。同時保有は両担当と他媒体の実建玉を含む片方向上限で制限します。

時刻は日本時間で設定します。米国基準は冬の23:30、TOPIX夜間補完は冬の翌01:30で、米国・英国の夏時間にはそれぞれ自動で1時間早めます。昼夜の手法は `methods.day`・`methods.night` のIDで選びます。従来と同じ売買条件を名前で指定する変更です。

`instance_id` は小文字ASCII英数・`_`・`-`を使い、1〜64文字で指定します。再起動時は同じIDと保存先を使います。旧形式で2商品を有効にした設定は起動を拒否します。旧版からの状態移行は[仕様](docs/仕様.md#旧版からの移行)を参照してください。

## 記録と復旧

相対保存先は実行ファイルのフォルダが基準です。商品別フォルダ内に次の記録が作られます。

| 保存先 | 内容 |
|---|---|
| `data/{モード}/{実行ID}/market.sqlite` | 受信した市場情報・判断材料の正本 |
| `data/{モード}/{実行ID}/{商品}.sqlite` | 発注意図・約定・所有建玉・復旧状態 |
| `log/{モード}/{実行ID}/market/` | 市場入力と詳細記録 |
| `log/{モード}/{実行ID}/{商品}/` | セッション別約定CSVと詳細記録 |

実注文は生のKabuStation APIリダイレクトへ送ります。永続化した注文識別子と上流の注文・約定・建玉IDで、自分の建玉だけを管理します。受付だけで約定扱いにせず、結果不明の注文は再送しません。**再起動時はSQLiteを削除しないでください。**

別商品用フォルダを作る場合は実行ファイルと `conf` を複製して、商品・実行ID・枚数と夜間手法ID（TOPIX系はT04、日経系はU06）を変更できます。既存の `data`・`log` を複製して同時運転しないでください。

同一OSユーザー・同一一時領域・controller URL・商品・モードの二重運転は、保存先を変えても拒否します。異なるユーザー・ホスト・一時領域や同じcontrollerを指す別URLまでは排他できないため、同一商品をその組合せで重複運転しないでください。

約定がなくても既定30秒ごとに受信・判断時刻と待機理由を表示します。寄前の「採用0行」は異常ではありません。日中の方向判定は当場の足を使い、08:45開始なら最短でも概ね09:50以降です。

実注文を開始する場合は対象設定の `dryrun=false` にして通常起動します。最初に[仕様](docs/仕様.md)、詳細は[運転と保存](docs/運転と保存.md)・[APIと注文照合](docs/APIと注文照合.md)・[アルゴリズム](docs/アルゴリズム.md)を参照してください。

配布物は `go run ./cmd/build-dist` で生成します。開発時は `go build -o sessiontrader.exe .` の後、アプリ直下の実行ファイルを起動します。`go run .` は一時実行ファイルの隣に `conf` がないため、運転用途には使いません。

配布の再作成は各商品フォルダの実行ファイル・説明書・設定サンプルを更新し、既存の実設定・`data`・`log` を保持します。OS直下の共通実行ファイルや旧設定フォルダは再生成しません。運転済みの商品は `instance_id` と既存DBをそのまま使います。旧配置からの引継ぎは[仕様](docs/仕様.md#旧版からの移行)を参照してください。

実controllerでのdryrun・復元・約定記録と自動試験の範囲は[検証結果](docs/検証結果.md)に記載しています。
