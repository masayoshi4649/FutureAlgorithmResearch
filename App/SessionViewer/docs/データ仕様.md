# リンク列挙とJSONLの仕様（第1版）

原板は既存ファイルを参照し、標準JSONLには約定だけを保存します。表示時に保有と損益を復元するため、毎ティックの価格や含み損益を二重保存しません。`.jsonl.gz`も読めます。

## 1. リンク列挙ファイル

拡張子は `.resources.json`。画面からこのファイルを選ぶだけで、リソースごとの5グラフを開けます。

```json
{
  "schema_version": 1,
  "resources": [
    {
      "id": "nk-day-baseline",
      "title": "日経・日中・基準",
      "symbol": "NK225",
      "session": "2026-10-27_Day",
      "product": "NK225micro",
      "method_id": "NK225_D164_15",
      "point_value": 10,
      "pnl_format": "trades",
      "pnl_basis": "gross",
      "pnl_path": "アルゴリズム調査/00169_セッションと売買経路の可視化/data/基準.trades.jsonl"
    }
  ]
}
```

- `id`は列挙ファイル内で一意。`symbol`は判断用原板の`NK225`又は`TOPIX`、`product`は枚数の単位です。
- `session`は`YYYY-MM-DD_Day`又は`YYYY-MM-DD_Night`。日本時間の日中08:45〜15:45、夜間17:00〜翌06:00を扱います。
- 原板は`data_root/{symbol}/{session}/book.jsonl`。別ファイルは任意の`market_path`で指定し、相対パスは`data_root`基準です。
- `pnl_path`及び画面のサーバー列挙ファイル指定の相対パスは、TOMLの`resource_root`基準。列挙ファイル自身の置き場所には依存しません。ブラウザから読み込んでも同じです。
- 任意の`path_base: "catalog"`を一覧の先頭へ指定すると、`pnl_path`は一覧ファイルの親フォルダ基準になります。サーバー上の一覧パスが最優先。生JSONのアップロードでは一覧内の絶対`base_dir`を使い、両方なければエラーです。原板の基準は変わりません。省略時は従来の`resource_root`基準を維持します。
- TOML内の相対ルートは実行ファイルのフォルダ基準です。LinuxではTOMLの2ルートだけを差し替え、列挙内は`/`区切り相対パスを共用できます。
- `point_value`は1価格単位・1枚当たりの円。約定形式では必須です。数量は`product`の実枚数で、micro100とmini10を同じ100枚と表示しません。
- `pnl_basis`は`gross`（手数料前）又は`net`（JSONLの各手数料を控除）。価格以外の独自費用も確定値を表示したい場合は後述の状態形式を使います。
- 約定形式の任意の`entry_method_id`は、新規時の手法に属する`position_id`の全行を抽出します。返済時の手法が異なっても落としません。同じJSONLを合計・手法別で共用できます。`method_id: "*"`は表示上の「全手法（合計）」で、実注文に使う手法IDではありません。

## 2. 標準：少量の約定JSONL

1行1約定片又は管理外移管。必須項目は`id,timestamp,type,position_id,qty`で、約定には`price`も必須です。

当場開始時の保有は0とし、当場の全約定を入力してください。途中だけ抜き出した約定から開始前の保有を推測復元する形式ではありません。

```jsonl
{"id":"f1","timestamp":"2026-10-27T09:00:00+09:00","type":"LongN","position_id":"p1","price":65000,"qty":10,"method_id":"NK225_D164_15","source_line":1000}
{"id":"f2","timestamp":"2026-10-27T09:02:00+09:00","type":"LongR","position_id":"p1","price":65020,"qty":4,"fee_yen":0,"source_line":1200}
```

- `LongN`買い新規、`LongR`買い玉返済、`ShortN`売り新規、`ShortR`売り玉返済。返済の売買方向と建玉方向を混同しません。
- `Detach`は指定数量を管理対象から外す記録です。例：`{"id":"d1","timestamp":"2026-10-27T10:00:00+09:00","type":"Detach","position_id":"p1","qty":6}`。価格を省略し、手数料は0。確定損益は変えず、以後の保有・含みからだけ除外します。返済・利確・損失の解消ではなく、管理外玉と手動決済の後続損益は図へ含めません。
- `id`は約定片ごとに一意。`position_id`で返済対象を明示し、FIFOで推測しません。同ID同方向への追加は加重建値。新規より前の返済・異方向・過剰返済・ID重複はエラーです。
- `qty`は正の整数。部分返済は同じ`position_id`を指定して減らします。複数対象の返済は対象ごとに行を分け、手数料を重複させないでください。
- `timestamp`は時差付きRFC3339。ファイルの行順を保持し、時計後退を勝手に並べ替えません。`source_line`は任意の原板物理行番号で、同時刻の前後関係を対応させたい時に指定します。
- `fee_yen`は省略時0、非負。同じ約定片の手数料です。`net`では新規手数料も即時に累積確定損益へ反映します。
- 含みは買い玉をラージBid、売り玉をラージAskで評価。不正・欠測気配では不明、保有0なら0です。mini/microの実際の約定可能価格とは区別します。
- 同時計の原板と約定に`source_line`の対応がなければ、同時計内の順序は不明と表示します。不明な未来側の気配で入口時点の含みを補完しません。
- 表示範囲の右端には、その時点以前の最後の既知状態を補助点として付けます。保有枚数・累積確定損益は表示右端まで維持し、最終観測時計より後の保有中の含みは`null`、保有0なら0です。含みは観測板による評価であり、未受信期間の現在値を保証しません。後続の板や同時計内の不明な順序で過去を埋めません。

## 3. 互換：状態JSONL

`pnl_format`を`snapshots`にすると、外部で計算した値をそのまま表示します。

```jsonl
{"timestamp":"2026-10-27T08:45:00+09:00","sequence":1,"long_qty":0,"short_qty":0,"realized_pnl_yen":0,"unrealized_pnl_yen":0}
{"timestamp":"2026-10-27T09:00:00+09:00","sequence":2,"long_qty":10,"short_qty":0,"realized_pnl_yen":0,"unrealized_pnl_yen":null}
```

数量・累積確定損益・含み損益を必要な変化時だけ保存します。含みの不明は`null`。初行前・末行後・明示的な`null`は0埋めせず、含み損益も再計算しません。同時刻は行順/`sequence`を保持します。極値だけの記録を連続した全実績として扱わないでください。

## 表示・API

価格・売保有・買保有・累積確定損益・含み損益の5段を同じ時間範囲で表示。数量と損益は階段状、損益のY軸はそれぞれ正負対称で中央0です。元データは保持し、画面へ送る点だけを表示幅に合わせて極値を残して縮約します。ズームで必要範囲を取り直します。

一覧内の`symbol → session → method_id`を個別に選択できます。同じ組合せに複数資源があれば`id`で区別します。選べる損益資料はリンク列挙に登録された範囲です。

`interval=raw|1|5|15`で足を指定します（既定`raw`）。分足の価格は全原行からOHLCを集計し、`price=last|mid|bid|ask`で対象を選びます（既定`last`）。縮約済み価格からOHLCを作りません。派生Midは正常な`Bid < Ask`の時だけ計算し、Last・Bid・Askの原価格はそれぞれ独立して扱います。時刻はJSTの時計分に整列し、区間は`[開始,終了)`、場の終端だけ最後の足へ含めます。セッション境界をまたいで合算しません。

分足の保有枚数・確定損益・含み損益は各区間の最後の状態です。区間終了時刻にプロットし、カーソルにはどの区間の末値かを表示します。区間末の値が不明なら`null`を保ち、平均・最大・合計には置換しません。区間内の一時的な保有・含みの変動はrawで確認してください。価格の観測がない足はOHLCを埋めません。収集中の未完の足は観測済み部分の暫定値です。

応答に`interval,candle_price,candle_columns,candles`を追加します。ローソクの列順は`[t,end_ms,open,high,low,close]`で、`t`は区間開始です。`states`は従来の列順を使い、分足時の`t`は区間終了です。表示範囲が足の途中で切れても、その足は同じ全区間から集計した値を返し、画面の範囲でクリップします。新しい保存データは不要です。

| API | 用途 |
| --- | --- |
| `GET /api/info` | 接続・ルート・初期列挙ファイル |
| `GET /api/sessions?symbol=NK225` | 原板のセッション一覧 |
| `POST /api/catalogs/load` | `{"path":"...resources.json"}`又は`{"catalog":{...}}`を読込 |
| `GET /api/data?catalog=ID&resource=ID&from=ミリ秒&to=ミリ秒&width=1200&interval=5&price=last` | 選択リソース・表示範囲・足種 |
| `GET /api/data?symbol=NK225&session=2026-10-27_Day` | 原板の価格のみ |
| `GET /api/resources?catalog_path=一覧パス` | GETでリソースを列挙 |
| `GET /api/chart?catalog_path=一覧パス&resource=ID&interval=1` | 画像・数値のURL、指紋、出所と約定 |
| `GET /api/chart.png?...` / `GET /api/chart.svg?...` | 同じ5段グラフの画像 |
| `GET /api/openapi.json` | AI・外部ツール用の読取API仕様 |

`catalog_path`は数値・画像APIでも直接指定できます。同時に`catalog`は指定しません。画像の大きさや更新時の指紋照合は[画像API](画像API.md)を参照してください。

共有URLは`/?catalog=列挙ファイルの相対パス&resource=リソースID&interval=5&price=last`。エラーは`{"error":"説明"}`で返します。画面とGoサーバーはREST APIで分離し、グラフライブラリのCDN、原板コピー、ディスクキャッシュを必要としません。
