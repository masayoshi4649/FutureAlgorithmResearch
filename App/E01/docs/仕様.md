# E01 注文プログラムの仕様

## 目的と取引対象

kabus-controller を唯一の市場データ・注文接続先として、1銘柄の E01 を継続実行します。Python・機械学習・ローカルの過去相場ファイルは必要ありません。既定は `TOPIXmini`、片方向上限10枚、初回5枚、dryrun です。

取引商品は `NK225` / `NK225mini` / `NK225micro` / `TOPIX` / `TOPIXmini` から1つ選びます。方向判断には常に NK225 と TOPIX の両市場を使い、発注対象・価格・損益倍率には選択商品を使います。mini / micro の観測値はラージと同一とは限らないため、従来のラージ価格による理想検証と売買時点・損益が変わる場合があります。

## 入口・途中・出口

| 段階 | 既定の動作 |
|---|---|
| 方向 | 確定1分足の短期・長期 EMA と傾きで方向を決め、NK225 と TOPIX の方向が一致した場合だけ新規を許可 |
| 入口 | 最良買気配・売気配の中値の短期変化が方向を支持した後、安値から0.25 ATRの反発で買い、高値から0.25 ATRの反落で売り |
| 損切り | 初回 ATR と枚数を基準に組全体の損失を制限。早期出口の損失幅は既定0.75 ATR。実約定後の価格・保有枚数も別に照合 |
| 利益の確保 | 2 ATRの順行で一部返済。1.5 ATRの順行から追跡を始め、通常3 ATRの幅を、3 ATRの順行後は0.75 ATRへ短縮 |
| 途中の悪化 | 順行到達後に新しい短期逆行情報が出た場合、保有を一度だけ減らす |
| 時間 | 最長360分。返済後は既定5分待機。終了時刻の既定10分前からセッション内返済を進める |

ATR は確定5分足から計算します。形成途中の足は使わず、足の確定後の待機時間と実際の取得時刻を守ります。相手市場も過去時点の指標を使い、同一秒の板を後から知ったことにしません。起動直後は必要な足と短期板の蓄積を待ちます。

途中の減量で、その後の E01 の入口・出口系列が変わらないように、内部では通常条件・早期出口条件を並行して計算します。実際の保有数量は別に管理します。これは複数口座の売買や両建てではなく、判断のための内部計算です。現 E01 は追加建てを行わず、初回枚数以下で保有・部分返済します。

## 設定

`-conf` で指定したフォルダ直下の `*.toml` をファイル名順に結合して読み込みます。既定は `conf`。同じテーブルの重複、未知のキー、型不正、初回枚数の上限超過などは起動時エラーです。設定の変更は再起動後に適用します。

配布版は `dist` に実行ファイルと `conf/*.toml.sample` を配置し、未作成の `conf/*.toml` もサンプルから生成します。サンプルは読み込み対象外です。`go run ./cmd/build-dist` で Windows / Linux amd64 を再ビルドできます。配布元には独立したサンプルを使い、ソース側の実用設定を複写しません。既存の配布先の実設定・記録・状態は保持します。

既定の設定パスは作業ディレクトリ基準なので、配布版は `dist` へ移動して起動します。この場合の記録・状態は `dist/log`・`dist/state` です。従来のソース側設定・保存先を使い続ける場合は `-conf ../conf` を指定します。

| ファイル | 主な設定 |
|---|---|
| `conf/trade.toml` | 取引商品、片方向最大枚数、初回枚数、dryrun、仮想約定方法 |
| `conf/strategy.toml` | `[E01]` の入口幅・損切り幅・部分利確・トレール・保有時間と、`[FEATURE]` のATR/EMA期間・公開待機・方向閾値 |
| `conf/system.toml` | controller の URL、取得・再接続間隔、価格鮮度、通信断猶予、終場前返済、保存先 |
| `conf/products.toml` | 参照する指数系統と、現APIに存在しない商品の呼値・円換算倍率 |

`TRADE.InitialQuantity = 0` は `MaxPositionPerSide / 2` の切捨て、最低1枚です。TOPIXmini 上限10なら初回5枚、NK225micro 上限20なら初回10枚になります。決済後の再エントリーは可能です。実注文の新規は口座内の同一銘柄・同一方向の他媒体建玉も含めて上限を確認し、手動建玉を返済して枠を空けることはしません。

`TrailStartATR` はトレール開始と、順行後の悪化減量を有効にする到達幅の共通設定です。既定係数を変えた設定の成績は、従来の E01 の検証結果と区別します。

`E01.SessionWarmupSeconds` と `FEATURE.warmup_seconds` はセッション開始からの準備時間（既定1200秒）、`RUNTIME.WarmupSeconds` は起動後の短期板の準備時間（既定120秒）です。`EntryCutoffSeconds` は強制返済時刻より何秒前に新規を止めるか（既定300秒）、`EntryPendingSeconds` は新規トレールの待機上限（既定300秒）です。`ShadowRiskATR` は通常影、`ActualRiskATR` は実建玉の追加損失予算で、どちらも既定1 ATRです。

## controller との役割分担

| 情報・操作 | 使用する API |
|---|---|
| 登録済み銘柄ID・限月・市場 | `GET /api/v1/sys/registrations/future` |
| 現在セッションと注文・建玉状態 | `GET /api/v1/orders/future?scope=all` |
| NK225 / TOPIX の確定足 | `GET /api/v1/history/{code}/candles/1min`、`5min` |
| 両参照市場と選択商品の生板（重複を除く） | `WS /kabusapi/websocket` |
| 条件成立後の新規・返済 | `POST /kabusapi/sendorder/future` |
| 既知の未完了注文の取消 | `PUT /kabusapi/cancelorder` |

銘柄ID、限月、営業時間、controller の認証情報を E01 側で再設定しません。セッションの開始・終了・送信窓はAPI応答を使います。異なるセッションや世代の足を混ぜず、切り替わったときは新しいセッションとして処理します。controller の休日・登録設定をこのプログラムから変更しません。

新規・返済とも全5商品で透過先物APIの**成行・FAK**を使います。E01 が条件成立を判定した後に送り、controller 側で再び価格条件の成立を待つ方式にはしません。発注は controller の共有送信経路を通ります。

- NK225micro：通常市場の日中23・夜間24。controller から得た当該セッションの市場を対応変換します。
- その他4商品：当該セッションのSOR市場33・34。

FAK は約定できた分を残し、未約定残を失効させる指定です。発注数量どおりの約定や判断価格での約定を保証する指定ではありません。SORの対象限月など、証券会社側の受付条件にも従います。

## dryrun と実注文

| モード | 約定と記録 |
|---|---|
| dryrun / `observed` | 選択商品の観測価格で仮想約定。注文APIへ送信しない |
| dryrun / `specified` | 条件価格で理想約定。価格指定のない返済は観測価格を使用 |
| 実注文 | 上流注文番号を保持し、注文の約定明細と建玉IDを照合して確定数量・価格を記録 |

`observed` も板を実際に消費するシミュレーションではなく、部分約定・滑り・手数料を再現しません。実注文では受付応答だけで保有枚数を増減せず、一部約定を含む照合結果を戦略へ反映します。注文の結果が確定するまでは、重複する判断を進めません。

送信前に発注意思を保存します。応答喪失や送信中の再起動では、同じ注文を自動で再発注しません。注文番号を取得できた場合はその番号で照合し、取得できなかった場合は似た注文から所有権を推測せず、確認が必要な状態として停止します。controller 再起動後もこの原則を守ります。

返済対象はこのプログラムの新規約定から対応を確認できた建玉だけです。手動取引・他アプリの建玉を自動的に取り込みません。

選択銘柄に別媒体の未完了注文・未発動予約があれば新規を見送ります。口座照会そのものの更新時刻にも、`AccountMaxAgeSeconds`（既定15秒）の上限を設けます。同じ口座・同じ商品を他プログラムが同時に増減させる運用では、その間の注文競合をこのプログラム単独で排他できません。

新規のFAK未約定残は追いかけません。返済は注文終了を照合してから未約定残だけを新しい意図として送ります。価格差による実現損益・残枚数は実約定に合わせ、二つの影は判断時の価格系列を保持します。部分新規でも損失予算は元の初回枚数基準です。実約定価格からすべての影を作り直す戦略ではありません。

## 通信断・終了・再起動

短いネットワーク切断は再接続を待ち、古い価格を新しい価格として扱いません。既定の価格鮮度は30秒、中断判定60秒、再接続猶予180秒です。長い中断では短期判断の根拠を蓄積し直します。実注文は新鮮な価格・接続・注文・建玉情報が揃っている場合に限ります。

板PUSHの受信と、最後の約定価格の時刻は別に管理します。板が届いているのに最後の約定が古いだけの場合、通信断として強制返済しません。その古い価格での新規・仮想約定は見送ります。nullの価格・時刻も除外して継続します。短い中断では建玉・返済条件を維持し、欠測をまたぐ短期根拠だけ破棄します。180秒を超える板中断や世代変更では、復旧後の有効価格で返済し短期準備をやり直します。

停止・終場前の実成行返済は、新しい約定PUSHを待たず、口座・接続状態が揃えば時計監視からも送ります。このとき損益に使うのは確認できた実約定価格です。dryrunの時計返済には鮮度内の観測価格が必要です。

セッションをまたぐ計画的保有はしません。終場前と通常停止時には保有返済を進めます。ただし通信断・市場停止・結果不明・未約定があれば、返済できたことにはせず、未返済を記録して確認を求めます。終場後の過去価格を使った帳尻合わせはしません。

`state` は注文台帳・所有建玉・戦略状態・約定記録の正本です。同じ設定と保存先で再起動すると復元します。設定不一致や破損は拒否し、同じ保存先の二重起動はOSロックで防止します。設定違いの比較には保存先を分けます。

送信結果が不明で注文番号もない場合は、証券会社・controllerの注文と建玉を確認して整合を解決する必要があります。未知の注文を推測で引き継ぐ機能や、確認せず状態を消して再開する機能はありません。監視・トレールはE01プロセス内で動くため、E01停止中も証券会社で継続する逆指値注文を置く仕組みではありません。

## CSV

| 立会 | 実注文 | dryrun |
|---|---|---|
| 日中 | `log/2026-10-02_Day.csv` | `log/2026-10-02_Day_dryrun.csv` |
| 夜間 | `log/2026-10-02_Night.csv` | `log/2026-10-02_Night_dryrun.csv` |

夜間の日付は立会開始日です。約定がないセッションにも見出しを作ります。CSV は UTF-8 で、約定確認時刻、銘柄、新規/返済、買い/売り、枚数、価格、実現損益円、理由、発注意思・上流注文・約定の各IDを含みます。実現損益は返済済み分だけで、費用と未実現損益を含みません。

記録はまず正本へ保存し、CSV を再構築します。CSV 書出し中の中断後も正本から復元し、同じ約定IDを重複計上しません。CSV を直接編集しても再生成で置き換わるため、集計・加工はコピーに対して行います。
