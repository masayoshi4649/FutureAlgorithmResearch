## 現時点の結果

金額は万円。ラージ１枚、両建ては買い１枚＋売り１枚。各脚の往復費用を２ティックと仮定し、費用を倍にした４ティックの結果も比較した。

|方式|NK225収支|TOPIX収支|NK225・費用倍|TOPIX・費用倍|
|---|---:|---:|---:|---:|
|① 方向検知＋反発・反落待ち＋広い追跡返済|+189|+62|+177|+56|
|方向検知＋固定損小利大|+91|+57.5|+51|+45.5|
|板由来の方向検知＋小損切りと追跡|+192|+55.5|+180|+49.5|
|両建て＋固定利確|+79|+36|+11|+16|
|両建て＋勝ち脚追跡|+101|+25.5|+77|+15.5|
|片側コイントス・100通り平均|約+19.87|約+7.63|約−2.83|約−1.02|

方向検知は24系統を中心に13,006条件、両建て108条件、片側コイントスは同じ108条件について100通りの方向乱数を比較した。①は各銘柄６取引、計12取引。そのうち９取引はセッション終盤の時刻返済で、保有中央値はNK225約358分、TOPIX343分だった。

①の全期間の利益は良好だが、５セッションを見て条件を選んだ成績である。最初の４セッションだけで選び直すと別の条件が選ばれ、9月23日デイのNK225は−54万円だった。また①のNK225は確定損失ゼロでも、１分終値評価で最大29万円の含み損、セッション内の資産高値から最大32万円の低下があった。

## 再現

プロジェクトルートで次を実行する。Pythonとnumpy・pandasが必要。APIへ接続せず、実注文も送信しない。

```powershell
python -X utf8 ./アルゴリズム調査/00001_波検知と売買ポイントの調査/手法1を再現.py
python -X utf8 ./アルゴリズム調査/00001_波検知と売買ポイントの調査/図解HTMLを生成.py
```

１本目は条件を選び直さず①を再生し、保存した全12取引との一致を確認する。２本目は保存版の５分足と取引明細からHTMLを生成する。保存版内の旧スクリプトは原形を保った記録であり、全探索をそのまま単独実行する場合は生板原本や過去の監査入力も必要になる。今回の再現用入口は上記２本とする。

元の[検証結果](保存版/work/wave_v5/検証結果.md)は保存当時の文章を維持した。今回の詳細説明では「新規時ATR」を**新規注文の待機開始時に固定したATR**と明確化し、`signal_time`も**注文に採用した１分足の確定時刻**と説明している。売買条件・収支を変更したものではない。

`保存ファイル一覧.csv` と `整理完了記録.json` は番号付きフォルダへ整理する前の記録であり、記載パスは保存当時のもの。現在の配置と入口は、このREADMEと[作業一覧](../README.md)を参照する。
