# D07・D03の売買条件

入口の土台はTG04です。基本担当5枚、追加担当3枚、別入口担当2枚を独立管理し、空き枠の貸借はしません。日経miniの片方向合計上限は10枚、全玉を場内で返済します。以下は元のTG04から変えた部分です。

## 昼：基本は利益返しを抑え、追加担当で取り直す

**基本担当＝P01。** 利益を伴う部分利確が実際に約定した後から、残玉の含み益の最高値を記録します。その最高含み益が正で、現在の含み益がその50%以下へ戻ったら、残りを全返済します。判断後の次の正常気配で約定するため、半分の利益を保証する注文ではありません。

この早期全返済後、同じ親取引への追撃は止め、次の新しい入口を待ちます。基本担当が同じ波へ何度も入り直す方式は、今回のP01には含みません。

**追加担当＝V05。** 初回の損切り幅Rと、利益を取る幅Uを分けます。Uは入口時に公開済みのATRから `max(80pt, min(R, 1.5×ATR))` として固定。1U順行したら利益玉から半数を切り捨てて返済し、残りは1.5Uの戻り幅で追尾します。1枚だけなら部分返済はしません。

取り直しには、直前の利確位置から0.75Uの有利な押し戻り、その極値から0.25Uの再進行、自己30秒・120秒の方向支持が15秒続くことを要求します。直前の利確価格より不利な取り直しを拒否し、条件を満たせば1枚追加。その回転玉自身が1Uの利益へ進めば返済して、再び条件を待ちます。既存の損失予算と3枚上限は維持します。

別入口担当は元のCS04を維持します。

## 夜：基本の残玉だけを短縮し、ドテンは長短の向きを確認

**基本担当＝R05。** 元の利益トレーリングが全返済を指示した場面で、他玉の確定利益を予算に1枚だけ残す元の仕組みを維持し、その追尾幅に160ptの上限を加えます。元の3Rが160ptより狭ければ、元の幅を使います。初回から全ての玉を160ptで切る変更ではありません。

**追加担当＝V16（D07）／V10（D03）。** Uによる利益追尾と、全利確後の再参加を使います。黒字の全退出後は最低60秒待ちますが、それだけで発注せず、元の入口が再成立するか、押し戻り・再進行と短期支持を確認します。損切り後は元の停止条件を引き継ぎます。60秒が普遍的な最適値だという結論ではありません。

ドテンは、旧玉の全返済後、5分差・120秒差が逆方向、価格が公開20分平均の逆側、30秒方向も逆向きを15秒確認してから、新しい親として発注します。**D07はさらに、公開40分差も新方向を支持することを要求**します。D03には最後の40分確認がありません。この追加確認はドテン経路だけで、通常入口を一律に40分方向で禁止する条件ではありません。

別入口担当はCS04の長い残玉保持を維持します。この担当まで短くすると、大きな順行を捨て、逆張りの新候補を解放して悪化したためです。

## 共通の優先順位

元の損切り・静観時間・場末返済を維持し、利確後の追加や反転より優先します。将来の高値・終値を判定に使わず、新規も返済も判断後の次の正常な売買気配を使います。旧基本源に残る場末時刻の例外と影響額は[検証の範囲](検証の範囲.md)に分けて記録しました。

実装の対応は、昼 `CG_P01 + A_V05 + CS_R00`、夜D07 `CG_R05 + A_V16 + CS_R00`、夜D03 `CG_R05 + A_V10 + CS_R00` です。[固定構成](../../work/research145_roles/役割別構成145.json)と[実装](../../work/research145_roles/run_roles145.py)に対応します。
