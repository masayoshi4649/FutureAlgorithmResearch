E01 リアルタイム仮想トレード

kabus-controllerの板PUSHと確定足で判断し、新規・返済をCSVに残し続けます。

10/02修正：無約定を通信断と誤認しない。3分以内の切断では建玉・返済条件を維持。

追加修正：start.pyでWindows・Linux共通の起動。セッション切替時の価格時刻nullは除外して継続。

1. 起動する

このフォルダでターミナルを開き、次を実行します。

Windows

python start.py

Linux

python3 start.py

Ctrl+Cで終了処理。実行中は市場データを受信し続けます。

Python 3.11以上と依存ライブラリが必要です。導入方法・引数はREADMEへ。別フォルダからファイルのパスを指定しても実行できます。Linux実機での運転は未検証です。

2. 記録を見る

起動後に作られる 運転記録 フォルダを確認してください。

ファイル内容
売買記録.csv新規／返済・時刻・方向・枚数・価格・理由・確定損益
稼働記録.csv受信中断・復旧・セッション切替・停止
現在状態.json建玉、受信状況、直近の判断材料

再起動で引き継ぎます。同じ保存先の二重起動は禁止。CSVが開かれていても正本DBに保存し、後でCSVへ反映します。

3. 売買ルール

入口両市場の主方向が一致。短期の板価格も支持したら、0.25ATRの反発・反落で入る。
途中2ATRで一部利確。順行後の短期逆行でも一度半減する。
出口初期損切り0.75ATR。利益を追跡し、3ATR順行後は追跡幅を0.75ATRにする。
枚数TOPIXミニ換算5枚／NK225マイクロ換算10枚。追加なし。上限は片方向10枚／20枚。

通常影による再参入待機も移植。注文器は同じ判定材料を使った過去17セッション×両銘柄で旧E01と完全一致。

運転上の扱い

確定済みで実際に受信した情報だけを使用。途中起動では指標を準備してから開始し、起動前の売買は作りません。

短い切断では新規だけを一時停止し、復旧価格で既設の返済条件を確認します。毎回120秒待つことはありません。3分超の無受信・世代変更は別扱いです。

同じ保存先で起動し直すと修正版へ移行します。旧台帳は自動でバックアップします。セッション終端まで返済できなければ未返済を記録して異常停止します。

既定は費用ゼロ・指定条件価格の仮想約定。大型先物の価格をミニ／マイクロの倍率へ換算します。
