## 起動

このフォルダでターミナルを開き、実行します。終了するまで継続監視します。Windowsでは次を使います。

```powershell
python start.py
```

Linuxでは次を使います。PowerShellは不要です。

```sh
python3 start.py
```

別フォルダからは `python /path/to/start.py` のようにファイルのパスを指定できます。標準保存先は常に `start.py` と同じフォルダの `運転記録` です。`--output` に相対パスを指定した場合は、コマンドを実行したフォルダが基準です。

この環境ではPython 3.14.3とwebsocket-client 1.9.0で動作を確認しています。別環境ではPython 3.11以上を用意し、このフォルダで `python -m pip install -r requirements.txt`、Linuxでは `python3 -m pip install -r requirements.txt` で依存を導入してください。Linuxの実機運転は未検証です。引数一覧は `python start.py --help`（Linuxでは `python3`）で確認できます。

**実注文機能はありません。** 接続先は `http://10.10.100.1:8080`。登録済み銘柄の照会・1分足と5分足のGET・受信専用WebSocketだけを使います。APIキーや証券口座の情報は使用しません。

## 記録

標準の保存先はこのフォルダ内の `運転記録` です。検証時に使用した `検証記録` とは別です。

| ファイル | 内容 |
| --- | --- |
| `売買記録.csv` | 新規・返済の時刻、セッション、商品、方向、枚数、価格、理由、確定損益、処理後枚数 |
| `稼働記録.csv` | 起動、セッション切替、受信中断、復旧、停止、エラー |
| `現在状態.json` | 10秒ごとの建玉・指標・受信数・新規待機・CSV出力状態 |
| `状態と売買.sqlite3` | 売買と建玉を同時に確定保存する正本。再起動・CSV修復に必要 |

CSVはUTF-8 BOM付きです。同じ保存先で起動し直すと記録を引き継ぎます。同じ保存先の二重起動は拒否します。CSVをExcelで開いて書込みが阻害された場合も正本に保存し、CSVを閉じた後に再出力します。**正本やCSVを運転中に編集しないでください。**

## 手法・枚数

直前まで検証していた **E01** を移植しました。機械学習やGPUは使いません。

| 項目 | 内容 |
| --- | --- |
| 新規 | 両市場のEMA15/60による主方向が一致し、板の最良気配中値の30秒変化がその方向を支持した後、0.25ATRの反発・反落で入る |
| 最初の枚数 | TOPIXミニ換算5枚、NK225マイクロ換算10枚 |
| 片方向上限 | TOPIX10枚・NK20枚。E01は追加しないため実際の最大は5枚・10枚 |
| 初期損切り | 0.75ATR。元の1ATR損失予算も監視 |
| 部分利確 | 2ATR順行で元枠の半分（TOPIX2枚・NK5枚）。既に返済した枠は二重に返済しない |
| 途中 | 通常影が1.5ATR順行した後、新しい短期逆行が出たら残す元枠を一度半減。復元なし |
| 利益追跡 | 1.5ATRから追跡、通常幅3ATR。3ATR順行後は幅を0.75ATRへ短縮 |
| 終了 | 最長360分。デイ15:35・ナイト05:50に返済条件を設定し、次の新鮮な観測で返済 |
| 再エントリー | 通常影が終了して5分待機。E01が先に全返済しても直ちに入り直さない |

ATRは確定5分足のTRを1/12で平滑化します。1分足は開始から120秒、5分足は開始から360秒経過し、かつ実際に受信した後だけ使用。相手市場の方向はさらに60秒待ちます。新しい条件は次の価格観測から有効です。

既定の `specified` は過去検証と同じ費用ゼロ・指定条件価格での仮想約定です。新設時点で通過済みの返済条件には次の観測価格を使います。`observed` を選ぶと通常の条件成立時も観測価格で約定します。

```powershell
python start.py --fill-mode observed --output ./観測価格版の記録
```

**大型NK225/TOPIX先物の価格を参照し、ミニ／マイクロの倍率で損益を換算します。ミニ／マイクロ自身の板での約定検証ではありません。**

## 継続運転と中断

- 起動時は現在セッションの確定足で指標を準備します。起動前の売買は記録せず、短期データを最低120秒観測してから新規を許可します。セッション開始直後はEMA60等が揃うまで待機します。
- 受信した順で判断します。短期特徴の時計を過去検証の時刻代理から実受信時刻へ変更しているため、全セッションを事後再生した損益との完全一致を約束するものではありません。途中起動の通常影も、その起動時点から開始します。
- 接続状態は銘柄ごとの**板PUSHを受信した時刻**で判定します。最後の約定から30秒を超えていても、板が届いていれば通信断にはしません。古い約定価格での仮想売買は見送ります。
- セッション切替で届く価格・価格時刻がnullのPUSHは除外し、次の有効価格を待ちます。足4系統のセッション情報が欠損・混在した場合も再取得します。既存建玉を架空の価格で返済せず、旧セッションの未返済検査は維持します。
- 実際のWebSocket切断、または板PUSHが60秒途絶えたときは新規だけを一時停止します。**180秒以内なら建玉・固定ATR・ストップ・通常影を保持**し、復旧後に条件判定を続けます。毎回120秒の準備をやり直しません。欠測を跨ぐ古い価格差を新しい30秒の入口根拠には使いません。
- 復旧後の最初の有効価格が既設ストップ等を越えていたら、**その観測価格**で返済します。CSVの約定モデルは `observed_recovery`。欠測中の価格経路や有利な約定を作成しません。
- 板PUSHを180秒超観測できない場合、またはcontrollerの世代変更等で連続性を失った場合は、復旧時に観測価格で返済し、短期指標を120秒準備し直します。猶予は `--reconnect-grace-seconds` で変更できます。
- `Ctrl+C` で終了処理に入り、新しい観測価格で返済を試みます。15秒以内に価格が来なければ建玉を保存して終了コード2で停止します。短時間の再起動は建玉・条件を維持し、長時間の停止は上記の長期欠測として処理します。
- データが届かずセッション終端まで未返済の場合は**異常として停止**します。前セッション終値や次セッション価格で返済したことにはしません。稼働記録と正本に未返済が残ります。
- PC・プログラム・通信が動いている間だけ監視できます。サービス登録や自動起動は設定していません。
- 今回は確認済みの旧版署名に限り、`更新前_日時.sqlite3` を作成してCSV・建玉を引き継ぎます。その他の未確認の戦略変更では、従来どおり状態の混在を拒否します。修正は起動し直したプロセスへ反映されます。

## 動作確認・再現

```powershell
python -m unittest discover -s papertrade -t . -p "test_*.py" -q
python start.py --seconds 180 --output ./試運転
```

Linuxでは上記の `python` を `python3` に置き換えます。試運転も条件が成立すれば仮想売買します。経過秒数0が連続運転です。異常終了時は終了コードをそのまま返し、例外が起きた場合は発生箇所も標準エラーへ表示します。過去データとの一致検証は[検証用](検証用)内に隔離してあり、通常運転は `work` の研究コードや保存済み相場データに依存しません。
