# E01連敗の原因・市場の性質・新手法の検証

最初に **[連敗原因と新手法の検証.html](連敗原因と新手法の検証.html)** を開く。

読む順序は、①市場と手法の性質、②連敗の原因、③比較済み手法の説明と各場損益、④30分区間の確定＋含み損益。詳細はHTML内で開閉・選択できる。

保存23セッション（2026/09/21〜10/06デイ）を対象とする。今回の追加4場は10/02ナイト、10/05デイ・ナイト、10/06デイ。過去研究で閲覧済みのデータであり、真正未見ではない。

## 今回の進め方

前半に行った条件比較269設定の結果と失敗も保存している。後半はユーザーの指示に従い、損益順位で手段を選ぶ追加探索を停止した。状態を現在の情報で固定して、価格の継続・反転・板圧力の持続性を調べる。未来価格は結果の測定にだけ使い、状態の閾値を成績で選び直さない。

## 数量・損益

- TOPIX miniは片方向上限10枚、初回5枚。NK225 microは上限20枚、初回10枚。
- 今回の比較候補は増玉なし。両建ては片側ごとに5枚／10枚で、両脚を必ず集計する。
- ラージの保存価格をTOPIX miniの1pt=1,000円、NK225 microの1pt=10円へ換算。mini／micro自身の約定再現ではない。
- 費用0。E01派生方式は元の指定価格約定、独立96方式と注文60方式は判断後の次有効観測価格で約定。この前提差を戦略の差だけと解釈しない。
- セッション返済期限はデイ15:35、ナイト05:50。後続原本行で返済し、対象全口座の場末0を確認した。
- 利益／損失枚数は返済数量の累計で、同時保有枚数とは異なる。損失金額は絶対値表示。
- 時価収支は「その区間の確定収支＋終了含み−開始含み」。30分区間合計は場損益と一致する。

## 再実行

このフォルダの `start.py` からも実行できる。`--task report` はレポート、`--task properties` は性質の測定とレポート、`--task trace` は生板トレース、`--task intervals` は30分会計。Pythonのnumpy・pandas・numba等と、既存研究の入力キャッシュが必要。

```text
python start.py --task properties
```

プロジェクトルートで実行する。今回の成果生成は既存研究キャッシュと全23場の保存データを参照する。

```text
python -X utf8 work/wave_v51/build_report.py
python -X utf8 work/wave_v51/raw_trace/trace.py
python -X utf8 work/wave_v51/raw_trace/verify.py
python -X utf8 work/wave_v51/interval_audit/run_all.py
```

1行目はレポート再生成、2行目は生板3方式の再生、3行目は原本指紋・ログ会計の確認、4行目は全11方式の30分会計を再生成する。原本の追加時には入力監査・公開足／ATRキャッシュ更新が先に必要であり、新しい原本を置くだけで未検証キャッシュを推測生成しない。

`raw_trace`は生JSONLの現在行から価格・時刻を読み、ATRだけその行に対応する既存の因果監査済み値を使う。未来配列は判断器に渡さない。`CurrentPriceTime`は約定時刻なので、板の実受信時刻や通信遅延までは復元していない。

「上下OCO」は研究内の呼び名で、買い・売りの二方向条件をスクリプトで排他監視する。kabus-controllerの同一売買方向を対象にしたAPI `method=oco`を、そのまま呼ぶ実装ではない。

現在APIへ接続せず、実注文を送らず、`App/E01`と旧00044レポートを変更していない。新条件を本番へ採用した成果ではない。
