# E01への回帰と改修

最初に見るファイルは [E01と改修の説明と全セッション損益.html](E01と改修の説明と全セッション損益.html)。

読む順序：

1. 主HTMLで元E01とR01の入口・途中・出口、全28場・後12場、各セッションの金額と枚数を確認。
2. [全16改修条件.html](全16改修条件.html) で単独変更と統合変更を比較。
3. [検証結果.md](検証結果.md) で約定前提と安定性の限界を確認。
4. 詳細を追う場合は [報告データ.json](報告データ.json)、[事前固定](../../work/wave_v67/事前固定.json)、[独立会計](../../work/wave_v67/audit/E01と改修全32条件の独立FIFO会計.json)、[接続器の因果検査](../../work/wave_v67/接続器の因果検査.json)。

初回はTOPIXミニ5枚・日経マイクロ10枚、片方向上限10枚・20枚。増玉なし。ラージ価格を小商品倍率で換算した研究で、小商品自身の実約定を再現するものではない。

元の00044は指定価格・費用0。今回、旧23場の全注文・決済・組を完全再現し、追加5場と手数料を加えた。発動行の観測値で建値から再運転する比較も残した。注文固定の売買気配置換は別の感度分析。

前16場だけで改修を選び、後12場も測定。ただし従来研究で後半にも既知データが含まれる。完全な未見試験と呼ばない。現在API取得・実注文0。App/E01と旧レポートは変更していない。

再現：Python環境でプロジェクトルートから `python -X utf8 work/wave_v67/study.py --model specified`、`python -X utf8 work/wave_v67/study.py --model observed`。保存済み結果は同じ入力口座数なら再利用する。`report.py` は表示と資料を再生成する。素材の原本変更がある場合は、新しい作業として固定からやり直す。
