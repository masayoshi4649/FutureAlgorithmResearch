# 00151：損切りなし・利益追尾・売買独立の固定再生仕様

実装は `engine_go/`、条件は `configs151.json`。原アプリ、00149・00150の凍結源と保存結果は変更しない。新しい金融再生は、試行登録成功と全指紋照合の後に親担当だけが実行する。

## 今回何を変えるか

00150 B04の独立した仮想運転が発注判断した新規通知を使う。実際に検証する在庫には元の損切り・方向反証・部分返済を適用せず、買いと売りを別IDで同時に保有できる。通常の返済は玉別の利益追尾だけで、終了時刻には損益を問わず全返済する。

B04の入口通知を使う条件は、仮想B04側の保有・損切り・再参加待ちによって入口機会が制限される。実在庫を利確した直後に仮想B04が次の入口を出すとは限らない。この制約を分離する4条件では、黒字返済した実玉の枠を40pt追尾新規へ戻し、元B04の次通知を待たずに反復できる。

00120は極値からの上下対称段階新規と利益玉回転を既に検証した。今回その入口一式は作り直さず、B04の入口と条件付き枠再使用を対象にする。旧結果には上限まで残る負け在庫・利益側を外した後の純方向・場末損失の問題があるため、確定利確だけでなく全玉時価を記録する。

## 原板・入口通知・因果順序

- 原資料は `../preus149/data/原資料一覧149.json` の完了25夜と取得済み10月26日途中。新API取得はしない。途中の範囲は同目録のcutoffまでで、疑似末尾精算をしない。
- B04の入力は `../preus150/results_round2/{session}.json`。`action=new` のID・担当・位相・方向・枚数・判断時計・原行添字・理由だけを `EntryNotice` 型へ取り出す。将来のfill・gross・exit・観測以後の価格は入口型にない。
- 末尾の `final_pending` に新規があれば同じ通知列へ含める。取消新規が示された入力は不完全入力として拒否する。固定26保存には末尾予約がなく、元再生器が発注済み全通知を次正常板で約定させたことも別途監査する。「将来約定できた通知だけ」を選ぶ処理にはしない。
- 原板のNK225採用添字は00149/00150と同じ0始まり。時計null・範囲外・時計逆行・非正/非有限Lastを除く。異常BBOは添字を持つ。市場ごとの `Features.Counts` なので、TOPIX原行数はNK225添字へ足さない。価格時計と売買成立時計を混同しない。
- 全通知で判断時刻とNK225原行添字を照合する。原行の正常BBOは有限かつ `0<bid<ask`。買いはask、売りはbidで、必ず判断原行より後の次正常原行に約定する。同秒でも別原行なら次行として扱う。
- 原B04の通知が同原行に複数ある場合は保存順。枠再使用も同じ行で候補になった場合は原B04通知を先に受け、その後に待機枠の作成順で受ける。

## 独立在庫と返済

1. 新規判断時に、実保有＋未約定新規が各方向10枚以下であることを検査する。返済注文中の玉は約定するまで保有のまま。原通知の拒否・縮小は後から復活させない。
2. 同じ新規通知の同価格・同時刻約定分を1ロットIDとして保存する。全枚数が同じ出口条件を持ち、そのロット全部を一度に返す。別通知・反対側・枠の次世代は別の建玉IDで、玉同士を平均建値に統合しない。
3. 買い玉の現在利益は `bid−買値`、売り玉は `売値−ask`。この返済可能価格で最高利益を追い、最高利益がA以上になって初めて追尾を有効にする。
4. `最高利益−現在利益>=T` で返済を判断する。利益玉限定条件はさらに現在利益>0が必要。P09/N05の通常追尾は、開始済みなら板飛びで現在利益が負でも返す。
5. 判断時に正でも次正常板が悪ければ赤字約定する。その損失を計上し、「利確だから必ず勝ち」としない。損切り、減速返済、方向反証返済、通常保有時間上限は設けない。

## 利益枠の追尾再新規

P10/P11/N06/N07だけに適用する。

- 利益追尾返済の**実約定損益が正**の場合だけ、同側・同枚数の未発注待機枠を作る。判断は黒字でも実約定が赤字なら作らない。場末・米国前の一括返済からも作らない。
- 返済fill行のLastを初期極値にし、その後の正常原行で買い枠は安値、売り枠は高値を更新。買いは安値＋40pt、売りは高値−40ptで新規判断し、次正常BBOで約定する。返済fillと同じ原行では再発火しない。
- 待機枠は未発注なので枚数上限へ予約計上しない。ただし発火時に同枚数を全て確保できなければ待機を残す。勝手に数量を分割せず、その後の正常行で再判定する。
- 枠IDごとに待機・未約定新規・実玉（返済予約含む）の1状態だけ。再利確後も次世代へ反復する。元B04の新しい入口通知は別枠で独立に受け付ける。
- 境界時刻には待機だけ解除する。既に発注判断済みの新規を未来の境界後価格で取り消さない。

## 米国前と場末

P群は米国開始15分前までのB04前半通知だけを使い、米国開始15分前に全返済を予定する。原行駆動なので、その時刻以上の最初の原行で返済判断し、次正常原行で返す。予定時刻・実判断時刻・完済時刻を別に保存する。

N群はB04前半・後半両方の新規通知を使い、米国前に在庫を清算しない。全夜を通じて片方向10枚を守り、翌05:50に全返済を予定する。境界をまたいだ発注済み新規は次正常板で約定し、その行で返済判断して、さらに次の正常板で返す。

P群の後半は00149 S04の保存約定を別の `ReusedPost` 型で再会計し、前半再生が終わってから加える。前半の全玉・全予約の完済時刻が保存後半の最初の新規判断時刻より**厳密に前**でなければ合算を拒否する。後半データは `step` の引数にしない。保存後半がない途中場は合算せず、現保有の気配時価を示す。

## 出力と会計

`results_go/{session}.json` に全条件をまとめる。

- `source_notices`：未来の結果を含まない元通知。
- `events`：新規・返済の所有ID、判断と約定の原行/原ファイル行番号・時刻・数量・価格・損益。
- `lots`：元枚数、残枚数、建値、最高/最低利益pt、返済情報、玉別確定損益。`slot_id` と `generation` で再参加を追跡できる。
- `pending` と `arms`：途中時点の未約定・未発注待機を分離。
- `decisions`：元通知の受理・縮小・拒否数量と理由。再参加の上限待ちは `reentry_cap_wait_rows`、新規判断回数は `reentry_new_count`。実約定回数はeventsから別に数える。
- `gross/profit/loss/unrealized`：今回変更した運転の確定収支・確定利益・確定損失・残玉時価。返済は各ロット全量なので新規ロットの完結会計と一致する。保存後半は部分返済があるため、正式比較の集計器で新規実約定IDへ返済を配賦する。
- `reused_post` と `combined_*`：保存後半と全夜合算の別会計。後半の未来収支は判断に利用しない。
- `minimum_equity`、`minimum_unrealized`、`maximum_drawdown` と各 `*_at`：全玉を気配清算した時価の悪化を毎原行で測定。該当原行・時刻・当時在庫・確定損益・含みを保存する。DDの出発点が初期現金0なら `index=-1`・場開始時刻で表す。
- 保有秒数・両建て秒数・片側上限滞在秒数・最大保有と予約数を記録。1分ごとと約定行の軽量時価snapshotも保存する。途中末尾以後の滞在を水増ししない。

**P群の時価DD・最低含み・保有率は変更した前半だけ。** 保存後半の未測定時価DDを加えて全夜DDと表示しない。後半の合算利益/損失は新規実約定ID単位へ揃え、旧レポートの親分類は上書きしない。
