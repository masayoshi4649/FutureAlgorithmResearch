# 転換点の検出と売買に関する独立監査

この作業は `00004` の追加検証であり、既存の v8 実装・結果・原本を変更しない。保存済みデータだけを使用し、現在セッションの API へ接続しない。

## 事前に固定する確認事項

- 移動平均の収束は転換準備の条件であり、それだけで売買方向を決めない。観測済みの傾きの反転、平均線の交差、収束帯からの離脱、板の偏りの反転など、方向を持つ初動を追加する。
- 「底・天井だった」と後から判定した時刻へ発注時刻を戻さない。左右の未来データを使う局所極値、中心移動平均、負の shift は使わない。
- 同じ転換イベントでは一度しか発注しない。返済、取消、期限切れの後も、次の転換イベントが発生するまでは同じイベントを再利用しない。
- 約定時計が同じ生板行も保存順序どおりに監視する。成立行と約定評価行を分離し、利益保護ストップの成立後に気配が飛んだ場合は、観測された不利な気配で約定評価する。
- 新規約定行の価格から、同じ行ですでに有利な高値・安値を通過したと仮定しない。保護注文は新規約定後の行から監視する。
- 初期損切り・追跡ストップは一度締めたら緩めない。収束・板反転の検出条件と出口条件を混同しない。
- 保存データが途中までのセッションは末尾で都合よく返済しない。未返済を確定損益から分け、通常セッションの返済締切を維持する。
- 各銘柄の保存順序は観測可能だが、二銘柄共通の受信時刻はない。相手銘柄を追加待機付きで参照する仮定と、その感度を明記する。
- 原本を途中で読むのを止めた場合と、全量を読んだ場合の過去の特徴、転換イベント、確定取引が一致することを検査する。

## 検査の限界

未来非依存の検査は、保存時刻が実際の受信時刻だったことや、本番の約定を保証しない。板の数量減少は取消と約定を区別できず、板フローは表示数量の変化の推定値として扱う。

## 手計算で照合する場面

1. 全行の最終約定時刻が同じでも、発注、条件成立、約定は別の生行になる。
2. 保有方向へ気配が進むと追跡ストップが締まり、その後の逆行時には、成立価格ではなく次行の最良気配で返済される。
3. ロング例を価格・方向とも反転させたショート例で同じポイント損益になる。
4. 古い新規逆指値の成立と新しい反対方向イベントが同じ行で重なる場合、古い注文の成立受付を優先し、後知恵で取消しない。
5. 返済締切に達した保有は次の生行で返済し、途中打切りでは最終行を人工的な返済としない。
6. ATRは5分足の確定後さらに1分待つ。全生板時点のATRをEWMAライブラリを使わない逐次式で再計算し、足自体の途中打切りも照合する。

## 実施結果

すべて保存済みデータで実施した。検査中の実装ファイル変更はない。

| 検査 | 対象 | 結果 |
| --- | --- | --- |
| 原本途中打切りからの転換イベント | 全12原本×2地点×自銘柄・相手銘柄、48比較、延べ5,041イベント | 全属性が完全一致 |
| ATRの独立再帰計算 | 全12系列、770,572生板観測時点 | 欠測位置一致、最大絶対誤差9.95×10^-14 |
| 足自体の途中打切り | 各系列2地点 | 過去ATRが完全一致 |
| 注文の手計算 | ロング・ショート、三出口、取消成立競合、締切・途中評価の10例 | 価格・生行順序・収支が一致 |
| 原本途中打切りからの確定売買 | 全15系統×両入口の代表30条件、1,440比較、延べ2,298確定取引、68,940属性 | 全属性が完全一致 |
| 約定価格からの損益再集計 | 5,118取引記録、1,080集計セル | 利益・損失・収支・勝敗・未返済数が一致 |
| 評価期間だけの収支改変 | 学習2〜5セッション×6群の24選択 | 学習時の全候補順位が不変 |

原本打切りの照合数は、同じイベント・取引を複数の条件や打切り点で照合した延べ数である。独立した取引機会数や新たな未見期間の数ではない。これらの検査は未来情報の混入と計算の整合性を確認するもので、将来収益の証明ではない。
