研究はラージの次正常原行気配を約定代理にし、アプリは発注商品のミニ／マイクロ気配を使います。受信時刻や価格源は異なりますが、**新規取引そのものが2回異なる点を、手数料差や単なる約定価格差だけでは説明できません。**

実装には、紙上の新規通知が出た時点で板・口座鮮度などが不適格なら実発注を見送り、同じ通知を後から自動再発行しない経路があります。これは候補原因です。当時の通知・見送り理由・板受信・設定を確認していないので、午後2件の原因と断定しません。判定の不一致を実運用の改善とも評価しません。

## 起動と場切替、理由表示

- **08:43の「採用0行」は正常な準備状態と整合。** 当場08:45より前の価格を判断に使わないためです。
- **15:45の「Night準備」はcontroller仕様と一致。** 保存先のセッション区分は15:45からNightになり、実際の夜間立会開始は17:00です。準備完了は売買開始の意味ではありません。アプリは当場開始前の価格を判断から除外します。
- **返済の「主担当の新規」は不適切な理由表示。** 提供された当日JSONLで返済区分`close`・理由番号`1`なのに「主担当の新規」と記録されていることを確認しました。日中の理由番号1は「組の損切り」です。約定方向・新規返済区分・損益は別の値で管理され、当該文字列が新規注文を意味するわけではありません。現行ソースでは昼夜・新規返済を分けた理由文へ修正済みです。

## 提供された実ログで確認できた範囲

指定フォルダにはCSV・JSONL合わせて8ファイルがありました。`market/2026-10-21_Day_dryrun.jsonl` は市場イベントではなくTOPIXミニの約定9明細、`NK225micro/2026-10-21_Day_dryrun.jsonl` は日経マイクロの約定9明細です。両方とも提示された標準出力と整合します。NightのJSONLは空、CSVは見出しのみです。

各約定には成立した判断の価格・指標・理由番号・入力IDが含まれます。ただし、不成立だった判断、発注の見送り、板・口座更新の中断を記録する`trace.jsonl`はこのフォルダにありません。そのため午後2件の欠落原因は引き続き未確定です。約定のない時間帯に判断も停止していたとは、この資料だけでは言えません。

提供された全18約定のCSV・JSONLは、時刻・商品・数量・価格・損益・理由・判断根拠が一致し、設定署名も共通でした。返済理由の誤表示4明細は、TOPIX11:03／11:19／12:21と日経10:30の理由番号1です。[提供ログの独立監査](../../work/logcompare132_20261021/provided_20261021/提供約定ログの範囲と新規欠落の監査.json)に記録しています。

**trace削除後の代替確認：** [journalの保存処理](../../../SessionTradeExecuter/internal/journal/journal.go)では`events`テーブルをSQLiteへ確定し、[ログ生成処理](../../../SessionTradeExecuter/internal/journal/projection.go)がその内容をtrace.jsonlへ書き出します。原板もmarket.sqliteの`books`に保存されます。ただし、ユーザーから当日の`market.sqlite`・`NK225micro.sqlite`も「ない」と回答があり、この経路での当時状態の確認はできません。
