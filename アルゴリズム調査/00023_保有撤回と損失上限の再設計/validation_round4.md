# 第４反復の敵対検査

最初に `反証規則の固定.json` を読む。新しい成績を見る前に数値基準を固定する。`反証実装の固定.json` は実行開始前にコードと入力の指紋を確定する。

対象は旧13セッションの96入口×288管理＝27,648条件だけである。現在セッションは読取・再試験・取得をしない。前三反復と現在一回照合の失敗を知って立てた仮説であり、未知期間の検証ではない。

入口stateと保有中の撤回方向contextを分離する。context_source=entryは別contextを渡さず従来と同じ挙動、mainは中期方向を渡す。基準と管理近傍には基準contextを用いる。時計・相手遅延・短期確認の近傍では変更specから入口と中期を両方再生成する。短期確認だけの変更で中期が不変であることも検算する。入口と中期のprefixを両方照合する。

時計窓・相手遅延の4条件、短期確認の閾値の2条件、入口幅の2条件、管理stop/trail/lock/timeout、損失・撤回制限を混ぜず判定する。時計4条件なら3条件以上が両銘柄黒字かつPF1.2以上。各カテゴリは有効条件の75%以上、各銘柄の中央値が元収支の半分以上、最悪値が元収支のマイナス25%以上を要求する。遅延1/5/15秒は入口と中期を両方遅延させる。観測価格約定を含む全4条件で両銘柄黒字・PF1.2以上を要求する。

損失・撤回制限はsession_budget_rとneutral_minを単独±20%、max_same_lossesを単独±1（下限1）で変形する。元値0は不使用として分母から除く。個別変数の成績も別に残す。session_budget_rは到達時の新規停止・次行返済の始動条件であり、次行の値飛びなどで損失が閾値を超えない保証ではない。

構造上使用しない値（成行入口幅、0の利益保護/時間上限、短期確認を使わない主方向のみ、単独F32の相手遅延）は分母から除外する。有効な変形でも今回の方向列が偶然同じなら、その件数・比率と台帳一致を表示する。時計小区分や個別管理変数の結果も分けて残し、平均値の裏で壊れる条件を隠さない。

探索上位30の異なる台帳と各信号思想の首位を最大75件まで検査し、合格から異なる信号思想・管理思想の組を最大10件、固定64seed×2の無予測対照へ進める。入口と中期を同じ30分乱数へ置換する。発火限定の場合、元state非ゼロで入口だけを絞り、中期は絞る前の乱数を用いる。真の中期予測を残さない。乱数の都合の良いseedを採らず正式な有意確率を主張しない。

方向反転・常時買売も両入力を同時に変更する。管理G08交換は従来管理としてcontext=Noneにする。`部品対照の事前注釈.json` に固定した「同じ退出規則でcontextだけentryに戻す」「損失制限だけ0にする」も全対象で表示する。これらは機構の診断であり、採用gateを追加したり有利な変形へ差し替えたりしない。

研究候補の選抜には、別途既定4波×2銘柄すべてで正方向ネット保有20分以上を要求する。一次反証通過と目的達成は分ける。選抜の追加条件は研究候補選抜の事前規則を参照し、このコードに現在照合機能は含めない。

費用0・指定価格約定を主条件として維持する。観測価格約定は費用とは別の補足耐性検査である。全玉合算、片方向保有限度、次観測以降の執行、場内返済を各再生で検算する。

実行順序:

1. `python work/wave_v28/validation_round4.py --rules-only`：結果を読まず数値規則だけ固定。
2. 信号コードと探索仕様が完成後、`python work/wave_v28/validation_round4.py --prepare`：実装指紋固定と合成検算。
3. 全探索終了後、`python work/wave_v28/validation_round4.py --workers 10`：固定候補へ一次反証。
4. `python work/wave_v28/validation_round4.py --workers 4 --random`：通過した思想へ64seed×2対照。

主結果は `一次反証の結果.json`、詳細は `adversarial/`、乱数要約は `無関係対照の要約.json`、全seedは `randomized/`。同じ反証実装指紋の結果だけを再開利用できる。
