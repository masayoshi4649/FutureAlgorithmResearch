# 赤字原因と改善案の検証

最初に見るファイルは **[赤字原因と改善案の検証.html](赤字原因と改善案の検証.html)** です。

読む順序：

1. HTML冒頭の赤字原因と代表比較。
2. 同じHTMLの方式選択から、各方式の説明・16セッションの利益／損失／収支と決済枚数。
3. 必要な場合だけ、折り畳んだ5分足図と機械的な条件の説明。
4. 詳しい数値は[全比較データ.json](全比較データ.json)、原因の証拠は[赤字原因.md](検証資料/diagnosis/赤字原因.md)。

対象は2026/09/21デイ〜09/30ナイトの16セッション。初回TOPIXミニ5枚・NK225マイクロ10枚、片方向上限10枚・20枚です。初回枚数と上限枚数は異なります。費用ゼロ・指定水準での約定を仮定し、場内に全玉返済。幅短縮時に既に通過した水準は次行観測価格で返済します。

既存候補1・2の見送り比較と、新しい追従／反復の試作器は分けています。後者には既存の減量・分割利確・通常影による待機がないため、差をモード切替だけに帰属させません。新条件は問題セッションを知った後の探索で、未見検証ではありません。00042の固定4手法や保存データは変更していません。API取得は0回です。

さらに既存候補1の入口を全件固定した早期保護10条件を比較しました。基準を含め、見送り26方式・新モード20方式・早期保護11方式、延べ57方式×32市場＝1,824口座。E01は初期損切り0.75ATRの損失軽減候補ですが、収支も下がります。採用済みという意味ではありません。

## 再現

作業領域は `work/wave_v49`。プロジェクトルートで以下を実行します。

```powershell
python work/wave_v49/chart_night.py
python work/wave_v49/modes/run.py
python work/wave_v49/early/run.py
python work/wave_v49/early/aggregate.py
python work/wave_v49/build_report.py
python work/wave_v49/verify_report.py
python work/wave_v49/publish.py
```

見送り再生の詳しい手順は[作業領域のREADME](../../work/wave_v49/gates/README.md)。特徴の閾値は[特徴定義](検証資料/modes/特徴定義.json)、新20方式は[事前固定書](検証資料/modes/方式の事前固定.json)。元データ、足・板のキャッシュ、原本行順を維持して再生します。

監査は[見送り比較の独立検算](検証資料/audit/見送り比較の独立検算.json)、[新モードの独立監査](検証資料/audit/自動モード実データの独立監査.json)、[人工経路](検証資料/audit/自動モード注文器の人工監査.json)、[特徴の未来参照検査](検証資料/modes/特徴監査.json)を参照してください。

早期保護は[条件の事前固定](検証資料/early/条件の事前固定.json)、[全比較と同一入口の差額](検証資料/early/早期保護の比較.json)、[独立監査](検証資料/audit/早期保護比較の独立監査.json)を参照してください。E09の「建値」は基準影の収支ゼロ水準であり、部分返済が異なる実口座の収支ゼロを保証するものではありません。

短縮した価格を既に通過したときの検算は[既成立注文監査](検証資料/audit/早期保護の既成立注文監査.json)。全方式の表切替と10,944セルの金額・枚数をブラウザ内で照合し、通常幅と狭い画面を確認しています。
